# 三进制互操作契约 v0（Ternary Interop Contract v0）

- **版本**：`0.1.0`（v0 冻结）
- **状态**：stable core 冻结；只允许向后兼容增补；破坏性变更走 v1 或新 profile。
- **适用范围**：`trit` 仓库内所有语言实现（Rust 参考实现、Go 参考实现、汇编验证、未来 C/C++/Lean 4/Java）。
- **规范用词**：MUST / MUST NOT / SHOULD / MAY，按 RFC 2119 解释。
- **Golden vectors**：[`interop/vectors/`](../vectors/)；格式见 [`interop/schema/vector.schema.json`](../schema/vector.schema.json)。

## 1. 目标与非目标

**目标**

- **语义统一**：`k3`、`kgate`、`pack5`、`belnap4` 四个 profile 的输入输出逐项一致。
- **字节统一**：pack5 的 trit 顺序、digit 映射、尾填充、非法字节处理一致。
- **可判红**：每个实现都能用同一组 golden vectors 做 conformance。
- **可演进**：新想法进 experimental profile，不污染 stable core。

**非目标**

- 不规定内存布局、寄存器布局、ABI、SIMD 指令。
- 不规定跨进程容器（v0 暂不纳入 stable core；见附录 A 的非规范性草案）。
- 不规定 SAT/BDD/ATPG 的算法或结果格式（它们不是 v0 profile）。
- 不规定语言特定的错误类型；只规定错误类别和必须拒绝的输入。

## 2. 一致性等级

- **Core conformance**：实现 MUST 通过 `k3`、`kgate`、`pack5` 的全部 vectors。
- **Belnap4 conformance**：实现 MUST 通过 `belnap4` 的全部 vectors（opt-in profile）。
- 实现可以只声明部分 profile；声明了就必须全过，不得跳过失败向量。
- 错误向量 MUST 返回结构化错误；不得 panic、不得静默钳位、不得返回默认值。

## 3. 通用 JSON 编码

- 文件 UTF-8，无 BOM；JSON 对象；不允许 NaN/Infinity。
- 语义值用字符串，不用数字枚举：
  - K3：`"F"` / `"U"` / `"T"`
  - Belnap4：`"N"` / `"T"` / `"F"` / `"B"`
- 平衡 trit 用整数 `-1` / `0` / `+1`；pack5 字节用整数 `0..255`。
- 数组顺序有意义；不要排序或去重。
- 每个 vector 文件包含 `spec_version`、`profile`、`encoding`、`vectors`。
- `id` 全局唯一、稳定；已发布 vector 不得重命名或改语义。

## 4. Profile: `k3`

### 4.1 值

`F`、`U`、`T`。`U` 是缺证据，不是概率 0.5，也不是 `F`/`T` 的别名。

### 4.2 运算真值表

**NOT**

| x | F | U | T |
|---|---|---|---|
| ¬x | T | U | F |

**AND（Kleene 强合取）**

| ∧ | F | U | T |
|---|---|---|---|
| **F** | F | F | F |
| **U** | F | U | U |
| **T** | F | U | T |

**OR（Kleene 强析取）**

| ∨ | F | U | T |
|---|---|---|---|
| **F** | F | U | T |
| **U** | U | U | T |
| **T** | T | T | T |

### 4.3 位平面编码

`F = (ones=0, unknown=0)`、`T = (1,0)`、`U = (0,1)`；`(1,1)` **非法**。

按位公式（`¬`/`∧`/`∨` 为逐位布尔运算）：

```text
false(x)    = ¬ones(x) ∧ ¬unknown(x)
and.ones    = ones(a) ∧ ones(b)
and.unknown = ¬(and.ones ∨ false(a) ∨ false(b))
or.ones     = ones(a) ∨ ones(b)
or.unknown  = ¬(or.ones ∨ (false(a) ∧ false(b)))
not.ones    = false(a)
not.unknown = unknown(a)
```

实现 MUST 拒绝 `(1,1)`；不得把它当 `U`、`T` 或 `F`。

### 4.4 Vectors

- [`k3.json`](../vectors/k3.json)：NOT/AND/OR 语义向量。
- [`k3_bitplane.json`](../vectors/k3_bitplane.json)：位平面 encode/decode 与 `(1,1)` 非法向量。

## 5. Profile: `kgate`

### 5.1 值

`required` 与 `verified` 都取 `F` / `U` / `T`；输出取 `F` / `U` / `T`。

### 5.2 准入表

| required \ verified | T | U | F |
|---|---|---|---|
| **F**（不需要） | T | T | T |
| **U**（需求未确认） | U | U | U |
| **T**（必需） | T | U | F |

这张表**不是** K3 蕴涵 `¬required ∨ verified`：当 `required=U`、`verified=T` 时，蕴涵会放行，本表仍为 `U`。

### 5.3 Vectors

- [`kgate.json`](../vectors/kgate.json)：9 个 `(required, verified)` 组合。

## 6. Profile: `pack5`

### 6.1 Trit 与 digit

平衡 trit `-1` / `0` / `+1` 映射为 digit `0` / `1` / `2`。

### 6.2 Pack

输入 `N` 个 trit；组数 `G = ceil(N / 5)`。每组 5 个 digit，低位在前：

```text
byte = d0 + 3*d1 + 9*d2 + 27*d3 + 81*d4
```

最后一组缺失的 trit MUST 用 `0`（digit 1）填充。输出长度 MUST 为 `G`。

### 6.3 Unpack

输入 `B` 个字节，`trit_count = N`；MUST 满足 `N <= 5*B`。每个字节 MUST `< 243`。按重复除 3 提取 5 个 digit，映射回 trit，输出前 `N` 个 trit。

### 6.4 错误

| 条件 | `expect_error` |
|---|---|
| pack 输入 trit 不在 `{-1,0,1}` | `invalid_trit` |
| unpack 字节 `>= 243` | `invalid_byte` |
| unpack `N > 5*B` | `short_input` |

### 6.5 Vectors

[`pack5.json`](../vectors/pack5.json)：

- `pack`：全部 243 种 5-trit 组合；
- `pack` 尾部：长度 1–4 的全部组合（尾填充 0）；
- `unpack`：全部 243 个合法字节（5 trit）；
- `unpack` 尾部：长度 1–4 的代表字节；
- 错误：非法字节 243–255、`short_input`、`invalid_trit`。

## 7. Profile: `belnap4`（opt-in）

### 7.1 值

`N`（neither）、`T`（true only）、`F`（false only）、`B`（both）。

位平面：`N=(0,0)`、`T=(1,0)`、`F=(0,1)`、`B=(1,1)`。与 K3 不同，`(1,1)` 在这里**合法**。

### 7.2 运算

```text
not:  truth' = falsity, falsity' = truth
and:  truth' = truth(a) ∧ truth(b), falsity' = falsity(a) ∨ falsity(b)
or:   truth' = truth(a) ∨ truth(b), falsity' = falsity(a) ∧ falsity(b)
```

### 7.3 Vectors

- [`belnap4.json`](../vectors/belnap4.json)：NOT 4 个、AND 16 个、OR 16 个。
- [`belnap4_bitplane.json`](../vectors/belnap4_bitplane.json)：4 个值的 encode/decode。

## 8. Golden vectors 格式

```json
{
  "spec_version": "0.1.0",
  "profile": "k3",
  "encoding": "semantic",
  "vectors": [
    {
      "id": "k3.not.F",
      "op": "not",
      "input": "F",
      "expected": "T"
    },
    {
      "id": "pack5.unpack.invalid.243",
      "op": "unpack",
      "input": 243,
      "trit_count": 5,
      "expect_error": "invalid_byte"
    }
  ]
}
```

规则：

- `expected` 与 `expect_error` 二选一；两者同时出现或都不出现均为非法 vector。
- `expected` 按 JSON 深度相等比较；数组元素顺序必须一致。
- `op` 是 profile 内的操作名；实现 MUST 拒绝未知 `op`，不得忽略。
- 错误比较只看 `expect_error` 类别，不看错误消息文本。
- Vectors MUST 由规范/真值表人工或脚本生成并评审；MUST NOT 用被测实现生成期望值来自证。

## 9. 版本与变更

- 当前 `0.1.0`。
- **增补**：新增 vectors、新增 profile、patch/minor 版本；已有 vector 的 `id`、输入、期望值 MUST NOT 改变。
- **破坏性变更**：新 major 或新 profile id；不得静默改语义。
- 每个 vector 文件的 `spec_version` MUST 与规范版本一致；runner MAY 接受同 major 的更高 minor。

## 10. 参考与优先级

- **Lean 4 为形式语义目标，Rust 为当前参考实现**。
- Lean 4 落地前：规范与 Rust 不一致时，以本规范为准，修 Rust 并补回归 vector。
- Lean 4 落地后：Lean 4 与本规范不一致时，以 Lean 4 的语义定义为准，更新规范/vectors/Rust。
- Vectors 是 conformance 的规范来源，不是 Rust 实现的导出物。

## 11. 附录 A：跨进程容器（非规范性，v0 不要求 conformance）

v0 只冻结语义与 `pack5` payload；跨进程容器留到 v0.2。草案：

```text
magic      4 bytes  "TRIT"
version    u16      little-endian
profile    u16      little-endian
trit_count u64      little-endian
payload_len u64     little-endian
checksum   u32      CRC32C of payload
payload    payload_len bytes (pack5)
```

在容器 vectors 补齐前，任何实现 MUST NOT 声称支持“容器 v0”。

## 12. 附录 B：实验 profile

新想法（Belnap 5/9 值、稀疏三值、压缩流、零拷贝 FFI 布局、GPU/WASM 共享缓冲区）MUST 使用新的 `profile` id，并在 `experimental/` 下提供自己的 vectors；不得修改 stable core 或复用已有 `profile` id。
