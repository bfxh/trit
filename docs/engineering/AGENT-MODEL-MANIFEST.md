# AGENT-MODEL-MANIFEST：前端 / 后端模型清单与双表面契约

状态：**契约草案**。本文和 [`agent-model-manifest.json`](agent-model-manifest.json) 是清单模板，不代表已经接入某个真实 provider、模型或插件；接入时只替换 `id`、`status` 和可验收能力，保留 `owner`、`modalities`、`must_not`。

目标：让前端模型、后端模型、智能体内核和插件各自看清自己的义务，不把“给人看的表面”和“给智能体读的清单”混在一起，也不把一次授权扩成永久职责。

## 1. 人类面与智能体面

| 表面 | 给谁 | 入口 | 内容 |
| --- | --- | --- | --- |
| `human` | 人 | GitHub README、面板、论文式看板、发布说明 | 名字、怎么用、是干嘛的；之后才是图、结论、限制、原始数据链接 |
| `agent` | 智能体 / 宿主 | [`agent-model-manifest.json`](agent-model-manifest.json)、回执、`GateReport`、结构化通知 | 稳定 ID、owner、能力、模态、状态、`must_not`、handoff、证据路径 |

**最外层不是智能体清单。** README 和面板是人的入口；智能体不得把 README 当机器契约，也不得把内部回执直接倒到人类面板上。人类面板也不得替代 `owner` / `status` / `must_not` 这些结构化字段。

## 2. 角色与默认义务

| 角色 | 默认负责 | 默认不负责 | 交给谁 |
| --- | --- | --- | --- |
| 后端模型 | 代码、复杂工程、高危工程、数学、后端产物、失败路径与测试 | 人类面板实现、图表/视觉叙事、论文排版、录像剪辑 | 前端模型 / 人类面板负责人 |
| 前端模型 | 人类面板、图表、图片、论文式布局、录像与可访问性 | 内核语义、后端核心代码、证据裁决 | 后端模型 / 内核维护者 |
| 智能体内核 | 任务 brief、能力门禁、owner 路由、结构化通知、产物交接 | 代替后端写核心代码；代替前端做面板 | 对应 owner |
| 插件 | 声明输入、输出、副作用、owner、失败关闭方式 | 静默降级、未声明的写操作、伪造指标 | 插件 owner |

`must_not` 默认拒绝。只有用户把跨角色动作明确写进任务 brief，才允许临时扩权；扩权必须单独标记 `explicit_override: true`，不能变成永久职责。

### 2.1 后端模型的硬边界

后端模型做：复杂工程、数学、可靠性、安全边界、失败路径、后端产物、测试、复现脚本，以及给前端的交接说明。

后端模型默认不做：人类面板、网页/桌面 UI、图表实现、论文排版、视频录制与剪辑；不为“看起来完整”补造对比数据；不把“需要前端”写成“后端做完了”。

任务只要后端产物时，正确交付是 **后端产物 + 一行 handoff 说明**，不是顺手把前端也做了。

## 3. 清单字段

[`agent-model-manifest.json`](agent-model-manifest.json) 使用 `trit.agent-model-manifest/v1`。必填字段：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定 ID，例如 `model.backend.primary`、`plugin.perf-benchmark-ab-dashboard`；发布后不复用 |
| `display_name` | 人类可读名字；不要只给数字编号 |
| `role` | `backend` / `frontend` / `kernel` / `plugin` |
| `owner` | 稳定责任角色；不写个人账号 |
| `status` | `required` / `planned` / `available` / `reference` / `unavailable` |
| `modalities` | `text` / `image` / `video` / `audio`；缺省视为不具备 |
| `capabilities` | 能做什么，必须能被复算或验收 |
| `must_not` | 默认不做什么；空数组也要显式写 |

`owner` 是智能体告诉后端“这是你的东西”的稳定依据。显示层可以换名字，`owner` 不能跟着改。

## 4. 多模态准入

1. 进入人类视觉表面的模型必须声明 `text + image`；缺任一模态，`eligible: false`，从候选清单剔除。
2. 论文式对比、实验录像、论文式证据必须声明 `video`；没有 `video` 的模型可以留在纯文本/静态图任务，但不得声称具备论文级证据展示能力。
3. 插件必须声明输入/输出模态；缺声明视为 `unavailable`，不进入推荐列表。
4. 多模态不止“能读图片”：人类面板还要求能把结构化结果转成图、表、录像和限制说明；做不到的模型不进 `human` 面的主候选。

## 5. 人类面板顺序

1. **名字**：人类可读名称，不用内部 ID 当标题。
2. **怎么用 / 是干嘛的**：3–5 行，说明入口、适用任务、不适用任务。
3. **身份与状态**：角色、owner、`available` / `planned` / `unavailable`、多模态徽标。
4. **视觉对比**：凡是对比，必须有图；表格只能作为图后的索引。
5. **论文式方法**：基线、当前、口径、样本数、平台、单位和判定规则。
6. **结果与限制**：强多少、差多少、是否复现、噪声、缺少什么。
7. **论文式录像**：实验/交互的录制链接或本地路径；没有录像的论文设计标记 `unrecorded`，不算完成。
8. **原始数据**：CSV/JSON/回执链接放最后，不把大表倒到首屏。

首屏不写背景长文，不堆未标注数字，不用“看起来很强”代替指标。人类先看到模型/插件现在是什么状态，再看到为什么、怎么样。

## 6. 对比、录像与证据

- **凡是比较，必须有图**：至少一张基线/当前对比图，标明方向、单位、样本数和判定阈值。
- **凡是论文式设计，必须录像**：屏幕录制、回放或可复现实验录像；没有录像就标 `unrecorded`，不得称“论文级证据”。
- 图不能伪造坐标轴、样本数或基线；没有数据时写 `pending` 和缺什么，不画假图。
- 录像不能替代原始样本；录像旁边仍要能追到 CSV/JSON 和 commit。
- 完成裁决仍归 `trit-orch` 的完成闸门和可信回执，不由面板自述决定。

## 7. 任务 brief 的最小字段

```text
TASK:        要做什么
OWNER:       model.backend.primary / model.frontend.collaborator / plugin...
SURFACE:     agent / human / both
DELIVERABLE: 产物路径或回执
MUST:        必须满足的约束
MUST NOT:    明确不做什么
DEFERRED:    现在不做但保留的事项
HANDOFF:     交给谁、交接什么、证据在哪
EVIDENCE:    测试、图、录像、原始数据
```

没有 `OWNER` 或 `MUST NOT` 的任务不进入执行；缺字段先补齐，不靠模型猜。

## 8. 意图边界

- 智能体只执行 brief 里的 `MUST`，不把“提到”扩成“要求”，也不把“暂时不做”缩成“没要求”。
- 默认严格只用于**代码质量与失败路径**：fail-closed、显式错误、测试失败路径、不静默降级；默认严格不用于扩大任务范围。
- 用户说“先做介绍，后面的对比不用搞”，正确动作是完成介绍并标 `comparison: deferred`，不是补造对比。
- 用户说“这不是你的责任”，正确动作是写 handoff，不是换个名字继续做。

## 9. 显示门禁与通知

- 能力是否可见走 `FeatureGate` / `GateReport`；人类面板先取门禁结果，再渲染。
- `locked` 的能力不显示入口；`disabled` 显示为关闭；`notices` 按 `owner` 路由，不向普通用户刷内部错误。
- 同一 `feature + reason.code` 进程内去重；发布说明汇总一次。
- 面板不得把内部路径、密钥、完整会话内容放进通知或截图。

## 10. 严格性

- 代码默认严苛，不因“演示”放宽：失败必须显式，降级必须可见，测试必须覆盖失败路径。
- 不写“应该”“大概”“可能已经”；不能证明的能力写 `unavailable` 或 `planned`。
- 不伪造指标、样本、录像、基线或 owner。
- 不用 `--update` 一类动作抬上限、洗白审计债；要腾空间就改结构或补证据。

## 11. 与现有模型路由的关系

[`AGENT-MODELS.md`](AGENT-MODELS.md) 解决“按角色选哪个模型、怎么派发、怎么留回执”；本文解决“这个模型/插件在人类面和智能体面分别承担什么义务”。两者不互相替代：路由配置是人的策略，清单是职责与表面契约。

## 12. 非目标

- 本文不是模型评测榜单；没有同口径数据就不排名。
- 不用 README 替代机器可读清单，也不用手写 JSON 替代运行时门禁。
- 不让后端模型默认承担前端面板，或让前端模型默认承担内核语义。
- 不把“多模态”当营销词；模态缺失就 fail-closed 剔除。
