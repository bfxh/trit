# 一篇文档必须有什么

> 定位：写给往 `docs/` 加文档、或改既有文档的人。它规定**骨架与硬规则**；放哪个目录、
> 怎么进索引见 [DOC-INDEX.md](DOC-INDEX.md)，用词口径见 [TERMINOLOGY.md](TERMINOLOGY.md)。
> 本文件自己的规则同样适用于本文件。

## 1. 骨架（四段，缺一段就不该提交）

| 段 | 内容 | 为什么 |
|---|---|---|
| **定位** | 开头两三行：这是什么、谁该读、读它解决什么问题 | 让读者三步内决定要不要继续读 |
| **边界** | 明确写「不做什么 / 不在范围内」 | 本仓的反复教训：边界不写就会被当成承诺 |
| **正文** | 读数、机制、复现步骤 | 见 §2 硬规则 |
| **未证栏** | 逐条列「哪些没验证、补证需要什么」 | 没有未证栏的结论，按未验证处理 |

`review/` 下的历史评审记录不要求改造，它们是当时快照。

## 2. 硬规则（每条都写明靠什么落地）

1. **能力句必须带读数或复算指针。** 「支持 / 已实现 / 完成 / 达标」这类词出现时，同一句要有**读数（带单位与规模档）**或**可直接执行的命令 / 文件行号**（判定脚本 `scripts/claims_evidence.py`）。
   落地：`门` `python scripts/claims_evidence.py`（口径正本 [STATUS.md](../positioning/STATUS.md) §1）。
2. **状态词只有四个**：已跑通 / 已实现未测 / 组件 / 已否证（正本 `docs/positioning/STATUS.md`）。
   落地：`门` `python scripts/model_status.py` 核对 [STATUS.md](../positioning/STATUS.md) §2 的表。
3. **三进制结论先归类再下结论**：`[A]` 原生红利 / `[B]` 模拟税 / `[C]` 生态路径依赖 /
   `[D]` 基数无关复杂度，且必须同时给二进制基线。
   落地：`人` 评审 + `门` `python scripts/cite_check.py` 查引用格式；归类本身没有门。
4. **不写机器状态**：不写本机盘符路径、用户名、临时目录。
   落地：`门` `python scripts/docs_hygiene.py`（盘符路径按文件计数，只许变少）。
5. **行号指针必须指得对**：`路径:行号` 形式的指针，所指文件必须存在、行号必须在范围内、
   行内容要与描述相符。
   落地：`门` `python scripts/doc_pointers.py`。
6. **markdown 链接必须可达**：相对链接与 `docs/` 路径必须解析到真实文件。
   落地：`门` `python scripts/doc_pointers.py`（链接可达性检查与行号检查同一趟扫描）。
7. **必须在索引里有一行**：[README.md](../README.md) 的分组表。
   落地：`门` `python scripts/doc_pointers.py` 的未索引检查。
8. **历史不改写**：`CHANGELOG.md` 与 `review/` 记录当时路径与读数，搬迁时不追改正文；
   只把**可点击链接**改到新路径，避免读者点到 404。
9. **命名**：文件名大写英文 + 连字符（`WSP-SHIELD.md`），目录名小写英文
   （`positioning/ reference/ results/ research/ security/ engineering/ plans/ specs/ review/`）。
   落地：`人` 评审（命名不合不会判红，但别新增风格）。
10. **数字必须同机同命令**：给命令、给规模、给对照；不同机的数字要分开列，不许混合平均。
    落地：`人` 评审。

## 3. 会被门拦住的写法（反例）

- 「已实现 WSP2 块索引」——缺读数与指针 ⇒ 规则 1 判红（`scripts/claims_evidence.py` 会拦）。
  「已实现，`cargo run -p trit-wspace -- index-artifact`，10240² 基面读一块 0.4 ms」——过。
- 「某个 `docs/` 文件第 42 行说……」但那一行其实是别的内容 ⇒ 规则 5 判红。
- 「见 `docs/WSP-SHIELD.md`」而文件已搬到 `docs/security/` ⇒ 规则 6 判红。
- 新文档写完了但 `docs/README.md` 没有它 ⇒ 规则 7 判红。
- 在文档里写 `<本机盘符>/…/target` 这类路径 ⇒ 规则 4 判红。

## 4. 未证栏怎么写

- 一条一行，写「没验证的是什么 + 现有证据到哪 + 补证需要什么数据/机器」。
- 汇总型未证栏见 [WSP-LIMITS.md](../research/WSP-LIMITS.md)（研究线）与
  [LESSONS.md](../results/LESSONS.md)（工程侧负结果）。
- 未证栏不是免责声明：它不影响结论的可用性判断，只说明适用边界。

## 5. 本文件自身的未证栏

  想做门需要先定义「二进制基线字段」的机器可读格式，尚未设计。
- 规则 9（命名）同理：没有门，也不打算有——避免为风格造检查器。
