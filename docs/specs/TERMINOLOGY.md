# 术语：「三进制」指哪一层

> 定位：读写本仓文档的人。它给出**唯一用词表**，用来止住一处长期混乱——「三进制」在本仓至少
> 指三件不同的事，而文档里长期混着用，读者分不清在说哪一个。
> 归因坐标（A/B/C/D）见 [TERNARY-BOUNDARIES.md](../positioning/TERNARY-BOUNDARIES.md)，两者正交。

## 1. 三层，各有所指

| 层 | 唯一用词 | 指什么 | 本仓落位 | 关键事实 |
|---|---|---|---|---|
| **L-逻辑** | **三值逻辑** | 值域语义：`{False, Unknown, True}` 与它的代数（K3 / Ł3 / B3，opt-in Belnap 四值） | `trit-core`（稳定 API）、`trit-eval` / `trit-sat` / `trit-bdd` / `trit-policy` | `Unknown` 是一等值，不是 `(bool, err)`；这块是主库的**主定位** |
| **L-权重** | **三值权重** | 训练与推理里的量化权重：每个权重取 `{-1, 0, +1}` 之一 | `trit-learn` / `trit-train`（稳定 API），`trit-net` / `trit-attn` / `trit-dot` / `trit-ops` / `trit-gpu`（实验层） | 收益口径是**带宽与乘法**：0.2 B/参数、`x·{-1,0,+1}` 退化成加减 |
| **L-数制** | **平衡三进制** | 数制与编码：数字位 `{-1,0,+1}`、`3` 的幂、整数 ↔ 文本、三进制浮点 | `trit-codec::balanced`（整数编解码）、`trit-float`（浮点），二者均为实验层；`other-languages/go/` 是参考实现 | i64 全域需要 41 位（`(3^41-1)/2 ≈ 1.82e19`）；同比特存储，三进制浮点误差上界约是二进制的 3 倍 |

- 三层共用的字面量都是 `{-1, 0, +1}`，**但语义完全不同**：一个是真值、一个是权重、一个是数位。
  混用会直接导致错误结论（例如把「平衡三进制负数不需要符号位」当成三值逻辑的性质）。
- 三层与主定位的关系：**主库定位是三值逻辑底座**（[DESIGN.md](../positioning/DESIGN.md) §1）。
  三值权重是学习库的量化口径；平衡三进制数制是**实验层**能力，不进稳定 API。
  所以「本库不是平衡三进制整数库」这句话只在**稳定 API 面**成立——见 §3。

## 2. 用词规则

1. 单写「三进制」时表示**统称**，同一段内必须立刻限定到某一层（「三值逻辑」「三值权重」「平衡三进制」）。
2. 标题与宣传句（README 首屏、GitHub 简介、crate 描述）点明层时写全，例如
   「三值逻辑 + 三值权重」，不写「三进制」了事。
3. 说「原生」「免费」时必须给**表示层事实**：几个 bit、几条电平、是否多一次编码
   （[TERNARY-BOUNDARIES.md](../positioning/TERNARY-BOUNDARIES.md) §硬规则 3）。
4. 跨层迁移要显式命名方向，例如「把 C 类日志收敛成 A 类值模型」。
5. 性能数字必须标层：`trit-dot bench` 的数字属**三值权重**层，`trit-codec pack` 的体积属
   **平衡三进制**层，两者不可互相引用为证据。

## 3. 已核实的边界事实（改写边界文档前先看这里）

- [TERNARY-BOUNDARIES.md](../positioning/TERNARY-BOUNDARIES.md) §「本库是什么 / 不是什么」写着
  「**不是**：平衡三进制**整数**库。没有 ±1、符号位、进位 / 借位、整数乘加或十进制整数转换 API」。
- 实测：`crates/trit-codec/src/balanced.rs` 提供 `encode(i64) -> String`、`decode(&str) -> i64`、
  `range(n) -> i128`（文件第 9 / 40 / 72 行），是**平衡三进制整数的文本编解码**；
  `crates/trit-float/src/lib.rs` 第 24 行是 `TritFloat { mantissa: i128, exponent: i32, precision }`。
- 两者的 `Cargo.toml` 都是 `publish = false`（实验层，不进 crates.io、不属于稳定 API）。
- 因此准确的写法是：**稳定 API 面**没有平衡三进制整数类型（没有整数乘加、没有 ±1 值类型作公共
  类型）；平衡三进制只作为**实验层的编码与浮点表示**存在。写「本库不是平衡三进制整数库」时，
  必须带上「稳定 API 面」这个限定，否则与实验层实现冲突。

## 4. 和 A/B/C/D 的关系

- L-逻辑 / L-权重 / L-数制 是**讨论对象**；A/B/C/D 是**归因坐标**（红利 / 模拟税 / 生态路径依赖 /
  基数无关复杂度）。同一个现象先定层、再定性：
  「双导轨每 trit 占 2 bit」是 L-逻辑 + `[B]`；「三进制浮点同比特误差 3 倍」是 L-数制 + `[A]` 的代价面。
- 不先定层就标 A/B/C/D，等于跳过前提直接下结论——这正是过去文档互相矛盾的主要来源。
