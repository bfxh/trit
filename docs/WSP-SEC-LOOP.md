# 三值 AI 安全线：语义红队 + 完整性审计模型（负结果与方向修正，2026-11-14）

本轮把安全线与三值 ML 线焊接：攻击三进制软件的**语义层**（上轮 #489 只打了
格式层），并尝试训练「模型挖漏洞」的完整性审计分类器。产出：语义不变量
5/5 守住的读数、完整性审计模型的**负结果与方向修正**。

## 1. 语义层红队（`tests/redteam_semantics.rs`，5/5 守住）

攻击者持有合法工具与完整写权限，目标是破坏语义不变量：

| 攻击 | 不变量 | 结果 |
|---|---|---|
| 「前缀合法 + 尾部越界」patch | 失败后网络逐位不变（事务原子性） | ✅ 守住 |
| apply→undo→apply→undo 循环 + scale/swap/negate | 回滚逐位一致（含 f32 自由度） | ✅ 守住 |
| 篡改日志条目的 patch 字段（`"to":"0"`→`"-"`） | `verify_chain` 断链 | ✅ 守住 |
| require-after 不满足的 Program | 整体回滚逐位不变 | ✅ 守住 |
| 同一日志重放两次 | 工件逐位一致（重放确定性） | ✅ 守住 |

**结论**：编辑/审计的语义层是硬的（validate-then-apply 两阶段 + 哈希链覆盖
patch 内容）。设计边界（非漏洞）：FNV 无密钥 + `recompute_chain` 是 pub，
写权限攻击者可"洗白"伪造历史——审计链提供**完整性**而非**真实性**（无签名
锚点），供应链威胁需要外部锚定。

## 2. 完整性审计模型（`examples/artifact_guard/`）——负结果

设计：合法 WSP2 工件 × 8 种攻击模式（trit 翻转/多处翻转/scale 篡改/结构位/
大块清零/**内容偷换**/填充注入/位平移，全部**重算校验和**排除平凡信号）+
合法样本，字节 4-gram 哈希特征 → QAT MLP 2048→64→9。

| 读数 | 值 |
|---|---:|
| 已见攻击 多类判别（9 类） | acc 0.115 ❌ |
| 已见攻击 二值（合法 vs 攻击） | acc 0.782，攻击 recall 0.870，**误报 0.833** ❌ |
| 未见攻击（位平移，holdout）泛化 | recall 0.627，误报 0 |

**负结果的根因（比读数本身有价值）**：

- **字节级特征对「检测工件篡改」没有增量价值**。FNV 校验和已经以 100% 检出
  率 + 零误报覆盖字节完整性；统计模型在同样信息（字节）上不可能超过精确
  校验和，只会引入误报（本轮实测误报 83%）。
- 攻击样本自动生成器本身是**成功的部件**（9 类模式、标注免费、可无限生成）
  ——错的是把它的输出喂给「替代校验和」的模型。

## 3. 方向修正：模型防御的正确战场是**行为级指纹**

校验和的真盲区是「**重算校验和的内容偷换**」：字节完全合法、校验和正确、
但模型已被换掉（后门/降级模型）。字节特征对此无信号（内容合法）；防御要
看**行为**：

- **模型身份识别**：加载时跑一组固定行为探针（已知输入 → 发布时的输出
  指纹），统计距离超阈即拒绝——这能用本仓的 QAT 管线训练（输入=探针响应
  特征，输出=身份/中毒二分类），是 `Oracle`/`probe` 原语的自然延伸；
- **后门触发检测**：对分类器工件，用差异化的探针输入扫「异常敏感方向」
  （#494 的 kill-switch 定位就是武器化版本——防御者反过来用它体检）。

这两项**未做**，列为本线后续；本轮交付的是负结果、根因与修正后的路线。
