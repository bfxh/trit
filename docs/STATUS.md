# 完成度口径（防"我以为做完了"）

> 这份文档存在的唯一理由：把**"有这段代码"**和**"这件事完成了"**分开记账。
> 起因是用户 2026-11-05 的指正：「有些地方我以为你完成了，但你没有完成——比如造模型，
> 我以为那些小模型是各种功能，结果是组件；好多地方有迷惑性，我最反感」。
> 下面第一条是口径，第二条起是按口径量出来的现状。**每条都带证据行号，可复算**。

## 1. 状态词只有四个，不许用别的说法

| 状态 | 含义（必须全部满足） | 不许怎么写 |
|---|---|---|
| **已跑通** | 有可执行的复算命令 + 真实读数 + 至少一条端到端断言 | "支持 X"、"做了 X" |
| **已实现未测** | 代码在、能编译，但**没有**端到端断言或没有读数 | 出现在"能力表"里冒充已跑通 |
| **组件** | 只是别人的一环（头/内核/编码），不单独完成任何用户可见任务 | 叫 `*Model` / `*Net` / "模型" |
| **已否证** | 跑过且失败，负结果在 CHANGELOG 里 | 删掉不提 |

规则：**"支持/可以/已实现/完成/达标"这类词，句中必须同时出现①复算命令或文件行号，②读数（含单位与规模档）**。
写不出这两样，就只能写 `已实现未测` 或 `组件`。命名也是口径的一部分：`Head`/`Layer`/`Net` 不许写成"模型"，
除非它端到端跑通并带读数。

## 2. 实例：`trit-parts` 里六个"像模型的东西"（实测，2026-11-05）

| 名字 | 定义处 | 内联 `#[test]` | 被 bin 用 | 被仓内其他模块用 | `tests/` 端到端 | 读数在哪 | 按 §1 判 |
|---|---|---|---|---|---|---|---|
| `DepthNet` | `depthnet.rs:25` | 7 | 4 | 2 | **0** | `docs/PARTS-RESULTS.md`（清单 + 独立复核） | **已跑通** |
| `TpmModel` | `tpm.rs:36` | 1 | 5 | 3 | **0** | 部分（同上文件，按族） | 已跑通（覆盖面窄） |
| `DepthUNet` | `depthunet.rs:113` | 3 | 1 | 0 | **0** | 有（同族留出） | **已实现未测**（端到端缺） |
| `DepthHead` | `depth.rs:14` | 3 | 1 | 0 | **0** | — | **组件**（名字已经是对的） |
| `MatNet` | `matnet.rs:41` | 3 | 1 | 0 | **0** | — | **组件** |
| `TriModel` | `model.rs:47` | 1 | 1 | 0 | **0** | — | 已实现未测 |

**这张表里最刺眼的一列是"tests/ 端到端 = 0"**：六个里面没有一个被 `crates/trit-parts/tests/` 覆盖，
所有断言都是同文件内联的单点测试（量化、形状、梯度这类局部性质）。
所以"我们有一堆三值模型"这句话在端到端意义上**不成立**——真正达到"已跑通"的只有 `DepthNet`（深度族，
有清单 + 独立复核 + 留出读数）和 `TpmModel` 的一部分。其余是**组件或未测**。

复算尺（谁都能重跑）：

```
for f in depth depthnet depthunet matnet model tpm; do
  printf "%-12s 内联#test=%s\n" "$f" "$(grep -c '#\[test\]' crates/trit-parts/src/$f.rs)"
done
grep -rlE "DepthNet|TpmModel|MatNet|TriModel|DepthUNet|DepthHead" crates/trit-parts/tests | wc -l   # 期望 0
```

## 3.5 门第一次实跑就抓到的东西（2026-11-05）

`python scripts/tech_collide.py` 在真账本上报 **8 条拦**：**交接账本里同一编号被两件事复用**。
例如 `A129` 同时是「化学仓 trit-chem M0：热力学/反应引擎」和「三值卷积栈 vs 3×3 MLP：MLP 赢」，
`A130` 同时是「Shomate 分段边界台阶修复」和「卷积栈加批归一化：更差」。
⇒ 这正是"我以为你完成了但没有"的最硬一种：**"A130 完成了"这句话无法判定指哪件**。
不修的话，任何按编号做的进度统计（含本文件）都是不可信的。修法：给复用的一方重新取号，并在账本头部
写明"取号必须取当前最大号 +1，写入后立刻复验唯一"（这条已经在跨智能体纪律里，但没有门）。

## 4. 还欠什么（不做就还是"你以为完成了"）

1. **能力句的门没写**：§1 那条"必须带命令 + 读数"目前只是文字，没有 `scripts/` 脚本判红。设计已经想清楚：
   扫 `README.md` 与 `docs/*.md` 的断言句（含"支持/已实现/可以/完成/达标/最快"），
   缺命令或缺数字 ⇒ 判红，存量进棘轮基线只许变少（和 `docs_hygiene` 同一套做法）。
2. **账本编号去重**：8 处复用要先清（谁复用谁改号），否则 §3.5 的判红会一直挂着，
   也不能把 `tech_collide` 挂进 CI（会把别人的历史卡住）。
3. **端到端断言补齐**：`trit-parts` 六个类型里 `DepthUNet`/`TriModel` 至少要各有一条 `tests/` 级断言，
   否则它们该在文档里被降级成"已实现未测"。
4. **命名整改**：`MatNet` 是组件（只有 1 个 bin 用、无仓内复用），按 §1 要么补端到端跑通并带读数，要么改名 `MatHead`。
   改名要走 `trit-look`/外部 pin 检查，所以排在门之后。
