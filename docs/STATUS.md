# 完成度口径（防"我以为做完了"）

> 这份文档存在的唯一理由：把**"有这段代码"**和**"这件事完成了"**分开记账。
> 起因是用户 2026-11-05 的指正：「有些地方我以为你完成了，但你没有完成——比如造模型，
> 我以为那些小模型是各种功能，结果是组件；好多地方有迷惑性，我最反感」。
> 下面第一条是口径，第二条起是按口径量出来的现状。**每条都带证据行号，可复算**。

## 1. 状态词只有四个，不许用别的说法

| 状态 | 含义（必须全部满足） | 不许怎么写 |
|---|---|---|
| **已跑通** | 有可执行的复算命令 + 真实读数 + 至少一条端到端断言 | "支持 X"、"做了 X" |
| **已实现未测** | 代码在、能编译，但**没有**端到端断言或没有读数 | 出现在"能力表"里冒充已跑通 |
| **组件** | 只是别人的一环（头/内核/编码），不单独完成任何用户可见任务 | 叫 `*Model` / `*Net` / "模型" |
| **已否证** | 跑过且失败，负结果在 CHANGELOG 里 | 删掉不提 |

规则：**"支持/可以/已实现/完成/达标"这类词，句中必须同时出现①复算命令或文件行号，②读数（含单位与规模档）**。
写不出这两样，就只能写 `已实现未测` 或 `组件`。命名也是口径的一部分：`Head`/`Layer`/`Net` 不许写成"模型"，
除非它端到端跑通并带读数。

### 2.1 `DepthUNet` 的读数（2026-11-05 实测，`cargo test -p trit-parts --test models_e2e`）

- 16×16、h=4、301 步：MSE **0.3602 → 0.01051**（34×）；左右两半均值 **−0.586 / +0.580**（目标 ∓0.6）
  —— 只断言"MSE 下降"会放过塌成常数的退化解，所以加了这条区域判据。
- 全 false 掩码一步 = **逐位不变**（`assert_eq!` 前向输出，不是容差比较）。
- `save` → `load` → 前向**逐位一致**；坏头报 `不是 U1` 而不是 panic。

### 2.2 `TriModel` 的读数（同上）

- 随仓 `models/parts_id8118.tpm`（13 层，3→32→…→32→16）加载 → `to_tri()` → `RefCpu` 跑通：
  res=8 输出 1024 个有限值、非退化；重新加载后**逐位相同**。
- 三值不变量：13 层每个 `|E|` 要么 0 要么等于该通道 `|scale|`（`q ∈ {−1,0,1}` 逐元素核过）。
- `truncate_head(4)` 后留下的 4 个平面**逐位不变**（head 是 1×1，逐通道独立）。
- 金样指纹（FNV-1a 64）：res=8 `f6de046f0b41c1f6`、res=16 `05f25dc40107c04a`。
  **判决性验过**：把 `RefCpu::pool` 的 `m.max(v)` 改成 `(m+v)/2.0` ⇒ 只有金样这条判红，其余 8 条全绿
  ⇒ 没有这条 pin，池化写错是拦不住的（这条就是"结构测试冒充端到端"的差别）。
- 对拍尺子自证：`compare_nhwc(a,a)` 报 `(1.0, 0.0)`；翻掉一个像素的 argmax ⇒ 一致率掉到 319/320（既判红又不误伤整帧）。

### 2.3 `DepthNet` 的读数（2026-11-05 实测，`cargo test -p trit-parts --test depthnet_e2e`）

内联的 7 条测的是"学斜坡 / 学常数 / mv 门"这类局部性质；`tests/` 这 4 条测的是**必须跨模块才看得见**的：

- **三值格不变量**：把 `c1.w[0]` 换成同一量化格内的另一个值（`q(w)=round(w).clamp(-1,1)`）⇒ 三值档前向
  **逐位不变**，`ternary=false` 档**必须变**（这一对同时钉住"标志位真的生效"）。
  判决性实测：把 `tconv/conv.rs:113` 的 `q` 改成恒等 ⇒ **只有这条判红**，其余 3 条全绿。
- **膨胀 = 感受野**：孤立冲击的可达集实测落在 dil 的格点上（`dil=1` 依赖 16 个像素 = {0,1,2,3}²，
  `dil=3` = {0,3,6,9}²、最远 (9,9)）。`(6,6)` 在 `dil=1` 下与前向**无关**、在 `dil=3` 下**相关**。
  判决性实测：`conv.rs:151` 的 `let d = self.dil as i32` 改成 `let d = 1` ⇒ 这条判红。
- **留出集泛化**：3 个方向训练、第 4 个方向（反对角）从没出现过，1200 步后 MSE **0.1710 → 0.00620**（27.6×）。
  只看训练图会被"背下来"糊过去，这条挡住它。
- **部署构成**：`cin=6 / pyr=1 / dil=2 / med=-0.75 / iqr=1.25 / ternary(1,1,0)` 存→读全字段一致、前向逐位一致；
  未知 magic 报错点名 `不是 DCN1/DCN2/DCN3/DCN4`。

**这一列以前全是 0**：六个类型没有一个被 `crates/trit-parts/tests/` 覆盖，
所有断言都在实现文件的 `mod tests` 里（量化、形状、梯度这类局部性质）。
所以"我们有一堆三值模型"这句话在端到端意义上**不成立**——现在 `tests/` 有 13 条断言（2 个文件），
够得上"已跑通"的是 `DepthNet`、`DepthUNet`、`TriModel` 与 `TpmModel` 的一部分。
仍欠：`DepthHead` 与 `MatNet` 是**组件**（只有 1 个 bin 用、无仓内复用），没有端到端可言。

复算尺（谁都能重跑）：

```
for f in depth depthnet depthunet matnet model tpm; do
  printf "%-12s 内联#test=%s\n" "$f" "$(grep -c '#\[test\]' crates/trit-parts/src/$f.rs)"
done
for t in DepthNet TpmModel MatNet TriModel DepthUNet DepthHead; do
  printf "%-10s tests提及=%s\n" "$t" "$(cat crates/trit-parts/tests/*.rs | grep -c "$t")"
done
```

## 3. 本轮已经知道自己会错在哪（同类事故，登记在册）

- CHANGELOG 被我自己的脚本覆盖成一行本机路径并**进了 main**，而 26 项 CI 全绿——因为**没有门读文档**。已修，并加了 `scripts/docs_hygiene.py`。
- 我在旧分支上做 trit-bench 时，条目被一次没有 `assert` 的 `replace` **静默丢弃**；当时我一度以为写进去了。
- 我写过一条**不判决的断言**（"种子 0 不退化"断成"不全为 0"，而退化序列其实是全 -1）⇒ 变异存活才暴露。
- 我量"这六个类型有没有测试"时，第一次 grep 口径漏了内联 `#[test]`，得出"全都没有测试"的错误结论；上面这张表是改正后的。
- `scripts/layers.py`、`docs_hygiene.py`、`tech_collide.py` **都还没进 CI**（`.github` 目录被别的会话认领中）。现在说"门"，指的是本地可判红 + 变异钉住，不是 CI 拦得住。
- 本轮重算 §2 那张表时，我第一次用了 `grep -c X crates/trit-parts/tests/*.rs | awk -F: '{s+=$2}'`：
  只有一个文件时 `grep -c` **不带文件名前缀**，`$2` 是空的 ⇒ 六个类型全报 0，看着像"补的测试没生效"。
  换成 `cat … | grep -c` 才拿到真数（`DepthUNet` 8 处 / `TriModel` 1 处 / `TpmModel` 2 处）。
  又一次"判据的输入不是我刚读到的"同型错误（这类在跨智能体纪律里已累计登记），记在这儿是为了让它可查。
- §2.3 那条"膨胀可达集"的夹具第一版选了角落 `(15,15)`，理由是"离冲击够远"；实测抽头只落在 **dil 的整数倍**格点上，
  15 不在 `dil=3` 的格子里 ⇒ 红的是夹具。改成 `(6,6)` 并实测依赖集（`dil=1`→16 个像素、`dil=3`→最远 (9,9)）才成立。
- 改 `planes()` 签名时用了一次**没有 `assert` 的字符串替换**，补丁空操作（调用点改了、函数体没改），靠编译报错才发现。
- §2.2 那条"对拍尺子自证"第一版写的是"把平面 0 抬高"，结果抬的正好是本来就是最大值的那个通道
  ⇒ 断言 `rate2 < 1.0` 报红，但**红的是夹具没翻转，不是尺子失灵**。改成"先读当前 argmax，再把另一个通道抬到它上面"
  才是真的在测尺子；顺手加了 `rate2 > 0.99` 反证，防止"改一个像素判整帧不一致"这种过头实现。

## 3.5 门第一次实跑就抓到的东西（2026-11-05）

`python scripts/tech_collide.py` 在真账本上报 **8 条拦**：**交接账本里同一编号被两件事复用**。
例如 `A129` 同时是「化学仓 trit-chem M0：热力学/反应引擎」和「三值卷积栈 vs 3×3 MLP：MLP 赢」，
`A130` 同时是「Shomate 分段边界台阶修复」和「卷积栈加批归一化：更差」。
⇒ 这正是"我以为你完成了但没有"的最硬一种：**"A130 完成了"这句话无法判定指哪件**。
不修的话，任何按编号做的进度统计（含本文件）都是不可信的。修法：给复用的一方重新取号，并在账本头部
写明"取号必须取当前最大号 +1，写入后立刻复验唯一"（这条已经在跨智能体纪律里，但没有门）。
