# 通用提取路线（C：全自建 Rust 三值）

目标：从现实图像里提取**任意物体 → 部件 → 多网格**，全链路自建、不依赖外部模型。
本文只做**账目与切片**，所有速率都是本机实测（RTX 4060 Ti，384²）。

## 0. 现状锚点（实测）

| 项 | 读数 | 来源 |
|---|---|---|
| 现模型容量 | **466,272** 个三值权重（13 层 32/64/128） | `models/parts_id8118.tpm` |
| 训练一步（前向+反向，384²） | **0.30–0.33 s** | 本轮多次训练日志 |
| 推理一帧（含两道门+解码） | **45–49 ms** | `parts-cli pipeline` |
| Blender 渲染一帧（384²、16 spp） | **0.34–0.50 s** | `blender_gt.py` 日志 |
| 每帧磁盘（rgb+depth+normal+seg） | **≈3.1 MB** | `lay-b-*` 目录实测 |
| 单卡每天训练步数 | ≈ **26 万步/天**（0.32 s/步） | 推算 |

结论：**数据生成不是瓶颈，标注定义与模型容量才是。**

## 1. C 路线真正的难点（先摆明）

1. **部件级标注在现成资产里几乎不存在**。CC0 模型（Poly Haven 等）多为整体网格，
   没有「这个螺钉属于哪个部件」的标注。⇒ 必须**用程序化部件库自己造场景**，
   标签由构造保证；代价是场景会长得像「程序化物体」，与真实照片有域差。
2. **多物体、遮挡、尺度**会把任务难度从「单物体固定布局」抬到「开放场景」。
3. **三值权重在通用任务上的容量未知**：466k 权重是专才规模；通用实例分割通常在
   10⁷ 参数级、10⁵–10⁶ 标注图上训练。我们只能从小做起、用门禁逐步验证。

## 2. 分期与验收门（每片都能判红）

### S1 · 数据引擎（3–5 天）
- 把现有 `part_cube` 扩成**程序化部件库**：方块/圆柱/板/螺钉/齿轮等 K 类，
  每类多尺寸、多材质；装配规则随机（数量、位姿、堆叠）。
- 场景合成器：随机背景（程序化 + CC0 贴图）、随机光照、随机相机轨迹。
- 标签：部件 id（清单）+ 实例 id + 深度 + valid。
- 规模：**2000 场景 × 8 视角 = 16,000 帧**（渲染 ≈1.8 h，磁盘 ≈50 GB）。
- **门**：标签自检（id→颜色→反解一致率 100%）、可见部件覆盖统计、清单外 id 0。

### S2 · 类无关实例分割（5–7 天）
- 任务从「135 个具名部件」退到「这张图里有几个物体、各自的掩码」。
- 模型：在现网基础上加实例分支（逐像素「是否物体 + 实例中心」），先 2 物体/场景。
- **门**：留出场景 mIoU ≥ 0.60、实例数误差 ≤1 的比例 ≥80%。

### S3 · 部件分解（1–2 周）
- 多物体场景下做部件级分割；指标：部件 mIoU ≥ 0.50、跨物体不串号。
- 这一步决定「拆模型」能不能成立；不达标就停在 S2（只能拆物体，不能拆零件）。

### S4 · 几何 → 多网格（约 1 周）
- 单视角：深度头在多物体数据上重训（此前单物体上与分割竞争，需重验）。
- 多视角：用已知相机做体素融合（比此前的「并集/投票」更严格：表面一致性 + 置信度）。
- 网格：体素 → Surface Nets（纯 Rust 实现，约 400 行）。
- **门**：每部件 3D IoU ≥ 0.5、mesh 水密率报数（不设通过线，先报）。

### S5 · 现实域（时间取决于素材）
- 合成域达标后再谈实拍：需要真实照片 + 少量人工校正；此前的教训是
  「合成训练 → 实拍」有未量的域差，必须先拿到真图再定预算。

## 2b. S1 实测（2026-10-31，第一片）

**数据引擎**：`s1_gen_scenes.py`（5 种布局、逐物体缩放/旋转、最小间距采样、xy 对齐相机注视点）
+ 渲染器扩展（`scale/rot`、`--elev-sweep` 逐帧仰角扫描，**默认参数与旧数据逐位一致**）
+ 标签自检 `s1_check_labels.py`。

| 项 | 读数 |
|---|---|
| 场景 / 帧 | **200 / 2,400**（12 视角，仰角 ±20° 扫描） |
| 标签正确性 | **100%**（id ⊆ 清单、digits↔id 一致、0 空帧） |
| 渲染吞吐 | **≈0.5 s/帧**（含场景启动约 3.5 s/场景） |
| 单帧可见部件 | 中位 **11**（场景部件中位 27） |
| 12 视角并集覆盖 | 中位 **0.474**（p10 0.17，<0.6 的场景 136/200） |
| 失败模式 | Blender 静默失败（rc=0 无产物）；根因 = **E 盘写满**；已加磁盘预检 + 产物帧数校验 + 重试 |

**结论**：引擎可用，但**部件堆得太密**——即使在 12 视角 + 仰角扫描下，也有一半部件从未被看到。
对 S2（类无关实例分割）够用（不可见部件 `valid=0`，无监督）；对 S3（部件分解）需要更稀的装配：
下一轮参数建议「每场景 8–16 个部件、间距 ×2.2、每场景 16 视角」。

## 2c. S2 实测（2026-10-31）：多物体数据改了 6 轮 + 基线达标

**数据侧迭代（每轮都是被一个测出来的缺陷推着走）**

| 版本 | 改动 | 结果 |
|---|---|---|
| v1 | 2–4 物体 x 排开，部件悬空 | 每实例中位 **3.5 个 2D 连通块**（悬空部件），实例距中位 6 px ⇒ 连通域不可能分对；实例头 2k 步 mIoU 0.211（塌成 2 个 id，pred/gt 恒 0.66） |
| v2 | 想加「部件咬合」但参数没接上（脚本替换被 CRLF 吞），只换了随机色 | 当颜色对照用（见下） |
| v3/v4 | 接上间距；`part_cube` 5.5 cm → 0.19–0.39 m | 仍不聚拢：布局在固定跨度里均匀撒点 |
| v5 | **链式贴附成团**（新部件贴在随机已有部件外侧） | 尺寸只按部件中心算 ⇒ 物体互吞、相机过近、整团出框 |
| **v6** | 尺寸/间距一律按**表面**包围盒（中心 ± 部件半径）；2 物体；物体表面间距 ≥0.3 m；逐部件随机色 | 每实例单连通块 **91%**；oracle 前景+CC 上限 **0.778** |

**v6 数据集**：`scenes_v6` 100 场景 / 800 帧（8 视角、仰角 ±15° 扫描），2 物体、6–12 部件/场景，
标签自检 100%（`s1_check_labels.py`，含实例区间连续性）。

**S2 基线（留出 20 场景 × 8 帧 = 160 帧，只算该帧可见实例）**

| 方法 | 实例 mIoU | 实例数误差≤1 | 前景 IoU |
|---|---|---|---|
| 部件模型前景（valid 头，未在这批数据上训练）+ Rust 4 邻域连通域 | 0.728 均值 / 0.982 中位（p10 0.30） | 95% | 0.989 |
| **边界头（7k 步）+ 分水岭（min-size 400）** | **0.7965 均值 / 0.9862 中位**（p10 0.33） | **97.5%** | 0.990 |
| oracle 前景 + 连通域（上限） | 0.778 | — | 1.0 |
| 实例头（平面头直出规范序 id，2k 步） | 0.346（负，塌成单 id） | — | 0.991 |

**门**：mIoU ≥ 0.60 ✅（0.7965）；实例数误差 ≤1 ≥80% ✅（97.5%）。
**局限**：均值-中位差大 = 物体在投影里重叠时连通域合并（43% 的物体对投影距离 ≤4 px）；
目前 2 物体/场景、合成域。

**负结果（架构）**：规范序实例 id 学不了（见 MODEL-CARD §4g）——平面头没有全局比较算子。
改走**边界头 + 分水岭**：边界只占前景 ~4%，普通 CE 一个点都不预测（两轮复现 F1=0），
加逐像素权重（`--bnd-weight 20`）后才学到；7k 步即超过连通域基线 +9.5%。

**旁证：颜色捷径（详见 MODEL-CARD §4f）**。训练场景 `big-r2.4` 同取景重渲，循环色 id 0.8352 /
随机色 0.1800 ⇒ 交付部件头的 id 指标约 4.6× 来自颜色。**前景头不受影响**（随机色多物体上前景 IoU 0.989），
所以 S2 基线成立；但 S3（部件级）必须在随机色数据上重训部件头，否则指标没有意义。

## 2d. S3 实测（2026-10-31，第一片）

口径：GT 用 `seg` 的部件 id（匹配与编号无关），只算该帧可见部件；门 = **部件 mIoU ≥ 0.50**。
数据同 v6（随机色，部件边界占前景 10–16%，`pbnd/` 由 `parts-inst prep --part-bnd` 生成）。

| 方法 | 部件 mIoU | 前景 IoU | 跨物体混合 |
|---|---|---|---|
| 前景 + 连通域 | 0.110 | 0.989 | — |
| 物体边界头（S2 那个）+ 连通域 | 0.132 | 0.990 | — |
| **部件边界头（6k 步，w=8）+ 分水岭（min-size 50）** | **0.518**（中位 0.522） | 0.985 | **10.1%** |
| oracle：GT 前景 + GT 部件边界 | 0.789 | 1.0 | 0 |

**门**：0.518 ≥ 0.50 ✅（勉强过）。**离上限还有 0.27**。
**已知缺口**：pred/gt 1.13、计数完全一致仅 15%；边界**过预测**（对 5 px 粗 GT：精确率 0.024 / 召回 0.897）
⇒ 下一轮把 `--bnd-weight` 从 8 降到 2–3，或改「种子点 + 分水岭」；10.1% 的预测部件实例跨了两个物体。
模型：`E:/runs/s3/pb_6k.tpm`（step 6000，467 KB）。

## 3. 算力与时间账

| 阶段 | 主要成本 | 实测/估算 |
|---|---|---|
| S1 | 渲染 16k 帧 + 写部件库 | **≈2 h 渲染 + 3–5 天工程** |
| S2 | 2 物体实例分割，~30 万步 | **≈1.5 天纯训练**（0.32 s/步）+ 调试 |
| S3 | 部件级，~60 万步 + 3 倍数据 | **≈3 天训练 + 1–2 周工程** |
| S4 | 网格 + 融合 | **≈1 周工程 + 少量训练** |
| 合计 | — | **合成域可用：4–6 周**；现实域：另计 |

若把模型放大到 5M 权重（约 10×），单步预计 **1.0–1.5 s**，同一步数的训练时间 ×4；
建议**先不放大**，用现有容量把 S1–S3 的流程打通，再决定是否扩容。

## 4. 与现有交付的关系

- 现有专才模型 + 两道门（域外 rc4 / 取景 rc5）**保持不动**，作为降级路径；
- C 路线的新模型走独立 crate/分支，不干扰 `parts_id8118` 的交付读数；
- 每一步的读数都写进模型卡与台账，负结果同样记录。

## 5. 风险清单（不隐藏）

1. **程序化场景 → 实拍**的域差未量，可能重演「跨布局零样本 0.0176」式崩盘；
2. **部件语义**在不同物体上没有统一定义（螺钉算不算部件？），需要先定口径；
3. 三值容量上限未知，S2/S3 可能卡在「能分物体、分不清部件」；
4. 单卡训练窗口有限（每天约 26 万步），大规模 sweep 不现实。

## 6. 扩展面（2026-10-31 调研）：文字→3D / 场景 / 纹理 / 特效 / 精度 / 重建

**约束前提**：真值只有合成引擎；算力是单张 4060 Ti；全部推理/训练走 Rust 三值；
**没有现成文本编码器**。下面每条都按这个前提判可行性，不按 SOTA 论文的默认资源假设。

### 6.1 参考（已查）

- 前馈 3D 重建综述 **arXiv:2507.14501**（LRM / iLRM 一系：单次前向出 3D 表示）；
- 3DGS 应用综述 **arXiv:2508.09977**；**GaussianDreamer**（text→3DGS，靠 2D 扩散先验蒸馏）；
- **TerDiT arXiv:2405.14854**：DiT 三值化到 600M–4.2B 仍可训练 —— 三值生成模型**不是死路**；
- **DreamMat arXiv:2405.17176**：几何条件 + 2D 扩散出 PBR 材质；
- **SceneFactor（CVPR'25）**：因子化生成——先粗语义盒布局，再几何/外观；
- LOD：**arXiv:2505.15190**（城市场景多分辨率表示），几何侧可先做「体素金字塔 + 简化」。

### 6.2 逐项可行性判定

| 诉求 | 主流做法 | 我们的路径 | 判定 |
|---|---|---|---|
| **3D 重建**（多视角→网格） | LRM/GS 前馈；或体素融合 | 已有 2D→3D 反投影 + 体素；补**多视角置信度融合 + Surface Nets**（组件已完成） | **可做，已开工** |
| **高/低精度都学** | 学习式 LOD / 多分辨率监督 | 先出几何 LOD（体素金字塔 + 顶点聚类，已实现）；再学「粗/中/细三级头」 | **可做，成本低** |
| **场景生成** | SceneFactor 式布局→几何→外观 | 程序化引擎已有布局/碰撞；先学**布局策略**，再学外观 | **可做，分两步** |
| **纹理/材质** | 2D 扩散 + 几何条件 | 没有 2D 生成先验 ⇒ 先做小尺寸程序化 + 三值微调；PBR 摆在 2D 生成器之后 | **中期** |
| **特效** | 视频/时序扩散 | 规则粒子/着色器先行；学习版要时序模型 | **远期** |
| **文字→3D** | 文本编码器 + 扩散 + 3D 解码 | 自训字节级三值文本编码器（配对数据 = 我们的模板描述）；开放式语义不在本赛季 | **分档可做** |
| **三值生成模型** | TerDiT 一类 | 采样器可 f32，去噪网三值；训练预算最大 | **可行但最贵** |

### 6.3 分期与门（每条都能判红）

- **N1 多视角几何**（下一刀）：8 视角体素融合（可见性/置信度加权）→ Surface Nets；
  **门**：逐部件 3D IoU ≥ 0.5；闭合率（非流形边 = 0 的部件占比）≥ 80%。
- **N2 学习式占据补全**：三值网预测体素占据，补未见区域；**门**：3D IoU 比 N1 +0.05。
- **N3 学习式 LOD**：粗/中/细三级监督（复用 e1/e2/e3 特征）；**门**：每级 3D IoU 报数，
  低精度档 ≥ 0.35 且导出体积 ≤ 最高档 1/4。
- **N4 场景合成**：布局策略（在引擎上学习，不碰像素）+ 外观；**门**：穿插率 0、覆盖 ≥ 阈值。
- **N5 纹理/材质**：小纹理生成器（三值 conv）；**门**：平铺无缝 + 属性词命中率。
- **N6 文字→结构化 3D**：字节级编码器 + FiLM 条件；**门**：模板句属性正确率 ≥ 90%。
- **N7 特效/视频**：押后，先不排期。

**S4 现状（本轮已落）**：`mesh.rs`（`fill_solid` / `surface_nets` / `downsample_occupancy` /
`simplify_cluster`，4 条单测：球面水密 + 体积误差 <10%）+ `parts-3d mesh --levels 0,2,4`。
单视角实测（scene0080 第 0 帧，1 cm 体素）：20,437 顶点 / 46,956 三角面；LOD×2 = 13,848 面、
LOD×4 = 3,892 面；**非流形边 2,840** ⇒ 单视角只是一面壳，闭合要靠 N1 的多视角融合。

### 6.4 N1 实测（2026-10-31）：几何过门，闭合没过

先修了两个**真 bug**（单帧自洽看不出来，只有多视角才暴露）：

1. `Camera::load` 把 meta 的 `T_cw`（**世界→相机**）当成了相机→世界 ⇒ 反投影点在相机背后；
   单帧预测/GT 用同一个错变换，IoU 不变，所以历史 3D 读数没被污染，但**世界坐标是镜像的**。
   现在读 `T_wc`。
2. `unproject` 没做 Blender→OpenCV 的 y/z 翻转（相机看 −Z、像素 y 向下）⇒ 点落到相机背面。
   修正后不同视角的 GT 点云才开始重合（2 cm 体素 IoU：相邻视角 0.62、对面 0.31，符合预期）。

多视角融合（`fuse.rs`）：隔帧取 4 个视角投票（按部件 id，`--min-votes` 去噪），留 4 个视角评测，
逐部件 3D IoU 对 GT 点云（同一格子索引空间，1 cm）：

| 场景 | 逐部件 3D IoU 均值 / 最差 | 外壳闭合率 |
|---|---|---|
| scene0080 | **0.759** / 0.669 | 14.3% |
| scene0081 | **0.578** / 0.400 | 30.0% |
| scene0082 | **0.704** / 0.533 | 0.0% |

- **几何门（均值 ≥0.5）✅**：三场景 0.578–0.759。
- **闭合门（≥80%）❌**：最好 30%。根因：绕圈视角永远看不到底面，壳体是「帽子」不是闭合面；
  `fill_solid` 的泛洪会从缺口灌进内部。视觉外壳（silhouette carving）能给出闭合体积，
  但它是膨胀的凸包近似（体积 IoU 0.05–0.18），不能当几何交付。
- 下一步只有两条：**N2 学出来的占据/隐式场**补底面（用物体的「落地」先验或学习先验），
  或者**多视角深度补全**（从可见面预测不可见面）。在这之前，`parts-3d fuse` 输出的是**开放表面**，
  能当点云/壳用，不能当水密网格用。

### 6.5 精度阶梯（2026-10-31）：体素 / 网格 / 高斯三档并排

同一批数据（v6 scene0080，融合视角 0,2,4,6，留出 1,3,5,7），一条命令 `parts-3d splat` 同时出三档：

| 采样格 | 体素数 | 网格顶点/面 | 网格非流形边 | 高斯数 | 留出视角 PSNR（前景） |
|---|---|---|---|---|---|
| 80 mm | 381 | 1,136 / 2,264 | 0 | 371 | 16.42 dB |
| 40 mm | 1,355 | 3,545 / 7,096 | 7 | 1,379 | 19.04 dB |
| 20 mm | 4,650 | 13,252 / 26,524 | 7 | 4,645 | 21.96 dB |
| **10 mm** | 14,258 | 49,288 / 98,708 | 35 | 14,339 | **23.92 dB** |
| 5 mm | 30,680 | 179,882 / 360,524 | 162 | 30,743 | 23.38 dB（半径要放大到 1.2×格，0.6×时只有 20.39） |

- 高斯半径 = `scale-k × 采样格`；10 mm 档 `scale-k=0.6 / alpha=0.8` 最优。
- **精度不是越细越好**：5 mm 必须同步放大半径，否则采样点之间露空；**PSNR 在 ~24 dB 饱和**——
  这是「不做梯度拟合」的上限（颜色直接取源像素、无 SH、无 densify）。真 3DGS 靠优化还能再涨，
  但那需要可微光栅化 + 反传（下一片）。
- 网格档在细分辨率下出现非流形边（162 @5 mm）：体素表面越细越糙，闭合问题仍是 N1 那个
  「底面不可见」的老问题，跟分辨率无关。
- **三值 vs f32 的取舍**：高斯的位置/协方差/颜色是连续量，f32（或二进制浮点）才对；
  三值留给「学」的部分（学习式占据 N2、学习式 LOD 控制器 N3、条件注入 N6）。这一档刻意不走三值。

### 6.6 N2 实测（2026-10-31）：学习式占据把开放壳补成闭合体——门过

做法（`occ.rs` + `parts-3d occ`）：
- **GT 实心来自原语解析**（`objects.json` 的 kind/center/scale/rot 直接判内外），不是点云 ⇒ 底面/背面也有标签；
- 每体素特征 = 4 个视角 × [是否在剪影内, clip((d_vox − d_obs)/0.2, −1, 1), 有效] + 常数 = 13 维；
  刻意**不用颜色**（颜色捷径已踩过）；
- 模型：13→16→1 **三值 MLP**（隐藏层 STE，输出层 f32——否则 logit 动态范围被压死），
  平衡采样、SGD 20k 步，三值零占比 ~22%；
- 推理：全体素 → 实心图 → 清边界 → `fill_solid` → `fix_diagonals` → `surface_nets`。

读数（训练 scene0080–83，**留出 84–91**，1 cm 体素）：

| 指标 | 值 | 门 |
|---|---|---|
| 体积 IoU（vs 原语实心） | **0.582** 均值（0.467–0.696） | ≥0.5 ✅ |
| 网格闭合率（边界边 = 0） | **8/8 = 100%** | ≥80% ✅ |

- **N1 的闭合问题被这一片解决了**：预测出实心后，`fill_solid` 补底面，网格不再漏。
- ⚠️ **闭合判据更正**：此前用「非流形边 = 0」判闭合是错的——naive Surface Nets 在复杂体上必然产生
  4 面共边（实测每场景 457–1106 条），那不是洞。新判据是**边界边（只被 1 个面用）= 0**。
  两条指标都报：边界边 = 0（无洞）与非流形边数（网格质量债）。
- **已知缺口**：GT 用的是原语解析，真实场景没有这种 GT ⇒ 自监督标签（用多视角几何一致性建标签）
  是走向现实域的前置；2 个场景单场景 IoU < 0.5（0.467/0.479）。

### 6.7 A 实测（2026-10-31）：可微高斯光栅化——先只拟合颜色

- 把光栅化拆成「几何/alpha 决定的**权重表**」（`splat::collect`）+「颜色线性合成」（`render_from`）：
  颜色对渲染是线性的 ⇒ `∂L/∂c_i = Σ_p 2(img_p − gt_p)·w_{i,p}` 是**精确梯度**，不需要数值差分。
- `fit_colors`：固定位置/尺度/alpha，SGD 拟合颜色；**只在 GT 前景像素上拟合**（和 PSNR 口径一致）。
  第一版没加掩码，把溅到地板上的像素也拉黑，拟合反而降分（24.41→24.34）——掩码后就正常了。
- 读数（scene0080，拟合视角 0,2,4,6，留出 1,3,5,7，`scale-k 0.6 / alpha 0.8 / 30 步`）：

| 采样格 | 拟合视角 PSNR | 留出视角 PSNR |
|---|---|---|
| 20 mm | 21.97 → 22.77 | 21.96 → **22.35** |
| 10 mm | 24.41 → 25.01 | 23.92 → **24.11** |

- 结论：只拟合颜色涨 **+0.2～0.4 dB**（颜色本来就取自同一批视角）；拟合视角涨得更多（+0.6～0.8 dB）
  ⇒ 是轻度过拟合。**要像真 3DGS 那样涨分，必须让位置/尺度/alpha 也进梯度**（权重表对几何的导数、
  densify/prune），那是下一片，不是再调 lr 能解决的。

### 6.8 A（续）几何梯度：位置进反传，留出 PSNR +0.2～1.5 dB

- 光栅缓存改成「投影 + 条目（w=a·g·pre）」；反传顺序：颜色（线性）→ 权重链 → (u,v,σ) → 相机雅可比 → 位置；
  另有 ∂σ/∂深度 把深度也接回位置。
- **踩了两个坑**（都靠有限差分逼出来）：
  1. 权重链项最初按「prefix sum」写，方向反了 ⇒ 位置更新让拟合视角从 24.58 掉到 14.97。
     正确形式是按像素**逆序**维护 `acc ← a·g·direct + (1−a·g)·acc`（透射率的衰减乘积），
     每个高斯的有效 `dL/dw = direct − acc`。
  2. 单高斯/双高斯的解析梯度已与有限差分一致（单测钉住）；5 个高斯密集重叠时数值差分本身被
     离散条目集与 f32 噪声污染（eps 1e-3→1e-4 时数值从 191 跳到 1214），只保留「方向能降损」的回归测试。
- 读数（scene0080，6 视角拟合 / 2 视角留出，10 mm，只动位置、lr 1e-3）：

| 配置 | 拟合视角 | 留出视角 |
|---|---|---|
| 颜色拟合（30 步） | 24.58 → 25.13 | 23.69 → 23.70 |
| 位置拟合 30 步 | 24.58 → 26.08 | 23.69 → **24.65** |
| 位置拟合 60 步 | 24.58 → 26.93 | 23.69 → **24.97** |
| 位置拟合 120 步 | 24.58 → 27.85 | 23.69 → **25.23** |
| 位置+尺度+alpha+颜色 30 步 | 24.55 → 26.55 | 23.69 → 24.56 |

- 另外两个场景（位置 60 步）：scene0081 23.44 → 23.61、scene0082 24.77 → 25.04。
- 结论：**位置梯度是有效项**（+0.2～1.5 dB）；尺度/alpha/颜色同时开反而略差（过拟合），
  因为我们的初始化已经贴近观测。要加强收益需要 densify/prune（欠覆盖处加高斯）与更多视角。

### 6.9 N2 自监督标签（2026-10-31）：不依赖物体定义，反而更准

标签规则（`occ::selfsup_solid`，只用多视角 RGB-D 剪影/深度，不用 `objects.json`）：
- 任一视角里「投到**背景像素**」或「在观测表面**前方 τ=3 cm** 之外」⇒ 自由空间（空）；
- 所有视角都落在剪影内、从未被判自由 ⇒ 实心（这等价于多视角剪影锥求交 + 深度自由空间雕刻）；
- 从未进入任何视野 ⇒ 空（防远场全实）。

读数（1 cm，训练 80–83 / 留出 84–91，三值 MLP 20k 步）：

| 指标 | 自监督 | 原语监督（上一版） |
|---|---|---|
| 标签自身 vs 解析实心 IoU | **0.768–0.893**（均值 ~0.83） | 1.0（定义如此） |
| 训练出的模型体积 IoU（vs 解析实心） | **0.655**（0.541–0.700） | 0.582（0.467–0.696） |
| 网格闭合率（边界边 = 0） | **8/8 = 100%** | 8/8 = 100% |

- 门（IoU ≥0.5、闭合 ≥80%）✅，且**摆脱了对场景定义的依赖**——现实域可直接用同一套标签。
- 反直觉但合理：自监督标签比原语标签更「贴合特征」——标签和特征都从同一批视角算出来，
  模型不用去拟合一个与观测无关的解析体；代价是标签上限只有 ~0.83（剪影锥的外凸误差）。
- 局限：τ 与视角数会影响标签（τ 大 → 更保守）；凹面会被剪影锥填平；
  极端遮挡/仅 2 视角时退化。

### 6.10 A（续）densify/prune：**在这批数据上没有收益**（负结果）

- 做法：每轮渲染拟合视角；前景像素残差 > `--densify-err` 的，在观测表面（深度反投影）补高斯
  （颜色取 GT、半径 0.6×格）；alpha < 0.02 的删掉；每轮后跑位置拟合。
- 读数（scene0080，6 拟合 / 2 留出，位置拟合 30 步/轮）：

| 配置 | 新增/删除 | 留出 PSNR |
|---|---|---|
| 无 densify，位置 30 步 | — | 24.65 |
| 无 densify，位置 60 步 | — | **24.97** |
| densify 1 轮（err 0.15） | +1784 | 24.55 |
| densify 3 轮（err 0.15） | +4412 | 24.76 |
| densify 2 轮（err 0.3） | +686 | 24.96 |
| densify 2 轮（err 0.5） | +133 | 24.97 |

- 结论：**没有超过「不 densify、只多走几步位置拟合」**。原因在本数据：初始密度已经够
  （14k 高斯覆盖 384² 的前景），残差主要来自光照/模糊与视角外推，不是覆盖不足；
  真 3DGS 的 densify 收益来自上百视角 + 梯度分裂/克隆判据 + SH 颜色。
- 保留实现（`--densify`、`--densify-err`），默认关；不要再拿它当涨分手段。

### 6.11 敏感性扫描 + 网格↔高斯一致性（2026-10-31）

**N2 自监督标签的敏感度**（1 cm，训练 80–83 / 留出 84–91；标签与模型都对着解析实心打分）：

| 视角数 | τ=1 cm | τ=3 cm | τ=6 cm |
|---|---|---|---|
| 2 | 0.547 | 0.547 | 0.547 |
| 4 | 0.613 | 0.610 | 0.574 |
| 6 | **0.742** | 0.745 | 0.705 |
| 8 | **0.744** | 0.682 | 0.669 |

- **视角数是主因**：2→6 涨 0.20，6→8 饱和；而且**视角要铺开**（相邻 4 视角 0.613 vs 隔帧 4 视角 0.655）。
- **τ 越小越好**：1 cm 与 3 cm 相当，6 cm 明显掉（自由空间被过度扩张，剪影锥被削）。
- 标签自身 IoU 随视角从 0.60（2 视角）升到 0.887（8 视角、τ=1 cm）——标签上限基本由视角覆盖决定。
- 生产默认改成 **8 视角、τ=1 cm**（原默认 4 视角/3 cm 只有 0.655）。

**网格 ↔ 高斯一致性**（`parts-3d align`，8 视角，1 cm）：

| 场景 | 高斯数 | 距网格面 ≤1 格 | ≤2 格 | 网格表面被覆盖 | 覆盖像素落在前景 |
|---|---|---|---|---|---|
| scene0080 | 16,704 | 72.0% | 97.8% | 18.8% | 89.4% |
| scene0081 | 50,826 | 80.6% | 98.5% | 26.3% | 95.2% |
| scene0082 | 31,210 | 83.0% | 98.6% | 28.2% | 94.8% |

- **两套表示几何上一致**：98% 的高斯在网格面 2 毫米内（2 格）。
- 「高斯在实心内」只有 29–44%：网格是视觉外壳，剪影边缘的高斯正好被雕刻掉一层——不是漂移。
- 「网格表面被高斯覆盖」只有 19–28%：网格包含**从未观测到的背面/底面**，高斯只覆盖观测面。
  这个差值就是「视觉外壳 vs 可见表面」的量化缺口，也是后续要学的地方。
- 高斯覆盖像素里 5–11% 落在背景：掠射角溅出，量级可接受。

### 6.12 补背面高斯 + 网格面按可见性拆分（2026-10-31）

**补背面高斯**（`parts-3d align --fill`）：取 N2 实心表面里**没有被任何高斯中心覆盖**的格，
按最近已观测高斯的颜色补一个低置信度高斯（alpha 0.35，半径 0.6×格）。

| 场景 | 补前表面覆盖 | 补后 | 补的数量 | 8 视角 PSNR（同视角，非留出） |
|---|---|---|---|---|
| scene0080 | 27.4% | **100%** | +11,967 | 23.00 → **24.65** |
| scene0081 | 34.2% | **100%** | +30,774 | 25.12 → **26.27** |

- 覆盖缺口被完全补上；PSNR 顺带涨 1.2–1.7 dB——因为「未覆盖表面格」里也有**观测面**的稀疏处。
- ⚠️ 背面颜色是「最近已观测高斯」的猜测，没有视角能验证；PSNR 是**同 8 视角**的重建拟合，不是泛化读数。
- 顺带修了一个索引口径 bug：高斯的格子用 `round`、补的格子用格心 ⇒ 覆盖统计少算；统一成 `floor(格心)`。

**网格面按可见性拆分**（`parts-3d obs-split`）：三角形重心投到任一视角落在前景、且深度差 ≤2×格 ⇒ 可见。

| 场景 | 面数 | 可见 | 不可见 |
|---|---|---|---|
| scene0080 | 64,262 | 62.2% | **37.8%** |
| scene0081 | 178,638 | 84.8% | **15.2%** |
| scene0082 | 100,608 | 76.7% | **23.3%** |

- 与高斯覆盖缺口（19–28%）同量级：**网格里 15–38% 的面从来没被看到**。
- 输出两份 PLY（`*.seen.ply` / `*.unseen.ply`），下游可以只对可见面承诺精度，
  不可见面明确标注为「补出来的」。
- 注意：这一版用的是**自监督实心**直接提网格（不经 N2 模型），边界边 30/66/0 —— 有轻微不闭合；
  N2 模型输出那一档是 0 边界边。

### 6.13 把 fill / obs-split 切到「闭合实心」——结论与预期相反（2026-10-31）

原计划：让 `align --fill` / `obs-split` 用 N2 模型（已训练、可泛化）的实心，消掉上一版
自举标签网格的 30/66/0 条边界边。实际做下来发现两件事：

1. **边界边的根因不是「用标签还是用模型」，而是自举标签没做闭合后处理**。
   两边都套上「清边界 → `fill_solid` → `fix_diagonals`」后，自举标签版的边界边变成 **0**
   （三场景 64,316 / 178,960 / 100,516 面全部闭合）。
2. **模型实心比标签实心差**（体积 IoU 0.70 vs 0.89；可见面占比 33.7/56.3/48.0% vs
   62.1/84.6/76.8%），因为模型只是近似标签的剪影锥结论，额外「实心」会把网格面推到观测之外；
   用它做背面填充会把 PSNR 从 25.12 拉到 22.87。

| 实心来源 | 边界边 | 可见面 | 补背面后 PSNR（8 视角） |
|---|---|---|---|
| 自举标签 + 闭合后处理 | **0** | 62.1/84.6/76.8% | 23.00→24.65 / 25.12→26.27 |
| N2 模型（同 8 视角）+ 闭合后处理 | **0** | 33.7/56.3/48.0% | 25.12→22.87（变差） |

**结论**：当前管线默认走「自举标签 + 闭合后处理」（`--model` 保留给「推理视角少于训练视角」
的场景）。模型的价值不在替代标签，而在标签算不出来时兜底；这条要在做 S5 现实域时重新量。

### 6.14 N5 第一块：顶点着色烘焙 + 程序化材质库（2026-10-31）

**顶点着色烘焙**（`parts-3d mesh-tex`）：网格顶点从最近高斯取颜色（半径 ≤3 格），
取不到的顶点写灰（128）表示「不可见/推断面」，并统计上色率：

| 场景 | 顶点/面 | 边界边 | 上色率 | 未观测顶点 |
|---|---|---|---|---|
| scene0080 | 32,118 / 64,316 | 0 | 85.7% | 4,590 |
| scene0081 | 89,159 / 178,960 | 0 | 97.7% | 2,050 |
| scene0082 | 50,139 / 100,516 | 0 | 90.9% | 4,543 |

输出带顶点颜色的 ASCII PLY（`property uchar red/green/blue`），可直接进 Blender/Three.js。

**程序化材质库**（`tex.rs` + `parts-3d tex`）：wood / marble / rust / grid 四种，全部用周期函数构造；
无缝度判据 `seam_ratio` = 边界相邻差 / 内部相邻差 p95（≈1 表示看不出接缝）：

| 材质 | 接缝比 |
|---|---|
| wood | 0.28 |
| marble | 0.30 |
| rust | 0.43 |
| grid | 0.94 |

- 判据改了一次：最初用「内部差均值」做分母，尖锐纹理（grid 的台阶）会被误判成有缝（8.47）；
  改成 p95 后回到 0.94，单测钉住「四种材质都 <2 且彼此可区分」。
- **诚实缺口**：这一块是**程序化**材质，不是学出来的；DreamMat 那种「几何条件 + 2D 扩散出 PBR」
  需要 2D 生成先验，本仓没有 ⇒ N5 的学习部分仍未开工，先把「有颜色的网格资产」这条链路打通。

### 6.15 pipeline 接网格着色 + N5 学习地基（2026-10-31）

**`parts-cli pipeline --mesh`**：一次命令出 `ids.bin` + `parts.ply` + `mesh.ply`（带顶点色）。
网格来自预测 id + 外部深度的点云（`--cell` 控制精度），顶点投回本视角、前景且深度一致才上色。

实测（训练装配 `big-r2.4` 第 0 帧，1 cm → 8 mm）：
`384² → 384² 50 ms，部件像素 4.02%`；`12,768 顶点 / 26,524 面（边界边 0，非流形 112）、顶点着色 61.6%`。
单视角着色率只有 61.6%（多视角 `mesh-tex` 是 86–98%），这是单视角的固有上限，不是 bug。

**N5 学习地基**（`parts-3d tex-prior`）：拿程序化材质当数据，训一个 **3×3 三值去噪算子**（9→16→1），
在**留出材质种子**上量 PSNR：

| 材质（seed 2） | 噪声 PSNR | 去噪后 |
|---|---|---|
| wood | 19.97 | **24.35** |
| marble | 22.26 | **27.12** |
| 均值 | 21.12 | **25.73（+4.62 dB）** |

- 30k 步不到 1 秒（CPU），三值零占比 ~29%；说明「三值小算子 + 合成材质数据」这条路能训起来。
- **仍不是生成**：这是去噪/回归算子，不是 DreamMat 那种「文本/几何 → PBR」的 2D 扩散。
  要跨到生成还缺：可微采样器、文本/属性条件、更大的感受野（3×3 只能吃掉局部噪声）。

### 6.16 N5 条件可学性验证（2026-10-31）：三值小网吃得住条件，但感受野不是越大越好

`tex-prior --patch N [--cond]`：输入 patch² 个灰度 + 材质 one-hot（4 维），9/49+4 → hid → 1。
评测在**留出材质种子**上，同时喂「正确条件」与「错误条件」，差值就是条件的实际使用量。

| 配置（64² 材质，4 种） | 步数/lr/hid | 留出 PSNR | 错条件 PSNR | 条件差值 |
|---|---|---|---|---|
| 3×3，无条件 | 30k / 0.03 / 16 | 24.82 | — | — |
| 3×3 + 条件 | 30k / 0.03 / 16 | 27.01 | 17.43 | **9.58 dB** |
| 3×3 + 条件 | 100k / 0.01 / 64 | **28.00** | 17.31 | **10.69 dB** |
| 7×7，无条件 | 30k / 0.03 / 32 | **5.15（训崩）** | — | — |
| 7×7，无条件 | 100k / 0.01 / 64 | 25.69 | — | — |
| 7×7 + 条件 | 100k / 0.01 / 64 | 24.22 | 19.86 | 4.36 dB |

结论：
- **「条件 → 纹理属性」确实能被三值小网学到**：错条件掉 10.7 dB，不是装饰。
- **感受野不是越大越好**：7×7 在 30k 步直接训崩（5.15 dB，比不平滑还差），100k 步才恢复到 25.69，
  仍不如 3×3 的 27–28 dB。扁平 MLP 的输入维度从 9 涨到 49，同样的逐样本 SGD 预算不够用。
- 给生成留的教训：要扩感受野应该**加深/加卷积共享权重**，不是把 patch 摊平塞进 MLP。
- 距「生成」仍差：可微采样器、真正的大感受野（深层）、以及比 one-hot 更丰富的文本/属性条件。

### 6.17 深层三值卷积 vs 3×3 MLP：**MLP 赢**（2026-10-31）

实现了 `tconv.rs`：3×3、same padding、隐藏层 ReLU、输出 sigmoid + BCE，权重三值（STE），
bias/输出层 f32；7×7 感受野只需 3 层（1→8→8→1，720 个三值权重），条件是 4 张 one-hot 常数图。

| 方法（64² 材质、留出种子、条件开） | 步数 | 正确条件 | 错条件 | 条件差 | 用时 |
|---|---|---|---|---|---|
| **3×3 MLP（hid 64）** | 100k | **28.00** | 17.31 | 10.69 | **<1 s** |
| 3×3 MLP（hid 16） | 30k | 27.01 | 17.43 | 9.58 | <1 s |
| **三值卷积栈（8,8）** | 10k | 20.45 | 12.15 | 8.30 | 2m17s |
| 三值卷积栈（8,8） | 30k | **18.07** | 12.38 | 5.69 | 6m49s |

- **结论：深度 + 共享权重没有赢**。相同步数下差 9 dB，相同墙钟时间下差得更多；30k 还比 10k 低
  （逐图 SGD 的高方差 + 三值 STE 在深层更难优化）。
- 过程中抓到一个**真 bug**：卷积层初始权重取 ±0.4，三值化后全是 0 ⇒ 整层恒零、梯度传不出去
  （损失 10k 步从 2793 只挪到 2792）。初始化放大到 ±1.2 后才开始学。单测 `learns_constant_target`
  钉住「常数图能学会」防回归。
- 梯度校验：在 `ternary=false` 的 f32 模式下与有限差分一致（三值前向是分段常数，数值差分为 0，
  不能直接对照；STE 的取舍与 `occ::Mlp` 一致）。
- 这说明扩感受野不能只靠「摊平 patch」**也不能只靠朴素加卷积层**；下一步要么给卷积栈加
  批/归一化与更低方差的学习率调度，要么承认 3×3 够用、把精力放到生成采样器上。

### 6.18 给卷积栈加批归一化：**更差**（2026-10-31）

在 `tconv` 上按通道做空间归一化（单图训练，running stats 供评测），BN 的 γ/β 用 0.02× 全局学习率。

| 配置（64² 材质，条件开，10k 步） | 正确条件 | 错条件 | loss |
|---|---|---|---|
| 卷积栈（无 BN，lr 0.02） | **20.45** | 12.15 | 2446 |
| 卷积栈 + BN（lr 0.02，BN lr = lr） | 6.70 | 7.45 | 2750 |
| 卷积栈 + BN（lr 0.02，BN lr = 0.02×lr） | 11.33 | 11.71 | 3018 |
| 卷积栈 + BN（lr 0.005，BN lr = 0.02×lr） | 10.70 | 9.54 | 4055 |

- **BN 没有救回来，反而更差**，且 loss 从 2772（随机）往上走 ⇒ 训练在发散，不是欠拟合。
- 排查过程（两个真问题）：
  1. BN 反向最初用 **running var**，前向用的是批统计 ⇒ 梯度错；修成批统计。
  2. 三值卷积层初始化 ±0.4 ⇒ 量化全 0（死层，上一节已修）。
- **BN 公式本身是对的**：纯 BN 的 `dx` 与有限差分一致（单测 `bn_backward_matches_numeric`），
  带 BN 的常数目标也能学会（`bn_learns_constant_target`）。所以失败在**优化动力学**：
  逐图 SGD + 三值 STE + 空间归一化三者叠加，步长方差过大。
- 结论：要判断 BN 的真实效果，必须先把优化器换成 Adam/动量 + 真正的批（多图梯度累积）。
  在那之前「BN 更差」只说明**当前训练配方带不动 BN**，不是 BN 无用。

### 6.19 Adam + 多图梯度累积 + 每通道缩放：卷积栈反超 MLP（2026-10-31）

三处改动（都在 `tconv`）：
1. **每输出通道可学缩放 `scale`**（三值权重只有 ±1，缺它整个网络的斜率调不了 —— 这是之前一直输的真正原因）；
2. **多图梯度累积**（`--batch K`：K 张图各自前反向、梯度累加后统一更新，批内除 K）；
3. **Adam**（`--adam`，β1/β2 = 0.9/0.999）；BN 的 γ/β 用 0.1× lr。

| 配置（64² 材质、条件开、留出种子） | 正确条件 | 错条件 | 条件差 | 步数×批 | 用时 |
|---|---|---|---|---|---|
| 3×3 MLP（基线） | 28.00 | 17.31 | 10.69 | 100k×1 | **<1 s** |
| 卷积栈 + 缩放 + Adam + 批 4 | **28.61** | 15.46 | 13.15 | 4k×4 | 5m41s |
| 卷积栈 + 缩放 + Adam + 批 4 + BN | 25.78 | 11.18 | **14.60** | 4k×4 | 6m46s |

- **卷积栈首次反超 MLP**（28.61 vs 28.00），条件差也更高（13.15 vs 10.69），代价是 340× 墙钟。
- **BN 现在能跑了但没帮上 PSNR**（25.78），条件差反而最高（14.60）。
- 之前 BN 「直接崩」的两个真因都修了：① 推理用了 running stats、训练用批统计（不一致）⇒ 推理改用
  **输入自身统计**（单图 InstanceNorm 语义）；② 缺 per-channel scale ⇒ 网络表达不出斜率。
- 缺 scale 的证据链：无 scale 时 loss 卡在 2400–2500（≈0.6/px）、PSNR 18–20；加 scale 后 loss 2278、
  PSNR 28.6。三值权重 + 只有 bias 的组合只能平移不能缩放。

### 6.20 可微采样器（DDIM）第一块：链路通了，去噪器撑不起结构（2026-10-31）

`diffuse.rs`：余弦噪声表（ᾱ_t = f(t/T)/f(0)）、加噪、**DDIM（η=0，x0 预测）**、去噪器 trait；
`parts-3d tex-gen`：在程序化材质上训 3×3/7×7 补丁 MLP 去噪器，再采样，并用三项统计量对照真实材质。

读数（48²，条件 = 材质 one-hot，T=50 采样步）：

| 配置 | 生成均值 vs 真实均值 | 生成 std | 接缝比 | 最近补丁距 |
|---|---|---|---|---|
| 3×3 MLP，20k 步（lr 0.003） | 0.438/0.944/0.436/0.595 vs 0.412/0.942/0.410/0.572 | **0.002–0.004** | 0.31–0.54 | 0.05–0.24 |
| 7×7 MLP，20k 步 | 0.91–0.97（发散） | ~0 | — | — |

- **采样链路本身是对的**：每种材质的生成均值都贴住真实均值（误差 ≤0.03），接缝比正常，
  去噪器的 x0 预测 MAE 随时间步单调上升（t=0.2/0.5/0.8 → 0.072/0.088/0.096）。
- **但结构塌了**：生成图 std 只有 0.5–1.0/255（纯平坦）。原因：逐像素 3×3 去噪器给出的 x0 是
  局部条件均值，DDIM 反复迭代把细节平均掉；7×7 反而因预算不足发散。
- 教训与 6.17 一致：**结构要靠感受野 + 稳定优化**，不是靠调采样步数。下一步有两条：
  ① 用已跑通的卷积栈（scale + Adam + 批 4）当扩散去噪器 —— 预计 50k 步 × 批 4 ≈ 60–90 min（CPU）；
  ② 把扩散训练搬到 GPU 路径（现有 WGSL conv 内核还没有对应训练循环）。
- 这一块**不算达标**：门（生成图与真实材质在统计与视觉上都可分）没有过；只证明了采样器/指标/链路可用。
  ⚠️ 2026-11-01 更正：本节的采样读数是在**起点分布写错**的采样器上测的（见 §6.23），重测后数值不同。

### 6.23 卷积去噪器接通 + **DDIM 起点与裁剪的真 bug**：第一次采出结构（2026-11-01）

三处实现：
1. `impl Denoiser for tconv::Net`：输入通道 = `[x_t, t/T]`（`Net::new(2, …)`），复用 §6.19 的 scale+Adam+批；
2. `Net::save/load`（文本 `TPC1`，单测钉住存读逐位一致）；
3. `tex-gen --conv 8,8 --batch 4 --adam --save/--load`，并用 `--holdout-names` 钉评测图。

**采样器两个真 bug（`diffuse.rs`）**：
- 起点写成 `0.5 + 0.5z`（均值 0.5、std 0.5），而训练时 `x_T ≈ ε ~ N(0,1)` ⇒ 去噪器拿到「偏暗的输入」，
  每步都往亮处修，50 步后均值被推到 0.82；
- 每步更新又 `clamp(0,1)`，把训练分布外的 `x_t` 硬压回区间内，进一步偏。
两处都在同一次改动里修掉（起点改标准正态、只在最后裁一次），并加 `initial_noise_is_standard_normal` 单测。

**同一份卷积权重（10k 步、批 4、64²、1297 张）修前/修后的采样**：

| 指标（Asphalt023S） | 修前 | 修后（50 步） | 真实 |
|---|---|---|---|
| 生成均值±std | 0.820±0.088 | **0.570±0.147** | 0.473±0.024 |
| 接缝比 | 0.46 | **1.26** | — |
| 最近补丁距 | 0.971 | **0.366** | — |

- 步数扫描（10/50/200）修后稳定：均值 0.542/0.570/0.586、std 0.142/0.147/0.149、接缝比 1.16/1.26/1.30
  ⇒ 之前的漂移不是「步数累积」造成的，就是起点分布错。
- 修前那张图是「灰底 + 黑边」的平滑块（std 0.088 基本来自边框伪影）；修后是**有空间结构**的粗斑块
  （std 0.147，接缝比 ≈1，没有边框伪影）。

**卷积 vs 补丁 MLP（同数据、同评测图、同修好的采样器）**：

| 7×7 补丁 MLP（20k，lr 0.003） | 0.887±0.006 | 0.30 | 2.81 | 5.3 min |

- MLP 的去噪器在真实图上预测均值就有 +0.3 偏（0.72 vs 0.41），采样只能塌成常数；卷积栈的
  x0 预测是准的（0.506/0.484/0.453 vs 0.473，MAE 0.06–0.08），这才是采样能出结构的前提。
- **仍未达标**：生成的是 ~8–16 px 的低频斑块，真实材质是细颗粒 speckle；7×7 感受野封死了细节，
  均值还高 0.10，最近补丁距 0.37 已经接近「抄训练集」的警戒线。
- 成本：卷积 10k×批 4 ≈ 11 min CPU；采样 50 步 ≈ 1 s（权重可存盘复用，不用重训）。

### 6.24 数据管线修正 + 定位「只会斑点」的真因：x0-预测本身在平均细节（2026-11-01）

**先修数据**：`tex-prior` / `tex-gen` 读真实图时若尺寸 ≠ n 就 `resize`——256² 缩到 128² 会把
沥青这类 1–2 px 的颗粒**直接抹平**，模型和评测都建在平滑过的图上。改成**源图够大时按原分辨率中心裁剪**
（`fit_rgb`）。影响立刻可见（7×7、298 张、100k、固定留出）：

| 数据口径 | 留出 PSNR |
|---|---|
| 旧（resize 到 128²） | 30.59 dB |
| 新（原分辨率中心裁剪） | **29.27 dB** |

⇒ 之前那张 28.7–30.6 的规模表是「平滑数据」上的读数，偏乐观，跨规模比较仍成立但要按新口径重读。
同口径下的复测还暴露了稳定性问题：3×3@298 100k = 28.08、60k = 28.12；7×7@147 100k = 27.25、
60k = 25.32；7×7@17 60k = 29.93 ⇒ **±2 dB 级别的抖动**，单点数字不能当趋势用。

**再定位生成为什么只有 8–16 px 斑块**：
1. 把已训好的 128² 卷积（x0-预测）用不同 DDIM 步数采样——步数越少细节越多但仍是斑块：
   细纹 0.523（5 步）/ 0.344（20 步）/ 0.217（50 步），真实为 0.332 且「雾感」0.95。
2. 结论：**x0-预测的目标是条件均值**，细纹理在给定局部上下文下的最优估计就是局部平均；
   DDIM 反复代回，把细节平均得更狠。**换更大感受野解决不了这个问题**（感受野越大，平均得越彻底）。

**ε-预测第一版**（`Net::linear_out` + MSE、`EpsDen` 把 ε̂ 换算成 x̂0；`tex-gen --eps`）：

| 配置（128²、8,8、批 4、5k 步） | 生成均值±std | 细纹 | 雾感 | 对比 | 最近补丁距 |
|---|---|---|---|---|---|
| x0-预测（同预算） | 0.325±0.068 | 0.217 | 0.52 | 0.22 | 0.35 |
| **ε-预测** | 0.654±0.238 | **0.777** | **0.77** | 0.78 | 0.71 |
| 真实（128² 原分辨率裁剪） | 0.474±0.038 | 0.332 | 0.95 | 0.12 | — |

- ε-预测把**高频内容带回来了**（细纹 3.6×、std 3.5×），视觉上从「平滑斑块」变成「多尺度颗粒+斑块」；
- 但**对比度过冲到 6.5× 真实、均值偏亮 0.18**，训练 5k 步时 ε 残差仍有 ~0.39（真值 1.0），
  ⇒ 还没收敛，先把「能出细节」这条钉住，标定留到下一轮（更长训练 + 末步裁剪/引导）。
- 成本：128² 5k 步 ≈ 21 分钟（8,8 三层、批 4）；权重可存盘，采样 1 秒。

std 0.384/0.308/0.238/0.182、接缝比 0.46/0.62/1.05/2.11。

### 6.27 ε 预测器的依赖性诊断：**模型是好的，采样器在放大误差**（2026-11-01）

按 §6.25 的计划做 D1（`tex-gen --diag`）：

| 口径 | 5k 模型 | 10k 模型 |
|---|---|---|
| 教师强制 t=0.2：corr(ε̂,ε) / 残差 | **0.968** / 0.358 | 0.960 / 0.319 |
| 教师强制 t=0.5 | 0.968 / 0.291 | 0.963 / 0.277 |
| 教师强制 t=0.8 | 0.963 / 0.282 | 0.960 / 0.295 |
| 自由运行（原 x0 形式 + 无裁剪） | 第 2 步 ε̂ rms → **2.3×10⁶** | 2.2×10⁶ |

- **教师强制 corr≈0.96**：ε 预测器本身不退化（之前「5 个种子输出一样」的推断要修正——
  不是模型常量，而是采样轨迹的问题）。
- 自由运行的爆炸是我那段诊断循环**没做裁剪**（与 `EpsDen` 不同）造成的，不能当结论。

**ε-空间更新**（新增 `tconv::ddim_sample_eps`，避免每步除以 √ᾱ）：
x_{t−1} = √(ᾱ_{t−1}/ᾱ_t)·x_t + [√(1−ᾱ_{t−1}) − √(ᾱ_{t−1}/ᾱ_t)·√(1−ᾱ_t)]·ε̂。

| 采样方式（10k 模型，50 步，Asphalt023S） | 均值±std | 接缝比 | 最近补丁距 |
|---|---|---|---|
| x0 形式（默认，`EpsDen`） | 0.236±0.199 | 0.97 | 0.788 |
| **ε-空间（`--eps-space`）** | **0.036±0.186** | **inf** | 1.295 |

- ε-空间在本机**不稳**：余弦表在高 t 的比值 √(ᾱ_{t−1}/ᾱ_t) ≈1.58，残差 0.3 被逐级放大，
  输出饱和成近黑白（接缝比 inf = 内部几乎全平）。
- 结论：**模型 → 采样器的接口是当前的瓶颈**，不是数据或容量。下一步不该再改训练，
  而该换参数化（v-prediction 或 σ-缩放）或在高 t 段用更多步数（非均匀时间步）。
  `--eps-space` 保留为对照开关，默认仍走 x0 形式。

### 6.28 v-prediction：目前最好的一版（细节与均值同时到位的一半）（2026-11-01）

参数化 `v ≡ √ᾱ·ε − √(1−ᾱ)·x0`，采样 `x̂0 = √ᾱ·x_t − √(1−ᾱ)·v̂`——高 t 没有除法，天然稳。
训练目标 v（线性输出 + 平方误差），同预算 128²/8,8/批 4/5k 步。

| 生成器（128²，5k 步） | 均值 | 对比 | 细纹 | 雾感 | 级数 | **hf1** | 接缝比 |
|---|---|---|---|---|---|---|---|
| x0-预测 | 0.325 | 0.22 | 0.217 | 0.52 | 21 | — | 0.67 |
| ε-预测 10k | 0.236 | 0.58 | 0.791 | 0.87 | 46 | **2.009** | 0.97 |
| **v-预测 5k** | **0.592** | 0.55 | 0.858 | 0.82 | 54 | **0.594** | 1.29 |
| 真实材质 p50 | 0.47 | 0.137 | 0.222 | 0.743 | 16 | **0.125** | — |
| 真实材质 p95 | — | 0.447 | 0.711 | 0.957 | 38 | **0.515** | — |

- **hf1 从 ε 的 2.009 压到 0.594**（≈真实 p95 0.515 的 1.15×，已在分布上沿而不是 p99 之外）；
  均值也从 0.24 拉回 0.59（真实 0.47）。
- 仍偏「干/硬」：对比 0.55 > p95 0.447、级数 54 > p95 38；步数扫描（10/20/100）只把 std 从
  0.148 调到 0.171，救不了这个偏差。
- **种子仍几乎不变**（5 个种子的均值 0.574–0.579、std 0.165–0.171）：说明模型对初始噪声依赖弱，
  这是下一个要查的点（可能是三值 STE 在 ε/v 目标下把输入细节分流掉了）。
- 结论：v-预测是目前唯一「细节回到分布内、均值也基本对」的路径，作为后续主线的参数化。

### 6.29 撤回「退化解」判断：像素是多样的，塌的是**统计分布**（2026-11-01）

**先撤回**：§6.25/§6.27 说「5 个种子输出几乎一致 ⇒ 模型塌成常量」，当时只比了均值/std/对比这些**统计量**，
没有做逐像素对拍。现在补齐：

| 口径（v 模型，两个种子 3 vs 7） | 读数 |
|---|---|
| 逐像素相关系数 | **0.026**（≈不相关） |
| 像素 rms 差 | 0.231（图自身 std 0.166） |

⇒ 两张图**完全不同**。之前那句「退化解」是**错的**，撤回。

**输入依赖探针**（`--diag` 已换成这个，旧的自由运行段会数值爆炸，已删除）：同一 `x0`、同一 t、
只换一组噪声，看预测变化多少：

| t | corr(ĥ, 目标) | 残差 | **换噪声后相对变化** | corr(ĥ, x_t) |
|---|---|---|---|---|
| 0.2 | 0.950 | 0.388 | 134.5% | 0.950 |
| 0.5 | 0.912 | 0.403 | 120.4% | 0.912 |
| 0.8 | 0.827 | 0.400 | 85.7% | 0.827 |
| 1.0 | **0.007** | 0.469 | 55.1% | 0.724 |

- 模型对输入**高度敏感**（变化量超过自身 rms），不存在「忽略输入」。
- t=1.0 时 corr 掉到 0.007：因为 `v ≈ −x0`（ᾱ→0），从纯噪声预测干净图本来就不可解；
  采样从 t=T 起步不受影响（此步几乎不改变 x）。

**真正的问题是统计欠分散**：8 个种子的对比/标准差全部挤在 0.55–0.59 / 0.165–0.171，
而真实材质的对比跨度是 p5 0.024 – p95 0.447。⇒ **像素多样、外观单模**：
模型学到了一个「高对比」外观，采样不出低对比/平滑那一支。

- 这条解释了为什么 6.24 的「hf1 偏高」和这里的「对比偏高」是同一件事：**不是采样器、不是容量，
  而是无条件模型只覆盖了分布的一个模式**。
- 下一步的正确方向是**加条件**（目标均值/对比、或材质类别），而不是继续加训练步数。
  训练步数只能让这个单一模式更清晰，不会让它变宽。

### 6.30 决定性一步：**数据没归一化**——归一化 + v-预测后，生成第一次落进真实分布（2026-11-01）

**条件通道被忽略**：给 v 模型加两路常数条件图（目标均值、目标对比）训 5k，然后点名请求
对比 0.03 / 0.14 / 0.40 —— 输出 std 0.107 / 0.104 / 0.100，**几乎不动**。
逐像素 MSE 下，条件对逐点最优预测贡献很小，网络直接忽略它。

**根因是尺度**：我们的 x0 在 [0,1]、per-image std 只有 ~0.17，而扩散噪声表 `ᾱ` 是按**单位方差**数据设计的。
信号 std 0.17 vs 噪声 std 1 ⇒ 中高 t 完全被噪声淹没，模型只能在浅层学到「均值」。

**改法**（`--normalize`）：每张图 z-score 到单位方差再训练；采样时用
`--want-mean / --want-std` **反归一化**。控制是显式的、不依赖网络学会（也就不会被忽略）；
`ddim_sample_opts(clamp=false)` 关掉 [0,1] 裁剪（归一化数据不能裁）。

**控制验证**（请求 vs 实测 std）：

| 请求 std | 0.02 | 0.043（数据中位） | 0.08 |
|---|---|---|---|
| 实测 std | **0.019** | **0.041** | **0.076** |
| 实测均值 | 0.492 | 0.493 | 0.497 |

**结构验证**（128²、8,8、批 4、5k 步、v-预测，对照真实 128² 裁剪）：

| | 均值 | 对比 | 细纹 | 雾感 | 级数 | hf1 | hf4/hf1 | 接缝比 |
|---|---|---|---|---|---|---|---|---|
| 未归一化 v | 0.592 | 0.55 | 0.858 | 0.82 | 54 | 0.594 | 0.68 | 1.29 |
| **归一化 v** | **0.493** | **0.14** | 0.372 | 0.86 | **16** | **0.145** | **0.92** | 0.60 |
| 真实（128² 裁剪） | 0.47 | 0.12 | 0.332 | 0.95 | 16 | 0.213 | 0.39 | — |
| 真实材质分布 p50 / p95 | 0.489 / 0.844（均值） | 0.137 / 0.447 | 0.222 / 0.711 | 0.743 / 0.957 | 16 / 38 | 0.125 / 0.515 | 0.93 | — |

- **均值、对比、级数、hf1、hf4/hf1 全部落进真实分布**（hf1 0.145 在 p25–p50 之间）；
  视觉上从「低频斑块」变成**细颗粒纹理**。
- 仍差两点：hf1 略低于真实（0.145 vs 0.213，缺最锐的 1 px 颗粒）；接缝比 0.60（边界略平）。
- 只训 5k 步（21 分钟）；归一化空间的损失下降更慢（R² 0.18→0.21），继续训应还能改善。

### 6.31 循环填充修边界伪影 + `seam_ratio` 会读反方向（2026-11-01）

**怎么发现的**：§6.30 的归一化 v 模型接缝比 0.60（零填充）。3×3 卷积在边界看不到对侧，纹理又本该可平铺
⇒ 加 `--circ`（Conv 支持循环填充，存盘升 TPC3、兼容读 TPC1/TPC2）。

**直接量边界**（最外一圈相邻差均值 ÷ 内部相邻差均值，新增 `look.border`）：

| | 均值 | 对比 | 级数 | hf1 | **边界比** |
|---|---|---|---|---|---|
| 零填充（默认） | 0.49 | 0.14 | 16 | 0.145 | **1.221** |
| **循环填充 `--circ`** | 0.49 | 0.13 | 15 | 0.141 | **1.054** |
| 真实（128² 裁剪） | 0.47 | 0.12 | 16 | 0.213 | **1.003** |

⇒ 循环填充把边界伪影从 1.22 压到 1.05（真实 1.00），其余统计量基本不动。

**顺手抓到一个度量陷阱**：`tex.rs::seam_ratio`（边界差 ÷ **内部 p95 差**）在同一对模型上给出
**相反方向**（零填充 0.60、循环 0.40）——因为分母用 p95，两个模型的内部尾部分布不同就翻号。
⇒ 跨模型比较用 `look.border`（均值口径），`seam_ratio` 只在同一模型的横向调参时可用。

### 6.32 步数与容量都到平台：剩下的是**损失口径**（2026-11-01）

归一化 + 循环填充 + v-预测这条主线，逐项加预算：

| 配置（128²、批 4） | 步数 | 损失(末) | 均值 | 对比 | 级数 | hf1 | 边界比 | 用时 |
|---|---|---|---|---|---|---|---|---|
| 8,8 | 5k | 6405 | 0.489 | 0.13 | 15 | 0.141 | 1.054 | 22 min |
| 8,8（续训） | 10k | 6304 | 0.496 | 0.13 | 15 | 0.147 | 1.044 | +22 min |
| **8,8,8（三层）** | 5k | **6339** | 0.502 | 0.14 | 16 | **0.152** | 1.059 | **75 min** |
| 真实（128² 裁剪） | — | — | 0.47 | 0.12 | 16 | **0.213** | 1.003 | — |

- **加步数无增益**（hf1 +0.006、损失在噪声内）；
- **加容量几乎无增益**（hf1 +0.005，代价 1.9× 计算、损失只降 1%）；
- ⇒ 在「MSE 回归 v」这个目标下，**hf1 到 0.15 就封顶**，与真实 0.213 的差不是预算问题，
  而是**平方误差本身偏好条件均值**（高频细节在不确定时被平均掉）。
- 下一步是换损失口径（最省的一条）：在 v/x0 上加**高通（Laplacian）匹配项**，
  或对低频/高频分别加权；预期能把 hf1 往上推，同时只牺牲一点 PSNR。
- 另外两条路更贵：感知损失（需要特征网）、对抗项（需要判别器）。三值主干 + f32 判别器可行，
  但要先把「高通项」这条便宜路试完。

### 6.35 S6.3 第一版：类别条件被忽略（负结果，附成因与下一步）（2026-11-01）

**做了什么**
- 标签：ambientCG `displayCategory` 归并成 8 个超类（tile/ground/wood/other/masonry/metal/stone/fabric，
  116–202 张/类），`D:/KF/trit-data/textures/labels.tsv`；tex-gen 按 assetId 前缀绑定，**命中 1297/1297**。
- 条件形式：**FiLM**（每隐层按类逐通道 `y = γ[c]·y + β[c]`，含空类），10% 条件丢弃；
  `--film K --labels tsv --want-class k`；存盘升 **TPC5**（兼容读 TPC1–TPC4），单测两条（按类调制、两类可学）。
- 评估：`scripts/eval_s63.py`——8 类各生成 2 张（同 seed/同权重），与真实同类分布比
  stroke/coherence/contrast/levels/hf1，并算跨类 Spearman。

**结果：条件没起作用**

| 类 | stroke | coherence | contrast | hf1 |
|---|---|---|---|---|
| fabric | 2.18 | 0.061 | 0.137 | 0.172 |
| masonry | 2.42 | 0.062 | 0.141 | 0.162 |
| wood | 2.34 | 0.064 | 0.137 | 0.161 |
| other | 2.31 | 0.062 | 0.141 | 0.165 |
| ground | 2.24 | 0.062 | 0.137 | 0.168 |
| tile | 2.37 | 0.062 | 0.141 | 0.161 |
| stone | 2.37 | 0.062 | 0.141 | 0.165 |
| metal | 2.36 | 0.062 | 0.141 | 0.164 |

跨类 Spearman：stroke +0.17、coherence +0.19、contrast 0.00、levels 0.00、hf1 +0.44（≈噪声）。

**为什么**：读权重就能看到——FiLM 几乎没学动。3k 步、lr 0.002 时 γ 行均值 0.999–1.000、β≈0；
把 FiLM 学习率放大 **30×** 再训 2k 步，γ 仍只在 **0.989–1.008**、β ±0.011。
⇒ 与 §6.30 的「常数条件通道被忽略」是同一个病：**逐点回归损失对类别没有可辨识性**，
网络用卷积权重就能解释数据，γ/β 的梯度自然趋零。

**下一步（已排好）**
1. **辅助分类损失**：用小分类器对 x̂0 判类，要求与请求类一致（最直接，能逼出类别信息）；
2. 或**每类独立输出头**（工程上等于 8 个小模型，能立刻验证「类别是否有用」的上界）；
3. 显式按类反归一化（每类的中位均值/标准差）只能控亮度/对比，控不了结构，别当 S6.3 的答案。

**顺带**：给 `--save` 加了每 1000 步的**断点**（本机常被直接关机，避免整轮白跑）。

### 6.36 S6.3 上界：每类独立模型 + 按类反归一化 → 类别信号确实存在（2026-11-01）

按 §6.35 的选项②做「每类独立模型」（同一套代码，`--only-class k` 过滤训练集，4000 步/类，64²）：

| 方案 | stroke | coherence | contrast | levels | hf1 |
|---|---|---|---|---|---|
| FiLM 条件（3k，lr×30） | +0.17 | +0.19 | 0.00 | 0.00 | +0.44 |
| 逐类模型 + **全局**反归一化 | +0.74 | +0.29 | **−0.81** | **−0.72** | +0.48 |
| **逐类模型 + 按类反归一化** | **+0.60** | +0.29 | **+0.85** | **+0.93** | **+0.90** |

（表内是「生成类的均值 vs 真实类均值」的跨类 Spearman；8 类，每类 2 张生成样本。）

- **结论一：类别信号是存在的**——逐类训练能把 stroke/contrast/levels/hf1 的跨类排序大幅对齐；
  所以 §6.35 的失败是**条件机制**（逐点损失下 FiLM 被忽略），不是数据没有类别差异。
- **结论二：反归一化必须按类**。第一版用全局中位 std，contrast/levels 直接负相关（−0.81/−0.72）；
  换成每类自己的中位均值/标准差后变成 +0.85/+0.93。这是 S6.5「显式参数」的又一个例证。
- **仍弱的是 coherence（+0.29）**：木材真实 0.57、生成只有 0.21——方向性/结构是最后一块硬骨头。
- 代价：8 个模型 = 8× 参数与训练时间（每类约 5 分钟@64²）；这也是「条件机制没做好」的应有代价。

**下一步**：把「辅助分类损失」加回**单一模型**（对 x̂0 判类，逼输出携带类别信息），
目标是逼近这张表的 +0.85/+0.93，同时不付 8 份权重；之后再看 coherence 怎么补。

### 6.37 S6.3 辅助分类损失：头自己都没学会（负结果，附诊断）（2026-11-01）

**做了什么**：在「最后一层隐特征」上做全局平均池化 → 线性分类头 → 交叉熵（`--aux λ`），
按 `(1−t)²` 加权（高 t 输入近纯噪声、类别本质不可辨），并打印辅助头自己的 CE/准确率。

| 配置（64²、8,8、批 4） | 步数 | 辅助头 CE（随机 2.079） | 准确率（随机 0.125） | 生成侧跨类 Spearman |
|---|---|---|---|---|
| λ=2，无 t 加权 | 2000 | — | — | ≈0 |
| **λ=8，(1−t)² 加权** | 3000 | **1.809** | **0.25** | stroke 0.00 / coh −0.48 / contrast 0.00 / levels −0.08 / hf1 +0.06 |

- **辅助头只到 2× 随机**：说明它在这个预算下几乎学不会「从带噪特征判类」，更谈不上把类别信息
  反向压进要去噪的特征里。
- 生成侧统计仍是平的 ⇒ 与 §6.35 的 FiLM 一样：**逐点回归 + 弱分类信号 = 条件被忽略**。
- 对照 §6.36 的上界（逐类模型 +0.85/+0.93）：类别完全可表达，问题纯粹在**单模型的机制**。

**下一步（按性价比）**：**每类一个输出卷积头**（共享主干、9 个头），这等于把上界的机制塞回单一模型，
参数量只多最后一个卷积；比继续调辅助损失更可能一次到位。coherence（木纹方向性）仍单独欠账。

### 6.38 S6.3 成功机制：**每类一个输出头（共享主干）**（2026-11-01）

把「逐类上界」的机制塞回单模型：主干共享，最后 1×1…实际是**每类一个输出卷积**（9 头含空类），
其余层共用；`--heads` 开关，存盘升 **TPC6**（兼容读 TPC1–TPC5）。

**小规模先验（2 类，wood vs metal，3k 步 / 64²、2 张/类）**

| | 生成 coherence | 真实 coherence |
|---|---|---|
| wood 头 | **0.297** | 0.573 |
| metal 头 | **0.079** | 0.224 |

方向一致（wood ≫ metal），量级约真实的 1/2–1/3。

**扩到 8 类（3k 步 / 64²，单模型，5 分钟）**

| 方案 | stroke | coherence | contrast | levels | hf1 | 成本 |
|---|---|---|---|---|---|---|
| FiLM（§6.35） | +0.17 | +0.19 | 0.00 | 0.00 | +0.44 | 1× |
| 辅助分类损失（§6.37） | 0.00 | −0.48 | 0.00 | −0.08 | +0.06 | 1× |
| 逐类独立模型（§6.36，上界） | +0.60 | +0.29 | +0.85 | +0.93 | +0.90 | 8× 训练 |

**下一步**：把 8 头扩到「头 + 每类反归一化」的完整采样流程（已在上表做），并把 coherence 继续攻

### 6.39 方向性损失：coherence 拉起来了，但做出来的是「细条纹」不是木纹（2026-11-01）

**做法**：对指定类（木纹，类 2，真实主梯度角 **89.9°**）加一项
`λ·mean((g·m)²)`，其中 `g` 是**预测 x̂0 的 Sobel 梯度**、`m ⊥ 目标方向`（抑制垂直方向的梯度分量），
梯度经 Sobel 转置回传；只在该类、且 v-预测（用 ᾱ 把 v̂ 还原成 x̂0）时生效。`--dir-class/--dir-angle/--dir-loss`。

**读数（8 头模型 + 方向损失，3k 步 / 64²，木纹类）**

| λ | 生成 coherence | 主方向 | stroke | hf1 |
|---|---|---|---|---|
| 0（基线，8 头） | 0.134 | — | 2.30 | 0.10 |
| **1** | **0.659** | 101° | **1.00** | 0.107 |
| 3 | 0.843 | 98° | 1.00 | — |
| 5 | 0.813 | 98° | 1.00 | — |
| 10 | 0.847 | 99° | 1.00 | — |
| 真实木纹 | 0.573 | 89.9° | 7.36 | 0.12 |

- **能拉、也能控**：λ=1 就把 coherence 从 0.134 拉到 0.659（略高于真实 0.573）；λ≥3 饱和在 0.82–0.85。
- **但指标被刷了**：stroke 从 2.30 掉到 **1.00**，图上是**细密单向条纹**（像拉丝金属），真实木纹是
  有宽度的木纹+板缝。也就是说「各向异性」这个单一标量可以被「高频光栅」满足，而光栅不是木纹。
- 主方向停在 98–101°（目标 90°）：二次型只惩罚「垂直于目标的那个分量」，任何绕该轴的各向异性都能
  让损失变小，不唯一。

**教训**：方向性不是单一标量。下一步要**同时匹配主尺度与两个特征值**（结构张量匹配：
`(λ1, λ2, θ)` 三元组一起约束，或按目标 stroke 加尺度项），否则「coherence 达标」可以靠光栅刷出来。

### 6.40 结构张量匹配：先修了 Sobel 转置的真 bug，然后发现损失「只匹配能量、不匹配各向异性」（2026-11-01）

**先撤回 §6.39 的一半**：上一节方向损失的梯度用的是 `sobel_adjoint`，而它**不是** Sobel 的转置
（新单测 `sobel_adjoint_is_transpose` 用内积恒等式直接判红）。同时 `sobel()` 的 gx/gy 一开始写反了
（gx 实际是竖直差分）。两处都已修正：gx=水平、gy=竖直，转置用数值推导出的 8 邻域系数。
⇒ **§6.39 的 coh 0.659/0.85 是在错误梯度下得到的，不能当「方向损失有效」的证据**，只保留
「单一各向异性标量可被高频光栅刷满」这个观察（那条与梯度无关，图像本身就是细条纹）。

**修好之后的结构张量矩匹配**（损失 = 相对误差平方：`((Jxx−J*)²+(Jyy−J*)²+2(Jxy−J*)²)/sc²`，
J 是 x̂0 的梯度二阶矩，目标取真实木纹 188 张的均值：`Jxx=0.0234, Jyy=0.0099, Jxy≈0.0002`）：

| λ | coherence | 主方向 | stroke | hf1 |
|---|---|---|---|---|
| 0（8 头基线） | 0.134 | — | 2.30 | 0.10 |
| 0.01 / 0.1 / 0.3 | **0.032** | 53° | 1.00 | **0.235** |
| 1 | 生成塌成常数（全 0） | — | — | 0 |
| 真实木纹 | 0.573 | 90° | 7.36 | 0.12 |

- λ=1 时梯度量级比 v-损失大 ~200×（这是第一次塌成常数的直接原因）；把 λ 压到 0.01–0.3 后不塌，
  但**能量项把 hf1 顶到 0.235（≈真实 2×），各向异性反而掉到 0.032**。
- 结论：**按绝对矩匹配的写法主要在匹配「梯度能量」，各向异性不是它的约束对象**。要控各向异性得
  把损失写在**归一化矩**上（coherence/角度），或用特征分解的两个特征值分别约束——后者需要
  可微特征分解，代价更高。

**这一轮的净收获**：一个真 bug（转置恒等式单测）、一条被撤回的结论、一张说明「为什么难」的表；
木纹的方向性仍未达标。
