# 通用提取路线（C：全自建 Rust 三值）

目标：从现实图像里提取**任意物体 → 部件 → 多网格**，全链路自建、不依赖外部模型。
本文只做**账目与切片**，所有速率都是本机实测（RTX 4060 Ti，384²）。

## 0. 现状锚点（实测）

| 项 | 读数 | 来源 |
|---|---|---|
| 现模型容量 | **466,272** 个三值权重（13 层 32/64/128） | `models/parts_id8118.tpm` |
| 训练一步（前向+反向，384²） | **0.30–0.33 s** | 本轮多次训练日志 |
| 推理一帧（含两道门+解码） | **45–49 ms** | `parts-cli pipeline` |
| Blender 渲染一帧（384²、16 spp） | **0.34–0.50 s** | `blender_gt.py` 日志 |
| 每帧磁盘（rgb+depth+normal+seg） | **≈3.1 MB** | `lay-b-*` 目录实测 |
| 单卡每天训练步数 | ≈ **26 万步/天**（0.32 s/步） | 推算 |

结论：**数据生成不是瓶颈，标注定义与模型容量才是。**

## 1. C 路线真正的难点（先摆明）

1. **部件级标注在现成资产里几乎不存在**。CC0 模型（Poly Haven 等）多为整体网格，
   没有「这个螺钉属于哪个部件」的标注。⇒ 必须**用程序化部件库自己造场景**，
   标签由构造保证；代价是场景会长得像「程序化物体」，与真实照片有域差。
2. **多物体、遮挡、尺度**会把任务难度从「单物体固定布局」抬到「开放场景」。
3. **三值权重在通用任务上的容量未知**：466k 权重是专才规模；通用实例分割通常在
   10⁷ 参数级、10⁵–10⁶ 标注图上训练。我们只能从小做起、用门禁逐步验证。

## 2. 分期与验收门（每片都能判红）

### S1 · 数据引擎（3–5 天）
- 把现有 `part_cube` 扩成**程序化部件库**：方块/圆柱/板/螺钉/齿轮等 K 类，
  每类多尺寸、多材质；装配规则随机（数量、位姿、堆叠）。
- 场景合成器：随机背景（程序化 + CC0 贴图）、随机光照、随机相机轨迹。
- 标签：部件 id（清单）+ 实例 id + 深度 + valid。
- 规模：**2000 场景 × 8 视角 = 16,000 帧**（渲染 ≈1.8 h，磁盘 ≈50 GB）。
- **门**：标签自检（id→颜色→反解一致率 100%）、可见部件覆盖统计、清单外 id 0。

### S2 · 类无关实例分割（5–7 天）
- 任务从「135 个具名部件」退到「这张图里有几个物体、各自的掩码」。
- 模型：在现网基础上加实例分支（逐像素「是否物体 + 实例中心」），先 2 物体/场景。
- **门**：留出场景 mIoU ≥ 0.60、实例数误差 ≤1 的比例 ≥80%。

### S3 · 部件分解（1–2 周）
- 多物体场景下做部件级分割；指标：部件 mIoU ≥ 0.50、跨物体不串号。
- 这一步决定「拆模型」能不能成立；不达标就停在 S2（只能拆物体，不能拆零件）。

### S4 · 几何 → 多网格（约 1 周）
- 单视角：深度头在多物体数据上重训（此前单物体上与分割竞争，需重验）。
- 多视角：用已知相机做体素融合（比此前的「并集/投票」更严格：表面一致性 + 置信度）。
- 网格：体素 → Surface Nets（纯 Rust 实现，约 400 行）。
- **门**：每部件 3D IoU ≥ 0.5、mesh 水密率报数（不设通过线，先报）。

### S5 · 现实域（时间取决于素材）
- 合成域达标后再谈实拍：需要真实照片 + 少量人工校正；此前的教训是
  「合成训练 → 实拍」有未量的域差，必须先拿到真图再定预算。

## 2b. S1 实测（2026-10-31，第一片）

**数据引擎**：`s1_gen_scenes.py`（5 种布局、逐物体缩放/旋转、最小间距采样、xy 对齐相机注视点）
+ 渲染器扩展（`scale/rot`、`--elev-sweep` 逐帧仰角扫描，**默认参数与旧数据逐位一致**）
+ 标签自检 `s1_check_labels.py`。

| 项 | 读数 |
|---|---|
| 场景 / 帧 | **200 / 2,400**（12 视角，仰角 ±20° 扫描） |
| 标签正确性 | **100%**（id ⊆ 清单、digits↔id 一致、0 空帧） |
| 渲染吞吐 | **≈0.5 s/帧**（含场景启动约 3.5 s/场景） |
| 单帧可见部件 | 中位 **11**（场景部件中位 27） |
| 12 视角并集覆盖 | 中位 **0.474**（p10 0.17，<0.6 的场景 136/200） |
| 失败模式 | Blender 静默失败（rc=0 无产物）；根因 = **E 盘写满**；已加磁盘预检 + 产物帧数校验 + 重试 |

**结论**：引擎可用，但**部件堆得太密**——即使在 12 视角 + 仰角扫描下，也有一半部件从未被看到。
对 S2（类无关实例分割）够用（不可见部件 `valid=0`，无监督）；对 S3（部件分解）需要更稀的装配：
下一轮参数建议「每场景 8–16 个部件、间距 ×2.2、每场景 16 视角」。

## 2c. S2 实测（2026-10-31）：多物体数据改了 6 轮 + 基线达标

**数据侧迭代（每轮都是被一个测出来的缺陷推着走）**

| 版本 | 改动 | 结果 |
|---|---|---|
| v1 | 2–4 物体 x 排开，部件悬空 | 每实例中位 **3.5 个 2D 连通块**（悬空部件），实例距中位 6 px ⇒ 连通域不可能分对；实例头 2k 步 mIoU 0.211（塌成 2 个 id，pred/gt 恒 0.66） |
| v2 | 想加「部件咬合」但参数没接上（脚本替换被 CRLF 吞），只换了随机色 | 当颜色对照用（见下） |
| v3/v4 | 接上间距；`part_cube` 5.5 cm → 0.19–0.39 m | 仍不聚拢：布局在固定跨度里均匀撒点 |
| v5 | **链式贴附成团**（新部件贴在随机已有部件外侧） | 尺寸只按部件中心算 ⇒ 物体互吞、相机过近、整团出框 |
| **v6** | 尺寸/间距一律按**表面**包围盒（中心 ± 部件半径）；2 物体；物体表面间距 ≥0.3 m；逐部件随机色 | 每实例单连通块 **91%**；oracle 前景+CC 上限 **0.778** |

**v6 数据集**：`scenes_v6` 100 场景 / 800 帧（8 视角、仰角 ±15° 扫描），2 物体、6–12 部件/场景，
标签自检 100%（`s1_check_labels.py`，含实例区间连续性）。

**S2 基线（留出 20 场景 × 8 帧 = 160 帧，只算该帧可见实例）**

| 方法 | 实例 mIoU | 实例数误差≤1 | 前景 IoU |
|---|---|---|---|
| 部件模型前景（valid 头，未在这批数据上训练）+ Rust 4 邻域连通域 | 0.728 均值 / 0.982 中位（p10 0.30） | 95% | 0.989 |
| **边界头（7k 步）+ 分水岭（min-size 400）** | **0.7965 均值 / 0.9862 中位**（p10 0.33） | **97.5%** | 0.990 |
| oracle 前景 + 连通域（上限） | 0.778 | — | 1.0 |
| 实例头（平面头直出规范序 id，2k 步） | 0.346（负，塌成单 id） | — | 0.991 |

**门**：mIoU ≥ 0.60 ✅（0.7965）；实例数误差 ≤1 ≥80% ✅（97.5%）。
**局限**：均值-中位差大 = 物体在投影里重叠时连通域合并（43% 的物体对投影距离 ≤4 px）；
目前 2 物体/场景、合成域。

**负结果（架构）**：规范序实例 id 学不了（见 MODEL-CARD §4g）——平面头没有全局比较算子。
改走**边界头 + 分水岭**：边界只占前景 ~4%，普通 CE 一个点都不预测（两轮复现 F1=0），
加逐像素权重（`--bnd-weight 20`）后才学到；7k 步即超过连通域基线 +9.5%。

**旁证：颜色捷径（详见 MODEL-CARD §4f）**。训练场景 `big-r2.4` 同取景重渲，循环色 id 0.8352 /
随机色 0.1800 ⇒ 交付部件头的 id 指标约 4.6× 来自颜色。**前景头不受影响**（随机色多物体上前景 IoU 0.989），
所以 S2 基线成立；但 S3（部件级）必须在随机色数据上重训部件头，否则指标没有意义。

## 3. 算力与时间账

| 阶段 | 主要成本 | 实测/估算 |
|---|---|---|
| S1 | 渲染 16k 帧 + 写部件库 | **≈2 h 渲染 + 3–5 天工程** |
| S2 | 2 物体实例分割，~30 万步 | **≈1.5 天纯训练**（0.32 s/步）+ 调试 |
| S3 | 部件级，~60 万步 + 3 倍数据 | **≈3 天训练 + 1–2 周工程** |
| S4 | 网格 + 融合 | **≈1 周工程 + 少量训练** |
| 合计 | — | **合成域可用：4–6 周**；现实域：另计 |

若把模型放大到 5M 权重（约 10×），单步预计 **1.0–1.5 s**，同一步数的训练时间 ×4；
建议**先不放大**，用现有容量把 S1–S3 的流程打通，再决定是否扩容。

## 4. 与现有交付的关系

- 现有专才模型 + 两道门（域外 rc4 / 取景 rc5）**保持不动**，作为降级路径；
- C 路线的新模型走独立 crate/分支，不干扰 `parts_id8118` 的交付读数；
- 每一步的读数都写进模型卡与台账，负结果同样记录。

## 5. 风险清单（不隐藏）

1. **程序化场景 → 实拍**的域差未量，可能重演「跨布局零样本 0.0176」式崩盘；
2. **部件语义**在不同物体上没有统一定义（螺钉算不算部件？），需要先定口径；
3. 三值容量上限未知，S2/S3 可能卡在「能分物体、分不清部件」；
4. 单卡训练窗口有限（每天约 26 万步），大规模 sweep 不现实。
