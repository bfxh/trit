# trit-flow：扩散与漂移（流匹配）共用的一套采样骨架

> 定位：**algo 层**，`publish = false`。一句话——把「生成模型的一步」抽成
> `v(x, t | cond)`，于是换模型只换一个实现，采样循环、批量组织与延迟读数都不用重写。

## 1. 为什么需要它

扩散（DDIM η=0）与流匹配（rectified flow / flow matching）在采样这一侧**是同一个 ODE**：

```text
dx/dt = v(x, t),  t: 1（噪声）→ 0（数据）
```

- 流匹配网络直接输出 `v`；
- 扩散网络输出 `x̂₀`，换算成 `v = (√ᾱ·x − x̂₀)/√(1−ᾱ)`（`X0ToVelocity`）；
- DDIM（η=0）的更新就是这个 ODE 的 Euler 步。

所以「扩散模型和漂移模型都能用」不是两套代码，而是**一个接口 + 一个桥**。

## 2. 四层

| 层 | 类型 | 口径 |
|---|---|---|
| 场 | `Field` | 批量求 `v`；`t` 与 `Δt` **按样本给**（不同步数的请求能同批推进）；`cond` 按样本；可选 `terminal_snap`（末步替换） |
| 桥 | `X0ToVelocity` | `x̂₀ ↔ v` 代数等价（`v = √ᾱ·ε̂ − √(1−ᾱ)·x̂₀`）；`t→0` 端按 `ᾱ ≤ 1−1e-6` 截断 |
| 积分 | `Scheme::{Euler,Midpoint,Heun}` | 步长负、时间递减；Euler 一阶、其余二阶（有对拍） |
| 执行 | `Executor` | 常驻 `Pool`（`std::thread` + `mpsc`）+ 按方案分组 + 按 `max_batch` 切块；在线与离线同一路径 |

### 约定（写死，不许各处理解不同）

- `t = 1` 是纯噪声，`t = 0` 是数据，`Δt < 0`；
- 因此**朝向数据**的收敛速度写成 `k(x − x₁)`（闭式解 `x(t) = x₁ + (x(1) − x₁)e^{k(t−1)}`）；
  写成 `k(x₁ − x)` 会指数发散（demo 踩过，L2 = 2.2e7）；
- 延迟 = 请求从到达执行器到完成最后一轮的墙钟毫秒；分位用线性插值（与 NumPy 默认一致）。

## 3. 读数

图 → 3D 场景：8³ 体素（512 维），条件 16 维（图像特征），`examples/img23d_flow.rs`。

### 3.1 正确性（理想漂移场 `v = 16·(x − x₁)`，64 步 Euler）

最大 L2 误差 **1.175e-6**（断言 `< 1e-3` 钉在 demo 里）。

### 3.2 吞吐（MLP 漂移场 512→64→512，64 请求 × 32 步）

| 配置 | p50/ms | p99/ms | req/s | 样本·步/秒 | 平均批 |
|---|---|---|---|---|---|
| 串行 `batch=1` | 42.60 | 42.60 | 1503 | 48 079 | 1.0 |
| 批 `batch=32` | 46.38 | 46.38 | 1380 | 44 157 | 32.0 |
| 批 + 并行 8 线程 | 7.93 | 7.93 | 8074 | 258 354 | 32.0 |
| 批 + 并行 16 线程 | 8.02 | 8.02 | 7984 | 255 479 | 64.0 |

**批单独不涨**（42.6 → 46.4 ms，批的拷贝与组批开销还略亏）：本仓的 MLP 场是逐样本循环，批不改变算术。
批的收益要等**一次 `eval` 映射成一次 GPU/矩阵乘启动**才显现；并行收益则是直接的（5.1× / 5.4×）。

### 3.3 扩散侧走同一执行器（`x̂₀` 桥，Euler 一阶）

| 步数 | 串行 p50/ms | 8 线程 p50/ms | 8 线程 req/s | L2（snap） | L2（无 snap） |
|---|---|---|---|---|---|
| 32 | 6.05 | 2.79 | 22 958 | **0.000e0** | 1.140 |
| 128 | 24.95 | 8.68 | 7372 | **0.000e0** | 0.779 |
| 512 | 94.06 | 35.64 | 1796 | **0.000e0** | 0.636 |

末步 snap 打开后，32 步就精确（理想去噪器下 L2 = 0）；关掉它，512 步仍欠积分。
**同样精度，32 步（6.05 ms）比 512 步（94.06 ms）快 15×**——这就是 `t→0` stiff 修法的实际价值。

### 3.4 图 + 深度 → 3DGS splat（占位真实场，`trit-parts` 的 example）

`crates/trit-parts/examples/img23d_splat.rs`：输入是**图 + 深度**，输出是**标准 3DGS PLY**，
中间全部走本 crate 的 `Field` / `Executor`。

| 项 | 读数 |
|---|---|
| 表示 | 256 高斯 × 8 参数（pos3 + scale + color3 + alpha）= 2048 维；条件 = 8×8 深度均值 + 亮度 = 128 维 |
| 正确性 | 终点 vs 目标模板最大 L2 = **1.103e-6** |
| PLY 往返 | 256 个高斯，最大逐项偏差 **7.451e-9**（写 → 读回逐项对账） |
| 读数（12 请求 × 32 步） | 串行 p50 1.42 ms / 8438 req/s；批 12 → 1.53 ms；批 + 并行 8 线程 1.33 ms / 9048 req/s |

**诚实话**：这是占位场——`v = k·(x − x₁)`，`x₁` 是条件最近的模板（检索式，未训练），
计算量极小，所以并发收益也小（1.42 → 1.33 ms）。**它证明的是管线与表示，不是算力上限**；
换成真权重（MLP / UNet）后才有真实读数——那部分的量级见 §3.2 的 MLP 场（串行 42.6 ms）。

## 4. 诚实缺口

1. ~~**扩散侧末端 stiff**~~ **已修（2026-11-15）**：`Field::terminal_snap`（默认 `false`）
   + `Cfg::snap`（默认 `true`）——积分最后一步之后，场可以给出数据侧估计替换结果；
   扩散桥 `X0ToVelocity` 实现为「直接取 `x̂₀`」（DDIM 惯例）。读数见 §3.3：
   32 步 L2 从 1.140 → **0.000e0**，且比无 snap 的 512 步快 15×。
   判据是 `tests/terminal.rs` 的 4 个测试（端点精确、纯速度场不受影响、条件参与、批+并行仍逐位一致）。
   仍开放的：**隐式/指数积分器**没有做——如果将来要在 `t→0` 端继续积分（而不是 snap），那才是它的位置。
2. **批收益依赖场实现**：见 §3.2，CPU 逐样本场吃不到批收益。
3. **没有服务面**：无 HTTP/gRPC、无超时取消、无鉴权；本层只给内核与读数。
4. **GPU 未接**：`Field` 是 CPU 批量口径；接到 `trit-gpu` / `trit-parts` 的 WGSL 后端时，
   一次 `eval` 应对应一次 kernel 启动（这才是批收益的来源）。
5. **没有训练**：`Field` 只前向；「图 → 3D 漂移模型」的权重从哪来由训练侧决定。

## 5. 跑法

```bash
cargo run --release -p trit-flow --example img23d_flow
cargo run --release -p trit-parts --example img23d_splat
cargo test -p trit-flow
```
