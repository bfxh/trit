# 模型卡：部件平面头（trit-parts）

`publish = false` 的实验层模型，**不属于稳定 API**。所有数字都是本仓可复现命令跑出来的，
不是引用值；未验的条目在「局限」里逐条写死。

## 1. 它做什么

输入一帧 **384×384 RGB**（合成渲染的装配体），输出 **部件 id 图**：
`k=5` 条三进制平面（`3⁵ = 243` 个槽位，当前清单用 135 个）+ 1 条 `valid`（有无部件）。
id 由平面按 `id = 1 + Σ digitᵢ·3^(k−1−i)` 拼出，`0` 表示背景。

```text
RGB ──► 三值卷积网络 ──► 5 平面 logits + valid ──► 清单约束 argmax ──► id 图
```

判据口径：**id 一致率**（整像素 id 完全相同）与 **部件 IoU**，只在 GT 部件像素上统计
（背景占 ~96%，全像素口径会灌水）。

## 2. 结构

```text
x → e1 → pool → e2 → pool → e3 → u3 → cat(b) → d2 → u2 → cat(a) → d1 → head
```

- 13 层，通道 32 / 64 / 128（编码器-解码器 + 两处通道拼接的跳跃连接）；
- **权重是三值** `{−1, 0, +1}`（1.58 bit/权重）+ **每输出通道一个 scale**；
- 每层 **per-channel affine**（`y = relu(γ·v + β)`）——可学习 BN 的等价物，无 running stats；
- 反向只对「有效权重 `E = q·scale`」求导（GPU），`E → latent/scale` 的 STE 映射在主机侧，
  口径来自 `trit-learn::quant`（与 `trit-train` 同一套，不另立）。

导出包 `TPM1` 只含 `q / scale / γ / β / bias`，**467 KB**，约为训练断点（7.5 MB）的 1/16。

## 3. 训练配方（交付模型的来源）

| 项 | 值 |
|---|---|
| 数据 | 同一装配体的 12 个相机距离（2.0–4.2）× 150 帧，384²，合成渲染 |
| 优化器 | Adam，梯度累加 6，lr 3e-4 线性衰减到 1e-4 |
| STE | Identity |
| 样本数 | 约 35k（含一次从 1e-4 回退到 3e-4→1e-4 的续训） |
| 增强 | 光度抖动/噪声默认关（实测对域外无收益，见负结果） |
| 留出 | 距离 3.6 与 3.9（各 150 帧，共 300 帧，训练中未使用） |

## 4b. 深度预测：三版全否（3D 几何不来自本模型）

| 方案 | 留出深度 MAE | δ<1.25 | 分割 id | 结论 |
|---|---|---|---|---|
| 冻结骨干 + f32 线性读出 | 1.21 / 1.50 m | ~0 | 0.758 | 语义特征线性解码不出几何 |
| 共享 head 扩通道（三值平面） | 1.66 / 1.96 m | ~0 | 退化 | 分割被带崩 |
| **独立深度头（第 14 层，骨干冻结）** | **1.20 / 1.47 m** | **0.185 / 0.095** | **0.7907 / 0.7407** | 唯一不伤分割的方案，但精度差一个量级 |
| 独立头 + 最后 4 层解冻 | 1.06 / 1.23 m | 0.378 / 0.342 | 0.5995 / 0.5318 | 深度变好，分割塌 |
| 独立头 + 解冻 + 冻结分割 head | 1.21 / 1.30 m | 0.315 / 0.286 | 0.4738 / 0.4431 | 更差（特征漂了 head 补不回）|

- **监督口径不是杠杆**：4/5/6 平面 × 两个视差区间的 6 格扫描全落在 1.2–1.7 m（差异在 seed 噪声内）。
- **结论**：单帧 384²、无位姿/尺度输入时，深度与分割是**竞争关系**；深度到不了 3D 可用（≲0.1 m）。
  交付口径：**分割来自本模型，几何深度来自外部**（GT 或外部重建管线）。
- 用法：`parts-3d infer --model <tpm> --scene <dir> --frame N --manifest <parts.json> --out out.ply [--depth <npy>]`
  —— 模型出部件 id，深度由 `--depth` 或 `scene/depth/N.npy` 提供，输出逐部件着色的点云。

## 4i. 卷积单目深度头（2026-11-02）：能训，跨场景只比常数基线好 8%

`depthnet::DepthNet`（conv3→H→convH→H→convH→1，隐藏层三值 STE，输出层 f32 + **外置** out_b）。
整图 64²（盒式降采样）、逐图 log 深度归一化、L2、hidden 32、dil 2、60 epoch × 466 样本。

| 指标（mat60：50 训练 / 10 留出场景 × 8 帧） | 数值 |
|---|---|
| 训练 MSE | 0.65 → 0.357 |
| 留出形状对齐相对误差（f32 / 三值） | **8.30% / 8.10%**（每图中位深度常数基线 9.01%） |
| δ<1.25（f32 / 三值） | 0.971 / 0.976 |
| 可部署（固定尺度）相对误差 | 12.9% |
| 单图 3D 体素 IoU（2 cm 体素） | 0.003–0.007 |

**三个实现级 bug（都已修）**：① scale 梯度未按像素数归一 ⇒ 单步 ±40、输出爆到 1e4；
② bias 在 scale 乘法之内 ⇒ 学 DC 时 scale 被推到 0；③ 中心裁剪只看到渲染的 1/6。
另修正了一个**测试自身的错**（按扁平数组前后半取均值 = 上下半）。详见 GENERAL-PLAN §6.87。

**能力边界**：单帧 64²、无尺度/位姿输入，留出场景 8.3% 相对误差 ⇒ 5 m 物体误差约 0.4 m，
2 cm 体素 IoU≈0。**不足以支撑「一张照片→可用 3D 网格」**；缺口是数据量（49 场景时训练 MSE 0.30
但留出仍在基线，典型过拟合）。

**扩容否证（2026-11-02）**：场景 49→288、同步数（约 2.8 万步）留出 **9.25% vs 8.30%**（基线 9.01%）
⇒ 瓶颈不是场景数，是 64² + RF 13 的容量/结构。另修两处部署级 bug：`DCN3` 存膨胀率
（原先 load 按 dil=1 跑，与训练不是同一函数）、`--holdout` 完整路径匹配。详见 GENERAL-PLAN §6.90。

**五杠杆全否证（2026-11-02）**：数据 6×（9.25%）、感受野 dil 4/6（8.59/8.40%）、
多尺度输入 6/9 通道（8.27/8.64%）、量化 f32 vs 三值（同）、**多视角一致性（8.11%，软鲁棒门）**——
全部贴着 9.01% 基线。多视角的几何实现已用 `--mv-check` 验证（相邻视角 GT 互投中位 0.3–0.6%），
所以这是信号层面的结论。训练 MSE 持续降而留出不降 ⇒ 过拟合，不是容量不足（§6.91/§6.92）。

**GPU 训练端口（2026-11-03）**：`parts-depth-gpu cnn-train` 复用 parts 的 wgpu conv/bwd 内核，
与 CPU 逐点对拍（前向 max|Δ| 1.3e-6；单步后参数 ≤6e-6）。1157 样本/epoch：
**145–155 s → 2.42 s（约 60×）**，300 场景 × 60 epoch 从 ~2.6 h 降到 **~2.4 min**。
留出（40 帧 / 114,504 px）**7.85%** vs 常数基线 7.91% —— 加速只降成本，不改「64²+3 层」的天花板。
逐样本 SGD 保持配方不变，主机往返仍是瓶颈（GPU 占空比 ~20%）。`--accum K`（mini-batch SGD）
+ 融合内核 + 持久化资源 + **跨样本拼批**（批次内核，K 个样本一次 dispatch）后：K=8
**1.04 ms/样本、1.20 s/epoch（~120×，~966 样本/秒）**；b=1 与单图逐位一致、accum=1 的 3 epoch

剩余瓶颈是每块一次同步读 loss。详见 GENERAL-PLAN §6.100。

**算力杠杆实测（2026-11-03，负结果）**：hidden 128（容量 ×16）+ 87 epoch（≈10⁵ 步）、`--accum 8`、
lr 0.002，整轮 21 分钟。训练 MSE 0.7385 → 0.7204，但留出 **7.94%**（hidden 32 的 60ep 是 7.99%，
常数基线 7.91%）——仍高于基线。⇒ 容量/算力不是瓶颈，§6.91 的杠杆 ① 否证；下一步只剩换监督或换输入表示。

⇒ 全局上下文同样不是瓶颈。真正的「降采样编码器」未做。详见 GENERAL-PLAN §6.103。

## 5. 局限（必须读）

1. **只对训练过的装配摆放有效**。换一套部件坐标必须重训——零样本 id 0.0176（≈随机）。
2. **换装配时 id 必须沿结构顺序密集编号**。同一布局上把 id 随机置换后，8k 步的 id 从 0.196 掉到 0.088；
   按 z 序重编号可回到 0.130（+47%），但 A 仍是 1.5×——差距全在最低位平面，因为原布局的 id 是
   沿 z 的密集单序列（相邻差 1），而置换后的坐标只有 ~20 个不同 z 值（同层内只能任意破并列）。
   ⇒ 生产口径：**新装配按结构（父→子、沿装配轴）连续编号**，不要按名字哈希或随机打散。
3. **真实照片：已测，不可用**。4 张域外图被标成 96–99% 部件（见 §4c）；模型无拒识，必须在管线前加检测门槛。
   域外**合成**渲染（同装配、换外观）也没验过。
4. **分辨率固定 384²**，缩放到别的分辨率没有对拍过。
5. **速度**：单帧前向 16 ms（本机 wgpu）；批量 CLI 含解码约 35 ms/帧。没有做端到端帧率承诺。
6. **背景与遮挡**：`valid=0` 只覆盖背景；被完全遮挡的部件没有标签，模型对它们没有监督。
7. **颜色捷径**：id 指标里约 4.6× 来自颜色（§4f）。随机色下同一场景 id 0.8352 → 0.1800。
   在随机色数据上重训之前，**不要把 0.8118 当作形状/几何理解能力**引用（前景头例外，见 §4g）。
8. **世界坐标曾整体镜像（2026-10-31 已修）**：渲染 meta 的 `T_cw` 是**世界→相机**，旧代码把它当
   相机→世界用，且没做 Blender（看 −Z）→ OpenCV 的 y/z 翻转。单帧预测与 GT 用同一个错变换，
   **历史 3D IoU 读数不受影响**；但导出的 PLY 世界坐标是镜像的，跨视角融合会直接散架（N1 实测）。
   现在 `Camera::load` 读 `T_wc`，`unproject/project` 互逆且有单测。
