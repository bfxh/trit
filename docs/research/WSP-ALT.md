# WSP-ALT：MXQ 之外的替代路线与排序

我的建议不是“继续把 BIAS/SCALE 做完”，而是：

1. **停止 4-bit 的权重修正**：L12 int4 全量 1379 对 Pearson `0.837505`，f32 `0.837595`，
   统计上已经平手；4-bit 没有可买的 Pearson，任何“再降层内误差”都不该再开 PR。
2. **把目标改成“更少字节”**：3-bit 全量 `0.818440`，距 f32 还有约 0.019；
   这是唯一还有头寸的档位。先做 WSP-BUDGET，在 int3 字节附近分配 int3/int4；
   若还不够，再做 ROTATE 或 3-bit GPTQ。
3. **MXQ 降为内层分配器**，只在 BUDGET 证明“矩阵间分配”有效之后再做。
4. BIAS/SCALE 的代码留在本地实验分支，作为负结果证据，不进 PR。

## 2. 现有能力与缺口

仓库现在已有：

- 三值 absmean、GPTQ 逐列补偿、per-row/per-group scale；
- 均匀 int3–8、全局 `TRIT_WEIGHT_BITS`、手动 `TRIT_F32_LAYERS`；
- SVD 低秩侧车、列侧车、int8 激活、24 线程与 f32 缓存；
- 结果：L12 int4 g32 13,436,928 B，Pearson 0.837505 / Spearman 0.832047；
  L12 int5 g32 16,091,136 B；L12 f32 84,934,656 B 线性权重。

明确没做：

- 均匀 int4 的 **Hessian 最优 scale**：`uniform::dequantize` 仍是 `max/qmax`；
- 量化后的 **bias 修正**：bias 保留原 f32 值，没有按校准集均值修；
- **全局字节预算分配器**：只有全局位宽和手写层回退，没有“给定总字节，自动选格式”；
- **层内混合位宽**：`WSP-BERT6-RESULTS.md` §4 已写；
- 旋转/AWQ、结构化剪枝、码本/RVQ、QAT、4-bit 激活。

## 3. WSP-BIAS：同字节的逐通道偏差校准（P0）

### 3.1 机制

量化后每个输出通道的误差 `e_{r,i} = w_{r,i} - \hat w_{r,i}` 通常有非零均值。
对校准集输入均值 `μ_i = E[x_i]`，输出偏差是：

```text
c_r = Σ_i e_{r,i} · μ_i
b'_r = b_r + c_r
```

`c_r` 直接加进已有的 f32 bias，**不新增任何张量、不新增字节、不改前向代码**；
它修的是“量化把输出整体推偏”的一阶项，不修方差。

如果同时开 SVD/列侧车，`\hat w` 必须把侧车也算进去，否则会把侧车的均值重复修一次。

### 3.2 预演：旧表有 padding 污染，mask-aware 重算只有 ~0.7%

旧版 `quant_compare_exact.py` 的 37–40% 是**校准口径错误**：它每 172 行抽一个 token，
没有跳 padding。`miniLM-l12-sts-full` 的 `input.f32` 有 176,512 行，`mask.u8` 只有
39,031 个有效 token，约 78% 是 padding；padding 行不是全零，而且带共同偏移，
所以“全行平均”的 `μ` RMS 是 0.396，按 `mask=1` 的**有效 token** 只有 0.103。
用前者算 `c_r`，层输出误差会假降 37–40%；用后者，真实降幅只有 0.4–0.8%。

mask-aware 重算（同一 L12 第 0 层、1,024 个有效 token 校准、最后 128 个有效 token eval、
int4 g32、max-scale）：

| 配置 | query | key | value |
|---|---:|---:|---:|
| int4 max（当前） | 20.581 | 19.692 | 9.584 |
| int4 max + bias | 20.439 | 19.610 | 9.508 |
| 层输出误差降幅 | **0.69%** | **0.42%** | **0.79%** |

3-bit 同样只有 0.76% / 0.85% / 0.81%：query 48.420→48.053、key 46.020→45.630、
value 22.548→22.366。也就是说，**在正确跳 padding 后，bias 修正不是 37% 的一刀，
而是不到 1% 的边角**。

旧表的 refit/MXQ 数字仍有参考价值，但只能当“layer 重建的相对排序”，不能当
“bias 能带来 37%”的证据；旧表如下，已作废：

| 配置（旧口径） | query | key | value |
|---|---:|---:|---:|
| int4 max | 21.754 | 21.786 | 10.399 |
| int4 max + bias | 13.695 | 13.338 | 6.524 |
| int4 重拟合 scale | 18.005 | 17.687 | 8.164 |
| MXQ 3/4/5 | 15.554 | 15.543 | 7.224 |

结论：**先修校准口径，再谈算法**。M1 端到端负结果与 mask-aware 的 0.4–0.8% 一致，
不是实现 bug，而是旧预演高估了偏差项。

预演脚本：`quant_compare_exact.py`（旧口径，已作废）、`rotate_preflight.py`
（mask-aware，含 bias 与旋转）。

### 3.3 实现

M1 最小改动：

1. 校准集逐层收集 `μ_i`（和 GPTQ 的 `h_i` 同一趟前向，不读标签）；
2. `QuantLinear::from` 增加 `calib: Option<&LayerCalib>`；
3. 反量化出 `\hat w` 后，按行算 `c_r`，加到 `bias[r]`；
4. JSON 报告 `bias_corr_norm`、`bias_corr_max`，字节账不变；
5. 测试：零残差时 `c=0`；确定性；无 NaN；字节数逐位不变。

开关：`TRIT_CALIB_BIAS=1`、`TRIT_CALIB=<dir>`（M1 只接到第 0 层 Q/K/V，复算见 §3.5）。

### 3.4 判据与风险

- M1（128 对）：`Pearson` 不得低于 int4 超过 0.002；否则停。
- M2（1379 对）：同字节，Pearson/Spearman 不低于 int4，且至少一个 10k 配对
  bootstrap 95% CI 下界 > 0；否则只记方向性/负结果。
- 风险：只修均值，不修方差；校准/评测分布漂移时可能反向；Q/K 的 bias 会改
  attention logits，LN/残差可能把收益吸收掉。必须用 **sentence-disjoint** 校准复验。

### 3.5 M1 实测（2026-11-24，负结果）

实现范围：第 0 层 Q/K/V；`TRIT_CALIB_BIAS=1` 用校准 token 的通道均值修 bias，
`TRIT_CALIB_SCALE=1` 用对角 `h` 重拟合每组 scale；两者都不增字节。
校准集是数据文件里按句均匀抽的 2,519 个非 padding token，评测是同一文件的 128/1379 对
（**不是 sentence-disjoint**，只用于快速判死；正因为不 disjoint，正结果才需要留出复验）。

128 对（同字节，L12 g32）：

| 配置 | int3 Pearson / Spearman | int4 Pearson / Spearman |
|---|---|---|
| baseline | 0.897582 / 0.927222 | 0.928494 / 0.950720 |
| + bias | 0.898554 / 0.928310 | 0.928617 / 0.951109 |
| + scale | 0.897778 / 0.927717 | 0.928493 / 0.951233 |
| + both | 0.898726 / 0.929020 | 0.928612 / 0.951310 |

128 对里 int3 的 `+0.0011` 看起来像信号，但全量一跑就塌了：

| 配置 | int3 Pearson / Spearman | Δ vs int3 | int4 Pearson / Spearman | Δ vs int4 |
|---|---|---|---|---|
| baseline | 0.818440 / 0.813362 | — | 0.837505 / 0.832047 | — |
| + bias + scale | 0.818481 / 0.813555 | **+0.000041 / +0.000193** | 0.837575 / 0.832149 | **+0.000070 / +0.000102** |

全量 f32 是 `0.837595 / 0.830894`；int4 的 Pearson 与 f32 只差 `-0.00009`，
**4-bit 已经在 f32 的统计噪声内**。int3 距 f32 约 `0.0192`，但 bias/scale 只补了
`0.00004`，连噪声下界都够不到。按 §3.4 的判据（M1 不得低于 int4 −0.002）没有“失败”，
但按“要有可观测收益”的实质标准，应当停。

为什么层内 0.4–0.8% 没穿过端到端：

1. **绝对量太小**：mask-aware 的 `μ` RMS 只有 0.103，bias 项只占层输出误差的
   不到 1%；旧预演的 37% 是 padding 污染，不是真实可修量。
2. **V 的常数偏移会被下一层 LayerNorm/残差消掉**；Q/K 的 bias 主要改 attention logits
   的常数/低秩项，softmax 对一部分平移不敏感，剩下的被 LN 吸收。
3. **只修了 12 层里的第 1 层**；后面 11 层的量化误差照旧，且会重新放大/抵消。
4. **4-bit 本身没有头寸**：int4 已和 f32 平手，修得再准也只能回到 f32，不能超过。
5. **层输出误差范数不是 STS 代理**：这是项目里反复出现的教训，这次再次成立。
   0.7% 是“权重重建”的边角，不是“语义排序”的胜利。

决定：M1 代码已存为 `wsp-bias-scale.patch`，仓库只保留本节负结果；**不进 PR、不扩到
全层**。除非先拿到“bias 修正能改变 attention 输出方向”的机制证据，否则不再投入。

## 4. WSP-SCALE：同字节的 Hessian 最优 group scale（P0，和 BIAS 同一 PR）

### 4.1 机制

均匀 int4 当前是：

```text
s = max(|w_group|) / qmax
q = clamp(round(w/s), -qmax, qmax)
```

改成固定码字后，用对角 Hessian `h_i = Σ_t x_{t,i}^2` 做一次加权最小二乘：

```text
s* = Σ_i h_i · w_i · q_i / Σ_i h_i · q_i^2
```

码字仍由 max-scale 得到，只重算 `s`；不增字节，不改运行时。若愿意多迭代一次
`q` 再重算 `s`，是 Stage 0b，但预演只做了单次重拟合。

### 4.2 预演

同一层、同一 96,768 B 预算：

| 矩阵 | int4 max 重建误差 | int4 重拟合 | 降幅 |
|---|---:|---:|---:|
| query | 3.581e3 | 2.403e3 | −32.9% |
| key | 3.565e3 | 2.317e3 | −35.0% |
| value | 8.284e2 | 5.387e2 | −35.0% |

层输出口径（held-out 128 token）见 §3.2：单独 scale 重拟合 −17% 到 −21%。
它比 BIAS 弱，但和 BIAS 叠加不冲突，且不需要新格式，所以值得和 BIAS 一起做。

### 4.3 实现

- `uniform::dequantize` 增加可选 `h` 参数；有 `h` 走重拟合，没有保持 max-scale；
- `run/main_flow.rs`/`model/loader.rs` 把逐层 `h` 传进 `QuantLinear`；
- `report.rs` 记录 `scale_refit=1` 与 `scale_delta_max`；
- 测试：同码字、同码值域、字节数不变；全零 group 不产生 NaN。

## 5. WSP-BUDGET：全局字节预算编译器（P1）

### 5.1 它新在哪

现在只有“全局 `TRIT_WEIGHT_BITS`”和“手写 `TRIT_F32_LAYERS`”。没有一个入口回答：

> 给定总字节 B，哪些矩阵用三值、int3、int4、int5、f32，或加 rank 侧车？

WSP-BUDGET 把 **总字节** 变成一等输入，输出 per-matrix 格式图和 manifest。
这不是再调一个位宽，而是把模型编译成“预算内的混合格式工件”。

### 5.2 设计

- block：默认按矩阵（`query/key/value/FFN` 各一块），不按单个 group，先控制元数据；
- 每块候选：`f32`、`ternary g32`、`int3 g32`、`int4 g32`、`int5 g32`，可选
  `sidecar rank r`；
- 代价 `C_{m,b}`：直接复用 `run/weight_format.rs` 的字节账，含 scale/bias；
- 敏感度 `J_{m,b}`：用逐层真实输入的 `h` 算 §4 的加权重建误差；MVP 可先用
  “权重 + 第 0 层 h”做代理，但必须标注；
- 分配：拉格朗日 `min Σ J + λ Σ C`，二分 λ，剩余字节贪心补齐；
- 输出 `budget.json`：

```json
{
  "schema": 1,
  "total_bytes": 13436928,
  "calib_sha256": "...",
  "blocks": [
    {"name": "layer0.query", "mode": "int5", "actual_bytes": 115200, "proxy_err": 1.2e3},
    {"name": "layer0.key", "mode": "int4", "actual_bytes": 96768, "proxy_err": 2.3e3}
  ]
}
```

`bert6` 读 `TRIT_BUDGET=<json>`，按块构造 `QuantLinear`；总字节必须可复算，
不允许“估算 13.4 MB、实际 15 MB”。

### 5.3 为什么可能有效

- 现有结果已经显示层间敏感度不一样：三值主干把末层换 f32，128 对 Pearson
  从 0.7893 跳到 0.9023；但 int4 叠末层 f32 只从 0.9191 到 0.9203。
  同一个“层回退”对不同格式价值不同，说明格式不该全局统一；
- L12 int4 已经和 L12 f32 统计平手，预算再往上加不一定买到 Pearson；
  但把字节从“不敏感矩阵”挪到“敏感矩阵”可能比全局 int5 更划算；
- 它把现有 `TRIT_WEIGHT_BITS`/`TRIT_F32_LAYERS` 的手工扫描变成可复算的分配器。

### 5.4 判据与风险

- M1：固定总字节 = L12 int3 g32 的**实际工件字节** `10,782,720 B`
  （含 per-group scale 与 per-row bias；weight-only 是 `7,962,624 B`，
  不能拿后者当预算）；先只允许 `int2/int3/int4`，不含 int5/f32/侧车；
- M2：同总字节，Pearson/Spearman 不低于纯 int3；至少一个指标 10k CI 下界 > 0；
- 风险：代理 `J` 与 STS 不同向；块粒度太粗；per-matrix 配置引入加载 bug；
  manifest 与实际打包字节不一致。所有字节必须由 `weight_format` 复算，不手填。

### 5.5 M1 实测（2026-11-24，严格同字节）

规划器第一版在 128 对上低于纯 int3，但全量是 `+0.001033 / +0.002893`；
严格同字节的 `v6e` 全量 `0.820686 / 0.818137`，相对纯 int3
`+0.002246 / +0.004775`。`v6e` 是“9 张 q/k 升 int4 + 层 9 o、层 11 i/f 降 int2”，
总字节正好 `10,782,720`。10k 配对 bootstrap：

| 指标 | Δ | 95% CI | 候选更好比例 |
|---|---:|---:|---:|
| Pearson | +0.002246 | [−0.000307, +0.004941] | 95.71% |
| **Spearman** | **+0.004775** | **[+0.002017, +0.007754]** | **99.98%** |

Spearman 过判据，Pearson 不过；结论只能写“Spearman-only 同字节小胜”，
不能写“追平 int4”（距 int4 Spearman 还差 `0.0139`）。关键失败是代理：
`v6e` 与 v1 的代理误差比同为 `0.91552`，只换了一个同形状 int2 块的位置，
全量 Spearman 就差 `0.001882`；权重 MSE 代理看不见块在残差流中的位置。

M1.1 新增 `scripts/wsp_budget_swap.py`，把 `v6e` 的三个 int2 降级块在同类同形状
块之间平移。128 对筛出 `I10`（把层 11 `intermediate.dense` 的 int2 移到层 10），
全量 `0.821621 / 0.818898`，相对纯 int3 `+0.003180 / +0.005536`；10k CI 分别为
`[+0.000157, +0.006370]` / `[+0.002192, +0.009004]`，两个下界都过 0。但 `I10`
对 `v6e` 只有 `+0.000934 / +0.000761`，CI 跨 0，不能写“已证升级”。

M1.2 再把 Q3、K4 两个 int4 升级平移到 K10、K11（`K10K11`）：全量
`0.823479 / 0.820549`，相对纯 int3 `+0.005039 / +0.007187`，10k CI
`[+0.001919, +0.008219]` / `[+0.003737, +0.010819]`；相对 I10
`+0.001858 / +0.001651`，50k CI 两个下界也过 0（Spearman 只有 `+0.000048`）。
但相对 v6e 的 Spearman CI 仍跨 0；距 int4 还差 Pearson `0.0140` / Spearman
`0.0115`。完整读数、字节账、边界与复算命令见 `WSP-BUDGET-RESULTS.md`。

M1.3 用新增的 `scripts/wsp_budget_perturb.py` 把纯 int3 的 72 个线性矩阵逐个
做 `3→2` 全量（每块 1,379 对），得到逐块敏感度表。按表把供体换成
F5/F7/V7（两张 f、一张 v 降 int2），int4 仍是 Q0–Q2、K0–K3、K10/K11，
得到严格同字节 `F5F7V7`：全量 `0.830384 / 0.828678`，相对 K10K11
`+0.006905 / +0.008129`，10k CI `[+0.002167, +0.011700]` /
`[+0.002507, +0.013961]`，双指标过 0；相对纯 int3 `+0.011944 / +0.015317`。
但它在 128 上是 `0.898538 / 0.928299`，反而低于 K10K11 的
`0.904783 / 0.937186`，128 与全量符号相反；它与 K10K11 的
`proxy_err_ratio` 仍同为 `0.91552`。距纯 int4 缩到

## 6. WSP-MXQ 在新排序里的位置

MXQ 仍然成立，但不再是第一枪：

- 它解决的是“同一矩阵内 group 敏感度不同”，预演同字节重建 −26% 到 −30%；
- 它不解决“整个矩阵/层该不该多给字节”，那是 BUDGET；
- 它不解决“量化后的均值偏差”，那是 BIAS；
- 在 BIAS 之上，MXQ 仍能再加约 3–5 个百分点（§3.2 的 mixed+bias）。

所以顺序应是：

```text
BIAS + SCALE（0 字节）→ 已试，STS 负结果，停
   ↓
BUDGET（全局格式，目标：int3 字节）
   ↓ 若还需要矩阵内自由度
MXQ（32 列 group 内 3/4/5）
```

原 `WSP-MXQ-PLAN.md` 的算法、判据、M0–M3 拆解不变，只是优先级后移；
但它的验收必须换成端到端 STS，不能再只看层内重建。

## 7. 第二波：三条不同轴

### 7.1 WSP-ROTATE：32 列块内 Hadamard

- 对每个 32 列 group 做正交旋转：`W' = W H`、`x' = H^T x`，量化 `W'`，
  推理时逆旋转或融合进 GEMV；
- 目的：把 group 内的 outlier 摊平，降低 max-scale；
- **2026-11-24 mask-aware 预演**：32 列块内 Sylvester Hadamard，max-scale，
  第 0 层 Q/K/V、int3/int4；query 约 −2.1%、value 约 −2.9%，key 在 3-bit 反而
  +0.1%、4-bit 持平。层输出误差只有 2% 级别的改善，不足以支撑运行时旋转的工程成本；
  **暂不实现**，除非改成全局旋转/更大块，或和 3-bit GPTQ 一起测。
- 风险：BERT 的 384 维不是 2 的幂，块内 32 点 Hadamard 可以，但跨块不旋转；
  运行时多一次变换；M1 可先离线反旋转，只验质量。

### 7.2 WSP-SLIM：结构化剪枝 + WSP 日志

- 按 head / FFN 神经元打分，删掉低贡献单元；用现有 Patch/Journal/Audit 记录
  “删了哪些行/列”，作为回滚依据（草案，未实现）；
- 它与量化是不同压缩轴：量化省每权重位宽，剪枝省整行/整列；
- 风险：改形状，加载器和前向都要改；BERT 残差宽度不变时，删 head 不一定省字节；
  应先做“零输出 head”的 STS 敏感性，再决定是否值得。

### 7.3 WSP-CODEBOOK / RVQ

- 4-bit 对称均匀只有 15 个正负级；学习式 16 级码本或 2–3 bit RVQ 可能更贴权重分布；
- 代价：码本存储、查表解码、训练/初始化；WSP4 的分块码表可复用一部分；
- 这是长期候选，不应和 BIAS/SCALE 抢第一个 PR。

## 8. 已算过但不建议先做

| 方案 | 预演/现状 | 判断 |
|---|---|---|
| 稀疏 f32 outlier group | 前 5% group 占 29–33% 误差（对角口径）；保 f32 每组多 107 B，5% group 就 +25% 字节 | 同字节打不过 MXQ；同额外字节下也没有明显优势 |
| 4-bit 激活 | int8 激活与 f32 几乎相同（0.7331 vs 0.7330）；权重才是瓶颈 | 不是当前瓶颈，先不做 |
| QAT / AdaRound | 没做；上限高但训练/校准成本高 | 作为 BIAS/SCALE/BUDGET 都失败后的重锤 |
| k 模型集成 | 2× 字节换平均；此前未排期 | 不作为新方案主线 |
| 只做整层 f32 回退 | 三值末层 +0.113，但同字节 int4 已更高；int4 叠末层只 +0.0012 | 只适合做敏感度诊断，不做存储方案 |

## 10. 边界

- 第 3–4、7 节的**层内预演**只覆盖 L12 第 0 层 Q/K/V，1,024 token 校准 + 最后
  128 token eval；不是全模型、不是 STS、不含 attention softmax/LN/残差/后续层传播；
- BUDGET M1 是 L12 全模型、STS 1,379 对，但仍只有单模型/单数据，且非
  sentence-disjoint；2-bit 代理按“uniform 2-bit”计费，运行时实际走三值路径，
  字节相同但误差语义不同；mixed 的实际字节已接进 `weight_format`，但仍是离线公式，
  不是容器序列化后的字节；
- BUDGET M1.1 的 I10 只验证了一个同形状块交换；I10 对 v6e 的两个 bootstrap CI
  都跨 0，不能写成“已证升级”；128 对的交换排名仍会高估，F3 的全量 Spearman
  已转负；
- BUDGET M1.2 的 K10K11 对 I10 的 Spearman 50k CI 下界只有 `+0.000048`，
  对 v6e 的 Spearman 10k CI 跨 0；它是 M1.2 优先点，不是全面优于 v6e 的强结论；
- BUDGET M1.3 的 72 行表只测单块 `3→2`，不能把 Δ 相加；`F5F7V7` 是整包验证的
  第一个组合。它在 128 上低于 K10K11、全量高于 K10K11，128 不能做位置判据；
  它与 K10K11 的 `proxy_err_ratio` 仍同为 `0.91552`，代理仍看不见位置；
- BUDGET M1.4 的 `3→4` 表同样只测单块升级，Δ 不能相加；45 双升 / 17 双降 /
  10 混合，`11k` 只有 `+0.000207`，`8v`/`3v` 等反而双降；`R15`（15 int4）
  两个指标都低于 `R12`（12 int4），说明 int4 数量不保证更好；
- `R12` 是同一批 1,379 对上的 in-sample 搜索与评测，没有 held-out 或
  sentence-disjoint；必须补留出验证后才能谈普遍有效；
- `R12` 距纯 int4 仍差 Pearson `−0.003834`，Spearman 点估计 `+0.003364`，
  50k 两个 CI 都跨 0；对 `R10` 的 `+0.000670 / +0.001035` 也两个 CI 都跨 0；
  按 6 个来源拆开，`R12` 对 int4 是 0/6 胜，总体反超更像跨来源排序效应；
  `R12` 在 128 上仍低于 K10K11；不能写“3-bit 追平/超过 int4”或“已证优于 R10”；
- `h` 是对角近似，不含通道间相关；bias 修的是均值，不修方差；
- 表里的误差是层输出范数，未按输出范数归一化，只比较相对；
- 字节只算线性权重 + scale + bias；不含容器对齐/打包；bias 修正本身 0 字节；
- 没有做 sentence-disjoint 校验；M1 必须补；
- 没有公开文献逐篇核对。bias correction、Hessian scale、混合精度、旋转、剪枝
  都不是新原理；项目-specific 的是同字节口径、现有 STS/字节账、WSP 审计闭环。
  本文不宣称“首次/只有我们才有”。
