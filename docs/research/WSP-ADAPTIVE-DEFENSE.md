# 自适应防御：探针生成器 + 对抗集成——防御侧 π_CP 落地（2026-11-20）

#539 创造性预激发的防御侧完整实现：#495 方向修正的收尾（冻结检测器 +
**训练探针生成器**）+ #499 对抗训练成员进 #497 集成的正交性定量验证。
防御侧的 π_CP 不生成攻击，它生成**探针**——「让嫌疑工件与基线的分歧
最大化」的输入选择器。

## 1. Part A：自适应探针 vs 固定探针（`examples/adaptive_defense/`）

```
干净工件 → 攻击池（6 种训练内模式 × 6 实例 = 36 个嫌疑工件，标注免费）
         → holdout（行交换/行取反 × 6 实例 = 12 个，不进池，只考泛化）
候选探针 = 200 个测试输入；签名 = 该输入上嫌疑工件预测符号与基线的分歧
固定集   = 盲选随机 50（不看任何攻击样本）
自适应集 = 贪心最大新增覆盖（每步选能新检出最多嫌疑工件的输入），预算同 50
```

- 攻击模式家族 = #495 artifact_guard 同款 8 种：单 trit 翻转 / 16 点稀疏 /
  整行置零 / 输出 30% 反转 / 输出整行置零 / 行交换 ×2 / 行取反 / scale×3；
- 检出定义：探针集内**任一**输入使嫌疑工件与基线的预测符号不同。

### 读数（SMS spam，#492 口径工件）

| k | 池检出（自适应） | 池检出（固定） | holdout 检出（自适应） | holdout 检出（固定） |
|---:|---:|---:|---:|---:|
| 1 | **0.333** | 0.167 | 0.0 | 0.0 |
| 2 | **0.444** | 0.167 | **0.167** | 0.0 |
| 8 | 0.444 | 0.167 | 0.167 | 0.0 |
| 50 | 0.444 | 0.333 | 0.167 | 0.0 |

**判读**：
- **效率 50×**：自适应 1 个探针 = 固定 50 个探针的池检出率（0.333）；2 个
  探针到顶（贪心在 0.444 处无新增覆盖，自动停）。#495 方向修正的结论
  「审计模型学不到（acc 0.11）→ 该训练的是探针生成器」至此闭环：探针
  生成器不需要学出攻击的分布，只需要会挑分歧最大的输入。
- **结构性上限是主要发现**：池检出天花板 0.444、holdout 只有 0.167——
  不是探针不行，是**输入探针原理上看不见大多数单行篡改**。三值稀疏下
  输出行只有 ~1/3 的 hidden 行权重非零：没连到输出行的行被置零/取反/
  换位，对任何输入的预测都零影响（这类篡改只能靠 checksum/签名审计抓，
  即 deploy 底线那道闸）。输入探针 + 行为验证的世界里，「隐身行」是
  免费攻击面——这是 #494 定点攻击的防御侧镜像。
- 泛化：holdout 两模式不进池，自适应探针仍检出 2/12（固定集 0/12）——
  挑出的分歧输入迁移到了没见过的攻击模式。

## 2. Part B：对抗集成——两种防御的正交性（#499 未证栏）

```
成员池 = 种子 101..130 依序训练，val F1 ≥ 0.5 的前 3 个进集成（可行性门）
红方   = 对 member 0 进化 kill-switch 基因组（#497 同款，4 代，k=16 行）
蓝方 A = 对抗成员：从被攻击权重出发，RowDropout 轮换吃红方点名行（#499 口径）
读数   = 单成员 vs 集成、普通 vs 对抗，同一攻击下的 F1 保持
        + 剔除输出行的同源攻击对照（区分失效机理）
```

### 2.1 新失败模式：初始化轨迹脆弱性（本轮最大发现）

可行性门揭穿了一个被既有实验掩盖的事实：**#492 口径下大多数种子塌缩**。
种子池扫描（101-115，凑满 3 个可用即停）：

| seed | val F1 | test F1 | 判定 |
|---:|---:|---:|---|
| 101 | 0.7925 | 0.7426 | **可用** |
| 102-106 | 0–0.018 | 0–0.035 | 全 ham 塌缩（5 个） |
| 107-111 | 0.0000 | 0.0000 | 全 ham 塌缩（5 个） |
| 112-113 | 0.0177 | 0.0000 | 塌缩（个别 TP） |
| 114 | 0.8333 | 0.8036 | **可用** |
| 115 | 0.8333 | 0.8036 | **可用** |

**12/14 塌缩（86%）**。此前 #492/#499 用的 seed 100/101 恰好是能活的——
塌缩被手工选种子掩盖了。这不是「训练不稳」的泛泛而谈：不平衡 hinge +
近零初始化下，输出行一旦先滑向 ham 侧就 tanh 饱和、隐藏层梯度消失，掉进
全 ham 死区爬不出来；能否逃脱取决于初始特征几何，所以是种子彩票。
另一个信号：seed 114 与 115 的 val/test F1 **逐位相同**——不同初始化
收敛到同一个决策边界，说明可行盆地里的解高度一致（这也预示集成多样性
比预想低，见 2.2）。

**假设检验（负结果）**：#499 未证栏猜「类别平衡采样」能治。类别加权
hinge（spam ×6.46 = ham/spam 比）重训 101/102/103：
- 101：0.7925 → 0.8155（好种子确有提升）；
- 102/103：0.0351 / 0.0351——**仍然塌缩**。

即塌缩不是（或不只是）类别不平衡驱动的，加权治标不治本；
「类别平衡采样治塌缩」的假设证伪，#499 该未证栏部分关闭。
**可用缓解**是工程性的：成员可行性门（val F1 ≥ 0.5 先验筛查）——
这也是集成防御的组成部分：塌缩成员本来就不该进集成。

### 2.2 正交性读数：被同一个坐标击穿（机理取证）

进化攻击（4 代，k=16）的攻击集取证：16 行里**包含输出行 (1,0)**——进化
重新发现了 #494 的 kill-switch 深井（fitness 最大化的必然归宿）。

全攻击下（16 行）：单成员 plain/adv、集成 plain/adv，外加 3 个成员逐个验
——**全部 F1 = 0.0**。两种防御零保护。

对照实验：**剔除输出行**，同源攻击只打 15 行 hidden：

| 口径 | clean F1 | 全攻击（含输出行） | 仅 hidden 攻击 |
|---|---:|---:|---:|
| plain member 0 | 0.7426 | 0.0 | **0.7437** |
| adv member 0（RowDropout） | 0.8295 | 0.0 | **0.8295** |
| plain 集成（3 成员投票） | 0.8036 | 0.0 | **0.8210** |
| adv 集成（3 成员投票） | 0.8393 | 0.0 | **0.8393** |

**判读（机理完全确认）**：
- 15 行进化 hidden 置零对任何成员/集成**零伤害**（F1 与 clean 持平，个别
  还略升=噪声）——hidden 行的冗余是真的（与 #499 round 3 的鲁棒信号一致，
  本配置下单轮 8 epochs 就够，因为攻击本身已经不构成伤害）；
- 进化攻击的**全部破坏力来自输出行一个坐标**：同构集成所有成员共享
  (1,0)，一行置零 = 每个成员独立熄火（输出恒 0 → 全预测 ham），多数投票
  无从投票——3 个成员死得一模一样；
- **#499 未证栏的答案：坐标定向攻击下，对抗训练与集成不叠加**。两者失效
  方式不同但被同一坐标击穿：对抗训练只硬化 hidden 行（设计边界：输出行
  置零=熄火，不是「行冗余」的对象），集成的多样性是权重的、不是架构的
  （114/115 连决策边界都相同）——同构集成的坐标系共享 = 攻击面共享；
- 防御推论：输出行是「王冠上的裸点」。行为防御（探针/集成/再训练）对
  单点熄火全盲——Part A 的探针也看不见它吗？看得见（输出行置零 = 输出
  全变，任何输入都分歧）但看不见**哪个 trit 被动**；能定位并阻断它的只有
  完整性校验（checksum/签名/refuse-load，deploy 底线那道闸）或架构级
  冗余（多输出行投票——未证栏）。

## 4. 未证栏

- 输入探针的「隐身行」上界是结构论证（输出行连接度 ~1/3）+ 36/12 工件
  实测，未做逐行连接度的直接统计；
- 塌缩的机理（tanh 饱和 → 梯度消失 → 全 ham 死区）是推断，未做逐 epoch
  的梯度/激活追踪；
- 加权 hinge 只试了一个权重（6.46），更小权重或 margin 调整未扫；
- 可行性门阈值 0.5 与种子池上界 130 都是先验拍的，未做敏感性分析；
- 「多输出行架构级冗余」（集成成员输出行坐标不同或单成员多输出行投票）
  是 2.2 推论指出的修复方向，未实现未验证；
- 15 行 hidden 零伤害的结论在 k=16 预算下成立；更大 k（如整行规模 64+）
  是否开始伤害未测（#497 全谱工作在其上）。
