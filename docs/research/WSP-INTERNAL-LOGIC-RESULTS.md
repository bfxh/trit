# WSP 内部逻辑读取：M0 读数

> 状态：**已跑通**（M0，`benchmarks/wsp-internal-logic`）。设计见 [WSP-INTERNAL-LOGIC.md](WSP-INTERNAL-LOGIC.md)。
> 域声明：`max_len = 3`、字母表 `{0,1}`、词表 15 条。**域外不主张任何等价性。**

## 1. 一句话

三值前馈网络 → 穷举判决 → 前缀树 → Moore 最小化 → 最小 DFA，与参考语言的最小 DFA
逐串对拍：`diff = 0 / 0`，状态数两边都是 7。

## 2. 案例

`at_least_two_ones`：语言「串里至少 2 个 1」，长度 `0..=3`。

网络吃 2 维/位置的编码（3 位 ⇒ 6 维输入；`0 → (Zero, Neg)`、`1 → (Pos, Neg)`、
填充 → `(Zero, Pos)`）：

- 层 1：`is_one` 每位复制两份（6 个单元）+ 3 个常量单元（bias `+1`）；
- 层 2：前 6 项 `+1`、后 3 项 `−1` ⇒ `sign(2·#1 − 3)`。

填充位的 `is_one = Zero` 不贡献，所以判决与串长无关。

## 3. 读数

```text
case=at_least_two_ones max_len=3 words=15 accepted=5
  dfa states: net=7 ref=7
  diff: net_vs_dfa=0 dfa_vs_ref=0
  PASS
cargo test --release → 4 passed
```

行为表（15 条）：

| 串 | #1 | 判决 |
|---|---|---|
| （空） | 0 | 拒绝 |
| `0`、`1` | 0、1 | 拒绝 |
| `00`、`01`、`10` | 0、1、1 | 拒绝 |
| `11` | 2 | 接受 |
| `000`、`001`、`010`、`100` | 0、1、1、1 | 拒绝 |
| `011`、`101`、`110` | 2、2、2 | 接受 |
| `111` | 3 | 接受 |

接受共 5 条，与程序读数一致。

## 4. 为什么是 7 个状态，不是 3

「至少 2 个 1」在**全域**（任意长度）上的经典最小 DFA 是 3 状态。这里 7 是**相对声明域**
（长度 ≤ 3）的最小：

- 前缀的「剩余可扩展长度」参与未来行为，不同长度的前缀不再等价；
- 前缀树尾部还有一个越界 `DEAD` 自环。

这正是设计文档 §1 要求「域必须写进报告」的实证：**最小性相对于域**，域一变状态数就变。

| 判据（设计文档 §6） | 结果 |

## 8. M0d：轨迹层读数（后加）

`--trace` 打印逐串轨迹（层 1 激活、输出层 pre-activation、输出、DFA 状态）。摘要：

```text
trace: hidden_classes=8 hidden_to_out_conflicts=0 hidden_to_state_conflicts=4 max_variants=4
```

| 读数 | 值 | 含义 |
|---|---|---|
| `hidden_classes` | 8 | 15 个串只产生 8 种不同的层 1 激活 |
| `hidden_to_out_conflicts` | **0** | 同一层 1 激活一定给同一输出 ⇒ 层 1 是信息瓶颈（causal sufficiency） |
| `hidden_to_state_conflicts` | 4 | 4 种层 1 激活各自对应多个 DFA 状态 |
| `max_variants` | 4 | 同一 DFA 状态最多对应 4 种层 1 激活 |

**第一个 0 是判据（不成立就是 FAIL）；第二个 4 是发现：**

- 层 1 只取 `is_one` 位，不编码「串长 / 结束」；而域内最小 DFA 的状态含「剩余可扩展长度」。
  例：`hidden=[0,0,0,0,0,0,1,1,1]` 同时对应 `""`（q0）、`"0"`（q1）、`"00"`/`"000"`（q3）。
- 所以**「提取的 DFA 状态」不等于「网络的内部状态」**：前者有一部分来自域截断，不是网络结构。
- 网络的真实内部状态是层 1 激活（域内 8 类），它决定输出，但不决定「还剩几位可扩展」。

这条负结果修正了一个读法错误：要读思考链，应该读 `hidden` 轨迹；DFA 状态是**行为等价类**，
不是内部状态。把两者当成一回事，就会把「域的人为截断」误读成「模型在数长度」。

### 8.1 一个具体的错读例子

若只报 DFA 状态，会看到 `""`→q0、`"0"`→q1、`"00"`→q3、`"000"`→q3，很容易得出
「网络在跟踪长度」的结论。但看 `hidden` 就知道：这四个串的层 1 激活**完全相同**，
网络根本没在数长度——长度信息只存在于我们的域声明里。


## 9. M0e：穷尽干预（承重矩阵）

`sweep` 的签名是 `(net, max_len, layer_idx, units, encode)`：手写两层网络用
`(0, 全部单元, word::encode)`，编译网络用 `(0, 状态位数, compile::encode3)`。
内部改成「改一个单元 → 用**尾部网络**（`layer_idx+1` 之后）重算输出」，
所以对任意层数成立，不再假设固定两层。

`--intervene` 对层 1 的 9 个单元逐个做「清零 / 取反」，域内 15 个串全部穷尽，不抽样：

```text
intervene: units=9 live=9 words=15
  unit 0: flips_zero=3 flips_neg=3
  unit 1: flips_zero=3 flips_neg=3
  unit 2: flips_zero=3 flips_neg=3
  unit 3: flips_zero=3 flips_neg=3
  unit 4: flips_zero=2 flips_neg=2
  unit 5: flips_zero=2 flips_neg=2
  unit 6: flips_zero=6 flips_neg=6
  unit 7: flips_zero=6 flips_neg=6
  unit 8: flips_zero=6 flips_neg=6
```

| 单元 | 角色 | 翻转数（清零 / 取反） |
|---|---|---|
| 0、1 | pos0 的 `is_one`（复制两份） | 3 / 3 |
| 2、3 | pos1 的 `is_one` | 3 / 3 |
| 4、5 | pos2 的 `is_one` | 2 / 2 |
| 6、7、8 | 常量 `Pos`（提供 `−3` 阈值） | 6 / 6 |

三条读数：

1. **9/9 承重**：没有装饰单元，每个层 1 单元至少在一个串上改变输出。
2. **常量单元承重最高**（6/15）：它们是阈值的来源，改一个就移动判决边界——
   这也是三值网络里「偏置」不能当免费参数删掉的原因。
3. **位置不对称**（3 vs 2）：pos0/pos1 的 `is_one` 在更多串上可能取 1，而 pos2 只在长度 3
   时才可能。承重率反映的是**编码结构**，不是权重大小。

判据：`live_units() > 0` 已进测试（`intervene_has_live_units`）。本案例实际 9/9，
若将来某个案例出现 `live < units`，那说明存在装饰单元，需要解释而不是忽略。



### 9.2 编译网络的状态位

编译网络的层结构是固定的：

```text
层 0        初始化（状态 one-hot + 输入副本 + 常量）
层 2+2·t    第 t 步的 OR 层（前 k 个单元 = 新状态）
层 2+2·t+1  第 t 步的 AND 层
最后一层     输出
```

所以「状态位」有了明确口径：**OR 层输出的前 `k` 个单元**。测试
`intervene_compiled_or_layer_states` 对 7 个程序 × 3 步逐层干预状态位，
每层都必须有承重单元（`live_units() > 0`，为 0 直接失败）。

注意层 0 的「状态」是**初始状态**，每个串都相同，干预它不承重是正常的——
上一版测试正是把这个当成 bug 写错了。


### 9.3 逐单元读数（编译 parity，`max_len = 3`）

```text
step 0: live=2/2   state 0 flips=9   state 1 flips=6
step 1: live=2/2   state 0 flips=11  state 1 flips=4
step 2: live=1/2   state 0 flips=15  state 1 flips=0
```

最后一步的 `state 1` **完全不承重**（0 次翻转）：它算出来了，但判决只看 `state 0`
（parity 的接受状态）。这不是装饰单元——它在该步的计算里是必要的中间量，
只是没被最终判决消费。这正是「逐单元读数」与「live > 0」两种口径的差别。

## 10. M0f：Tracr 反向闭环（变长域）

`src/compile.rs` 把 DFA 编译成展开式三值前馈网：每个时间步 2 层（AND 项 + OR 状态），
状态 one-hot 取 `{Neg, Pos}`，输入每位置 3 维 one-hot（`0 / 1 / End`）。

**End 冻结**：字母表扩成 `{0, 1, End}`，`End` 一律自环（`δ(q, End) = q`），
所以「读完就冻结」不需要 running 标志——这是变长串能进定长前馈网的关键。

测试 `compile_then_decompile` 对 6 个程序走完整闭环（变长域，`max_len = 3`）：

```text
parity / mod3 / paren / four_sources / ends_with_1 / contains_01
  → compile（展开 3 步 + End 自环）
  → 提取器（前缀树 + Moore 最小化）
  → 状态数 / 转移表 / 接受集 逐项相等
```

三项全等才算恢复；`cargo test --release` 7 passed。

### 10.1 过程中修掉的两个真 bug

1. **编码不兼容**：`word::encode` 把 0 编成 `Zero`（为了让线性阈值忽略填充），
   而阈值门 `sign(x + y − 1)` 需要 `{±1}`——`Zero` 会让 AND 门输出 `Zero` 而不是 `Neg`。
   编译器因此改用独立编码 `encode_sym`（`0 → Neg`）。
2. **AND 项的符号位接错**：`a = 0` 的项要接 `−sym`，第一版接成了 `+sym`，
   导致「读 0」和「读 1」用同一个门。

这两个都是「提取器和参考程序一起犯错也看不出来」的反例——正因为有独立编译器，
才暴露出来。这是 M0f 存在的理由。

### 10.2 未证

- 已测十个程序：`parity`、`mod3`、`paren`、`four_sources`（4 源）、`ends_with_1`、
  `contains_01`（3 源）、`mod5`（5 状态）、`star8`（8 状态、9 源）、`mod10`（10 状态）、
  `mod20`（20 状态），在变长域（长度 ≤ 3）上都是
  「状态数 / 转移表 / 接受集」逐项相等。
- End 冻结已实现（3 符号 + 自环），不再是缺口；原先「三项 OR 阈值门」的障碍
  由 §10.3 的常量单元方案消掉了。
- 编译器仍要求 DFA 状态数 ≥ 1、`max_len ≥ 1`；空 DFA 未测。
- 只测了小 DFA（≤5 状态、≤4 源）；更大的程序未测。
- 编译网络的状态位已有口径（§9.2：OR 层前 `k` 个单元），7 个程序 × 3 步都验证了
  `live_units() > 0`；但**每个状态位分别承重多少**还没有逐单元读数，只断言了非零。



### 10.3 OR 扇入：用常量单元补阈值

`OR(x1..xn) = sign(Σxi + (n−1))` 里的 `n − 1` 不能写成 bias（bias 只能 ±1/0），
但可以由 `n − 1` 个恒为 `Pos` 的常量单元供给——权重全 +1，阈值自然推到 `n − 1`：

- 全 `−1`：`−n + (n−1) = −1` → 拒绝；
- 任意一个 `+1`：`(2−n) + (n−1) = 1` → 接受。

于是每步仍是 2 层（AND + OR），不需要树形归约。这条把原先的「≤2 源」限制去掉了，
`four_sources` 程序（4 源）验证了 n = 4。

同样的结构也适用于输出层的「多接受状态」OR。


### 10.4 多域闭环与 End 自环性质

- `compile_then_decompile_across_max_len`：6 个程序 × `max_len = 1..=4`，每一档都检查
  状态数 / 转移表 / 接受集逐项相等（共 24 组）。
- `end_padding_is_inert`：同一串在 4 位域与 5 位域上的判决必须一致——这是 End 自环的
  直接性质；冻结逻辑一旦写坏，这条会最先红。

`cargo test --release` = 9 passed。

| 程序 | 状态数 | 最大转移源 |
|---|---|---|
| `parity` / `mod3` / `paren` / `ends_with_1` | 2–3 | 2 |
| `four_sources` | 3 | 4 |
| `contains_01` | 3 | 3 |
| `mod5` | 5 | 2 |
| `star8` | 8 | **9** |
| `mod10` | 10 | 2 |
| `mod20` | **20** | 2 |

十个程序全部闭环通过。规模到 **20 状态、9 源**都没有撞到结构上限；成本主要落在

`star8` 是最重的一档：9 源需要 8 个常量单元，`max_len = 3` 时 `and_w = 41`。

## 11. 状态爆炸预算

`--budget` 用编译器的 `parity` 程序扫 `max_len = 1..=6`：

```text
max_len words states_ref states_net same
1 3 3 3 true
2 7 5 5 true
3 15 7 7 true
4 31 9 9 true
5 63 11 11 true
6 127 13 13 true
7 255 15 15 true
8 511 17 17 true
9 1023 19 19 true
10 2047 21 21 true
11 4095 23 23 true
12 8191 25 25 true
13 16383 27 27 true
14 32767 29 29 true
```

两条读数：

1. **词表指数、状态线性**：前缀树节点数 = `2^(max_len+1) − 1`（指数），
   而域内最小状态数 = `2·max_len + 1`（线性，实测 3 / 5 / 7 / 9 / 11 / 13）。
2. **线性来自「剩余长度」**：parity 在全域只有 2 个状态；域内状态 = 奇偶 2 种 ×
   剩余长度 `(max_len + 1)` 再合并 1 个，正好 `2·max_len + 1`。

含义：

- **计算成本**（穷举词表）随域指数增长，这才是 M0 只能到 6 位的原因；
- **读出的程序**（DFA）只随域线性增长，所以「读不动」首先卡在穷举，不是卡在程序大小；
- 域内状态数里有一半是「长度」这个人为信息，不是语言的真实结构——这和 §8 的负结果同源。

这条预算也给出一个可操作的门槛：若要把域从 6 位推到 10 位，词表从 127 涨到 2047，
提取器本身仍然是线性的，成本全在穷举次数上。


## 12. M3：循环执行（真串行）

`compile_cell` 只编**一步**：输入 `[state(k), sym(3)]`，输出 `new_state(k)`；
`recurrent::run` 用同一个 cell 跑 `max_len` 步，状态由外部携带——同一组权重重复用。

测试 `cell_loop_matches_expanded`：对每个 ≤2 源的程序，循环结果与展开式前馈逐串等价，
且 `trace.len() == max_len`。当前 7 个 ≤2 源程序 × 15 个串全部通过。

三点差别：

| 项 | 展开（`compile`） | 循环（`compile_cell` + `recurrent`） |
|---|---|---|
| 层数 | `2·max_len + 2`（随步数增长） | 固定 2 层 |
| 权重复用 | 每步一组新权重 | **同一组权重重复调用** |
| 支持扇入 | 任意（常量单元补阈值） | ≤2（输出维度就是 `k`，没地方放常量） |
| 轨迹 | 需要单独抽取中间层 | `Run.trace` 天然是每步状态序列 |

「常量单元」是展开式前馈多出来的自由度：循环里输出宽度就是状态数，塞不进常量，
所以扇入被卡在 2。这条差异把两种实现的结构成本说清楚了。
