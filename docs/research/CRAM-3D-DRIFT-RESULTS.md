# CRAM + 3D 漂移：M0 负结果（2026-11-18）

> 对应任务包 [`CRAM-3D-DRIFT.md`](CRAM-3D-DRIFT.md) 的 M0a/M0c 最小切片。
> 状态：**数据→训练→采样→能量 的链路打通，生成器 0% 可行（六条路径全部 0%）**。
> 没有训练时能量项，没有 3D，没有 CRAM 原文的 Hopfield 能量。

## 环境

- RTX 4060 Ti / Vulkan；driftnet `a4ab629`（三值 4.83M 参数，1-NFE）；
- 数据：M0a 的 2D 障碍网格轨迹（8×8 网格 → 32×32 三通道图像；
  数据工具在 `benchmarks/cram-drift-2d`，独立 PR #509）。

## 根因

生成器是**无条件**的 `z → 32×32`；所有训练轨迹起点都在 `(0,0)`，但训练目标
（SWD / patch SWD + hinge）里没有「起点/连通」约束。模型学到了竖直轨迹的形状，丢掉了起点。
**加数据（1k→10k）和步数（2k→5k）都没有改变可行率——约束不在 loss 里，不是容量问题。**

推理侧「起点补丁」（把 `(0,0)` 的 4×4 块强制点亮）把能量从 50 降到 26，但可行率仍 0%：
生成的竖线在中间列，与起点不连通。这说明**只补起点不够**——无条件生成器学的是
「竖线的形状」，不是「从起点到终点的一条路径」。

**软条件也失败**：把 goal 坐标写进 `z[0:2]`（不改变模型结构）再训 5k 步，可行率仍 0%，
能量 50。128 维噪声里 2 维条件信号太弱，且训练目标仍没有端点/连通约束。

**可微能量惩罚也失败**：在 loss 里加「起点块应亮 + 点亮比例接近 0.15」的软惩罚（权重 1.0），
5k 步后能量反而升到 76：起点确实亮了，但整张图过亮、多列互不连通。点亮量惩罚的梯度
被 SWD 主导，且连通性本身不可微。

**64 维强软条件也失败**：把 goal 的 one-hot 覆盖 `z` 的前 64 维（不是 2 维坐标），再训 5k 步，
可行率仍 0%、能量 50，竖线还在中间列、起点未亮。条件信号再强，只要模型的唯一入口是
`fc(z)` 的随机权重，5k 步内就会被 SWD 梯度淹没。

**真条件通路也没拿到可行轨迹**（第六条）：把结构改掉——goal one-hot 不再借 `z` 的头部，
而是接到 `fc` 的独立 64 维（`fc` 宽度 128 → 192），5k 步后 `select --n 256` 仍 **0%**，
最优能量 50 → **20**：`(0,0)` 第一次被点亮，连通分量有 8 格，但另外 10 格是孤立的
（`comp×2 = 20`）。这是六条里最接近的一条，但离可行（能量 0）还差一整片连通性。

```text
#.#.....
#.#.....
#....#.#
#.#.....
#.#.....
#.#....#
#.#.....
#.#.....
```

权重侧核对（`artifacts/traj_cond64/weights.bin`）：64 个 cond 列的 rms 是 0.042，
128 个 latent 列是 0.0398，同量级；三值量化后的 0 化率 24% 对 26%。换一个 goal
只让 `fc` 的输出变化 0.077，而潜变量 128 维的总贡献是 0.45（**17%**）。也就是说
**通路是通的、没被训死，但条件只被当成一组常量偏置**：训练里 goal 恒定（全部 63）、
损失里没有 goal / 能量 / 连通项，梯度没有理由让输出「随 goal 变」。换结构能改分布
（能量 50 → 20 就是证据），但改不出「按条件生成」。

## 多 goal + goal 感知惩罚：条件第一次被用起来（第七到第九条）

前六条的 goal 要么是常量、要么损失里根本没有 goal。这一轮同时换掉两件事：

1. **多 goal**：训练数据换成 M0a 的真实 `goals.bin`（10,000 条、64 个终点，(7,7) 占 44%），
   goal 走 `cond` 独立通路（`fc` 宽度 192）；
2. **goal 感知的可微惩罚**（`--traj-weight`）：起点块与**该样本自己的 goal 块**都向 1 收，
   R 通道点亮比例向 0.15 收（sigmoid 近似）。连通性仍不可微。

5k 步 × 三个权重的可行率见上表（全 0%，最优能量 50 / 20 / 46）。真正的新读数是
**goal 敏感性**——`select --seed 7 --n 64 --goal 63` 与 `--goal 0`，同一批 z，只换条件：

| 模型 | 换 goal 的 \|ΔR\| | 占样本间差异 | 请求格增益 |
|---|---:|---:|---:|
| w=0（对照） | 0.00054 | **5.2%** | (0,0) +0.00114 |
| w=1.0 | 0.00981 | **82.9%** | (7,7) +0.00134 |
| w=3.0 | 0.01427 | **73.6%** | (7,7) +0.00027 |

**这是七条里第一次看到条件真的被用起来**：换一个 goal，输出改动量从「样本间差异的 5%」
跳到「83%」——对照模型基本不听条件，加了惩罚的模型听。但改动是**弥散**的：请求的终点格
只比不请求时亮 0.00134，而生成图在 `(0,0)` 的平均亮度是 +0.25、在 `(7,7)` 是 −0.85。
模型没有学会「把请求的终点点亮」，更没有连起来。

可微近似给不出路径结构：连通性不可微，「两端各亮一下 + 点亮量」不等于「一条连通的路径」。
条件能传进网络并被使用（这一步已解决），「按条件画出连通路径」仍然学不到。

## E2：primer 分层 + GRPO（第十条）

按 [`CRAM-3D-DRIFT-CREATIVE.md`](CRAM-3D-DRIFT-CREATIVE.md) 的 P1/P3 实现：**冻结**
`artifacts/traj_mg_w10`（cond=64、多 goal），只训一个 16 维「过程码」`π ~ N(µ(goal), σ²)`；
`π` 经固定随机投影 A（16×128，scale 0.3）加到 z 的前 128 维，goal one-hot 位置不动。
奖励只回流 primer：可行（能量）、新颖（到训练集 1024 张的 8×8 最近邻）、多样（同 goal 组内
两两距离），组内标准化 → REINFORCE + Adam。规模：8 goal × 8 π × 2 z = 128 张/步，
lr 3e-3，σ 0.5 退火到 0.05，3000 步约 124 秒（生成器全程冻结）。

三个评估口径（`select --primer-noise`，n=256、goal=(7,7)、4 个 seed 共 1024 张）：

| 口径 | 可行率 | best_energy |
|---|---:|---:|
| 无 primer | **0%**（1024 张） | 20 |
| π = µ（确定性） | **0%** | 20 |
| π ~ N(µ, 0.05²) | **0%** | 20 |
| π ~ N(µ, 0.23²) | **0%** | 20 |
| π ~ N(µ, 0.5²) | **0%**（1024 张） | 20–22 |

**结论：primer 没有效果，训练日志里的 11.7% 不可复现。**

1. 注入是通的：有/无 primer 的样本逐样本都不同（mean \|Δ\| 0.0026），带噪与不带噪也不同
   （σ=0.5 时 0.0015）。
2. 但这点差异改不动 8×8 二值化 → 能量指标一模一样：全是 0%、`best_energy` 20
   （带噪偶见 22）。
3. 训练日志里只有 step 1800（9.4%）与 step 3000（11.7%）出现过可行样本，其余 11 个日志点
   全是 0%；用训练同款噪声（σ=0.5）在评估口径下 1024 张里**一张可行都没有**。
   最可能的解释是**训练与评估口径不同**：训练走 trit 后端、BN 用当前 batch 统计；
   评估走 burn、BN 用 running stats——两者的样本分布不能直接对比。
4. 上一轮把 11.7% 解释成「输入侧扰动有信号」是**错的**，被单步读数 + 口径差异误导。
   第一版 tanh 输出层确有实现问题（µ 饱和成 16 维 ±1、不同 goal 的 µ 几乎相同），
   改 softsign 后 µ 不饱和（散布 0.157），但**这不改变上面的结论**。

方法论教训：**训练侧读数必须与评估侧同口径**，否则单步波动会被当成能力。

### 口径对齐：同一步的两口径读数

`primer` 训练里内嵌了 burn 口径评估（`--eval-every`，与 `qat select` 同一套加载：
running stats 的 BN + `ternarize_col`），每个日志点并排记 `feasible`（trit）与
`eval_feasible`（burn）：

| step | trit 口径 `feasible` | burn 口径 `eval_feasible` | burn 口径 `eval_energy` |
|---|---:|---:|---:|
| 1 | 0% | 0% | 22.84 |
| 300–1500 | 全 0% | 全 0% | 23.0–23.1 |
| 1800 | **9.4%** | **0%** | 23.02 |
| 2100–2700 | 全 0% | 全 0% | 23.0–23.2 |
| 3000 | **11.7%** | **0%** | 22.99 |

同一份策略、同一时刻：trit 口径能出 9.4%/11.7% 可行样本，burn 口径 256 张一张都没有。
而且 burn 口径的能量一直稳定在 23 附近（trit 口径在 42–57 波动），说明两者的样本分布
本来就不是一回事。**E2 的「11.7%」是 batch-BN 口径特有的假象，不是能力。**

## E3：条件码位置（头部 vs 尾部）与 patch_swd 下的可行率（第十一条）

> 2026-11-19。对应 [`CRAM-3D-DRIFT-CREATIVE.md`](CRAM-3D-DRIFT-CREATIVE.md) §3 的 E3：
> 同数据、同超参，只改 goal one-hot 写进 `fc` 输入的哪一端。

```bash
# 数据：benchmarks/cram-drift-2d，10k 条 32×32×3（NHWC uint8）
cargo run --release -- --tasks 10000 --images images10k.bin --goals goals10k.bin --out dataset.jsonl

# 训练（driftnet 仓，分支 feat/e3-cond-pos）
qat train --data images10k.bin --goals goals10k.bin --cond 64 --cond-pos head \
    --steps 5000 --ch 1024 --ternary --ternary-fc --loss patch_swd --seed 0 --out e3head
# tail 组同上换 --cond-pos tail；patch_adv 对照再换 --loss patch_adv --out e3tail_adv

# 评估：同 seed 的 z，只换 goal（n=256）
qat select --dump e3head/weights.bin --n 256 --seed 0 --goal 63
```

| 组 | 换 goal 输出差 mean\|Δ\|/样本（0–255 尺度） | 相对 | 可行率 goal=63 | 可行率 goal=0 | 训练耗时 |
|---|---|---:|---:|---:|---:|
| head（one-hot 在输入头部） | 0.0854 ± 0.0033 | 8.8% | 44.1% | 38.7% | 552 s |
| tail（尾部，默认） | 0.0674 ± 0.0029 | 7.0% | 43.0% | 40.2% | 553 s |
| tail + `patch_adv`（loss 对照） | — | — | **0.0%** | **0.0%** | 1920 s |

逐样本 256 点、Welch t = 4.13（df ≈ 501）：头部比尾部高 **26.6%**，显著。但可行率只差
1.1 pp，且 goal 互换后方向反过来（head 38.7% / tail 40.2%）。**位置只影响「条件被读到的
程度」，不影响「画得对不对」**——E3 证实 R2 的方向（输入层布局影响条件读取）在自训
5.88M 三值网上弱复现，但不构成可用收益。E3 判据要求「头部显著更高则复现」，
所以这条记「方向复现、收益为零」。

### 附带结论：前九条的「可行率恒 0」有一部分是 loss 的坑

同数据、同步数（5k）、同 `cond=64`、同尾部位置，**只换 loss**：`patch_swd` 43.0%，
`patch_adv` 0.0%（日志 `d_loss 0.00000`、`d_sep 6.37`——判别器完美区分真假，生成器拿不到
有效梯度；README 的「判别器失衡」一节早就记过 20k 步 loss 卡 0.46）。

所以前九条「六条路径全部 0%」不能全部归给「结构学不会路径」：至少 `patch_adv` 那几组
是 loss 的坑。**负结果的适用范围收窄为「SWD 目标下」**；`patch_adv` 的组要用 `patch_swd`
重跑才成立。这也解释了第十条 E2 的读数为什么是 0%——primer 组沿用的仍是 `patch_adv` 口径。

## E1 × patch_swd：掩码解码下的可行率与多样性（第十二条）

> 2026-11-19。E1（掩码解码）原本是在 `patch_adv` 训出的模型上测的（可行率 0% → 100%，
> 多样性「4 → 31」）。第十一条发现 loss 才是可行率的瓶颈，于是这里把 E1 接到
> `patch_swd` 训出的模型上重测，并用同数据同步数的 `patch_adv` 组做对照。

```bash
# 模型：第十一条的三组（10k 数据、5k 步、cond=64、尾部）
qat select --dump e3tail/weights.bin     --n 256 --seed 0 --goal 63 --decode-mask 1
qat select --dump e3tail_adv/weights.bin --n 256 --seed 0 --goal 63 --decode-mask 1
# 旧模型对照：artifacts/traj_cond64/weights.bin（同样是 patch_adv）
```

| 模型（loss） | n=64 可行率 | n=64 paths | n=256 可行率 | n=256 paths |
|---|---:|---:|---:|---:|
| `patch_swd`（e3tail） | 100% | **61** | 100% | **225** |
| `patch_adv`（e3tail_adv，同数据同步数） | 100% | 11 | 100% | 19 |
| `patch_adv`（旧 `traj_cond64`） | 100% | 11 | 100% | 16 |

- **可行率在掩码解码下对所有模型都是 100%**——那是结构性保证（只允许与已点亮格 4-邻接的
  格被点亮），不区分模型好坏。注意它**不检查终点**：真实到达率见第十四条
  （`patch_swd` 26.2%，`patch_adv` 0%）。
- **多样性（不同路径数）完全由 loss 决定**：同一份数据、同样步数，`patch_swd` 61/64
  （n=64）、225/256（n=256，88% 唯一）；`patch_adv` 只有 11/64、16–19/256。
- 温度采样对多样性的影响很小：temp 1.0 / 1.5 / 2.0 → paths 225 / 222 / 226（n=256）。
- 多 goal 一致：goal ∈ {0, 16, 32, 47, 63} 全部 100% 可行，paths 220–230（n=256）。

所以「多样性从 31 提到 64」这个待办在 `patch_swd` 下已经不存在：同 n=64 口径是 **61/64**。
旧读数的 31 是 `patch_adv` 模型 + 当时温度设置的产物，不能再当作掩码解码的上限。

剩下的真问题变成**路径质量**而不是路径计数：长度分布、是否塌缩到少数几何形状、
到达 goal 的方式是否单一。那需要新的度量（Chamfer / 长度直方图 / 与 BFS 参考的编辑距离），
靠提高 `paths` 计数回答不了。

## 几何塌缩检测：路径集合是不是「同一形状的平移」（第十三条）

> 2026-11-19。第十二条证明 `patch_swd` 下多样性计数不是瓶颈，这里换成几何度量回答一个更硬的
> 问题：那 225 条路径会不会只是同一形状的平移，只是起点/位置不同？

```bash
# 掩码解码后的 8×8 格（driftnet 分支 feat/e3-cond-pos 的 --dump-paths；`--dump-out` 是修复前
# 的原始输出，不能用于这一步——实测原始输出按 4×4 块求和会在部分样本上正负抵消）
qat select --dump e3tail/weights.bin     --n 256 --seed 0 --goal 63 --decode-mask 1 --dump-paths paths_swd.bin
qat select --dump e3tail_adv/weights.bin --n 256 --seed 0 --goal 63 --decode-mask 1 --dump-paths paths_adv.bin
```

| 指标 | `patch_swd` | `patch_adv` |
|---|---:|---:|
| 原始路径数（paths） | 225 | 19 |
| 去平移后的唯一形状数 | 225 | 19 |
| 最常见形状占比 | 1.6% | 37.9% |
| 路径长度（格） | 11.5 ± 3.6（8–24） | **8.0 ± 0.0（全是 8）** |
| 外接框（宽×高） | 5.2 × 6.4 | 3.5 × 3.1 |
| BFS 最远终点 top1 | (7,7)，25% | **(1,2)，68%** |
| 平均 BFS 步数 | 9.4 | 3.4 |
| 连续特征第一主成分解释率 | 76.9% | 60.6% |

判读：

- **「同一形状的平移」在两组都不成立**：去平移后的唯一形状数等于原始路径数（225/225、19/19），
  每条路径的相对几何都不同，没有出现「一个模板平移复制」。
- **真正的塌缩在 `patch_adv`**：形状空间被压在一条窄带里——长度 256 条**全是 8**（正是能量惩罚
  `lit < 8` 的下限）、外接框 3.5×3.1、BFS 终点 68% 挤在 (1,2)、最长形状占 37.9%。
  这是「同一族短折线」的微变，不是同一形状的平移。
- `patch_swd` 没有这种压窄：长度 8–24 有分布、外接框 5.2×6.4、终点分散（(7,7) 只占 25%，
  低于训练集的 44%），说明它没有简单复刻数据分布。

主成分 76.9% 不是塌缩证据：那只是「长度 / 宽 / 高 / 重心」几个连续特征彼此相关（长路径自然
更宽更高）；几何多样性由「去平移唯一形状数」衡量。

### 仍未测的

- 与 BFS 参考的**编辑距离**（生成的路径像不像最短路径）；
- 路径长度 / BFS 最短距离的**绕路比**；
- 这两项才能把「多样」和「合理」分开——目前只证明了前者。

## 编辑距离、绕路比，以及「可行率 100%」的真面目（第十四条）

> 2026-11-19。第十三条测了几何多样性，这条测**合理性**：生成的路径离 BFS 参考有多远、
> 有没有绕路，以及一个更要紧的问题——它们真的走到 goal 了吗。

```bash
# 生成路径（掩码解码后的 8×8 格）
qat select --dump e3tail/weights.bin     --n 256 --seed 0 --goal 63 --decode-mask 1 --dump-paths paths_swd.bin
qat select --dump e3tail_adv/weights.bin --n 256 --seed 0 --goal 63 --decode-mask 1 --dump-paths paths_adv.bin
# 参考：benchmarks/cram-drift-2d 的 dataset.jsonl（10k 条；goal=63 有 4426 条带障碍 BFS 最短路径）
```

| 指标 | `patch_swd` | `patch_adv` |
|---|---:|---:|
| 与最近参考路径的对称差（/64，中位） | 6 | 15 |
| 完全一致（diff = 0） | 34/256 | 0/256 |
| 绕路比（生成长度 / 参考长度中位 15） | 0.67 | 0.53 |
| **路径包含 goal (7,7)** | **67/256（26.2%）** | **0/256（0%）** |
| 路径长度中位 | 10 | 8 |

判读：

- **`patch_swd` 的路径离真实 BFS 路径不算远**：对称差中位 6/64（约 9% 的格子不同），
  13% 与某条参考路径完全一致；`patch_adv` 中位 15/64、一条都不一致。
- **绕路比 < 1 不是「高效」，是「没到终点」**：从 (0,0) 到 (7,7) 至少需要 15 格，
  而生成路径中位只有 10 格。长度不够 ⇒ 根本走不到 goal。
- **「可行率 100%」是判据的假象**：`traj_energy` 只验「从 (0,0) 出发的连通点亮 + lit ≥ 8」，
  **不检查终点**。所以掩码解码下的 100% 只等于「连通且够长」，不等于「完成任务」。
  旧掩码解码后的到达率：`patch_swd` 26.2%、`patch_adv` 0%——但旧掩码会把孤立的 goal 块
  擦掉；**原生到达率见第十五条（`patch_swd` 53.9%）**。

### 后果与下一步

- 第十二、十三条的多样性 / 几何读数都建立在「短路径」上，必须连着这条一起读：
  它们说明「路径形态丰富」，不说明「任务完成」。
- **评估口径要补终点项**：给 `traj_energy` 加「goal 格必须点亮」（或 `select` 新增
  `--require-goal`），此后所有「可行率」才是完成率。
- **训练侧同样缺这个信号**：现有 loss 里没有终点项，条件 one-hot 只影响形状偏好。
  要把 26.2% 推上去，得让终点变成可学信号（教师轨迹回归，或对终点做可微项）。

## 终点口径、掩码解码的终点缺陷，与「到达率」的真读数（第十五条）

> 2026-11-19。第十四条发现「可行率 100%」不含终点。这条做三件事：给评估加 `--require-goal`；
> 修掉掩码解码会擦掉 goal 块的结构缺陷；再用它测「终点项」是否有效。

### 1. 评估口径：`--require-goal N`

`qat select --require-goal N` 在原有能量判据之外额外要求 goal 格点亮，输出的 `feasible`
才是**完成率**；`goal_hit` 单独报（终点命中与否，与连通判据解耦）。

复算：

```bash
qat select --dump e3tail/weights.bin --n 256 --seed 0 --goal 63 \
    --decode-mask 1 --require-goal 63      # 结构完成率 100%、paths 152
qat select --dump e3tail/weights.bin --n 256 --seed 0 --goal 63 \
    --require-goal 63                      # 原生到达率 138/256
```

### 2. 掩码解码的结构缺陷：它不认终点

`repair_connectivity` 原先只从 `(0,0)` 取主分量，把孤立但正确的 goal 块**擦掉**：
`traj-weight=10` 的模型原生输出有 63/256 命中 (7,7)，掩码解码后变成 **0/256**。
修法：加 goal 参数，从主分量多源 BFS 到 goal、把最短连接补进来。

修复后（`--decode-mask 1 --require-goal 63`，n=256，seed 0）：

| 模型 | 结构完成率 | paths |
|---|---:|---:|
| `patch_swd`（e3tail） | 100% | 152 |
| `patch_swd`（head） | 100% | 152 |
| `patch_adv` | 100% | 5 |
| `traj-weight=10` | 100% | **1** |

这里的 100% 是**结构保证**（掩码把终点连进来），不区分模型好坏；`paths` 才是可比的。

### 3. 原生到达率（无掩码）才是能力指标

| 模型 | goal=63 到达率 |
|---|---:|
| `patch_swd`（e3tail） | **138/256（53.9%）** |
| `patch_swd`（head） | 142/256（55.5%） |
| `patch_adv` | 0/256（0%） |
| `traj-weight=10` | **63/256（24.6%）** |

修正第十四条：那里报的 26.2% 是**旧掩码解码后**的到达率（goal 被擦掉），不是模型原生能力；
原生是 53.9%。

### 4. 条件有效性很弱：到达率随 goal 剧烈变化

`patch_swd`，无掩码，n=256：

| goal | 0（起点） | 16 | 32 | 47 | 63 |
|---|---:|---:|---:|---:|---:|
| 到达率 | 100%（退化） | 9.0% | **0.8%** | 50.0% | 53.9% |

右列 / 右下角（47、63）能到一半，左侧中部（16、32）几乎为 0。模型学的是「一条从 (0,0)
出发、多半偏右下的路径」，不是「按 goal 走」。E3 证明的「条件被读到」（换 goal 改输出
26.6%）与这里的「到达率」是两件事：**读到 ≠ 走对**。

### 5. 终点项 `--traj-weight` 的负结果

`--traj-weight 10`（起点块 + goal 块点亮项，5k 步，同数据同步数）：
到达率 53.9% → **24.6%**，掩码后 paths 从 152 塌到 **1**。终点项把模型压成
「固定 goal 块 + 最短填充」，多样性几乎归零——**判为有害**（至少 weight=10）。

## 教师逐格 BCE：给了中间格的监督，到达率反而垮掉（第十六条）

> 2026-11-19。第十五条把评估口径补上终点后，缺口很明确：模型只学到「一条偏右下的路径」。
> 这一条试最直接的教师监督——训练图本身就是 BFS 路径渲染，**每一格都有现成标签**。

```bash
# 新增 --grid-weight（教师逐格 BCE 的权重）与 --grid-pos-weight（正样本权重）
qat train --data images10k.bin --goals goals10k.bin --cond 64 --cond-pos tail \
    --steps 5000 --ch 1024 --ternary --ternary-fc --loss patch_swd \
    --grid-weight 100 --grid-pos-weight 16 --seed 0 --out e3grid2
```

实现：对生成图的 8×8 块求均值 → `sigmoid(4·mean)` → 与教师格（`lit8` 同口径）做 BCE，
梯度按 `traj_penalty_g` 的通道写回 R 通道；正样本只占 1/64，故加 `--grid-pos-weight`。

### 先纠正一个实现 bug（这段值得记）

第一版把 `dy` 的 **`None` 分支**（`--loss patch_swd` 走这里）留成了 `d_patch2`（SWD 梯度），
于是教师梯度**整段被丢掉**：日志里 `grid` 有值、`swd` 照常下降，但**权重文件 md5 与基线完全相同**
（`6fd91a8c…`），三组权重（grid 1 / grid 100 / grid 100+pos16）也完全相同。
教训：判断「训练有没有生效」不能看 loss 曲线，要**比权重 md5**。

### 修复后的读数（同数据同步数，5k 步）

| 配置 | swd 终值 | g16 | g32 | g47 | g63 |
|---|---:|---:|---:|---:|---:|
| 基线（只有 patch_swd） | 0.015 | 23 | 2 | **128** | **138** |
| 教师逐格 BCE（grid 100 + pos 16） | **0.65** | 0 | 2 | 27 | **4** |

- 权重 md5 变了（`5a2ef6d4…`），说明教师梯度真的进了反向传播；
- 但 swd 停在 0.65（基线 0.015），说明模型被拉去拟合教师图，**分布匹配被放弃**；
- 到达率反而**暴跌**：g63 138 → 4，g47 128 → 27，g16 23 → 0。

### 诊断：z 与教师样本没有配对，BCE 退化成「回归条件均值」

生成器是 1-NFE：`(z, goal) → 图像`，`z ~ N(0, I)` 与训练样本**无对应关系**。
逐格 BCE 要求每个 `(z, goal)` 都逼近「该 goal 的某一条路径」，但同一 `goal` 下有几千条
不同路径；模型能找到的最小期望损失解是**输出这些路径的平均图**——一张模糊的、哪里都有一点
亮度的图。于是「路径是否到达 goal」这种离散判据直接崩掉，同时 swd 也只能停在 0.65。

这与经典 mode collapse 同型：**逐样本回归 + 无配对潜变量 ⇒ 条件均值**。
`--traj-weight`（第十五条）和这一条都栽在同一件事上：**只要监督要求「某个具体输出」，而 z 不携带
该样本的信息，模型就只能塌到均值**。

### 结论

- 在「1-NFE + 随机 z」的设定下，**逐格回归/端点回归都是有害的**（一个把多样性压到 1，
  一个把到达率打到 4/256）。
- 要让「终点」变成可学信号，必须先让 `z` 有意义：用编码器把教师路径编成 `z`（配对），
  或者干脆放弃 1-NFE 改迭代采样。否则任何「逐样本监督」都会被均值解吞掉。

## 让 z 携带教师信息：条件有效性上去了，多样性塌了（第十七条）

> 2026-11-19。第十六条证明「无配对的 z + 逐格监督 ⇒ 塌到条件均值」。这条给 z 加语义：
> 用教师路径的确定性编码替代随机 z，看条件是否真的学得会。

### 方法（不改内核）

生成器的反向传播只给参数梯度（`backward_g` 返回 `GenG`，**不返回 dz**），所以端到端训
encoder 要改内核。这里用最小切片：

1. **编码**：每张训练图的 8×8 亮格（64 维 ±1）经固定随机正交投影到 **32 维**，得到 `z`；
2. **训练**：`--z-file z10k.bin`，`G(z_i, goal_i)` 对教师格做逐格 BCE（`--grid-weight 100
   --grid-pos-weight 16`），z 与样本一一配对；
3. **推理**：`--z-file + --z-goals`，**从同 goal 的 z 池里采样**（这些 z 对应真实路径）。

```bash
qat train --data images10k.bin --goals goals10k.bin --cond 64 --cond-pos tail \
    --steps 5000 --ch 1024 --ternary --ternary-fc --loss patch_swd \
    --grid-weight 100 --grid-pos-weight 16 --z-file z10k.bin --seed 0 --out e3z
qat select --dump e3z/weights.bin --n 256 --seed 0 --goal 63 \
    --z-file z10k.bin --z-goals goals10k.bin --require-goal 63
```

### 读数

| 指标 | 基线（随机 z） | e3z（编码 z + 逐格 BCE） |
|---|---:|---:|
| `grid` loss | 卡在 0.83 | **0.077** |
| 原生到达 g16 | 23 | **85** |
| 原生到达 g32 | **2** | **127** |
| 原生到达 g47 | 128 | 103 |
| 原生到达 g63 | 138 | 76 |
| 无掩码可行率 | 0% | 0%（不连通） |
| 掩码后 paths（g16/32/47/63） | 203/200/164/152 | **80/74/30/27** |

### 判读：一半是正结果，一半是新问题

**正结果——条件第一次真的可学**：`g32` 从 2/256（0.8%）涨到 **127/256（49.6%）**，
`g16` 从 23 涨到 85，`grid` loss 从卡住的 0.83 掉到 **0.077**。这证明第十六条的判断是对的：
**不是监督不够强，是 z 没带信息**。一旦 z 与样本配对，「按 goal 画」就变成可学问题。

**新问题——多样性塌缩**：掩码后的不同路径数从 152–203 掉到 27–80。原因很直接：32 维固定
投影把「一条路径」压成一个确定点，模型学到的是 `G(P(x)) ≈ x`（自编码），推理时只能复现
z 池里已有的路径形态，插值能力很弱。

**连通性仍然缺失**：逐格 BCE 只监督「哪些格亮」，不监督「连成一条」，所以原生
`feasible=0`；掩码解码能补到 100%，但那是补出来的，不是生成的。

### 下一步

三件事按性价比排序：

1. **提高 z 的信息量**：32 → 64 维，或改用 PCA（保留几何主成分）而不是随机投影——直接
   针对「多样性塌缩」；
2. **加连通性项**：在逐格 BCE 之外惩罚「孤立亮块」（可微近似：亮格数与从 (0,0) 出发的
   连通分量数之差），让原生 `feasible` 不再是 0；
3. **容量/步数**：当前 5.88M、5k 步；重建 256 条路径的训练任务可能欠拟合（`grid` 0.077 还
   没到底）。

## z 无损化 + 连通惩罚：多样性回来一半，连通与到达率都没救回来（第十八条）

> 2026-11-19。第十七条留下两个问题：32 维投影把多样性压死（paths 152→27），逐格 BCE 不约束
> 连通（原生 feasible=0）。这条同时试两个修法。

### 改动

1. **z 无损**：不再投影，直接用教师的 8×8 亮格（64 维 ±1）当 z（`z64.bin`）；
2. **连通软惩罚**：`--connect-weight`，`iso = Σ p_k · Π_{nbr}(1 - p_nbr)`（孤立亮格），
   梯度同通道写回——试图让逐格 BCE 别画散点。

```bash
qat train --data images10k.bin --goals goals10k.bin --cond 64 --cond-pos tail \
    --steps 5000 --ch 1024 --ternary --ternary-fc --loss patch_swd \
    --grid-weight 100 --grid-pos-weight 16 --connect-weight 1.0 \
    --z-file z64.bin --seed 0 --out e3zc
```

### 读数（同数据同步数 5k 步）

| 指标 | 基线 | z32（第十七条） | z64 + 连通 |
|---|---:|---:|---:|
| 原生到达 g16 | 23 | 85 | 80 |
| 原生到达 g32 | 2 | 127 | 66 |
| 原生到达 g47 | 128 | 103 | 103 |
| 原生到达 g63 | 138 | 76 | 25 |
| 原生 feasible | 0% | 0% | 0–0.4% |
| 掩码后 paths（g16/32/47/63） | 203/200/164/152 | 80/74/30/27 | **144/145/64/63** |
| `grid` loss | 卡在 0.83 | 0.077 | **1.12** |
| `conn` loss | — | — | 1.93 → 1.35 |

### 判读

**做成的**：多样性回来了——paths 从 80/74/30/27 抬到 **144/145/64/63**（基线 203/200/164/152）。
无损 z 确实保住了「同一 goal 下有多种走法」。

**没做成的两件**：

1. **连通惩罚无效**：`conn` loss 1.93 → 1.35，但原生 feasible 仍是 0–0.4%。原因清楚——
   `iso` 只罚「孤立亮格」，不约束「从 (0,0) 连到 goal」；一整块断开的路径并不孤立，依然
   不可行。**这是错的可微近似**。
2. **到达率反而降了**：g63 76→25、g32 127→66。同时 `grid` 从 0.077 升到 1.12——说明这轮
   **训练更不充分**（64 维 z + 三项损失，5k 步不够），不是编码变差。

### 结论

- 无损 z 解决多样性、不解决连通；孤立惩罚是错的对象（该罚「不连通」而不是「孤立」）；
- 当前真正的瓶颈是**容量与步数**：`grid` 1.12 离 0.077 差一个量级。

### 下一步

1. 20k 步 / `--ch 2048` 各跑一次，先看 `grid` 能否稳定压到 0.1 以下；
2. 连通项改成**可微 BFS 近似**（对每格算「到 (0,0) 的软最短距离」，惩罚不可达格），
   而不是孤立格；
3. 或者干脆把「连通」交给解码器（掩码修复就是干这个的），生成器的目标改成「给出候选格集」。

## 容量与权重都不是瓶颈：逐格 BCE 卡在 1.1（第十九条）

> 2026-11-19。第十八条留下一个判断：「`grid` 1.12 说明训练不充分，瓶颈可能在容量/步数」。
> 这条直接检验它，并给出否定答案。

### 实验

| 配置 | 参数 | 步数 | `grid` 终值 |
|---|---:|---:|---:|
| 第十八条基线 | 5.88M | 5k | 1.12 |
| 加容量 | **11.38M**（`--ch 2048`） | **20k** | **0.946** |
| 加权重 | 5.88M | 5k | **1.118**（`--grid-weight 1000`） |

```bash
# 加容量
qat train ... --ch 2048 --steps 20000 --grid-weight 100 --z-file z64.bin --out e3big
# 加权重
qat train ... --ch 1024 --steps 5000  --grid-weight 1000 --z-file z64.bin --out e3w1k
```

### 判读：两个解释都被排除

- **加 4 倍参数 + 4 倍步数**：`grid` 1.12 → 0.946（约 16%），远未到 z32 版的 0.077；
- **`grid-weight` 从 100 提到 1000**：`grid` 1.118 vs 1.12，**没有变化**。

所以「容量不够」和「SWD 抢梯度」都不是原因。

### 瓶颈在哪：fc 丢掉了 z 的空间结构

z 是 8×8 亮格展平成的 64 维**无序向量**，而生成器第一层是 `fc`（192 → 32768）。要让 64 个数
变回 8×8 的空间排列，`fc` 得自己学出「空间索引」——它没有卷积的平移/邻接归纳偏置。

`grid` 卡在 1.1 ≈ 每格概率 0.28（接近「不知道」），与「学不到空间映射」的表现一致。这也解释了
为什么 z32（随机投影）反而能到 0.077：投影后的 32 维已经是一组「全局摘要」，`fc` 不需要还原
空间布局；而无损的 64 维要求它做空间重建，反而更难。

### 下一步（三条，按改动量排序）

1. **让 z 保留空间性**：把 z 做成 8×8（或 32×32）的特征图，用 `conv` stem 接入，替代 `fc`；
2. **条件注入**：z 作为逐格条件图（类似 SPADE 的归一化调制），仍然走卷积；
3. **换路线**：放弃「从 z 生成」，改成「教师图引导的修复」——z 退化为噪声，目标是用现有
   掩码解码 + 局部修正完成路径。

前两条要改 `Gen` 架构（当前 `fc → 3×conv`），是结构性改动；第三条能复用现有解码器。

## conv stem：原生可行率第一次非零（第二十条）

> 2026-11-19。第十九条把 `grid` 卡在 1.1 归因于「`fc` 学不出 z→8×8 的空间映射」。
> 这条先更正那条诊断的**前提 bug**，再单独检验「给 z 卷积归纳偏置」是否仍有价值。

### 先更正：第十九条的前提有 bug

`z_from_file` 把「每样本 z 宽度」写成了常量 `ZD = 32`，而 `z64.bin` 每样本是 **64** 维
（2,560,000 B ÷ 10,000 ÷ 4）。于是 `src = idx * 32` 读到的是**别的样本的半张亮格**——
第十八条以来所有 z64 实验里，z 与图像根本不配对。

| 文件 | floats | 每样本 | 旧代码（按 32 取下标） |
|---|---:|---:|---|
| `z10k.bin`（第十七条） | 320,000 | 32 | 正确 |
| `z64.bin`（第十八、十九条） | 640,000 | **64** | **错配** |

修法：训练侧加 `--z-dim`（0 = 按 `zf.len() / n_img` 自动推断，要求整除）；评估侧 `select`
按 `zf.len() / zg.len()` 推断。

同数据同步数重跑（5k / `ch 1024` / `grid-weight 100` / z64）：

| 指标 | 第十八条（z64） | 第十九条（ch2048+20k） | **修好 z 宽度** |
|---|---:|---:|---:|
| `grid` 终值 | 1.12 | 0.946 | **0.064** |
| 原生 goal_hit g16/32/47/63 | 80/66/103/25 | 141/21/50/44 | **55/176/160/186** |
| 掩码后 feasible | 0.4% | — | 100% |
| 掩码后 paths | 144/145/64/63 | 166/119/144/185 | 52/46/10/7 |

**判读**：第十九条「容量与权重都不是瓶颈」的结论仍成立，但它的**解释**是错的——
`fc` 学得出空间映射，之前是数据错位。`z32` 能到 0.077 也不是因为「全局摘要更好」，
而是它恰好匹配了那个硬编码的 32。修复后 z64 反而是更好的编码（0.064 < 0.077）。

同时暴露一个新问题：`grid` 好了，**多样性却塌了**（paths 52/46/10/7，第十八条是
144/145/64/63），且原生 feasible 仍 0%。

### conv stem：让 z 以空间形式进入

```
z[0..64]  ──reshape [bs,1,8,8]──► conv3×3 s2 p1 ──► [bs,ch,4,4] ─┐
                                                                  ├─相加─► up2→conv→BN→ReLU ×3
z[64..win] ──────────────────► fc ─────────────► [bs,ch,4,4] ─────┘
```

- stem 恒 f32、不三值（只有 `ch*9` 个参数，三值没有意义）；
- `--stem conv` 是一个开关，默认 `fc` 路径逐位不变（stem 的初始化放在 rng 序列末尾）；
- 覆盖三处后端（CPU 参考、显存 `gen_gpu_opt`、burn）与权重通路（QDMP `stem.0.*`、meta `"stem"`）。

```bash
qat train --data images10k.bin --goals goals10k.bin --cond 64 --cond-pos tail \
    --steps 5000 --ch 1024 --ternary --ternary-fc --loss patch_swd \
    --grid-weight 100 --grid-pos-weight 16 --z-file z64.bin --stem conv \
    --seed 0 --out e3stem
```

### 读数（同数据同步数）

| 指标 | e3zfix（无 stem） | **e3stem** |
|---|---:|---:|
| 参数 | 5.88M | 4.83M（fc 宽度 192→128） |
| `grid` 终值 | **0.064** | 0.093 |
| 原生 goal_hit g16/32/47/63 | 55/176/160/186 | **165/222/186/177** |
| **原生 feasible** | **0%** | **19.9 / 3.5 / 5.9 / 4.3%** |
| 掩码后 feasible | 100% | 100% |
| 掩码后 paths | 52/46/10/7 | **84/57/67/69** |

### 判读

**`grid` 略差（0.093 vs 0.064），但其余三项全面改善**：原生 goal_hit 普遍 +50~110，
**原生可行率第一次非零**（此前所有轮次都是 0%），掩码后多样性从 52/46/10/7 回升到 84/57/67/69。

这个组合有点像「生成器不再只拟合条件均值」：空间归纳偏置让它能画出结构上更像路径的图，
代价是逐格概率没那么尖（`grid` 差一点）。原生可行率非零意味着**掩码解码不再是可行性的
唯一来源**——这是第十六条以来第一次。

### 下一步

1. **多 seed + 更长步数**：单 seed 5k 步的读数，`grid` 的 0.093 可能是欠拟合（stem 很浅）；
2. **stem 加深**：当前只有一层 3×3，可以试 2~3 层带通道扩张的小 stem；
3. **沿可行率继续**：3.5–19.9% 离可用的 90% 还远，但这是第一个可优化的非零起点——
   可以试「对可行样本加权」或把掩码解码的修复能力当作数据增强回灌给生成器。

## 多 seed 与长步数：第二十条的「原生可行率非零」不可复现（第二十一条）

> 2026-11-19。第二十条只跑了**单 seed、5k 步**，它自己也留了两个疑问：`grid` 0.093
> 是不是欠拟合？19.9% 的原生可行率是不是种子运气？这条把两个都测了。

### 实验（一律 n=256 评估、同数据同损失）

| run | 结构 | 步数 | seed | `grid` 终值 | 原生 feasible g16/32/47/63 | 掩码后 paths |
|---|---|---:|---:|---:|---|---|
| `e3zfix` | 无 stem | 5k | 0 | **0.064** | 0 / 0 / 0 / 0% | 52/46/10/7 |
| `e3zfix20k` | 无 stem | 20k | 0 | 0.076 | 0 / 0 / 0 / 0% | 53/48/10/5 |
| `e3stem` | stem | 5k | 0 | 0.093 | **19.9 / 3.5 / 5.9 / 4.3%** | 84/57/67/69 |
| `e3stem20k` | stem | 20k | 0 | 0.097 | 0 / 0 / 0 / 0% | 72/36/12/4 |
| `e3stem-s1` | stem | 5k | 1 | **0.485** | 0.8 / 0 / 0.8 / 0% | 88/43/37/20 |
| `e3stem-s2` | stem | 5k | 2 | 0.108 | 0.4 / 0 / 0 / 0% | 79/36/17/5 |

```bash
# 20k / seed 0（前 5k 步与 e3stem 逐位相同）
qat train ... --stem conv --steps 20000 --seed 0 --out e3stem20k
# seed 1 / 2
qat train ... --stem conv --steps 5000 --seed 1 --out e3stem-s1
qat train ... --stem conv --steps 5000 --seed 2 --out e3stem-s2
# 对照：无 stem 20k
qat train ...                --steps 20000 --seed 0 --out e3zfix20k
```

### 判读：两个疑问都得到否定答案

1. **不是欠拟合**。步数翻 4 倍，两种结构都没有改善：无 stem 0.064 → 0.076（略差），
   stem 0.093 → 0.097（略差）。`grid` 在 5k 步就到平台，继续训只是围着平台震荡。
2. **19.9% 不可复现**。四个 stem run 里只有 `e3stem` 一个超过 1%：
   - 换 seed：seed 1 只有 **0.8%**、seed 2 只有 **0.4%**；
   - 同 seed 多训 15k 步：`e3stem20k` 直接回到 **0%**。
   `e3stem` 与 `e3stem20k` 是同一条轨迹（前 5k 步逐位相同），所以这不是换种子造成的，
   而是**同一个模型在训练过程中短暂出现过、随后消失**的能力。
3. **`grid` 上 stem 反而略差**（0.093/0.097 vs 0.064/0.076）。也就是说「给 z 卷积归纳偏置」
   在逐格监督这一项上没有回报。

### 顺带发现：训练不稳定

`e3stem-s1` 的末段很干净地展示了这一点：第 4000→5000 步，`swd_patch` 从 0.366 掉到
**0.036**（图整体分布贴近真实），但 `grid` 从 0.111 跳到 **0.485**（逐格监督同时崩掉）。
同一个模型、同一批梯度里有两种力在反向拉扯，谁赢取决于这一步落在哪。

这解释了为什么原生可行率会「闪现」：它不是一个稳定学到的能力，而是两个损失短暂对齐时的
副产物。

### 结论

- 第二十条「原生可行率第一次非零」应降级为「**观察到过一次 19.9% 的偶发峰值**」，
  不是结构带来的可复现能力；
- 「z 的空间编码方式」（无损 vs 投影、fc vs conv stem）已经不是瓶颈——三种编码的
  `grid` 都在 0.06–0.10，差别在噪声范围内；
- 掩码后 paths 上 stem 在 g16 稳定更高（84/88/79/72 vs 52/53），但 g63 反而更低
  （69/4/20/5 vs 7/5）——多样性也没有系统性优势。

### 下一步

1. **先解决训练稳定性**：seed 1 的末段崩溃说明「SWD 与逐格 BCE 的权重配比」在训练后期
   失衡。可试权重调度（前期 SWD、后期 grid）、梯度裁剪、或对两者的更新方向做冲突消解
   （PCGrad 类的投影）。这比再换编码方式更可能是根因。
2. **停止在 z 编码上打转**：无损/投影/stem 三种都测过了，`grid` 都在 0.06–0.10。
3. 若要重新评估任何「可行率」类的正结果，**至少三个 seed**，并报告同 seed 的轨迹
   （否则会重复这次的误判）。

## 梯度范数平衡：止住了崩溃，但没提升可行性（第二十二条）

> 2026-11-19。第二十一条把「原生可行率闪现」归因于训练不稳定（SWD 与逐格 BCE 在反向拉扯），
> 并把「解决训练稳定性」列为下一步。这条先量化拉扯的**性质**，再按性质选手段。

### 诊断：不是方向冲突，是尺度失衡

新增 `--grad-cos`，在逐格 BCE 分支里对**实际参与更新的两个分量**（SWD 侧 `d0` 与 `w·d1`）
算余弦与范数比，按 `log_every` 区间累积写进日志。两条轨迹（stem/5k，粒度 250 步）：

| | `gcos`（余弦） | `gratio`（逐格BCE / SWD 的范数比） |
|---|---:|---:|
| seed 0 | 0.005 – 0.026 | 7.5 万 – 290 万 |
| seed 1 | 0.000 – 0.023 | 6.6 万 – 24 万 |

两条结论都很硬：

- **余弦接近 0，不是负相关**。两个梯度几乎正交——不存在「把同一批权重往相反方向推」；
- **范数比是 6.6 万倍以上**。逐格 BCE 的梯度完全碾压 SWD，`grid_weight = 100` 名义是 100，
  实际是「100 × 6 万」。

崩溃点（seed1 的 step 5000，`swd` 0.036 / `grid` 0.485）余弦仍只有 0.0069——所以那个突变
也不是「冲突爆发」，而是优化器在 BCE 主导的更新下偶然走进了 SWD 的低损区域。

### 手段选择：三个候选里两个半不对症

| 候选 | 判定 |
|---|---|
| PCGrad / 冲突投影 | **无效**：余弦 ≈ 0.01，正交而非负相关，没有冲突可投影 |
| 权重调度（前期 SWD、后期 grid） | **不对症**：`gratio` 从 step1 的 290 万只缓慢降到 step4750 的 7 万，全程同一量级，不存在「前期正常、后期恶化」的转折 |
| 梯度裁剪 | **不对症**：问题是两项**相比**失衡 6 万倍，不是任何一项的绝对范数爆炸（两者各自都很稳） |
| **范数平衡** | **对症**：直接把强项缩放到与弱项可比 |

### 实现

`--grad-balance`（默认关，行为不变）：

```
dsum = d0 + grid_weight · gscale · d1,    gscale = ‖d0‖ / ‖d1‖
```

于是逐格 BCE 项的实际贡献范数 = `grid_weight · ‖d0‖`，`grid_weight` 终于表示**真实的相对话语权**。

```bash
qat train ... --stem conv --grad-balance --grad-cos --steps 5000 --seed 1 --out e3bal-s1
```

### 读数

训练侧（step 5000）：

| run | 原版 `swd` → `grid` | 平衡版 `swd` → `grid` |
|---|---|---|
| seed 1（原来会崩） | 0.036 → **0.485** | **0.046 → 0.105** |
| seed 0 | 0.233 → 0.093 | **0.048 → 0.085** |

SWD loss 全程从 0.36–0.43 降到 **0.036–0.048**（8–10 倍），说明 SWD 终于真正参与优化；
seed 1 的末段崩溃消失。

任务侧（n=256）：

| run | 原生 feasible g16/32/47/63 | 掩码后 paths |
|---|---|---|
| `e3bal-s0` | 1.6 / 0.4 / 0.8 / 0.0% | 77/34/13/6 |
| `e3bal-s1` | 0.8 / 0.0 / 0.4 / 0.0% | 77/25/12/6 |
| 原版 `e3stem`（s0） | 19.9 / 3.5 / 5.9 / 4.3% | 84/57/67/69 |

### 判读

**做成的**：训练稳定性问题真实存在、且被真正解决了。SWD 从「被 6 万倍大的梯度淹没」
变成「与逐格 BCE 等量级参与」，崩溃消失，这是不依赖种子的稳定改善。

**没做成的**：任务指标没变好。原生可行率 0.4–1.6%（和原版 seed1/2 的 0.4–0.8% 同量级），
掩码后多样性 77/25–34/12–13/6 甚至低于原版 84/57/67/69。

所以第二十一条的假设要修正：**训练不稳定不是可行性的瓶颈**。把这个障碍清掉之后，
可行性仍然是 ~1%。

### 下一步

1. **重扫 `grid_weight`**：100 是在 6 万倍失衡前提下调出来的，平衡后语义完全变了
   （现在 100 = 真的 100 倍话语权）。可能 1–10 才是合适区间，这一步最便宜且直接。
2. 若重扫后可行率仍停在 ~1%，则「逐格 BCE + SWD」这个组合在 8×8 网格任务上的上限
   基本探明——那时应转向目标函数本身（例如把连通性做成可微的路径搜索，而不是逐格分类）。

## 下一步

结构不是瓶颈，**目标函数才是**：七到九条已经证明「条件能传进网络并被使用」

- **创造力机制**：见
  [`CRAM-3D-DRIFT-CREATIVE.md`](CRAM-3D-DRIFT-CREATIVE.md)——Creative Priming 的

  （burn + running stats）的读数不能直接比，否则任何「训练变好了」都可能只是口径差。
  口径统一之后仍值得试的：奖励改组内排序、「到最近可行样本的能量差」、π 调制 z 的
