# MiniLM 完整 6 层：f32 对照与三值线性权重

把 `bias_e2e` 的三段线性链升级成 MiniLM 的真实 6 层前向：attention（12 heads）、
LayerNorm、GELU、残差都在 f32 里跑，只把线性权重三值化。目标是回答两个问题：

1. 三值权重在**真实 transformer 链**上到底掉多少，而不是只掉在三段线性段上；
2. 第 0 层单段 `output` 的“随机输入低估”结论，能不能外推到完整模型。

## 1. 协议

- 模型：`sentence-transformers/all-MiniLM-L6-v2`（6 层、384 hidden、12 heads、1536 FFN）。
- 文本：`mteb/stsbenchmark-sts` test 前 8 句，padding 到 `seq=64`。
- 输入：PyTorch 第 0 层输入 hidden states（`q0` hook）+ attention mask。
- 参照：PyTorch `last_hidden_state`；逐层另存 `layer0..5` 用于对齐。
- Rust 前向：6 层 BERT，Q/K/V/O + FFN 线性权重三值化（absmean 逐行 scale，
  保留 f32 bias）；LayerNorm/GELU/softmax/残差保持 f32。只比较 `mask=1` 的 token。
- GELU 用 erf 解析近似；f32 对齐读数见下（6e-7，足够把实现误差与三值化误差分开）。

导出脚本（只作对齐基线）：

```bash
TRIT_DATA=<数据根> HF_HUB_OFFLINE=1 \
  python crates/trit-wspace/examples/export_bert6.py \
  "$TRIT_DATA/miniLM-bert6" 8
```

复算：

```bash
cargo run --release -p trit-wspace --example bert6 -- \
  --file "$HF_HOME/hub/models--sentence-transformers--all-MiniLM-L6-v2/snapshots/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/model.safetensors" \
  --data-dir "$TRIT_DATA/miniLM-bert6"
```

## 2. 读数

| 项 | `rel_l2` | `cosine` |
|---|---:|---:|
| Rust f32 vs PyTorch 参照 | **6.06e-7** | **1.0000** |
| 三值（真实输入）vs f32 | **1.1594** | **0.4690** |
| 三值（随机输入）vs 同输入 f32 | **1.5488** | **0.3117** |

逐层 f32 对齐：`layer0..4` 的 `rel_l2 = 0`，`layer5 = 1e-6`；实现与 PyTorch 实质逐位一致。

output 段（FFN 的 GELU 后输入）统计：

## 3. 读法

1. **f32 对齐 6e-7**：Rust 6 层前向可以当 PyTorch 的近似等价实现；下面的三值读数
   不是实现误差。
2. **三值化所有线性权重后，真实输入 `rel_l2 1.16 / cosine 0.47`**：完整 6 层不是
   “三段线性链的 0.92”，也不是“单层 0.49”；误差在 attention/FFN 之间重新分配。
3. **随机输入在完整 6 层上反而更差**：`rel_l2 1.55 / cosine 0.31`，比真实输入高
   **34%**（1.549/1.159）。这与第 0 层单段 `output` 的“随机低估 1.72×”**方向相反**。
4. 因此：**单层 output 段的重尾（kurt 99.6）不足以解释完整模型**；经过后续
   LayerNorm/残差/GELU 后，随机输入落到了更不利的分布。任何“随机输入是乐观还是悲观”
   的结论都必须写明是哪一层、哪一段、是不是完整链。
5. output 段真实输入的 layer0 重尾（99.6、max 8.83）仍然是最强的局部信号；它解释了
   第 0 层单段为什么对输入分布敏感，但不能外推到 6 层最终读数。

## 3.5 全三值激活（LN 也三值）

`--activation-mode` 三档：`f32`（LN/激活保持 f32，只三值化线性权重）、`ternary-ln`
（LN 的 weight 三值化，bias 保 f32）、`ternary-all`（LN weight 三值化 + LN/GELU 输出
符号三值化）。

| 模式 | 真实 `rel_l2` | 真实 `cosine` | 随机 `rel_l2` | 随机 `cosine` |
|---|---:|---:|---:|---:|
| f32（仅线性权重） | 1.1594 | 0.4690 | 1.5488 | 0.3117 |
| ternary-ln | 1.3647 | 0.3516 | 1.6907 | 0.2312 |
| ternary-all | **2.4475** | **0.0345** | **3.0896** | **0.0382** |

读法：

1. 只把 LN 的 weight 三值化，真实 cosine 从 0.469 掉到 0.352（−25%）；
2. 再把 LN/GELU 输出符号三值化，cosine 掉到 **0.03**，方向信息几乎全丢；
3. **当前 absmean LN weight + sign 激活方案在 `ternary-all` 下真实 cosine 只有 0.0345**
   （复算：`--activation-mode ternary-all`）。要保留方向，
   需要 QAT/学习式 scale、混合精度（LN 输出保 f32）或残差侧车；
4. 随机输入在三种模式下都比真实输入更差（rel_l2 高 25%–34%），方向与 §3 一致。

## 3.6 STS 任务头（128 句 / 64 对）

把 `bias_e2e` 的 hidden 读数接到 STS benchmark：`export_bert6.py` 现在同时导出
`pairs.json`（64 对、人工分）；Rust 侧按 mask 做 mean pooling + L2 normalize，
对每对算余弦，再与人工分算 Pearson / Spearman。

| 模型 | `rel_l2` | `cosine` | STS Pearson | STS Spearman |
|---|---:|---:|---:|---:|
| PyTorch f32 参照 | — | — | **0.9230** | **0.9243** |
| 三值线性权重（f32 激活） | 1.1660 | 0.4695 | **0.7330** | **0.7437** |
| ternary-ln | 1.3999 | 0.3583 | **0.5461** | **0.5310** |
| ternary-all | 2.5051 | 0.0275 | **0.2472** | **0.2494** |

读法：

1. **仅三值化线性权重**，STS 相关性从 0.923 掉到 0.733（−0.19；相对 −21%）。
   这比 hidden `cosine 0.47` 看起来“好看”，但仍是明确掉点。
2. **LN weight 也三值化**：STS 相关性再掉到 0.546；**全三值激活**只剩 0.247，
   基本丢失 STS 相关性。
3. 任务头方向与 hidden 读数一致：越往激活侧三值化，相关性越低；`ternary-all`
   的 0.247 已经是“弱相关”而不是可用的句向量。

## 3.7 激活 scale：per-token vs per-channel

在 `ternary-all`（LN/GELU 输出纯 sign）之上加两种幅度 scale：

- `ternary-all-scale`：每个 token 的 `mean(|x|)`（per-token）；
- `ternary-all-channel`：用 f32 forward 在校准集上统计的 per-channel absmean
  （`scales.json`，由 `export_bert6.py` 导出）。

| 模式 | `rel_l2` | `cosine` | STS Pearson | STS Spearman |
|---|---:|---:|---:|---:|
| 仅线性权重（f32 激活） | 1.1660 | 0.4695 | **0.7330** | **0.7437** |
| ternary-ln | 1.3999 | 0.3583 | 0.5461 | 0.5310 |
| ternary-all（纯 sign） | 2.5051 | 0.0275 | 0.2472 | 0.2494 |
| ternary-all-scale（per-token） | 1.5598 | 0.1837 | 0.3576 | 0.3846 |
| ternary-all-channel（per-channel，f32 校准） | 1.2373 | 0.0100 | **0.4322** | 0.3889 |

读法：

1. per-token scale 把 STS Pearson 从 0.247 拉到 **0.358**（+0.11），cosine 0.03→0.18；
2. per-channel scale 再拉到 **0.432**，**超过 0.4 目标**（Pearson），但 Spearman 0.389 仍差一点；
   cosine 只有 0.01——固定 per-channel 幅度能把排序救回一些，但 hidden 方向仍严重偏离；
3. 学习式 scale 的闭式解 `s=(q·y)/(q·q)`：当 `q=sign(y)` 时它**就是** per-channel absmean，
   所以 `ternary-all-channel` 的 0.432 已经是最小二乘闭式解在这个量化口径下的读数；
   用三值模型的 q 与 f32 目标 y 求 scale 会更小，需要额外对齐，未做；
4. 距仅线性权重的 0.733 仍有 0.30；要逼近它，需要残差侧车或混合精度，而不是继续调激活 scale。

## 3.8 残差侧车：top-k 列 f32 修正（负结果）

对每个三值线性层算 `R = W − s·T`，按列范数保留 top-k 列，推理时
`y = s·T x + R_k x_k`；`ternary-all-channel` + 侧车，扫 k=0/4/8/16。

| rank | `rel_l2` | `cosine` | STS Pearson | STS Spearman |
|---:|---:|---:|---:|---:|
| 0（仅三值） | 1.2373 | 0.0100 | **0.4322** | 0.3889 |
| 4 | 1.2363 | 0.0116 | 0.4091 | 0.4109 |
| 8 | 1.2356 | 0.0128 | 0.3940 | 0.3961 |
| 16 | 1.2386 | 0.0077 | 0.4259 | 0.4028 |

结论：

1. **top-k 列侧车没有把 0.432 推向 0.733**：Pearson 0.432 → 0.409 / 0.394 / 0.426，
   `rel_l2` 几乎不变（1.2373 → 1.2363/1.2356/1.2386）；
2. 误差主导在**激活三值化**，不在权重残差；k≤16 的列修正量太小，且与激活量化误差
   不同向，不能救回 hidden 方向；
3. 要逼近 0.733，需要混合精度（LN/残差流保 f32）、更大的 rank（接近 in_dim 时等价于
   f32 线性层），或改激活侧量化——不是继续加列侧车。

## 3.9 混合精度：LN/残差 f32、matmul 输入三值（负结果）

`--activation-mode mixed`：LN/残差流保持 f32，权重三值，Q/K/V、intermediate、FFN 输出的
matmul 输入在进入线性层前符号三值化；attention context 保持 f32。

| 模式 | `rel_l2` | `cosine` | STS Pearson | STS Spearman |
|---|---:|---:|---:|---:|
| mixed | 1.6053 | 0.0082 | 0.2191 | 0.1896 |
| 全三值 + per-channel | 1.2373 | 0.0100 | 0.4322 | 0.3889 |
| 仅线性权重（f32 激活） | 1.1660 | 0.4695 | 0.7330 | 0.7437 |

读法：

1. 只把 matmul 输入三值化、LN/残差保 f32，Pearson **0.219**，比全三值激活的 0.247 还低；
2. 瓶颈是 **matmul 输入的三值化本身**，不是 LN/残差；即使 context 保持 f32（去掉对
   context 的量化），也只回到 0.219/0.190；
3. 所以“LN/残差 f32 + matmul 输入三值 + 权重三值”没有把 0.432 推向 0.733；
4. 真正可用的混合精度是 **仅权重三值 + 激活 f32**（`f32` 模式，0.733）；要进一步接近
   PyTorch 的 0.923，需要权重侧精度（GPTQ/更大侧车）或 8-bit 激活，而不是三值输入。

## 3.10 int8 激活：权重三值 + 8-bit matmul 输入

`--activation-mode int8`：权重三值，LN/残差 f32，matmul 输入 per-token 对称 int8
（`scale = max|x|/127`，反量化后参与 matmul）。

| 模式 | `rel_l2` | `cosine` | STS Pearson | STS Spearman |
|---|---:|---:|---:|---:|
| int8（权重三值） | 1.1660 | 0.4695 | **0.7331** | **0.7446** |
| 仅线性权重（f32 激活） | 1.1660 | 0.4695 | 0.7330 | 0.7437 |
| 全三值 + per-channel | 1.2373 | 0.0100 | 0.4322 | 0.3889 |
| mixed（matmul 输入三值） | 1.6053 | 0.0082 | 0.2191 | 0.1896 |

读法：

1. **int8 激活与 f32 激活几乎完全相同**（Pearson 0.7331 vs 0.7330，Spearman 0.7446 vs
   0.7437），说明 8-bit 足够保留激活信息，**激活带宽不是瓶颈**；
2. 权重三值化本身把 PyTorch 的 0.923 拉到 0.733（−0.19）；要接近 0.923，必须做
   **权重侧精度**（GPTQ 逐列补偿/更大 rank 侧车/混合权重），而不是继续压激活；
3. 三值激活这条线已经到顶：纯 sign 0.247 → per-token 0.358 → per-channel 0.432 →
   matmul 输入三值 0.219；int8 是唯一不损失激活精度的低比特方案。

## 3.11 权重侧 GPTQ 逐列补偿：STS 0.7330 → 0.8065

`--gptq`：用 f32 校准集的 `H = XᵀX`（6 层 × 6 段线性层，128 句、mask 后的 2048 个 token）
逐列量化三值权重并把量化误差补偿到尚未处理的列：

```text
q_j = clamp(round(w_j / s), -1, 1)
e_j = (w_j - s·q_j) / [H⁻¹]_jj
w_k -= e_j · [H⁻¹]_jk              (k 尚未量化)
```

列顺序按 `diag(H)` 降序（GPTQ 的 act-order），`H` 加 1% 对角阻尼保证可逆；`s` 仍是
逐行 absmean，所以两边的 `trits` 只差补偿/重排带来的少数列，可直接对照。

导出 Hessian 与复算：

```bash
TRIT_DATA=<数据根> HF_HUB_OFFLINE=1   python crates/trit-wspace/examples/export_bert6.py "$TRIT_DATA/miniLM-bert6-sts" 128
cargo run --release -p trit-wspace --example bert6 --   --file "$HF_HOME/hub/models--sentence-transformers--all-MiniLM-L6-v2/snapshots/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/model.safetensors"   --data-dir "$TRIT_DATA/miniLM-bert6-sts" --activation-mode f32 --gptq
```

| 权重三值化 | `rel_l2` | `cosine` | STS Pearson | STS Spearman |
|---|---:|---:|---:|---:|
| absmean 逐行（上一节基线） | 1.1660 | 0.4695 | 0.7330 | 0.7437 |
| **GPTQ 逐列补偿** | **1.0491** | **0.5551** | **0.8065** | **0.8320** |
| PyTorch f32 对照 | — | — | 0.9230 | — |

读法：

1. **GPTQ 把权重侧 Pearson 从 0.7330 拉到 0.8065**（+0.0735，相对 +10.0%），
   Spearman 0.7437 → 0.8320，`rel_l2 1.1660 → 1.0491`、`cosine 0.4695 → 0.5551`；
   这是第一次在**不改激活**的前提下把 0.733 推过 0.8。
2. **补偿系数必须用 `H⁻¹` 而不是 `H`**。第一版实现按 `H[j,k]/H[j,j]` 补偿（漏了求逆），
   H 加权误差从 absmean 的 `0.266` **涨到** `0.860`（36 个矩阵全部变大），端到端
   Pearson 掉到 **0.4924**——比 absmean 的 0.733 还低。修正后 36 个矩阵的 H 加权误差
   全部下降（query 段 `0.266 → 0.167`，−37%）。这条负结果留在
   `crates/trit-wspace/src/gptq.rs` 的模块文档里，并有 `tests/gptq.rs` 的方向性断言守着。
3. 与 PyTorch f32 的 0.9230 还差 **0.1165**；剩下的缺口在权重侧（更大 rank 侧车、
   混合权重、per-group scale、QAT），激活侧已经证明不是瓶颈（§3.10）。

## 3.12 per-group scale + GPTQ：STS 0.8065 → 0.8290

`--gptq-group N`：把每行的 scale 从"整行一个 absmean"改成"每 N 列一个 absmean"，
与 §3.11 的 GPTQ 逐列补偿叠加（不用重新导出校准数据）。

```bash
cargo run --release -p trit-wspace --example bert6 --   --file "$HF_HOME/hub/models--sentence-transformers--all-MiniLM-L6-v2/snapshots/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/model.safetensors"   --data-dir "$TRIT_DATA/miniLM-bert6-sts" --activation-mode f32 --gptq-group 32
```

`scales` 布局是 `(row * groups + g)`，`groups = ceil(cols / group)`，末尾不满组按实际
长度算 absmean；`group >= cols` 退化为 §3.11 的 per-row。

| 权重三值化（激活 f32） | `rel_l2` | `cosine` | STS Pearson | STS Spearman |
|---|---:|---:|---:|---:|
| absmean per-row（§3.11 基线） | 1.1660 | 0.4695 | 0.7330 | 0.7437 |
| GPTQ per-row | 1.0491 | 0.5551 | 0.8065 | 0.8320 |
| GPTQ group=128 | 1.0468 | 0.5612 | 0.8144 | 0.8333 |
| GPTQ group=64 | 1.0437 | 0.5562 | 0.8159 | 0.8408 |
| GPTQ group=32 | 1.0479 | 0.5558 | 0.8272 | 0.8464 |
| **GPTQ group=16** | 1.0448 | 0.5599 | **0.8290** | 0.8460 |

读法：

1. **粒度越细 Pearson 越高**：0.8065 → 0.8144 → 0.8159 → 0.8272 → 0.8290；
   group=32 比 per-row 再 +0.0207（+2.6% 相对），group=16 只再 +0.0018 ⇒
   **32 附近已饱和**，再细的粒度不值得 4 倍 scale 存储。
2. `rel_l2` 与 `cosine` 并不随粒度单调（1.0491 → 1.0468 → 1.0437 → 1.0479 → 1.0448），
   说明 per-group 改的是**误差在行内的分配**，行级幅度几乎不变；STS 对这种分配更敏感。
3. 相对 absmean：group=32 的 Pearson +0.0942（**+12.9% 相对**）；相对 PyTorch f32 的
   0.9230 仍差 0.0940。
4. 只改权重侧：激活保持 f32（§3.10 已证 8-bit 不损失精度），校准集与 §3.11 同一份。

## 3.13 128 对复验：0.829 是 64 对的偏乐观读数，排序与相对增益稳定

把评测/校准数据从 128 句（64 对）扩到 256 句（128 对），导出脚本、口径、Hessian 提取
（mask 后前 2048 个 token）都不变：

```bash
TRIT_DATA=<数据根> HF_HUB_OFFLINE=1   python crates/trit-wspace/examples/export_bert6.py "$TRIT_DATA/miniLM-bert6-sts-128" 256
```

| 配置（权重三值 + 激活 f32） | 64 对 Pearson | 128 对 Pearson | 64→128 |
|---|---:|---:|---:|
| PyTorch f32 基线 | 0.9230 | 0.9235 | +0.0005 |
| absmean per-row | 0.7330 | 0.6966 | −0.0364 |
| GPTQ per-row | 0.8065 | 0.7457 | −0.0608 |
| GPTQ group=32 | 0.8272 | **0.7893** | −0.0379 |

| 配置 | 64 对 Spearman | 128 对 Spearman |
|---|---:|---:|
| absmean per-row | 0.7437 | 0.7058 |
| GPTQ per-row | 0.8320 | 0.7580 |
| GPTQ group=32 | 0.8464 | 0.8084 |

读法：

1. **f32 基线在扩样本后几乎不动**（0.9230 → 0.9235），说明 128 对的评测口径与 64 对一致，
   下面的下降不是口径变化。
2. **三值配置全部下降 0.034–0.061**：`0.829` 只能当"前 64 对"的读数，128 对上的 GPTQ
   group=32 是 **0.7893**。后 64 对（第 129–256 句）明显更难，小样本会系统性偏乐观。
3. **排序与相对增益稳定**：GPTQ 相对 absmean 在 64 对是 +0.0735、128 对 +0.0491；
   group=32 相对 per-row 在 64 对 +0.0207、128 对 **+0.0436**（更大）。两条改进都不是
   小样本噪声。
4. 权重三值化相对 f32 的代价：absmean −0.2269、GPTQ per-row −0.1778、GPTQ group=32
   **−0.1342**（128 对口径）。
5. 以后报读数必须写明子集大小（64 对 / 128 对），不能把不同子集上的数字混着比。

## 3.14 全量 STS（1379 对）：f32 基线 0.8274，GPTQ 增益收窄，per-group 几乎消失

## 3.15 低秩残差侧车：全量 rank 16 回收 55% 的权重差距，代价是字节 ×2

三值主干 `W ≈ s·T` 把误差 `R = W − s·T` 整块丢掉；GPTQ 只是把 R 在 Hessian 方向上压小，
并没有把 R 留下来。本节把 R 的前 r 个奇异三元组留成 f32 侧车：

```text
y = s·(T x) + U_r Σ_r V_rᵀ x
```

`rank = min(rows, cols)` 时行为上等价于完整 f32 线性层（8 句数据上 `rel_l2 = 2.6e-7`，
sidecar 参数 15.9M，是 dense 的 1.5×）；更小的 rank 是同一组奇异向量的**前缀**，
`set_rank` 只收缩不重排，所以**权重误差**关于 rank 单调。STS 是句向量余弦的排序指标，
不保证随权重误差单调——全量上 rank 32/64 都停在 rank 16 水平甚至略低（见读法 3）。

侧车按 `rank·(rows + cols)` 个 f32 存储；分解走 `RᵀR` / `R Rᵀ` 的 Jacobi 全分解
（`crates/trit-wspace/src/residual.rs`），36 个矩阵一次性构建约 100 s
（全量进程实测 `build_ms = 100.8`；8 句空载对照：无侧车 0.17 s、有侧车 81.9 s）。

复算（全量 1379 对）：

```bash
TRIT_NO_LAYERS=1 cargo run --release -p trit-wspace --example bert6 -- \
  --file "$HF_HOME/hub/models--sentence-transformers--all-MiniLM-L6-v2/snapshots/1110a243fdf4706b3f48f1d95db1a4f5529b4d41/model.safetensors" \
  --data-dir "$TRIT_DATA/miniLM-bert6-sts-full" \
  --activation-mode f32 --gptq-group 32 --sidecar-svd 16,64,128 \
  --out "$TRIT_DATA/tmpfull-svd.json"
```

| rank | 侧车参数 / dense f32 | 侧车字节 / 三值主干字节 | `rel_l2` | `cosine` | Pearson | Spearman | 差距回收 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 0（GPTQ g32，§3.14） | 0 | 0 | 1.1365 | 0.5192 | 0.7143 | 0.7190 | — |
| 16 | 6.25% | 1.0× | 0.8736 | 0.5908 | **0.7769** | **0.7776** | **55%** |
| 32 | 12.5% | 2.0× | 0.8318 | 0.6040 | 0.7752 | 0.7760 | 54% |
| 64 | 25% | 4.0× | 0.7912 | 0.6413 | 0.7677 | 0.7696 | 47% |
| 128 | 50% | 8.0× | 0.6580 | 0.7584 | **0.7995** | **0.7966** | **75%** |
| f32 权重基线（§3.14） | — | — | — | — | 0.8274 | 0.8203 | 100% |

rank16/64/128 来自同一趟（`tmpfull-svd.json`）；rank32 是单独一趟（同机、同数据、同参数，
把 `--sidecar-svd` 换成 `32`、`--out` 换成 `tmpfull-svd-r32.json`）。两趟的 f32 与 rank0
读数逐位一致（Pearson 0.827406… / 0.714308…），可交叉复核。

读法（全量口径）：

1. **rank 16 回收 55% 的权重差距**（`(0.7769−0.7143)/(0.8274−0.7143)`），代价是侧车字节
   恰好等于 2-bit 三值主干（权重存储 ×2，折合 dense f32 的 12.5%，不含 scale/bias）。
   这是目前性价比最好的一档：比 GPTQ 的 +0.0253 大一个量级，也比翻倍字节的 rank 32 略高。
2. **rank 128 回收 75%**（0.7995），但侧车是主干字节的 8×、dense 参数的 50%。
   16→128 的 Pearson 差 0.0226；按 Fisher z（n=1379，1 SE ≈ 0.027 z ≈ 0.011 r）约 **2.1 SE**，
   超出噪声。
3. **rank 16 / 32 / 64 在统计上不可区分，中间档不值**：rank 32 的 `rel_l2`（0.8318）和
   `cosine`（0.6040）都比 rank 16（0.8736 / 0.5908）好，Pearson 却低 0.0017
   （0.7752 vs 0.7769，约 0.2 SE）；rank 64 同样 `rel_l2` 更低，Pearson 低 0.0092（0.9 SE）。
   三档落在 0.7677–0.7769，跨不过噪声；只有 rank 128 跳到 0.7995（比 rank 16 高 0.0226，
   约 2.1 SE）。从 rank 16 加到 32 会让侧车字节翻倍（1×→2× 主干）却不涨点，要跨噪声得直接
   上 8× 的 rank 128。**STS 不随权重误差单调，报侧车读数必须同时给 `rel_l2` 与 STS，
   不能拿前者代理后者**。
4. **存储口径**：主干 1 trit = 2 bit；侧车 1 参数 = 4 B。「×N」只算权重，不含 per-group
   scale/bias，也不含容器开销。
5. **[B] 归类**：侧车是二进制硬件上的混合精度实现（f32 附加张量 + 约 100 s 离线构建），
   不是三值原生红利；能回收多少误差取决于 rank 与 GPTQ 残差结构，结论只在给定 rank 下成立。
   二进制基线是同字节预算的「三值主干 + f32 侧车」本身（`rank = 0` 行与 f32 行），
   没有拿三值去比未压缩的 f32 权重。

## 3.16 均匀位宽反扫：5-bit 在 1379 对上首次越过 f32

（1 = 均匀位宽走 GPTQ）、`TRIT_F32_LAYERS`（逐层保 f32）和 `TRIT_LAYERS`（层数）。

p=0.0072），但字节更多、Pearson 反而比 int4 低 0.000965；**int4 是 Pareto 更优档**。

结果，而且来源是容量（12 层）而不是位数运气：L12 int4 对 L12 自己的 f32 是
−0.000089 Pearson / +0.001154 Spearman（95% CI 含 0，p=0.523），统计上平手；
int4 比 int5 高 +0.000965 Pearson（p=0.315，不显著），但字节少 2,654,208 B，
所以 **int4 是 Pareto 更优档**。int5 的增益也显著，只是被 int4 支配。

字节口径仍是线性权重；把 g32 的 f32 scale（2,654,208 B）和 bias（165,888 B）算进去，
L12 int4 合计 13,436,928 B，是 L6 f32 总字节 42,550,272 的 **31.58%**（3.17×）；
L12 int5 合计 16,091,136 B（37.82%，2.64×）。即使按总字节，int4 仍比 6 层 f32 少 2/3。

### 3.16.4 留出集与配对 bootstrap：方向稳定，幅度不显著

用 `TRIT_DUMP_PREDS=1` 在同一进程导出 f32 与 int5 g128 的逐对余弦；前 128 对是
g64/g128 的选档集，留出集取后 1251 对，不参与选档：

| 集 | n | f32 Pearson | g128 Pearson | Δ Pearson | f32 Spearman | g128 Spearman | Δ Spearman |
|---|---:|---:|---:|---:|---:|---:|---:|
| 全量 | 1379 | 0.827406 | 0.829203 | **+0.001796** | 0.820325 | 0.821784 | **+0.001459** |
| 选档集 | 128 | 0.923497 | 0.924824 | +0.001327 | 0.943015 | 0.943714 | +0.000699 |
| 留出集 | 1251 | 0.813994 | 0.815779 | **+0.001785** | 0.803284 | 0.804803 | **+0.001519** |

留出集绝对值低于全量是样本难度差异，不能横向比绝对 Pearson，只看同一行的 Δ。
**Δ 在留出集仍是 +0.001785 / +0.001519，方向和全量几乎一致**：选档泄漏不是符号的
来源，g128 相对 f32 的微小优势不是「只在选档集上出现」。

10k 配对 bootstrap（同一批 pair 有放回重采样，每次重算两模型的 Pearson，单侧检验
`Δ > 0`）：

| 集 | Δ 95% CI | bootstrap 中位数 | p(Δ ≤ 0) |
|---|---:|---:|---:|
| 全量 | (−0.000376, +0.004016) | +0.001787 | 0.053 |
| 留出集 | (−0.000616, +0.004369) | +0.001779 | 0.075 |

两个 95% 区间都含 0；留出集单侧 p=0.075，5% 水平不显著，10% 水平也只是边缘。
结论：**+0.0018 是方向稳定但幅度不显著**，不能称为「稳定超过 f32」；要把它变成
可辩护结论，需要更多独立 STS 数据、重复训练/容量路线，而不是继续在同一 1379 对上
换 group。

### 3.16.5 归类与边界

- **`[B]` 二进制硬件**：int3/4/5/6/8 是标准二进制对称量化，per-group f32 scale；
  不是三值原生红利。二进制基线是同字节的 int4/rank16，不是未压缩 f32。
- **没有 QAT、AdaRound、学习式 scale**；int4 GPTQ 只做了 OBS 误差补偿，没有调 scale。
- 5-bit 的「越过」是同一全量、两个 group（g64/g128）；两档都由 128 对先导选出。
  已做 1251 留出集 + 10k 配对 bootstrap：留出 Δ 仍为 +0.001785，但 95% CI 含 0、
  单侧 p=0.075，**不能称稳定更强**；多 group 独立复现仍未做。
- 12 层已跑全量，并且用 L12 自己的 embedding 重导第 0 层；先导复用 L6 embedding 的
  数字作废（§3.16.3）。L12 int4 对 L6 f32 的 +0.010099 / +0.011723，全量与留出集
  两个 95% CI 都不含 0，留出集 p=0.0029，是当前唯一稳定越过的结果。
- L12 int4/int5 的 GPTQ 没跑：GPTQ Hessian 只有 6 层数据，L12 的 int4/int5 都是 RTN。
- 所有字节仍是估算：没有打包、没有容器/加载路径，scale 按 f32 记。

### 3.16.6 评测加速：24 线程按句并行，逐位一致

原来的全量评测是单线程，而且每趟跑 4 次全量前向：f32 real、f32 random、量化 real、
量化 random；后两次只服务 `random_vs_f32` 诊断，不进入 STS。L12 1379 对一趟约
99 分钟，峰值内存 5.5 GB。加两个开关：

- `TRIT_THREADS=24|auto`：按句子切 batch，每句独立跑完整 12 层；只在 `capture=false`
  的全量路径启用，逐层快照仍走串行。
- `TRIT_SKIP_DIAG=1`：跳过两次 random 前向，`random_vs_f32` 写 `null`，STS 和
  `real_vs_f32` / `real_vs_reference` 不受影响。

实测（同一 L12 数据、同一二进制源码）：

| 运行 | 旧：1 线程 + 全诊断 | 新：24 线程 + 跳诊断 | 加速 |
|---|---:|---:|---:|
| 128 对 int5 | 约 10 分钟 | 17 s | 约 35× |
| 1379 对 int5 | 99 分 22 秒 | 171.7 s | 34.7× |
| 1379 对 int4 | — | 174.0 s | — |

加速不靠近似：每句的 12 层顺序、LayerNorm/softmax/GELU 的归约顺序都没变，只是把
不同句子分到不同线程；输出按原 batch 下标写回。验证结果：

- 128 对：f32 Pearson `0.9318602118665735`、int5 `0.9304698138104717`，与旧路径
  逐位相同；128 个 preds 的 `maxdiff=0`。
- 1379 对：f32 `0.8375945675304496 / 0.8308938533093636`、int5
  `0.8365400335581058 / 0.8305785821400108`，与旧路径逐位相同；1379 个 preds
  的 `maxdiff=0`。

默认不设 `TRIT_THREADS` 仍是 1 线程，不设 `TRIT_SKIP_DIAG` 仍输出 random 诊断，
所以 CI 与既有复现命令不受影响。24 线程的收益来自 24 个物理核；线程数超过 batch
时会被截到 batch。缓存 f32 后只跑量化前向的线程扩展：1/6/12/24 线程分别为
148.66 / 25.85 / 14.18 / 8.24 s（128 对 int5），24 线程仍有约 1.7× 于 12 线程。

### 3.16.7 f32 基线缓存：同模型同数据跨趟复用，量化 STS 逐位不变

第 3.16.6 的 24 线程已经把 1379 对压到约 173 s，但每趟仍重算一次 f32 real 前向；
f32 只服务 `f32_sts`、`real_vs_f32` 和 `f32_vs_reference`，同一模型 + 同一
`data_dir` + 同一 layers 下结果不变。新增 `TRIT_F32_CACHE=<json>`：

- 首次运行算 f32，并把 `f32_sts`（含 `TRIT_DUMP_PREDS=1` 的 preds）写入缓存；
- 后续命中直接复用，跳过 f32 Bert 加载和前向，只跑量化模型；
- 缓存键含 `schema=1/model/data_dir/hidden/batch/seq/layers/preds`，键不符不会误用；
- `activation=all` 或带 `--sidecar-svd` 时禁用缓存，因为这些路径依赖完整 `f32_out`；
- 命中时 `f32_vs_reference`、`real_vs_f32`、`random_vs_f32`、逐层对照写 `null`，
  量化模型的 STS 不受影响；f32 的 271 MB 输出不缓存。

实测（L12、int5、24 线程、跳诊断）：

| 运行 | 无缓存 | 缓存命中 | 加速 |
|---|---:|---:|---:|
| 128 对 | 16.3 s | 8.0 s | 2.0× |
| 1379 对 | 173.1 s | 88.6 s | 1.95× |
| 1379 对 int4 | — | 85.2 s | — |

缓存命中后的 f32/int5/int4 `f32_sts` 与 `modes.f32.sts`（含 preds）和未缓存跑
逐位相同：128 对 f32 `0.9318602118665735`、int5 `0.9304698138104717`；1379 对
f32 `0.8375945675304496 / 0.8308938533093636`、int5
`0.8365400335581058 / 0.8305785821400108`、int4
`0.8375051638742783 / 0.8320473843142945`。缓存读写用 `serde_json` 的
`float_roundtrip` 特性，否则 preds 会出现 1 ULP 的重解析差。

其他加速路线本轮没有落地，原因是实测或账算不划算：

- **多进程分片**：24 线程已经吃满 24 个物理核；把同一份总计算拆成 2 进程 × 12 线程
  只是把同样的活分到同样的核上，每个进程还要各复制一份模型和激活内存（本趟峰值
  5.5 GB），内存按分片数翻倍，同机会争抢带宽。更适合多机，不适合当前单机。
- **SIMD/BLAS**：只试了 `RUSTFLAGS=-C target-cpu=native` 的自动向量化，128 对 int5
  16.3 → 15.8 s（约 3%），preds 仍逐位相同；收益小且产物不再可移植。显式 AVX2/BLAS
  若改变 `f64` 归约顺序就不再逐位一致；只做“多输出行并行、每行仍顺序累加”又受
  内存带宽限制，没有继续投入。
- **GPU**：L12 int4 线性权重只有 10.6 MB，加 scale/bias 13.4 MB；一次前向的传输和
  调度开销大于可并行的计算量，不划算。

### 3.16.8 层 0 bias/scale 修正：旧预演 37% 是 padding 污染，端到端只是噪声

`feat/wsp-bias-scale` 在 L12 第 0 层 Q/K/V 上做了两个零字节修正：

- `TRIT_CALIB_BIAS=1`：用校准 token 的逐通道均值 `μ_i` 修量化后的输出偏差
  `c_r = Σ_i (w_{r,i} − \hat w_{r,i}) μ_i`，加进已有 f32 bias；
- `TRIT_CALIB_SCALE=1`：用对角 Hessian `h_i = Σ_t x_{t,i}^2` 重拟合每组 scale
  `s* = Σ h_i w_i q_i / Σ h_i q_i^2`，码字仍是 max-scale 的 `q`。

校准集是数据文件里按句均匀抽的 2,519 个非 padding token。旧层内预演（第 0 层 Q/K/V，
1,024 token、128 token eval、每矩阵 int4 96,768 B）报“层输出误差降 37–40%”，
但那个脚本每 172 行抽一个 token、**没有跳 padding**：176,512 行里只有 39,031 个有效
token，padding 行带共同偏移，全行均值 RMS 0.396，mask-aware 有效 token 只有 0.103。
用全行均值做 bias 修正会假降 37–40%；用 mask-aware 均值只有 0.4–0.8%
（query/key/value：0.69% / 0.42% / 0.79%，3-bit 0.76% / 0.85% / 0.81%）。
同一修正接到 `bert6` 全模型后：

| 数据 | 配置 | int3 Pearson / Spearman | int4 Pearson / Spearman |
|---|---|---|---|
| 128 对 | baseline | 0.897582 / 0.927222 | 0.928494 / 0.950720 |
| 128 对 | + bias + scale | 0.898726 / 0.929020 | 0.928612 / 0.951310 |
| 1379 对 | baseline | 0.818440 / 0.813362 | 0.837505 / 0.832047 |
| 1379 对 | + bias + scale | 0.818481 / 0.813555 | 0.837575 / 0.832149 |

全量增益：int3 `+0.000041 / +0.000193`，int4 `+0.000070 / +0.000102`。
128 对里 int3 的 `+0.0011` 是噪声，全量一跑就塌。对照全量 f32
`0.837595 / 0.830894`，**int4 的 Pearson 与 f32 只差 0.00009**，4-bit 已经在
统计噪声内；bias/scale 只能把 4-bit 拉回 f32，不可能超过。

原因不是实现错，而是两层口径错：一是旧预演把 padding 当校准 token，37% 是假信号；
二是 mask-aware 后 bias 项本身不到 1%，V 的常数偏移还会被下一层 LayerNorm/残差消掉，
Q/K 的 bias 主要改 attention logits 的常数/低秩项，softmax 对一部分平移不敏感；
而且只修了 12 层里的第 1 层。层输出误差范数不是 STS 的代理，这条在 §3.16.4 已经
出现过一次。

结论：M1 负结果，代码存为 `wsp-bias-scale.patch`，不进 PR；4-bit 不再做权重修正。
要继续压字节，BUDGET M1 已在严格同字节 `10,782,720 B` 上跑完：`v6e` Spearman
`0.813362→0.818137`（10k CI 下界 `+0.002017`），Pearson 仍跨 0；M1.1 的 `I10`
块交换把全量推到 `0.821621 / 0.818898`，相对纯 int3 两个 10k CI 下界都过 0。
M1.2 的 `K10K11` 再把 Q3/K4 的 int4 升级移到 K10/K11，全量 `0.823479 / 0.820549`，
相对纯 int3 `+0.005039 / +0.007187`，两个 10k CI 下界都过 0；对 I10 是薄优势
（50k Spearman 下界 `+0.000048`），对 v6e 的 Spearman CI 仍跨 0。
M1.3 用 `scripts/wsp_budget_perturb.py` 做了 72 块逐块 `3→2` 全量（每块 1,379 对），
按表把供体换成 F5/F7/V7，得到 `F5F7V7`：全量 `0.830384 / 0.828678`，相对
K10K11 `+0.006905 / +0.008129`，距 int4 缩到 `−0.007121 / −0.003369`。
它在 128 上反而低于 K10K11（`−0.006245 / −0.008888`），是 128 与全量符号相反的
直接反例。详见 `WSP-BUDGET-RESULTS.md` §8。它仍不是“3-bit 追平 int4”。
M1.4 再把 72 块逐个做 `3→4` 全量（45 双升 / 17 双降 / 10 混合），并用两张表
重排同字节候选：`R12`（6 int2 / 54 int3 / 12 int4，仍 `10,782,720 B`）
全量 `0.833671 / 0.835411`，相对 F5F7V7 `+0.003287 / +0.006733`；相对纯 int4
Pearson `−0.003834`、Spearman `+0.003364`，两个 50k CI 都跨 0。按 6 个来源拆开，
`R12` 对 int4 是 **0/6 胜**（MSRvid/headlines 各低 `−0.017`），总体 Spearman
反超更像跨来源排序/校准效应，不是逐来源都更好。`R12` 在 128 上仍低于 K10K11
（`−0.005378 / −0.007479`）；它是同一批 1,379 对上的 in-sample 搜索，没有
held-out。数据里 2,758 个句子 ID 全部唯一，按 pair 切分天然 sentence-disjoint，
但本轮还没做切分复验。下一步应做 leave-one-source-out / train-test 切分或第二
模型复验，而不是继续修 4-bit 的偏差或宣称“3-bit 超过 4-bit”。详见
`WSP-BUDGET-RESULTS.md` §9。

M1.5 做了三套外部复验：SICK-R、STS12、STS13 各前 1,000 对、同一 L12。
`R12`/`R10`/`F5F7V7` 在 SICK-R 负、在 STS12/13 正（R12 的 STS13
`+0.021556 / +0.017861`，双 10k CI 过 0）；`K10K11` 在 SICK-R/STS12 正、
STS13 轻微负（`−0.000308 / −0.000291`）。已测 6 个同字节配置里只有
`v6e`/`I10` 三套外部点估计全正，且 `I10` 只有 SICK-R 双 CI 过 0。所以
STS benchmark 上的 R12/K10K11 是 in-domain 选择，外部保守默认是 I10；
没有单一候选同时赢两边。三套都有句子跨 pair 复用（SICK-R 1,088、STS12
1,891、STS13 1,898 唯一句 / 各 1,000 对），不是 sentence-disjoint。详见
`WSP-BUDGET-RESULTS.md` §10。

### 3.16.9 第二模型 L6：位宽布局不能按层号搬

`all-MiniLM-L6-v2`（6 层/384 hidden）的全量 STS 1,379 对，f32 基线
`0.827406 / 0.820325`；纯 int3 `0.814594 / 0.810425`（`−0.012813 / −0.009900`），
纯 int4 `0.826061 / 0.819354`（`−0.001346 / −0.000971`）。L6 的 3-bit 绝对损失
比 L12 小（L12 是 `−0.019155 / −0.017532`），但模型内 Δ 才能比较，f32 绝对值
不可横向比。

把 L12 的 `I10`/`K10K11`/`R12` 按绝对层号投影到 L6、再按字节配平到
`1 int2 / 31 int3 / 4 int4`，三个都低于 L6 纯 int3（ΔS `−0.0011` 到
`−0.0033`）；按输出端对齐缩放的 R12 尾段（`3/30/3`）是 `−0.000702` ΔS，
10k CI `[−0.005731, +0.004212]` 跨 0，只是中性。L6 自己重扫 36 块得到的
`5 int2/26 int3/5 int4` 是 `0.828687 / 0.821084`，相对纯 int3
`+0.014093 / +0.010660`（双 10k CI 过 0），对纯 int4 点估计
`+0.002626 / +0.001731` 但两个 CI 都跨 0；两折 held-out 的 ΔS 为
`+0.009694 / +0.000707`，CI 都跨 0。新增 `scripts/wsp_budget_rescan.py`
后按“每形状组 2 降 2 升”选到 `6/24/6`，全量 `0.831304 / 0.824457`
（高于 int4 点估计），但两折 held-out 对 int3 CI 全跨 0、对 int4 点估计
转负；固定结构仍会过拟合。详见 `WSP-BUDGET-RESULTS.md` §11。

### 3.16.10 选择器的 5 折 × 2 种子交叉拟合

新增 `scripts/wsp_budget_cv.py`：每个 repeat 把 1,379 对切成 5 折，每折只用
其余 4 折的单块 ΔSpearman 选 `per_shape=2`，候选只在测试折计分，5 个测试折
拼成 OOF 向量。两个种子的 OOF 是 `0.827074 / 0.821085` 和
`0.824388 / 0.817272`，均值 `0.825731 / 0.819179`；相对纯 int3 均值
`+0.011137 / +0.008754`（10 折中 P 9/10、S 8/10 正），相对纯 int4 均值
`−0.000330 / −0.000175`（10 折中只有 5/10 正）。折级均值与 OOF 差小于
`0.0005`，不是拼接假象。**两折的 50% 训练让方差压过均值；5 折后选择器
procedure 稳定优于 int3，但只打平 int4。** 全量 `0.831304 / 0.824457`
仍是 in-sample 选块点估计，不能当泛化读数。详见
`WSP-BUDGET-RESULTS.md` §11.7。

### 3.16.11 跨模型相对深度规则：L12→L6 可用，L6→L12 对 int4 为负

`scripts/wsp_budget_rule.py` 只读源模型的逐块 ΔSpearman，把每个 `kind`
看成相对深度 `layer/(L-1)` 的折线，给目标模型插值选块；目标模型的块表
完全不读。L12→L6 选出 `6/24/6`，`0.828707 / 0.824484`，对纯 int3
`+0.014113 / +0.014060`（10k CI 都过 0），对纯 int4
`+0.002646 / +0.005131`（CI 都跨 0）；和 L6 自己的重扫候选同档。
反过来 L6→L12 选出 `6/60/6`，`0.827813 / 0.823365`，对纯 int3
`+0.009373 / +0.010004`（CI 过 0），对纯 int4
`−0.009692 / −0.008682`，Pearson CI `[−0.018357, −0.000968]` 整段为负。
**同一条规则两个方向不对称；它稳定优于 int3，但没有在任一方向统计上超过
int4，不能当跨模型默认。** 详见 `WSP-BUDGET-RESULTS.md` §11.9。

### 3.16.12 第三模型与同深度交叉检验：L12→L6 的正向是模型对特定

M1.10 把同一规则投到两个新模型：L3（`paraphrase-MiniLM-L3-v2`，3 层）和
par-L6（`paraphrase-MiniLM-L6-v2`，6 层、同架构、不同训练目标）。规则仍
只读源表和目标 base budget，不读目标块表。

- L3 上两条规则候选相对纯 int3 是 `−0.012450 / −0.010778`（L12 先验）和
  `−0.010801 / −0.013168`（L6 先验），10k CI 都整段为负。原因落到块上：
  两个方向都选了 `0o` 降 int2，而 L3 上 `0o→2` 是 `−0.006315 / −0.006519`，
  属于 layer 0 最伤的降级块；源表的排序在 L3 上整体反转。L3 的原生重扫
  k1 `3/12/3` 只打平 int3（`+0.000045 / +0.002787`，CI 都跨 0），k2
  `4/10/4` 的 Pearson 转负（`−0.004695`），说明 3 层模型没有同字节
  headroom；但原生 k2 仍比规则候选高 `0.006–0.008`（P）/`0.011–0.014`（S）。
- par-L6 上，L12 先验选出的块与 §11.9.1 完全相同（`6/24/6`），在
  all-MiniLM-L6 上是 `+0.014113 / +0.014060`（对 int3），在 par-L6 上是
  `−0.016161 / −0.007308`；L6 自己的最优 `6/24/6` 布局在 all-MiniLM-L6 上
  是 `+0.016710 / +0.014032`，投到 par-L6 是 `−0.011203 / −0.008646`。
  **同一布局、同一字节账、同为 6 层，Δ 双指标符号翻转。**

结论：L12→L6 的正向不能写成跨模型规则，只能当这对模型的候选生成器；
运行时默认仍是 `I10` 外部保守、`K10K11`/`R12` STS in-domain。边界是
par-L6 没有 36 块原生表，只能否定“布局可迁移”，不能说“par-L6 无 headroom”；
两套新模型都只跑 STS-B 1,379 对，pair-level bootstrap。详见
`WSP-BUDGET-RESULTS.md` §11.10。

### 3.16.13 检索任务头：STS 最优布局不转 SciFact

M1.11 按 §3.16.12 的方向先做检索头，不做分类头。数据集是 `mteb/scifact`
（corpus 5,183、queries 1,109、去重后 300 个 qrels query、共 6,292 条文本，
seq 64、mean pooling + L2），八档 embedding 由 `WSPEMB1` 落盘后做 query×corpus
余弦排序；指标是 MRR@10、Recall@10/100、nDCG@10/100，query-level 10k bootstrap。

- L12 `R12`（6/54/12，10,782,720 B）的 STS 对 int3 是
  `+0.015231 / +0.022050`，Spearman 对 int4 也高 `+0.003364`；但检索 MRR
  `0.482` 低于 int3 `0.497`、int4 `0.529`，nDCG@10 `0.526` 低于 `0.532`/
  `0.568`。对 int3 的 MRR/nDCG CI 都跨 0；对 int4/f32 的 MRR/nDCG CI 基本
  整段为负。Recall@100 `0.866` 比 int3 `0.843` 高，但低于 int4 `0.893`，
  CI 也跨 0。
- L6 `rescan-k2`（6/24/6，5,391,360 B）的 STS 对 int3 是
  `+0.016710 / +0.014032`，对 int4 是 `+0.005243 / +0.005103`；但检索 MRR
  `0.474` 显著低于 int3 `0.510`（10k CI `[−0.065, −0.008]`），nDCG@10
  `0.515` 显著低于 int3 `0.541`（CI `[−0.052, −0.001]`）。Recall@100
  `0.892` 点估计略高，但 CI 跨 0。

结论：**STS 相关性的块级增益没有转成检索增益；`R12`/`rescan-k2` 只能留在
STS in-domain，不能进检索任务头默认。** 机制上，STS 只看同一对句子的相对
分数，检索依赖 corpus 全体的绝对几何；本轮没有做几何诊断，所以这只是解释
假设，不是因果结论。边界是单检索集、300 query、seq 64、两个 MiniLM、无检索
微调、分类头未开始。详见 `WSP-BUDGET-RESULTS.md` §11.11。

### 3.16.14 分类任务头：STS 布局不转 SST-2

M1.12 按 §3.16.13 之后的分类方向做 SST-2：`SetFit/sst2` 6,920 train /
1,821 test，seq 64、mean pooling + L2，编码器冻结，只训练 logistic 线性
probe；`C` 由 train 内 5 折 `StratifiedKFold` 在 `{0.01,0.1,1,10}` 中选出，
test 只评一次，10k test-level paired bootstrap。

- L12 `R12`（6/54/12）accuracy `0.814937`，低于 int3 `0.823723`、int4
  `0.840198`；`R12−int3 = −0.008842`，CI `[−0.021417,+0.003844]` 跨 0；
  `R12−int4 = −0.025402`，CI `[−0.041735,−0.009336]` 整段为负。
- L6 `rescan-k2`（6/24/6）accuracy `0.802306`，对 int3 `−0.007209`
  CI `[−0.022515,+0.007688]`、对 int4 `−0.002220` CI
  `[−0.013180,+0.018122]`，两个 CI 都跨 0。
- 另一条不属于 BUDGET 布局的观察：L12 均匀 int4 比 f32 高 `+0.040088`
  （10k bootstrap CI 整段为正），int3 高 `+0.023613`；L6 上这些差值缩到
  不显著。它更像量化的正则化/表示变化，不能写成 `R12` 的增益。

结论：**STS 的块级增益没有转成 SST-2 分类增益；`R12`/`rescan-k2` 仍只能
留在 STS in-domain。** 边界是单数据集、单二分类任务、单线性 probe、无 encoder
微调、seq 64、两个 MiniLM；不能外推到所有分类/生成任务。f32 probe 直接迁移
到量化档会显著掉（L12 `−0.029` 到 `−0.062`，L6 `−0.051` 到 `−0.091`），
说明任务头比较必须重训 probe。详见 `WSP-BUDGET-RESULTS.md` §11.12。

### 3.16.15 第二种线性头复验：SVM 复现同一排序

M1.13 不改 SST-2 embedding/split，只把 §3.16.14 的 logistic probe 换成
平方 hinge `LinearSVC`，`C` 仍由 train 内 5 折选出，10k test-level paired
bootstrap。

- L12：`int4−f32 = +0.043783`（CI `[+0.025261,+0.062603]`），
  `int3−f32 = +0.020769`（CI `[+0.001098,+0.040088]`）；
  `R12−int3 = −0.004502`（CI `[−0.019220,+0.010434]`），
  `R12−int4 = −0.027516`（CI `[−0.042834,−0.012630]`）。
- L6：`int3−f32 = +0.006939`、`int4−f32 = +0.002492`、
  `rescan-k2−f32 = +0.000303`，三个 CI 都跨 0；档间两两 CI 也全跨 0。
- 与 logistic 对照：L12 `int4` 从 `0.840198` 升到 `0.841845`，f32 从

结论：**L12 均匀 int4 高于 f32 不是 logistic 损失特有；但 R12 仍不高于

SVM transfer `0.650–0.690`），说明线性边界方向变了；没有几何诊断，不能
因果化。边界同 §3.16.14，且没有 MLP（用户口径明确排除）、没有第二分类集。
详见 `WSP-BUDGET-RESULTS.md` §11.13。

### 3.16.16 第二分类集 CoLA：int4 正向没有跨数据集泛化

### 3.16.18 SST-2 子样本稳定性：L12 int4 的正向不是单次划分偶然

M1.16 固定 SST-2 官方 test（1,821 条），只在 train（6,920 条）上重复做
分层 5 折 × 5 个种子（seed 7–11），共 25 次重训；每次用 4/5 train
（5,536 条）训练、C 固定为全量 train 选出的值，在完整 test 上评一次。
这样只改变 probe 的训练样本，不改变 test，也不重新选 C。实现见
`scripts/wsp_classify_subsample.py`。

- L12 logreg `int4−f32`：全量 test `+0.040088`，25 次子样本均值
  `+0.042987`（sd `0.005372`，min `+0.028556`，max `+0.050522`），
  **25/25 为正**。
- L12 SVC `int4−f32`：全量 `+0.043932`，子样本均值 `+0.044437`
  （sd `0.004632`，min `+0.034596`，max `+0.052718`），**25/25 为正**。
- L12 `int3−f32`/`R12−f32`：两套 probe 也都 25/25 为正，均值
  `+0.020–0.025` / `+0.019–0.020`，幅度小于 int4。
- L6 logreg `int4−f32 = +0.006304`（min `−0.002746`，22/25 正），SVC
  `+0.003580`（min `−0.010983`，19/25 正）；`rescan-k2` 接近 0。

**结论：SST-2 上 L12 int4 对 f32 的优势在训练子样本上稳定，均值与官方
test 的 `+0.040/+0.044` 一致，不是某一次 train 划分的偶然。** 但 L6 只有
小幅且不稳定的正向，CoLA/hate 仍不复现；所以这是 L12 在 SST-2 这个任务/
分布上的稳定表示效应，不是量化普遍提升线性分类，也不是块级 `R12` 增益。
边界：C 固定自全量 train，只测训练样本变化，不测 C 选择或 test 重采样；
5 折训练集重叠，25 个差值不独立，正负计数只作描述；只做 SST-2、两个
MiniLM、两个线性头，无 MLP/encoder 微调。详见
`WSP-BUDGET-RESULTS.md` §11.16。

### 3.16.19 几何诊断：SST-2 的 int4 正向对应类别方向低秩集中

M1.17 不再加数据集，而是对同一批 embedding 做几何诊断和 PCA 干预。所有
`WSPEMB1` 行都是单位范数，样本范数这条先排除；SST-2 L12 的 f32 有效秩只有
`77.6`、两类质心余弦 `0.994`，int4 把有效秩提到 `200.1`、质心余弦压到
`0.943`，类均值差方向落在前 4 个主成分的比例从 `0.405` 提到 `0.855`
（test `0.422→0.821`）。CoLA/hate 的 `signal_top4` 基本不动
（`0.166→0.161`、`0.476→0.481`），有效秩还略降。

PCA 干预（train 拟合、test 只 transform；仍只训练 logistic 线性头）：
SST-2 L12 只保留 4 个主成分时 `int4−f32 = +0.166392`
（CI `[+0.138935,+0.194399]`，f32 `0.603`、int4 `0.769`），`keep16`
`+0.125755`、`keep64` `+0.081274`；白化后仍有 `+0.049423`
（CI `[+0.028556,+0.070291]`）。CoLA balanced（`keep4 −0.004794`、
`keep16 −0.008629`、`keep64 +0.010547`）的所有 mode CI 都跨 0；hate
除 L6 raw（`−0.014631`、CI 全负）外也都跨 0；
L6 SST-2 的 `keep4` 有 `+0.089511`，但 raw 只有 `+0.006590`、CI 跨 0。

**结论：SST-2 的 L12 int4 优势可以描述成数据集特异的“类别方向低秩集中”：
量化压平了 f32 的共同方向，同时把类别信号挤进少数主成分，线性头因此受益；
CoLA/hate 没有发生这件事。** 这不是样本范数，也不只是协方差谱（白化不消掉
差值）；但 PCA 是对固定 embedding 的线性干预，不是量化过程的因果消融。
边界：三个单句二分类集、两个 MiniLM、seq 64、一个 logreg、一个 seed；
CoLA 用 balanced + macro-F1，SST-2/hate 用无权重。详见
`WSP-BUDGET-RESULTS.md` §11.17。

### 3.16.20 跨档 PCA 子空间迁移：低秩基不足以复现 int4 增益

M1.18 给 `wsp_classify_pca.py` 加 `--pca-fit NAME`：PCA 在一档的 train 上
拟合，另一档的 train/test 投到同一组主成分，probe 仍各自重训。SST-2 L12
上，把 int4 的基搬到 f32 能救回一部分掉点（`keep4 0.603→0.694`、
`keep16 0.680→0.722`），但同维数下 int4 仍有 `0.769 / 0.806`，
`int4−f32` 从 raw `+0.040088` 扩到 `+0.075233 / +0.083470`；反方向把
int4 投到 f32 基，`keep4 +0.033498`、`keep8 +0.043932`、`keep64
+0.047776`，优势也没消失。CoLA/hate 两个方向的 `keepN` CI 基本跨 0，
只有 hate L12 `fit=f32 keep8 +0.009829`（CI `[+0.001463,+0.018288]`）
一个单点。

**结论：SST-2 的 int4 正向不能由“更好的低秩子空间”单独解释；低秩集中是
伴随读数，优势跟着 int4 自己的坐标/尺度走。** 这仍是固定 embedding 的
线性变换，不是量化算子消融。边界：三个单句二分类集、两个 MiniLM、
seq 64、一个 logreg、一个 seed；bootstrap 只算 accuracy，macro-F1 是点
估计。详见 `WSP-BUDGET-RESULTS.md` §11.18。

### 3.16.21 跨档类方向旋转：SST-2 的方向转了，CoLA/hate 没转

M1.19 不再看各自基里的 `signal_topK`，而是直接比较两档的类均值差方向
`d = mean(x|y=1) - mean(x|y=0)`：cos/夹角、范数比，以及 `d` 落在自己
和对方前 K 个主成分的能量占比。SST-2 L12 的 cos 只有 `0.5715`（test
`0.5891`），夹角 `55.1°`（test `53.9°`），`||d_int4||/||d_f32|| = 1.94`；
f32 的方向只有 `27.8%` 在 int4 前 4 个主成分里，int4 的方向只有 `7.2%`
在 f32 前 4 个主成分里。L6 同向但小一些（cos `0.620`、夹角 `51.7°`、
范数比 `1.54`）。CoLA/hate 的两档方向几乎同向：cos `0.970–0.976`，
夹角 `12.6–14.1°`，范数比 `0.91–0.98`，跨基 top4 与自基 top4 接近。

**结论：M1.18 的负迁移不能只归因于“基不够好”：基对齐了，方向没对齐；
M1.17 的 `signal_top4 0.855` 是 int4 自己旋转后方向的集中度，不是两档
共享的低秩类别子空间。** train/test 方向读数一致，但这是点估计、没有
CI；仍是观测性诊断，不是量化算子的因果消融。详见
`WSP-BUDGET-RESULTS.md` §11.19。

### 3.16.22 旋转对照与类可分性：方向角是症状，sep 只在 SST-2 L12 同向

M1.20 检查方向角本身是否足以解释精度。正交旋转是可逆线性变换，线性
probe 可以把边界原样转回去。`wsp_classify_rotate.py` 用 train 上的类均值
差方向估计 Householder 反射，把 f32 的类方向转到 int4 方向，test 只做
同一变换，probe 在旋转后的 train 上重训。SST-2 L12 的 f32 仍是
`0.800110`、`int4−f32` 仍是 `+0.040088`；L6 也逐位不变；把 int4 反向
转到 f32 方向同样不变。CoLA 只有 1 条 test 样本翻转（`±0.000952`），
hate 不变。**方向角可被线性 probe 吸收，不是独立机制。**

真正随 int4 变化的是 `sep = sqrt(between/within)`（Fisher 比值的平方根，
正交旋转下不变）：SST-2 L12 train `0.1547→0.1993`（`1.288×`）、test
`0.1691→0.2091`（`1.236×`），Fisher `1.659× / 1.529×`；L6
`1.126× / 1.073×`，Fisher `1.267× / 1.152×`；CoLA/hate 都在 1 附近。
SST-2 L12 的 `between_sq` 增 `3.757×`、`within_sq` 只增 `2.264×`，类间
信号跑得比类内散度快；CoLA/hate 两者基本同向变化，`sep` 不升。

**结论：M1.20 在 SST-2 L12 上看到“类可分性上升”，不是“类方向旋转”；
M1.17 的低秩集中、M1.18 的基迁移失败、M1.19 的方向夹角都是伴随读数。
但 M1.21 的剂量-反应显示 `sep` 不是跨数据集的普遍中介量（见 §3.16.23）。
** 旋转只改方向、保持范数，`sep` 还包含方向长度和类内散度，所以它只排除
“方向角”，不排除“长度/类内结构”。仍不是量化算子的因果拆解。边界：
三个单句二分类集、两个 MiniLM、seq 64、一个 logreg、一个 seed；`sep` 是
欧氏 Fisher-like 比值，不是完整协方差 LDA。详见
`WSP-BUDGET-RESULTS.md` §11.20。

### 3.16.23 量化误差剂量-反应：SST-2 L12 低剂量早饱和，sep 不是普遍中介量

M1.21 在 f32 和 int4 之间插值 `x(λ)=normalize(f32+λ(int4−f32))`，
`λ=0,1/16,1/8,1/4,1/2,3/4,1`，每个 λ 重训同一个线性 probe，并同步算
`sep`。SST-2 L12 的 `int4−f32` 在 1/16 剂量就是 `+0.0104`、1/8
`+0.0253`（约最终 `+0.0401` 的 63%）、1/4 `+0.0390`（约 97%）、1/2
`+0.0417`，全剂量 `+0.0401`；而 `sep` 到 1/8 只有 `1.068×`、到 1 才
`1.288×`。SST-2 L6 的精度峰值在 1/8（`+0.0198`），全剂量回落到
`+0.0066`，`sep` 到 1/2 才见顶。CoLA L12 的 `sep` 降到 `0.936×`，
accuracy 反升 `+0.0115`（CI 跨 0）；SVC 也升 `+0.0086`（CI 跨 0）。

**结论：SST-2 L12 的正向是低剂量、早饱和的表示效应，不是 `sep` 的连续
函数；`sep` 只是 SST-2 L12 的伴随读数，M1.20 的“类可分性解释”不能写成
跨数据集中介量。** 仍不是量化算子的因果拆解：插值路径每个 λ 是固定
非线性映射，probe 重训、C 重选；没有 train-only/test-only 噪声对照或
f32/int4 交叉迁移矩阵。详见 `WSP-BUDGET-RESULTS.md` §11.21。


## 4. 未证栏

- 基础对齐与逐层快照只有 8 句、`8×64` token；STS 读数另有 128 对与 1379 对两档，但都不是
  训练/检索任务。
- 只三值化线性权重；LN/GELU/softmax/残差保持 f32。全三值激活已做 `ternary-all`，
   cosine 只有 0.03（见 §3.5）；没有 QAT、学习式 scale；逐层混合精度只测了「整层保 f32」
  （§3.16.2），没有测层内混合位宽；层 0 Q/K/V 的 bias/scale 修正测了，端到端为负结果
  （§3.16.8）。
- absmean / GPTQ / per-group / 均匀 int3–8 / SVD 残差侧车都测过；侧车和均匀位宽都只在
  `examples/bert6` 的前向里验证，
  **没有进 WSP/TTX 容器，也没有导出/加载路径**，因此上面的字节数是估算不是落地格式。
- 检索任务头已做（§3.16.13）：SciFact 上 `R12`/L6 `rescan-k2` 的 STS 增益没有
  转到检索。分类任务头也已做：SST-2 线性 probe（§3.16.14）没有转成分类增益，
  第二种线性头 `LinearSVC`（§3.16.15）复现了同一排序但同样不是 `R12` 的增益；
  第二分类集 CoLA（§3.16.16）没有复现 L12 均匀 int4 对 f32 的正向
  （logreg `+0.013341`、SVC `+0.008467`，CI 都跨 0），第三分类集 hate
  （§3.16.17）也没有复现。§3.16.19 的几何/PCA 诊断把这层差异描述成
  “SST-2 类别方向低秩集中”，§3.16.20 又把 int4 的 PCA 基搬到 f32：
  能救回 f32 的部分掉点，但没有复现 int4 的优势，说明低秩基不是充分条件；
  §3.16.21 进一步定位到两档类均值方向本身旋转（SST-2 cos `0.571`，
  CoLA/hate `0.97+`），而不是同一方向在另一组基里的坐标变化；但
  §3.16.22 的旋转对照表明方向角可被线性 probe 吸收，`sep` 只在 SST-2
  L12 上和精度同向；§3.16.23 的剂量-反应再显示 SST-2 L12 在 1/8 剂量
  已拿到约 63% 的最终增益、1/4 约 97%，而 `sep` 到 1 才 `1.288×`；L6
  精度峰值早于 `sep`，CoLA `sep` 降而精度升。因此 `sep` 只是 SST-2 L12
  的伴随读数，不是跨数据集的普遍中介量。这一串都是观测性干预，不是
  量化过程的因果证明；仍不能写成量化普遍提升分类。`cosine` 与 Pearson
  仍不能直接换算成分类/生成任务掉点。
- BUDGET 的 `R12` 只在同一批 STS 1,379 对上选块并评测，没有 held-out、
  sentence-disjoint 或第二模型；外部三套里 R12/R10/F5F7V7 在 SICK-R 负、
  STS12/13 正，K10K11 在 STS13 轻微负，只有 v6e/I10 三套外部点估计全正
  （I10 仅 SICK-R 双 CI 过 0）。不能把 R12 的 STS 点估计当留出验证或
  “3-bit 超过 4-bit”的证据；三套外部都有句子跨 pair 复用，也只有一个模型。
- 跨模型相对深度规则已在 L12/L6 双向、第三模型 L3 和同深度 par-L6 上测过
  （§3.16.11/§3.16.12）：L12→L6 的正向在 L3/par-L6 上都翻负，不能当通用规则；
  L3 的 3 层原生重扫只打平 int3，par-L6 没有 36 块原生表，不能反推“par-L6
  无 headroom”。
- GELU 用 erf 近似；f32 对齐 6e-7，但严格逐位复现仍需与 PyTorch 用同一近似。
- 只从第 0 层输入开始；embedding/tokenizer 不在 Rust 侧。

## 5. 接口

- `examples/export_bert6.py`：导出 input/mask/reference/layer0..5；
- `crates/trit-wspace/src/activations.rs`：`read_matrix`（`WSPACT1`）/
  `read_mask`（`WSPMSK1`）；
- `crates/trit-wspace/src/residual.rs`：`LowRankResidual`（`R = W − s·T` 的 top-r SVD，
  `build` / `set_rank` / `projections` / `correction`），`tests/residual.rs` 守满秩重构、
  截断单调与宽/高两种取向；
- `examples/bert6/`：`main.rs` 入口；`run/main_flow.rs` 主流程、`run/f32_base.rs` f32 基线缓存、
  `run/modes.rs` 激活模式、
  `run/sidecar_svd.rs` 侧车 rank 扫描、`run/weight_format.rs` 字节账、`model/` 前向与加载、
  `linear/` f32 / 三值 / 均匀位宽线性层；`sts/metrics.rs` 指标与逐对预测；输出
  `f32_vs_reference` / `real_ternary_vs_f32` / `random_ternary_vs_f32` / `output_stage` /
  `sidecar_svd` / `weight_format` 统计。`tests/gptq_bits.rs` 守均匀位宽 GPTQ 的码值域与
  H 误差下降。
- CLI：`--activation-mode f32 --gptq-group 32 --sidecar-svd 0,16,32,64,128`。
- 实验环境变量：`TRIT_WEIGHT_BITS=2..8`（2 = 三值，3..8 = 均匀对称）、
  `TRIT_UNIFORM_GPTQ=1`（均匀位宽走 GPTQ，需数据目录有 `gptq/`）、
  `TRIT_F32_LAYERS=0,5`（整层保 f32）、`TRIT_LAYERS=6|12`（模型层数）、
  `TRIT_DUMP_PREDS=1`（在 STS 结果里附逐对余弦，供留出集/bootstrap 用）、
  `TRIT_THREADS=24|auto`（全量按句并行，逐位一致）、
  `TRIT_SKIP_DIAG=1`（跳过 random 诊断前向，`random_vs_f32` 记 null）、
  `TRIT_F32_CACHE=<json>`（跨趟复用同模型同数据的 f32 `f32_sts`，量化 STS 逐位不变）。
- 12 层数据必须用 L12 自己的 embedding 重导第 0 层；`export_bert6.py` 支持
  `TRIT_MODEL_ID=sentence-transformers/all-MiniLM-L12-v2`。本轮的 L12 第 0 层由
  同一 tokenizer/embedding 公式离线重算，并用 L6 的 `input.f32` 对照，`rel_l2` 8.6e-8。
