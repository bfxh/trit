# WSP-MXQ：字节预算内的层内混合位宽

> 状态：**计划草案，未落地**。本文只有层内重建误差预演，没有 STS 读数，不能当能力结论。
> 目标是把现有 `bert6` 的“整张矩阵一个位宽”推进到“每个 32 列 group 一个位宽”，
> 在**总字节不变**的前提下降低量化误差，再用端到端 STS 验收。
>
> 后续排序见 `WSP-ALT.md`：同字节 BIAS/SCALE 的 M1 已跑完 128/1379 对，
> **端到端仅 +0.00004~+0.00007 Pearson，负结果**；MXQ 的层内 −26~30% 同样不能直接
> 当 STS 结论，验收必须换端到端。MXQ 在新排序里降为内层分配器，不再建议第一枪。

## 1. 一句话

现有量化只有全矩阵同位宽；WSP-MXQ 把位宽当成**字节预算下的离散资源**，
用真实激活的 Hessian 对角权重做率失真分配：大部分 group 保持 4-bit，
高敏感 group 升到 5-bit，低敏感 group 降到 3-bit，总字节与 int4 基线完全相同。

## 2. 现状与缺口

当前 `bert6` 已有的量化能力：

- `TRIT_WEIGHT_BITS=2..8`：全矩阵统一的对称 per-group 位宽；
- `TRIT_F32_LAYERS`：整层回退 f32；
- `TRIT_UNIFORM_GPTQ=1`：整矩阵 GPTQ；
- SVD 残差侧车：给全矩阵加低秩 f32 修正；
- 字节账：线性权重 + per-group f32 scale + f32 bias。

明确没做的：

- **层内混合位宽**：没有“同一张矩阵里不同 group 用不同位宽”；
- 没有按敏感度分配字节的求解器；
- 没有把位宽图作为可审计工件（WSP patch / journal）保存。

这就是缺口。继续扫 group size、换 GPTQ、整层 f32 都还在“一个矩阵一个位宽”的框里；
WSP-MXQ 换的是**分配粒度**，不是再调一个超参。

## 3. 方案

### 3.1 表示

一张 `rows × cols` 的线性权重，按 `g=32` 列切 group。每个 group 独立选择
`b ∈ {3,4,5}`（MVP 集合）：

- 码值：`q_i = clamp(round(w_i / s0), -Q_b, Q_b)`，`Q_b = 2^(b-1)-1`；
- scale：每个 group 一个 f32，先按 `s0 = max|w| / Q_b` 取初值，再做一次**加权最小二乘重拟合**
  `s* = Σ h_i w_i q_i / Σ h_i q_i^2`；
- 反量化：`ŵ_i = s* q_i`；
- bias、LayerNorm、GELU、softmax、残差都保持 f32，不改现有前向。

`h_i` 是该层输入第 `i` 个通道的真实激活平方和：`h_i = Σ_t x_{t,i}^2`。
它是对角 Hessian，衡量“这个通道上的权重误差会不会被真实输入放大”。

### 3.2 每个候选的代价与误差

对 group `(r, g)`、位宽 `b`：

```text
c(b) = ceil(g*b/8) + 4 + 1          # 码值字节 + f32 scale + 1 字节位宽标记
e(r,g,b) = Σ_i h_i (w_i - s* q_i)^2
```

`c(3)=17 B`、`c(4)=21 B`、`c(5)=25 B`（g=32）。int4 基线总预算
`B = G × c(4)`，`G` 是整模型 group 数；把 scale 和位宽标记都算进去，避免“省了码值、
被元数据吃回去”。

### 3.3 分配

独立 group 下这是一个可分离的率失真问题：

```text
min  Σ e(r,g,b)
s.t. Σ c(b) ≤ B
```

用拉格朗日乘子：

```text
b*(λ) = argmin_b [ e(r,g,b) + λ c(b) ]
```

对 `λ` 二分，使总字节落在预算内；剩余字节按“每多 1 B 能降多少误差”贪心补齐。
`λ` 固定、按 `(row, group)` 字典序打破平局，保证同输入同分配。

**为什么是 3/4/5**：预算等于全 4-bit 时，把一个 group 升到 5-bit 要多 4 B，
必须把另一个 group 降到 3-bit 才能补回来。所以它是“3/4/5 跷跷板”：
用低敏感 group 的 1 bit 换高敏感 group 的 1 bit。预演里把候选从 3/4/5 扩到 2..8，
三张矩阵只多拿 0.6–1.7 个百分点的误差下降，MVP 不值得为它们加打包复杂度。

### 3.4 运行时

M1 先走“反量化回 f32”的实验路径：加载时按位宽图把每个 group 反量化成 `F32Linear`，
前向与现有 int4 路径相同，**不增加每 token 分支**；字节账单独算。

M3 再做真正的打包格式（`WSPQ1`）：

```text
magic | rows | cols | group | bits[G] | scales[G] | packed codes
```

位宽图 1 B/group，scale 4 B/group，码值按 group 内 `b` 位打包。先保证字节账精确，
再谈随机读/mmap。

## 4. 预演：同字节重建误差

数据：L12 第 0 层真实输入（`miniLM-l12-sts-full/input.f32`），均匀抽样 1024 个 token；
只算 `encoder.layer.0.attention.self.{query,key,value}.weight` 的线性投影误差；
`g=32`，`h_i` 为输入平方和，bias 不计，字节含 scale 与 1 B 位宽标记。

每个 384×384 矩阵的 int4 预算为 **96,768 B**（4,608 个 group × 21 B）。
下表所有 mixed 都在同一预算内：

| 矩阵 | int4 max-scale | mixed 3/4/5 max-scale | int4 重拟合 scale | mixed 3/4/5 重拟合 scale | mixed 重拟合 vs 当前 int4 |
|---|---:|---:|---:|---:|---:|
| query | 3.581e3 | 2.139e3（−40.3%） | 2.403e3 | 1.785e3（−25.7% vs 重拟合） | **−50.2%** |
| key | 3.565e3 | 1.985e3（−44.3%） | 2.317e3 | 1.626e3（−29.8% vs 重拟合） | **−54.4%** |
| value | 8.284e2 | 4.823e2（−41.8%） | 5.387e2 | 3.985e2（−26.0% vs 重拟合） | **−51.9%** |

query 的 3/4/5 直方图为 `3-bit: 573 groups, 4-bit: 3,462, 5-bit: 573`（重拟合）；
max-scale 下是 `658 / 3,292 / 658`。几乎正好是 12.5% / 75% / 12.5%，
因为每升一个 5-bit 就要降一个 3-bit。

两个对照：

- **只换 scale、不换位宽**：重拟合把 query 误差从 3.581e3 降到 2.403e3（−32.9%），
  说明 scale 重拟合本身也是免费收益；它应该是 WSP-MXQ 的 Stage 0，不是对照外的变量。
- **全 5-bit**：同一矩阵 115,200 B（+19%），query 误差 7.968e2（max-scale）/ 5.323e2
  （重拟合）。mixed 在 int4 字节下打不过“全 5-bit 多给 19% 字节”，这是预期；
  mixed 的目标是**同字节赢 int4**，不是替代 5-bit。

同一层 `query` 如果按**行**分配而不是按 32 列 group 分配，同预算只降 3.7%
（2.315e3 vs 2.403e3，重拟合尺度；max-scale 下也只降 6.5%）。这就是选 group 粒度
而不是 row 的直接原因：行内 384 列里敏感度差异很大，按行会被平均掉。

预演脚本：`mixed_preflight_groups.py`（group 级，主预演）、`mixed_options.py`
（3/4/5 与 2..8 的候选集消融）、`mixed_preflight.py`（行级对照）。
脚本只读本地 L12 权重与第 0 层输入，不依赖 numpy；是重建误差，不是 STS。

## 5. 为什么可能有效，为什么可能失败

**可能有效**：

- 量化误差在线性层里按输出通道传播；用真实输入 Hessian 加权，能优先保护“真的会被
  大激活打到”的通道；
- 同字节下 group 级混合比全矩阵 4-bit 多一个自由度，且没有增加 f32 侧车字节；
- 预演里三张注意力矩阵都稳定降 40–44%，不是单张矩阵的偶然；
- 全部是离线分配，运行时仍是同一条 GEMV，速度不变。

**可能失败**：

- 层内重建误差和 STS 不同向。项目已经踩过：int4 GPTQ 把 `rel_l2` 从 0.2750 压到
  0.2271，Pearson 只涨 0.000068，仍低 f32 0.00128（`WSP-BERT6-RESULTS.md` §3.16）。
  所以预演好不等于 STS 好，必须端到端验收；
- `h_i` 只取对角，忽略通道间相关；如果敏感通道强相关，分配会偏；
- 位宽图和每 group scale 的元数据可能吃掉收益；预演已把 5 B/group 算进去，但真实打包
  还有对齐/容器开销；
- 3-bit group 可能引入离群误差，层内误差均值降了、尾部反而变差；STS 是句子级，
  可能被少数句子拖垮；
- 用第 0 层输入做校准，深层输入分布不同；必须逐层收集，不能一套 `h` 用到底。

## 6. 实验设计

### 6.1 预注册判据

先定判据，避免看完数字再改口。

- **M1（128 对，L12）**：mixed 与 int4 同总字节；Pearson 不得低于 int4 超过 0.002，
  否则直接停；若不低于，进入 M2。
- **M2（1379 对，主判据）**：同总字节（含 scale、位宽标记、bias），
  Pearson 和 Spearman 都不低于 int4，且至少一个指标的 10k 配对 bootstrap
  95% CI 下界 > 0；做不到就只记“方向性/负结果”，不写成稳定提升。
- **Pareto 备选**：如果同字节只打平，但能省 ≥10% 总字节且质量 CI 下界
  不低于 −0.002，算“同质量省字节”，也值得落地。
- 128 对只做 smoke，不拿 128 的 +0.001 当结论；主判据只看全量 1379 和 1251 留出。

### 6.2 消融

| 消融 | 问题 |
|---|---|
| max-scale vs 重拟合 scale | 收益有多少来自 scale，多少来自位宽分配 |
| 3/4/5 vs 2..8 | 多出的 2/6/7/8 bit 值不值得打包复杂度 |
| group 16/32/64/128 | group 越小分配越细，元数据越贵；32 是现有 int4 的基线 |
| 对角 Hessian vs 均匀 h | 真实激活加权是不是真的有用 |
| 逐层 h vs 第 0 层 h | 深层分布是否必须单独校准 |
| RTN vs GPTQ 基底 | GPTQ 已经补偿过误差，混合分配是否还叠加 |
| L6 vs L12 | 容量更大的模型是否同样受益 |
| 行级 vs group 级 | 预演已显示行级差；全模型是否一致 |

### 6.3 计算与数据

- 校准：对每层收集 f32 前向的输入（`X`），算 `h_i = Σ_t x_i^2`；不读 STS 标签，
  避免标签泄漏；句子划分上尽量让校准句与评测对不重叠，至少做一次 sentence-disjoint
  复验。
- 分配：每层 group 数 = `rows × ceil(cols/32)`；L12 的 384×384 矩阵是 4,608 group，
  FFN 的 1536×384 是 18,432 group。`3` 个候选 × 每 group 32 列，单层毫秒到秒级；
  全模型离线一次。
- 评测：复用现有 `TRIT_THREADS=24`、`TRIT_SKIP_DIAG=1`、`TRIT_F32_CACHE`；
  L12 1379 对热缓存约 89 s，适合多轮消融。
- 字节账：必须同时报“线性权重字节”“含 scale/元数据字节”“含 bias 总字节”，
  并与 int4 g32 的 13,436,928 B 对齐。

## 7. 实施拆解

### M0：预演（已完成，未进仓）

- `mixed_preflight_groups.py`：读 safetensors + `WSPACT1`，纯 Python，验证分配器与
  同字节重建误差；
- `mixed_options.py`：3/4/5 与 2..8 的候选集消融。

### M1：原型（2–3 天）

1. `linear/uniform/mixed.rs`（或 `mixed/{quant,alloc,report}.rs`，按 800 行预算拆）：
   - `Candidate`：每个 group 的 b、scale、codes、误差；
   - `allocate`：拉格朗日 + 贪心补齐，输出位宽图；
   - `dequantize`：按位宽图反量化成 `F32Linear`，前向不变。
2. `run/main_flow.rs` / `model/config/opts`：新增开关
   - `TRIT_MIXED_BITS=3,4,5`（MVP 固定即可）；
   - `TRIT_MIXED_BUDGET=int4|<bytes>`；
   - `TRIT_MIXED_CALIB=<dir>`（逐层激活/`h` 缓存）。
3. `run/mixed_report.rs`：输出
   - `bits_histogram`、`bytes{linear,scale,meta,total}`、`err_proxy`、`per_layer`；
   - 不把 `err_proxy` 当成 STS 结论。
4. `tests/mixed_bits.rs`：
   - 预算恰好不超；位宽直方图与字节账可复算；
   - 同输入同分配（确定性）；
   - 每个 group 的 `Q_b` 边界、零权重 scale 不为 NaN；
   - 候选误差随 b 增大单调不增（浮点允许 1 ULP，不做逐位）。
5. 128 对 smoke；只跑 L12 query/key/value 先验证。

### M2：全量与消融（2–3 天）

- 1379 对 + 1251 留出 + bootstrap；
- 与 int4 g32、int5 g32、f32 三基线；
- 按 §6.2 消融，至少完成 scale 重拟合、group size、逐层 h 三项；
- 负结果也写进 `docs/results/LESSONS.md`。

### M3：打包与工件（可选，3–5 天）

- `WSPQ1` 容器：位宽图 + scale + packed codes；
- 将位宽图作为 WSP patch 工件：改一个 group 的位宽 → patch/journal/audit，
  字节可精确回滚；
- 这一步才真正省内存；M1/M2 只证明质量和字节账。

## 8. 与现有路线的关系

- **不是替代 GPTQ**：GPTQ 改码值，WSP-MXQ 改位宽分配；两者可叠加，也可分开做消融。
- **不是替代 sidecar**：sidecar 是全矩阵低秩 f32 修正；WSP-MXQ 是码值位宽分配，
  侧车字节另算。若两者同时开，必须把侧车字节纳入总预算，否则不是同字节比较。
- **不是整层 f32 回退**：层 f32 是 0/1 决策，WSP-MXQ 是 group 级 3/4/5；
  预演显示 group 粒度更细，但全模型仍需对照。
- **不是“只有我们才有”的新原理**：混合精度量化在公开文献里有很长的历史；
  本文不宣称首次。项目-specific 的是：
  同字节预算、真实激活 Hessian、现有 STS 数据/字节账、以及后续 WSP patch 审计闭环。

### 8.1 备选路线比较

| 路线 | 预演/现状 | 判断 |
|---|---|---|
| 仅 scale 重拟合 | 同字节 query 误差 −32.9%，不增字节 | 保留为 MXQ 的 Stage 0；单独做上限太低 |
| 行级混合位宽 | 同字节 query 只降 3.7%（重拟合）/6.5%（max） | 不如 32 列 group，放弃 |
| 低秩/列侧车 | 现有 SVD/列侧车已验证；小 rank 在 STS 上无提升 | 不是新路线，且 f32 侧车字节贵 |
| Hadamard/AWQ 旋转 | 可打散 outlier；但要在运行时改激活，破坏现有归约顺序，收益未证 | 作为第二阶段候选，不进 MVP |
| RVQ/码本量化 | 2–3 bit 的潜在上限更高；但码本训练、存储、查表解码都更重 | 长期候选，复杂度高于 MXQ |
| 激活量化 | 是另一个产品边界；会动 LN/GELU/softmax 之外的数值路径 | 不与本方案混做 |
| WSP patch 修复 | 可在分配后修 top 误差 group；复用 patch/journal/audit | 作为 M3 可选，不是主分配器 |

选择 MXQ 的理由：它填的是仓库已经写明的“层内混合位宽”缺口；预演收益最大且
不改变运行时前向；失败也能得到可解释的负结果，不会把 QAT/码本训练的成本拖进来。

## 9. 边界

- 预演只覆盖 L12 第 0 层 Q/K/V，1024 个 token，**不是全模型，也不是 STS**；
- 预演用对角 Hessian，不含 attention softmax、LayerNorm、残差和后续层传播；
- 预演只做 max-scale 与一次重拟合，不是 GPTQ；
- 字节数只算线性权重 + scale + 位宽标记，不含容器对齐/打包开销；
- 没有证明 3/4/5 在 L6、L12 全量、留出集上都有效；
- 没有证明 packed GEMV 的速度；M1 仍反量化成 f32，速度应与 int4 相同；
- 没有做公开文献逐篇核对；混合精度不是新原理，落地前应补一次相关论文对照。

## 10. 建议

先做 M1，不直接上打包：

1. 固定 `g=32`、候选 `{3,4,5}`、预算等于 int4 g32；
2. 用 L12 第 0 层 Q/K/V 的预演分配器接进 `bert6`，128 对 smoke；
3. 128 对不崩，再跑 1379 对 + 留出 + bootstrap；
4. 全量同字节没有稳定收益就停，把负结果写进 LESSONS；
5. 有稳定收益再考虑 `WSPQ1` 打包和 WSP patch 审计。

按预演的 40–44% 重建误差下降，M1 值得一试；但项目已经证明“重建误差不等于 STS”，
所以第一道门必须是端到端的 128 对，而不是继续优化层内误差。
