# 模型侧红队：真实开源模型三值工件的比特翻转攻击读数（2026-11-14）

攻击对象是**本仓自己的三进制软件栈**（授权红队，同 `docs/WSP-REDTEAM-STACK.md`）。
这一次的目标不是解析器，而是**三值化之后的开源模型工件本身**：攻击者能改写工件
（供应链投毒/共享目录），想知道「翻多少 trit 能打坏模型」以及「聪明攻击者比随机
攻击强多少」。

## 1. 目标与口径

- **目标模型**：`EleutherAI/pythia-70m`（GPT-NeoX 架构，F16 safetensors），
  取 6 层 MLP 链 `dense_h_to_4h`(512→2048) → `dense_4h_to_h`(2048→512)，
  共 **12 层 12,582,912 个 trit**。absmean 三值化（`Layer::from_f32`），
  f32 bias 直读。
- **攻击原语**：库自己的编辑原语 `Edit::SetTrit` + `Patch`（攻击者用工件编辑
  API，与正常用户同一入口——这也是威胁模型的一部分：编辑原语无身份校验）。
- **度量**：攻击后输出 vs 干净三值输出的余弦与相对 L2（口径同 #447；
  输入 `uniform(-1,1)` 128 组，每档 10 次重复取中位数）。任务级精度不在
  本读数内（Pythia 无分类头）。
- **复算**：
  ```bash
  cargo run --release -p trit-wspace --example redteam_flip -- \
    --file pythia-70m.safetensors --inputs 128 --trials 10
  ```

|---:|---:|---:|---:|
| 1 | 6.8e-6 | 3.9e-5 | 5.7× |

## 3. 判读

1. **三值网络对稀疏比特翻转异常鲁棒**：翻 1 万个 trit（占 0.08%）输出余弦仍
   0.9999。原因与 #447 的量化基线一致：absmean scale 把大权重行的破坏摊薄，
   符号激活饱和吞掉小扰动；单 trit 的 |scale·t| 贡献太小。
2. **聪明攻击者的优势随 k 递减**：小 k（≤100）时按行方差挑点比随机强 2.6-5.7×；
   k 大之后随机撒满全网络，行级信息量摊薄（0.8×）。想继续放大优势需要
   `analyze` 级别的逐点实测（成本 1 次前向/trit，1.26 千万 trit 不可行）——
   **攻击者的经济学在 trit 级定位上，而不在翻转本身**。
3. **对防篡改的含义**：既然 k≥1000 才有可测行为偏移（rel-L2 ~0.4%），而
   容器 FNV 校验和对**任意 1 bit** 修改 100% 检出（`tests/wsp2.rs`
   `rejects_checksum_tamper`）、审计哈希链对**任何插入/篡改**重放即断——
   防篡改的覆盖面远大于攻击的有效面。剩余风险是「攻击者重算校验和 +
   重建审计链」（需要写权限 + 完整重放能力），见下节边界。

## 4. 边界（未证栏）

- 随机 `uniform(-1,1)` 输入，非真实激活（同 #447 口径）；无任务精度读数
  （Pythia 无分类头；接 MMLU/困惑度需要完整 transformer 前向，超出本 crate
  的 MLP-only 边界）。
- 「智能攻击」是行方差代理，不是 `analyze` 实测定位（成本论证见 §3.2）；
  梯度级攻击（STE 打分器反向传播到 trit）未做。
- 只测了 MLP 链；attention QKV/dense 的三值化与攻击未做（QKV 是融合头，
  需要按 head 拆分才能链式化）。
- 只测 Pythia-70M 一个模型；更大的模型/不同量化口径（#460 的 6 层级联读数
  是 MiniLM）未做。
- 检测与恢复：容器校验和/审计链能**检出**，但「检出之后如何恢复」只有
  Journal 回滚（编辑会话内）；工件级备份/恢复流程未测。
