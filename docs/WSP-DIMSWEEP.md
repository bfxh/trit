# 降维运行扫描（dimsweep）：一段思考要多少维度、多少步

## 目标

「有些思考过程没必要」，这句话要能算。本文件把三件事量成曲线，判据仍是 `editset_gate`
的双集合：**edit 全对且 keep 全对**才算过。

- **宽度**：384 维输入投影到前 k 个方向，降维学生是 `Layer::new(rows, k)` + 原读出层。
- **步数**：k 维学生上跑带 `keep` 约束的 `repair`，看预算够不够补回来。
- **必要性**：最大子空间上逐维剔除，报每一维的边际违规增量。

## 方法

协议与 `editset_gate` 一致：输入是真实 `embeddings.word_embeddings.weight` 的行（384 维，
absmean 三值化）；教师是 f32 `query` 行与 f32 读出向量的点积取符号；学生是三值 `query` 层
+ 三值读出层。edit 集 = 学生判错的样本，keep 集 = 判对的样本。

降维的两条路径必须分开看，否则会误判：

| 路径 | 做了什么 | 只含哪种损失 |
|---|---|---|
| 三值 | 投影 + absmean 三值化 | 投影 + 量化 |
| f32 对照 | 只看投影，不三值化 | 只有投影 |

输入不中心化：`absmean` 本来就不去均值，且这样降维层不需要常数偏置项
（`w·x ≈ (Uᵀw)·(Uᵀx)`），三值偏置不会吃掉一个 f32 常数。

基有两种（`--basis`）：

- `pca`（默认）：真实词向量二阶矩的主方向，方差降序。
- `supervised`：判据方向打头，其余用与它正交的 PCA 方向补齐。

主方向用 **Jacobi 全分解**求（384×384，12 轮 sweep）。不用幂迭代：这个谱的特征值比接近 1，
一次 Gram–Schmidt 给不出严格正交基，会把伪影混进曲线。

## 读数：监督基（判据方向）——k=1 就够

判据是线性的：`readout · (query·x) = w_eff · x`，其中 `w_eff = queryᵀ readout`。
`--basis supervised` 直接把 `w_eff` 放在第 0 维，其余用与它正交的 PCA 方向补齐。

| k | trit edit/keep | f32 edit/keep |
|---:|---|---|
| 128 | 0.438 / 0.645 | 1.000 / 1.000 |
| 64 | 0.469 / 0.695 | 1.000 / 1.000 |
| 32 | 0.625 / 0.664 | 1.000 / 1.000 |
| 16 | 0.469 / 0.707 | 1.000 / 1.000 |
| 8 | 0.531 / 0.656 | 1.000 / 1.000 |
| 2 | 0.688 / 0.754 | 1.000 / 1.000 |
| **1** | **1.000 / 1.000** | **1.000 / 1.000** |

`minimum = {k: 1, max_edits: 0, beam_width: 0}`：**一维、零搜索、零违规**。

三条读出来的事实：

1. **判据方向与方差第一主方向几乎正交**：`criterion_cos_pca1 = 0.0086`。这就是 PCA 基
   全盘失败的根因——承载判据的方向在方差上看几乎为零。
2. **k>1 反而更差**（k=2 掉到 0.688/0.754，k=16 掉到 0.469/0.707）：多出来的方向是干扰，
   混进 `sign` 判决后破坏 k=1 的完美映射。这是「加维不是加信息」最干净的一个例子。
3. **必要性排序第一次有了意义**：组件 0（判据方向）Δ=+58，压倒性最必要；最不必要的是
   10(−15)、8(−13)、14(−11)、15(−10)、117(−8)——去掉它们违规反而更少。

**9/9 全中，不是特例。** 机制是结构性的，不是数值巧合：

1. 判据线性：`readout · (query·x) = w_eff · x`，投影到 `w_eff` 单方向保留 100% 判据信息。

所以「PCA 排序找不到判据方向」也是通则，不是某一行碰巧。

## 读数四：零违规 ≠ 保真（`agree_full`）

`agree_full` = 降维学生与**全维三值学生**在全部 2048 个样本上的一致率。必须在全量上算：
edit/keep 两个子集正是按「与教师是否一致」挑出来的，在那上面算会得到 0/1 的假象。

row 0（全维学生与教师一致率 0.652）：

| k | edit | keep | agree_full |
|---:|---|---|---|
| 1 | 1.000 | 1.000 | **0.652** |
| 2 | 0.688 | 0.754 | 0.599 |
| 4 | 0.563 | 0.668 | 0.565 |
| 8 | 0.531 | 0.656 | 0.560 |
| 16 | 0.469 | 0.707 | 0.592 |
| 32 | 0.625 | 0.664 | 0.581 |
| 384 | 0.000 | 1.000 | **1.000** |

跨 4 个判据行复现同样的形状：k=1 的 `agree_full` 与「全维学生与教师的一致率」逐个吻合
（0.652 / 0.653 / 0.669 / 0.635）。

**这说明 k=1 的「零违规」不是压缩，是替换。**

- 判据是 `edit = 学生判错的样本`、`keep = 学生判对的样本`。k=1 的降维学生退化成 f32 教师
  （线性判据），因此在「更像教师」这个方向上必然满分——判据本身偏袒教师。
- 中间 k（2–32）的 `agree_full` 只有 0.50–0.65，比 k=1 和 k=384 都低：它们既不像教师，
  也不像原学生。
- 只有 k=384（恒等）才 1.000 保真，但它在 edit 集上 0.000（因为 edit 集就是「全维学生错」的样本）。

所以「降维运行」有两个不同的问题，答案相反：

| 目标 | 可行域 | 结论 |
|---|---|---|
| 满足线性判据（edit/keep 全对） | k=1 | 可行，但那是换成了教师 |
| 复现全维三值学生的行为 | 无（k<384 都不行） | 不可行 |

## 读数五：判据的非线性边界（`--teacher`）

前四节的判据都是线性的（`sign(readout·(query·x))`）。这一节换判据形状，检验「k=1 零违规」
是不是只依赖线性。4096 采样、`--max-k 32`、`--basis supervised`、`--readout-row 0`：

| teacher | 判据 | k=1 trit | k=32 trit | min_k | disagree |
|---|---|---|---|---:|---|
| linear | `sign(r·(q·x))` | 1.000 / 1.000 | 0.625 / 0.664 | 1 | 1425/4096 |
| tanh | `sign(r·tanh(q·x))` | 1.000 / 1.000 | 0.625 / 0.664 | 1 | 1423/4096 |
| two-tap | `sign((r1·v)(r2·v))` | 0.375 / 0.711 | 0.469 / 0.563 | **null** | 2032/4096 |

**tanh 不是非线性检验。** 它与 linear 逐格相同，连 disagreement 都只差 2 个样本：`query·x` 的
幅度很小，`tanh(v) ≈ v`，符号结构不变。教训是：判据的非线性程度取决于**数值尺度**，不是函数形式。
要真正测非线性，必须让压缩量级可见（例如 `tanh(αv)` 配大 α），或者直接用二次型。

**two-tap 打破 k=1。** `sign((r1·v)(r2·v))` 是二次型，`w_eff` 不存在。此时：

- k=1 只有 0.375 / 0.711，`min_k = null`（没有任何 k 零违规）；
- k=32 也只有 0.469 / 0.563（f32 路径 0.781 / 0.633）；
- `agree_full` 在所有 k 上与 linear 相同——因为全维学生没变，变的是判据。

所以边界可以写死：**「k=1 零违规」依赖「判据能写成单个线性方向」。** 一旦判据是二次型，
32 维都不够。这不是样本量或量化问题，是判据的代数形状决定的。

## 读数六：判据对准谁（`--criterion`）

前面所有读数都用「学生 vs f32 教师」划分 edit/keep，而 k=1 的降维学生恰好退化成教师——
判据在结构上偏袒教师。`--criterion full` 把「过判据」换成「与**全维学生**完全一致」：

| criterion | 判据含义 | min_k | trits | 占全维 |
|---|---|---:|---:|---:|
| teacher | 满足 f32 教师 | **1** | 1,153 | 0.78% |
| full | 复现全维学生 | **384** | 148,225 | 100% |

两种判据下 `width` 的每一格都相同（同一张表），分岔只在 `min_k` 的定义——
「过」的两种意思。

**这是整条线的收口：**

- 判据对准教师：k=1 就够，0.78% 参数，零违规。
- 判据对准学生：只有 k=384，100% 参数，才 1.000。
- 中间 k（1–32）的 `agree_full` 在 0.564–0.652 之间，**比两端都低**，即降维既不像教师也不像原学生。

所以「有些思考没必要」这句话要带限定词：在**满足某个线性判据**的意义下，128 个方向里 127 个
不必要；在**复现原模型行为**的意义下，一个都不能省。两个答案都是真的，差别只在判据对准谁。

## 读数七：保真阈值曲线（`tau_curve`）

把「过判据」从「完全一致」放宽成「`agree_full ≥ τ`」，一次扫 8 个 τ：

| τ | min_k | 占全维 |
|---|---:|---:|
| 0.99 | 384 | 100% |
| 0.95 | 384 | 100% |
| 0.90 | 384 | 100% |
| 0.80 | 384 | 100% |
| 0.75 | 384 | 100% |
| 0.70 | 384 | 100% |
| 0.65 | 1 | 0.78% |
| 0.60 | 1 | 0.78% |

**这是一条阶跃曲线，不是渐变。** 原因在表里：k=1..32 的 `agree_full` 全部挤在 0.564–0.652
（0.652 / 0.614 / 0.570 / 0.564 / 0.586 / 0.576），既上不去也下不来。所以：

- τ 只要高于 0.652，唯一的选择就是 k=384（100% 参数）；
- τ 低于 0.652，k=1（0.78% 参数）就够——但那是「像教师」，不是「像自己」。

**降维运行的完整负结果**：保真可行域是**二值的**。要么用 0.78% 参数换来「像教师」，要么用
100% 参数换来「像自己」，中间没有折中档。这不是搜索没找到，而是 `agree_full` 在 k=1..32 上
本来就没有可用的中间值。

## 读数八：稀疏化对照（`prune_curve`）

前七节都在测「投影」——所有维度都参与，只是被压扁。但「有些思考没必要」更自然的读法是「删掉」，
即只让少数列参与。两者在三值网络里代价不同：投影会搅混坐标，置零不会。

按 `|w_eff|` 降序保留 top-m 列、其余置零，同一份 4096 采样：

| m（保留列） | 非零 trit | agree_full | edit/keep |
|---:|---:|---|---|
| 16 | 4,531 | 0.552 | 0.594 / 0.570 |
| 32 | 8,723 | 0.568 | 0.563 / 0.633 |
| 64 | 17,144 | 0.618 | 0.688 / 0.742 |
| 96 | 25,640 | 0.649 | 0.500 / 0.746 |
| 128 | 34,101 | 0.656 | 0.344 / 0.754 |
| 192 | 51,108 | 0.690 | 0.406 / 0.801 |
| 256 | 68,047 | 0.713 | 0.313 / 0.805 |

对照：投影 k=1 用 **1,153** 个 trit（0.78%）拿到 **0.652**；k=32 用 13,057 个只有 0.576。

**三条读出来的事实：**

1. 稀疏化**单调**（0.552 → 0.713），比投影的抖动更干净——置零没有「加维反而更差」的问题。
2. 但到 m=256（46% 非零 trit，约 21% 的结构）才 0.713，仍远低于 1.0；而投影 k=1 用 0.78%
   就拿到 0.652。**同等保真下，投影的参数效率高一个量级。**
3. 原因在方向：判据 `readout·(query·x) = w_eff·x` 的 `w_eff` 是**稠密**的，每一列都有贡献，
   删列就是删信息；把 384 列压成一个方向，保留的正是那一个和。

所以「有些思考没必要」不能按坐标轴理解。**在坐标轴上删，是删信息；在方向上压，才是压缩。**
这也解释了为什么 k=1 的投影能零违规：它不是「省掉了 383 个思考」，而是「把 384 个思考换成了
它们的一个加权和」。

## 读数九：换排序（`PruneOrder`）

读数八只用 `|w_eff|` 排序，没验证它是否最优。这一节加三种对照：

- `weff`：判据方向 `|w_eff|`，线性可加假设下的精确贡献；
- `variance`：输入列的方差，与标签无关；
- `fisher`：`|μ₊−μ₋| / σ`，列与标签的相关性（互信息的线性代理）；
- `random`：固定种子随机排列，下界基线。

| m | weff | fisher | variance | random |
|---:|---:|---:|---:|---:|
| 16 | 0.552 | **0.562** | 0.526 | 0.493 |
| 32 | 0.568 | 0.569 | 0.536 | 0.524 |
| 64 | 0.618 | 0.598 | 0.573 | 0.557 |
| 96 | 0.649 | 0.615 | 0.594 | 0.564 |
| 128 | 0.656 | 0.636 | 0.610 | 0.593 |
| 192 | 0.690 | 0.671 | 0.637 | 0.627 |
| 256 | 0.713 | 0.689 | 0.687 | 0.685 |

**两件事：**

1. **m=16 时 `fisher` 反超 `weff`**（0.562 vs 0.552）。小规模稀疏化时，「列与标签的相关性」
   比「线性加权和」更能挑出关键列——因为 `w_eff` 假设各列贡献可加，而 Fisher 直接看类间可分性。
   m≥32 后 `weff` 反超并保持领先，说明列一多，加权和的信息优势才显现。
2. **排序不是瓶颈**。四种排序最大差距只有 6 个点（m=64：0.618 vs 0.557），且 m=256 时全部
   收敛到 0.685–0.713。而投影 k=1 只用 1,153 个 trit 就有 0.652。

所以稀疏化的问题不在「留哪些列」，而在「列本身不够」：判据 `w_eff·x` 的稠密性由数据决定，
任何排序都无法把它变成稀疏可分的。**换排序救不了一个稠密的方向。**

## 读数十：换判据框架——非线性教师（`deep-sign`）

前面九节的判据都是**线性教师**（`sign(readout·(query·x))`）或人造二次型。要测「真正的非线性」，
最自然的是让判据本身带上中间 `sign`：

```text
deep-sign:  teacher = sign(readout · sign(query · x))
            student = sign(readout_trit · sign(query_trit · x_trit))
```

这正是「三值学生的 f32 版」——判据不再能写成单个线性方向，`w_eff` 失效。

8192 采样、`--basis supervised`、`--max-k 32`：

| k | edit | keep | f32 edit/keep | agree_full |
|---:|---|---|---|---|
| 1 | 0.656 | 0.852 | 0.656 / 0.852 | 0.637 |
| 2 | 0.656 | 0.750 | 0.656 / 0.848 | 0.601 |
| 4 | 0.563 | 0.656 | 0.750 / 0.832 | 0.560 |
| 8 | 0.531 | 0.680 | 0.625 / 0.844 | 0.564 |
| 16 | 0.469 | 0.668 | 0.625 / 0.820 | 0.581 |
| 32 | 0.625 | 0.656 | 0.563 / 0.816 | 0.577 |
| 384 | 0.000 | 1.000 | 1.000 / 1.000 | 1.000 |

`min_k = null`：**k<384 没有任何一档能零违规。**

disagreement = 3060/8192（37.4%）——三值学生与 f32 非线性教师的差距足够大，edit 集非空（32 条），
所以这个框架是**可用的**（不像「学生≈教师」那种退化情形）。

### 四种教师的完整对照

| teacher | 判据 | w_eff 存在 | k=1 | min_k |
|---|---|---|---|---:|
| linear | `sign(r·(q·x))` | 是，且精确 | 1.000 / 1.000 | 1 |
| tanh | `sign(r·tanh(q·x))` | 名义上有，实际≈精确 | 1.000 / 1.000 | 1 |
| two-tap | `sign((r1·v)(r2·v))` | 不存在（二次型） | 0.375 / 0.711 | null |
| deep-sign | `sign(r·sign(q·x))` | 不存在（带中间 sign） | 0.656 / 0.852 | null |

**边界三方确认**：只有 `linear` 与「无效的 tanh」能让 k=1 零违规；真正的非线性（two-tap、
deep-sign）都是 `min_k = null`。所以「k=1 零违规」是**线性判据的产物**，不是「思考可以压成一维」
的普遍性质。

## 读十一：换任务判据（`stssweep`）

前十节问的都是「压到多低还像原来的学生」。这一节换问题：**压到多低还能把任务做对**。
任务沿用 `editset_sts` 的判定式（句向量余弦），数据用 MiniLM 词向量随机配对（仓库无真实
`sts-pairs.json`）。

### 三次方法修正（实测暴露的）

| # | 初始做法 | 症状 | 修正 |
|---|---|---|---|
| 1 | `cos >= 0.5` 切正负 | `positive_rate = 0.005`，accuracy 0.999 是「全判负」假高分 | 按余弦分位数取 top/bottom quarter |
| 2 | `cos_trit >= 0.5` 判定 | 全维 `pos_recall = 0.013`（三值 cos 分布与 f32 不同） | 改成比较**排序**：top-quarter 重叠率 |
| 3 | 重叠率 | k=1 得 1.000（`pairs` 正例在前 + 稳定排序 + 取值高度并列） | 打乱 pairs；k=1 仍 1.0 ⇒ 并列是主因，该 k 不可用 |

### 读数（2048 对，随机期望 0.25）

|---:|---:|---:|
| 1 | 1.0000（并列伪影） | 768 |
| 2 | 0.6055 | 1,152 |
| 4 | 0.4902 | 1,920 |
| 8 | 0.4941 | 3,456 |
| 16 | 0.4473 | 6,528 |
| 32 | 0.4805 | 12,672 |
| 64 | 0.4844 | 24,960 |
| 128 | 0.4922 | 49,536 |
| 384 | 0.4766 | 147,840 |

### 换指标：Spearman（overlap 有并列伪影）

上一小节的 `top-quarter overlap` 在 k=1 给出 1.0，是并列造成的假象（k=1 只有 3 种模式、cos 只有
6 个取值，并列太多）。换成 **Spearman 秩相关**（并列取平均秩）后：

| k | spearman | trits | 相对全维 |
|---:|---:|---:|---:|
| 1 | 0.3661 | 768 | 58.0% |
| 2 | 0.4938 | 1,152 | 78.2% |
| 8 | 0.5351 | 3,456 | 84.8% |
| 16 | 0.5285 | 6,528 | 83.8% |
| 32 | 0.5528 | 12,672 | 87.6% |
| 64 | 0.5595 | 24,960 | **88.7%** |
| 128 | 0.5438 | 49,536 | 86.2% |
| 384 | 0.6311 | 147,840 | 100% |

**这修正了上一小节的结论**：overlap 说的「全维也只有 0.48」是指标失真。真实情况是：

- 全维（k=384）Spearman = 0.6311；
- **k=64（1/6 参数）保住 88.7%，k=32 保住 87.6%**；
- 降维的边际成本在 k≥32 之后很小（0.553 → 0.560 → 0.631，翻 10 倍参数只涨 14%）。

所以「三值化本身不行」要改成「三值化有损失但可量化，且降维到 32–64 维的代价可接受」。
**这是整条线唯一一个正面的可行域结论**：不是「能不能降维」，而是「降到 1/6 时能保住近九成」。

## 读十二：真实 STS 数据为何没跑成（负结果）

`stssweep` 用的是 MiniLM **词向量随机配对**，不是真实句对。这一节记录把它换成真实 STS 的
尝试与失败原因，避免以后有人把代理数字当基准。

### 查到了什么

本机 HF 缓存里确实有真实数据：

```text
~/.cache/huggingface/datasets/mteb___stsbenchmark-sts/default/0.0.0/<sha>/
  stsbenchmark-sts-train.arrow
  stsbenchmark-sts-validation.arrow
  stsbenchmark-sts-test.arrow
```

### 两道坎

| # | 阻碍 | 证据 |
|---|---|---|
| 1 | 读不了 arrow | `python -c "import pyarrow"` → `ModuleNotFoundError: No module named pyarrow` |
| 2 | 编不出句向量 | 本地无 `transformers` / `torch`；`stssweep` 吃的是 384 维向量，不是文本 |

**这两道坎决定了：当前环境里「真实 STS」不可达，词对代理不是偷懒，是唯一能跑通的选择。**

### 所以那些数字怎么读

- 真实 STS 句对的语义结构更复杂，这个数大概率会降；降多少正好是「三值化在真实任务上的代价」，

## 读十三：真实输入上的 f32 对照（`agree_real`）

`examples/agree_real/` 把同一套监督基放到**真实词向量行**上跑（1000 行，不是随机三值），
并给两条降维路径加了共同的 f32 基准：未压缩的 `sign(readout · (query·x))`。

| k | 三值投影 vs 三值学生 | f32 投影 vs f32 基准 | 三值投影 vs f32 基准 |
|---:|---:|---:|---:|
| 1 | **0.603** | 1.000 | **0.740** |
| 8 | 0.603 | 1.000 | 0.740 |
| 32 | 0.589 | 1.000 | 0.727 |
| 64 | 0.568 | 1.000 | 0.692 |
| 128 | 0.558 | 1.000 | 0.647 |
| 384 | 0.598 | 1.000 | 0.582 |

- f32 列恒为 1.000 是恒等：`score = w_eff·x` 且 `w_eff = queryᵀreadout`，基第 0 维就是
  `w_eff`，投影到它再做 f32 点积不丢信息——**压到一维本身零损失**。
- 因此 0.603 与 1.000 之间的差就是「三值化权重 + 三值化输入」的全部代价，与维度无关。
- `trit_vs_f32` 随 k 单调下降：维度越多，被 absmean 量化的方向越多，扰动越大；这也解释了
  为什么 `rate`（对三值学生）在 k=1 最高。

### 四象限：损失来自哪一半

同口径下逐个打开 absmean 三值化；最后一列把「保留 scale」与「丢弃 scale」（与 `Layer` 一致）分开：

| k | f32/f32 | 权重三值 | 输入三值 | 两半都三值 | 两半保留 scale | readout 三值 | k维输入+sign | 真实网络 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 1.000 | 1.000 | 0.740 | 0.740 | 0.740 | 0.740 | 0.740 | 0.740 |
| 8 | 1.000 | 0.752 | 0.740 | 0.731 | 0.764 | 0.635 | 0.740 | 0.740 |
| 32 | 1.000 | 0.679 | 0.740 | 0.686 | 0.707 | 0.594 | 0.727 | 0.727 |
| 64 | 1.000 | 0.685 | 0.740 | 0.674 | 0.695 | 0.596 | 0.692 | 0.692 |
| 128 | 1.000 | 0.776 | 0.740 | 0.708 | 0.716 | 0.607 | 0.647 | 0.647 |
| 384 | 1.000 | 0.750 | 0.740 | 0.678 | 0.584 | 0.673 | 0.582 | 0.582 |

- **输入量化是固定底噪**：同一批 384 维三值输入，投影到任何 k 都丢 26 点（0.740），与维度无关。
- **权重量化随维度变差**：k=1 的 1.000 是恒等（单元素 absmean 只剩符号，别读成「无损」）；
  k≥8 丢 22–32 点。
- 两半叠加已接近真实网络的低 k 读数。
- **丢 scale 不是高 k 差距的主因**：保留 scale 在 k=8..128 只回补 1–3 点。
- **完整前向列与真实网络逐位相等**：`k维输入+sign` = 0.740 / 0.740 / 0.727 / 0.692 / 0.647 / 0.582，
  与真实网络完全相同（bias 恒零、scale 不影响符号判决），实现自检通过。
- **k=384 的差距（0.673 → 0.582）来自第一层逐行 sign**，不是 bias，也不是 scale；
  `readout 三值` 列把第一层当线性层，因此高估了 readout 量化的代价。
- 修正上一轮：`readout 三值` 在中等 k 掉的 9–10 点里混入了中间 sign 的代价；
  只有 `k维输入+sign` 是真实网络口径。

### 体积：压缩到底省多少

同一套降维网络的 WSP 编码体积（原网络 = 148225 trits / 38630 B 的 WSP2）：

| k | trits | WSP1 (B) | WSP2 (B) | WSP2 压缩比 | trit_vs_f32 |
|---:|---:|---:|---:|---:|---:|
| 1 | 1153 | 4702 | 1862 | **20.7×** | 0.740 |
| 8 | 3841 | 10078 | 2534 | 15.2× | 0.740 |
| 32 | 13057 | 28511 | 4838 | 8.0× | 0.727 |
| 64 | 25345 | 53087 | 7910 | 4.9× | 0.692 |
| 128 | 49921 | 102240 | 14054 | 2.7× | 0.647 |
| 384 | 148225 | 298848 | 38630 | **1.0×** | 0.582 |

- **满秩不省体积**：k=384 的 trits 与 WSP2 字节和原网络完全相同；「满秩投影」只是换行为，
  不换体积。
- **k≤8 是甜点**：k=1 20.7×、k=8 15.2×，保真都停在 0.740；k≥32 体积收益递减且保真下降。
- WSP1 是文本格式（每 trit 一字符），只作 diff/审阅参考；WSP2（2-bit 定长）才是体积口径。

### 舍入边界（自检）

`examples/agree_real_selftest`（2123 例，不依赖模型）：库的 f32 absmean 与诊断的 f64 口径
2122 例逐位一致。唯一分歧是 `[0.1, 0.2, 0.3]`——f32 下 `0.1/scale` 恰落 `0.5`
（round 远离零 → 1），f64 下略低于 `0.5`（→ 0）。真实权重上未触发这个边界，
`k维输入+sign` 与真实网络仍逐位相等；自检默认只报告，`--strict` 才失败。
- **k=384 反常**：保留 scale 反而更差（0.584 vs 0.678）——满秩时行级 scale 把行间幅度差带回来，
  与 f32 readout 叠加后偏离基准；丢 scale 相当于按行归一化，反而更稳。

## 结论

- k≥4 全部落在 **0.45–0.49**，不随 k 单调改善；**全维（k=384）也只有 0.4766**。
- 也就是说：三值学生在 STS 类排序任务上**本来就不行**，这不是降维的锅，是**三值化本身**的损失。
- 与前面九节互补：那边全维能 1.000 复现自己（行为克隆），这边全维只有 0.48（任务）。
  **换判据后，主要矛盾从「能不能降维」变成「三值化能不能保住任务」。**

## 结论

1. **PCA 基下不支持降维运行；判据基下 k=1 就够**——差别不在维度，在方向。
2. **量化代价不是常数**：PCA 基下同 k 的三值与 f32 差 14 点，但方向选对时 k=1 的三值路径
   也能 1.000。三值化本身不贵，贵的是「把判据混进一堆无用方向里再取符号」。
3. **方差排序 ≠ 思考必要性**：`cos = 0.0086` 给了定量证据；只有监督基的排序才有意义。
4. **非单调是真实的**，监督基把它推到极端：k=1 最好，k=2 立刻变差。
5. **「有些思考没必要」的可计算形式**：在固定判据下，128 个方向里 127 个不必要；剩下那 1 个
   不能靠无监督方差找到。

## 未证栏

- 只验了一个判据（`readout_row = 0`）与一个教师（f32 `query×x`）；多判据下 `w_eff` 会变，
  k=1 是否仍零违规未测。
- `max_edits > 1`、更大的 `beam_width` 与样本量未试。
- 降维后的 `trits` 没对齐 WSP 编码体积（这里只报 trit 数）。
- 必要性排序的跨 seed 稳定性未测。
- 小样本（edit 8）下的早期读数全在噪声内，已废弃不引用。

## 库化：`Layer::project`

上面十节的结论已经落成库能力：`crates/trit-wspace/src/project.rs` 的 `Layer::project(&basis)`。

```rust
// 用三值基把一层从 cols 维压到 k 维
let compressed = layer.project(&basis)?;   // rows × k
```

语义与 `dimsweep` 里的降维学生一致：`out[r][i] = sign(Σ_j basis[i][j] · self[r][j])`。
不同之处是**基不再是实验内部的 `Vec<f64>`，而是一层三值权重**——所以它能被 `patch` 编辑、
被 `repair` 修补、被 `certify` 验证，也就能存成工件、跨模型复用。

`tests/project.rs` 钉了四条不变量：恒等基不动、维度按 k 缩减、列数不匹配报错、bias 保留。

CLI 已接：`project <artifact|-> --basis <artifact> --out <path> [--layer N]`。
基不需要新格式——它本身就是一层三值权重，按普通 WSP 存即可。

导出基：`dimsweep --out-basis basis.wsp`——当前基（`pca` 或 `supervised`）逐行三值化后写成
一层 WSP，实测 `arch [384, 32]`、`trits 12320`。于是整条链路闭环：

```text
dimsweep --basis supervised --max-k 32 --out-basis basis.wsp
trit-wspace project net.wsp --basis basis.wsp --out small.wsp
trit-wspace certify small.wsp --keep ...
```

注意：导出维度由 `--max-k` 决定，没有单独的「导出多少个基向量」参数。

### `project` 的默认健康检查

`project` 写完工件后会顺手报一个 `agree`：在 64 个随机三值输入上，把原输入按基投影到 k 维，
再比较**原网络**与**投影网络**的输出一致率。

```json
"agree": { "samples": 64, "same": 41, "rate": 0.640625 }
```

这是「压完值不值」的第一道读数：rate 太低就该换更大的 k 或换基，不必再手动串 probe / certify。
注意随机输入不含真实分布信息，真实数据上的 agree 可能更高。

**三条已补齐**：

- `--samples N`：采样数可调（默认 64）。
- `--agree-from <oracle.json>`：用 oracle 工件里的真实输入采样，`source` 会标 `oracle`；
  这是把 `rate` 从「随机粗筛」变成「真实分布保真度」的开关。
- `mismatches`：前 3 个不一致样本（输入 + 两侧输出）。

为腾出模块台账空间，顺带把 `cmd_read` / `cmd_diff` 拆成了独立文件（`cli.rs` 653 → 627）。
