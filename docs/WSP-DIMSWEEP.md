# 降维运行扫描（dimsweep）：一段思考要多少维度、多少步

## 目标

「有些思考过程没必要」，这句话要能算。本文件把三件事量成曲线，判据仍是 `editset_gate`
的双集合：**edit 全对且 keep 全对**才算过。

- **宽度**：384 维输入投影到前 k 个方向，降维学生是 `Layer::new(rows, k)` + 原读出层。
- **步数**：k 维学生上跑带 `keep` 约束的 `repair`，看预算够不够补回来。
- **必要性**：最大子空间上逐维剔除，报每一维的边际违规增量。

## 方法

协议与 `editset_gate` 一致：输入是真实 `embeddings.word_embeddings.weight` 的行（384 维，
absmean 三值化）；教师是 f32 `query` 行与 f32 读出向量的点积取符号；学生是三值 `query` 层
+ 三值读出层。edit 集 = 学生判错的样本，keep 集 = 判对的样本。

降维的两条路径必须分开看，否则会误判：

| 路径 | 做了什么 | 只含哪种损失 |
|---|---|---|
| 三值 | 投影 + absmean 三值化 | 投影 + 量化 |
| f32 对照 | 只看投影，不三值化 | 只有投影 |

输入不中心化：`absmean` 本来就不去均值，且这样降维层不需要常数偏置项
（`w·x ≈ (Uᵀw)·(Uᵀx)`），三值偏置不会吃掉一个 f32 常数。

基有两种（`--basis`）：

- `pca`（默认）：真实词向量二阶矩的主方向，方差降序。
- `supervised`：判据方向打头，其余用与它正交的 PCA 方向补齐。

主方向用 **Jacobi 全分解**求（384×384，12 轮 sweep）。不用幂迭代：这个谱的特征值比接近 1，
一次 Gram–Schmidt 给不出严格正交基，会把伪影混进曲线。

## 读数：PCA 基（真实 all-MiniLM-L6-v2）

2048 采样、32 edit / 256 keep、`--max-k 128`（前 128 主成分解释 0.7054 能量）。

| k | trit edit | trit keep | f32 edit | f32 keep | trits | 占全维 |
|---:|---:|---:|---:|---:|---:|---:|
| 384 | 0.000 | 1.000 | 1.000 | 1.000 | 148,225 | 100% |
| 128 | 0.563 | 0.637 | 0.625 | 0.777 | 49,921 | 33.7% |
| 64 | 0.438 | 0.605 | 0.625 | 0.750 | 25,345 | 17.1% |

| 16 | 0.469 | 0.613 | 0.594 | 0.648 | 6,913 | 4.7% |

`min_k_zero_loss = null`：没有任何 k 让 edit 与 keep 同时全对。

步数（k=16，`max_edits=1`、`beam_width=8`）：`found=false`，edit_loss 17 / keep_loss 99。

## 读数：监督基（判据方向）——k=1 就够

判据是线性的：`readout · (query·x) = w_eff · x`，其中 `w_eff = queryᵀ readout`。
`--basis supervised` 直接把 `w_eff` 放在第 0 维，其余用与它正交的 PCA 方向补齐。

| k | trit edit/keep | f32 edit/keep |
|---:|---|---|
| 128 | 0.438 / 0.645 | 1.000 / 1.000 |
| 64 | 0.469 / 0.695 | 1.000 / 1.000 |
| 32 | 0.625 / 0.664 | 1.000 / 1.000 |
| 16 | 0.469 / 0.707 | 1.000 / 1.000 |
| 8 | 0.531 / 0.656 | 1.000 / 1.000 |
| 2 | 0.688 / 0.754 | 1.000 / 1.000 |
| **1** | **1.000 / 1.000** | **1.000 / 1.000** |

`minimum = {k: 1, max_edits: 0, beam_width: 0}`：**一维、零搜索、零违规**。

三条读出来的事实：

1. **判据方向与方差第一主方向几乎正交**：`criterion_cos_pca1 = 0.0086`。这就是 PCA 基
   全盘失败的根因——承载判据的方向在方差上看几乎为零。
2. **k>1 反而更差**（k=2 掉到 0.688/0.754，k=16 掉到 0.469/0.707）：多出来的方向是干扰，
   混进 `sign` 判决后破坏 k=1 的完美映射。这是「加维不是加信息」最干净的一个例子。
3. **必要性排序第一次有了意义**：组件 0（判据方向）Δ=+58，压倒性最必要；最不必要的是
   10(−15)、8(−13)、14(−11)、15(−10)、117(−8)——去掉它们违规反而更少。

## 跨 readout_row 复现（9/9）

换 9 个判据行（`--readout-row 0,1,2,3,4,5,8,13,21`）重跑同一配置：

| row | k=1 trit | k=1 f32 | k=2 trit | min_k | cos(w_eff, PCA1) |
|---:|---|---|---|---:|---:|
| 0 | 1.000 / 1.000 | 1.000 / 1.000 | 0.688 / 0.754 | 1 | 0.0086 |
| 1 | 1.000 / 1.000 | 1.000 / 1.000 | 0.625 / 0.730 | 1 | 0.0157 |
| 2 | 1.000 / 1.000 | 1.000 / 1.000 | 0.531 / 0.770 | 1 | 0.0162 |
| 3 | 1.000 / 1.000 | 1.000 / 1.000 | 0.750 / 0.809 | 1 | 0.0159 |
| 4 | 1.000 / 1.000 | 1.000 / 1.000 | 0.625 / 0.813 | 1 | 0.0557 |
| 5 | 1.000 / 1.000 | 1.000 / 1.000 | 0.625 / 0.762 | 1 | 0.0410 |
| 8 | 1.000 / 1.000 | 1.000 / 1.000 | 0.688 / 0.750 | 1 | 0.0123 |
| 13 | 1.000 / 1.000 | 1.000 / 1.000 | 0.531 / 0.777 | 1 | 0.0032 |
| 21 | 1.000 / 1.000 | 1.000 / 1.000 | 0.813 / 0.730 | 1 | 0.0093 |

**9/9 全中，不是特例。** 机制是结构性的，不是数值巧合：

1. 判据线性：`readout · (query·x) = w_eff · x`，投影到 `w_eff` 单方向保留 100% 判据信息。
2. 单元素 absmean 三值化 `scale = |v|`，`v/scale = ±1`，`round` 后仍是 ±1——**符号严格保持**，
   不会像多维那样被绝对均值阈值抹成 0。
3. 于是 1 维三值输入就是判据符号本身；网络退化成「读一个符号」，edit/keep 自然全对。

`criterion_cos_pca1 ∈ [0.003, 0.056]`：判据方向与方差第一主方向在 9 个判据上都近正交，
所以「PCA 排序找不到判据方向」也是通则，不是某一行碰巧。

## 结论

1. **PCA 基下不支持降维运行；判据基下 k=1 就够**——差别不在维度，在方向。
2. **量化代价不是常数**：PCA 基下同 k 的三值与 f32 差 14 点，但方向选对时 k=1 的三值路径
   也能 1.000。三值化本身不贵，贵的是「把判据混进一堆无用方向里再取符号」。
3. **方差排序 ≠ 思考必要性**：`cos = 0.0086` 给了定量证据；只有监督基的排序才有意义。
4. **非单调是真实的**，监督基把它推到极端：k=1 最好，k=2 立刻变差。
5. **「有些思考没必要」的可计算形式**：在固定判据下，128 个方向里 127 个不必要；剩下那 1 个
   不能靠无监督方差找到。

## 未证栏

- 只验了一个判据（`readout_row = 0`）与一个教师（f32 `query×x`）；多判据下 `w_eff` 会变，
  k=1 是否仍零违规未测。
- `max_edits > 1`、更大的 `beam_width` 与样本量未试。
- 降维后的 `trits` 没对齐 WSP 编码体积（这里只报 trit 数）。
- 必要性排序的跨 seed 稳定性未测。
- 小样本（edit 8）下的早期读数全在噪声内，已废弃不引用。
