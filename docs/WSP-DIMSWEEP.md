# 降维运行扫描（dimsweep）：一段思考要多少维度、多少步

## 目标

「有些思考过程没必要」，这句话要能算。本文件把三件事量成曲线，判据仍是 `editset_gate`
的双集合：**edit 全对且 keep 全对**才算过。

- **宽度**：384 维输入投影到前 k 个方向，降维学生是 `Layer::new(rows, k)` + 原读出层。
- **步数**：k 维学生上跑带 `keep` 约束的 `repair`，看预算够不够补回来。
- **必要性**：最大子空间上逐维剔除，报每一维的边际违规增量。

## 方法

协议与 `editset_gate` 一致：输入是真实 `embeddings.word_embeddings.weight` 的行（384 维，
absmean 三值化）；教师是 f32 `query` 行与 f32 读出向量的点积取符号；学生是三值 `query` 层
+ 三值读出层。edit 集 = 学生判错的样本，keep 集 = 判对的样本。

降维的两条路径必须分开看，否则会误判：

| 路径 | 做了什么 | 只含哪种损失 |
|---|---|---|
| 三值 | 投影 + absmean 三值化 | 投影 + 量化 |
| f32 对照 | 只看投影，不三值化 | 只有投影 |

输入不中心化：`absmean` 本来就不去均值，且这样降维层不需要常数偏置项
（`w·x ≈ (Uᵀw)·(Uᵀx)`），三值偏置不会吃掉一个 f32 常数。

基有两种（`--basis`）：

- `pca`（默认）：真实词向量二阶矩的主方向，方差降序。
- `supervised`：判据方向打头，其余用与它正交的 PCA 方向补齐。

主方向用 **Jacobi 全分解**求（384×384，12 轮 sweep）。不用幂迭代：这个谱的特征值比接近 1，
一次 Gram–Schmidt 给不出严格正交基，会把伪影混进曲线。

## 读数：监督基（判据方向）——k=1 就够

判据是线性的：`readout · (query·x) = w_eff · x`，其中 `w_eff = queryᵀ readout`。
`--basis supervised` 直接把 `w_eff` 放在第 0 维，其余用与它正交的 PCA 方向补齐。

| k | trit edit/keep | f32 edit/keep |
|---:|---|---|
| 128 | 0.438 / 0.645 | 1.000 / 1.000 |
| 64 | 0.469 / 0.695 | 1.000 / 1.000 |
| 32 | 0.625 / 0.664 | 1.000 / 1.000 |
| 16 | 0.469 / 0.707 | 1.000 / 1.000 |
| 8 | 0.531 / 0.656 | 1.000 / 1.000 |
| 2 | 0.688 / 0.754 | 1.000 / 1.000 |
| **1** | **1.000 / 1.000** | **1.000 / 1.000** |

`minimum = {k: 1, max_edits: 0, beam_width: 0}`：**一维、零搜索、零违规**。

三条读出来的事实：

1. **判据方向与方差第一主方向几乎正交**：`criterion_cos_pca1 = 0.0086`。这就是 PCA 基
   全盘失败的根因——承载判据的方向在方差上看几乎为零。
2. **k>1 反而更差**（k=2 掉到 0.688/0.754，k=16 掉到 0.469/0.707）：多出来的方向是干扰，
   混进 `sign` 判决后破坏 k=1 的完美映射。这是「加维不是加信息」最干净的一个例子。
3. **必要性排序第一次有了意义**：组件 0（判据方向）Δ=+58，压倒性最必要；最不必要的是
   10(−15)、8(−13)、14(−11)、15(−10)、117(−8)——去掉它们违规反而更少。

所以「PCA 排序找不到判据方向」也是通则，不是某一行碰巧。

## 读数四：零违规 ≠ 保真（`agree_full`）

`agree_full` = 降维学生与**全维三值学生**在全部 2048 个样本上的一致率。必须在全量上算：
edit/keep 两个子集正是按「与教师是否一致」挑出来的，在那上面算会得到 0/1 的假象。

row 0（全维学生与教师一致率 0.652）：

| k | edit | keep | agree_full |
|---:|---|---|---|
| 1 | 1.000 | 1.000 | **0.652** |
| 2 | 0.688 | 0.754 | 0.599 |
| 4 | 0.563 | 0.668 | 0.565 |
| 8 | 0.531 | 0.656 | 0.560 |
| 16 | 0.469 | 0.707 | 0.592 |
| 32 | 0.625 | 0.664 | 0.581 |
| 384 | 0.000 | 1.000 | **1.000** |

跨 4 个判据行复现同样的形状：k=1 的 `agree_full` 与「全维学生与教师的一致率」逐个吻合
（0.652 / 0.653 / 0.669 / 0.635）。

**这说明 k=1 的「零违规」不是压缩，是替换。**

- 判据是 `edit = 学生判错的样本`、`keep = 学生判对的样本`。k=1 的降维学生退化成 f32 教师
  （线性判据），因此在「更像教师」这个方向上必然满分——判据本身偏袒教师。
- 中间 k（2–32）的 `agree_full` 只有 0.50–0.65，比 k=1 和 k=384 都低：它们既不像教师，
  也不像原学生。
- 只有 k=384（恒等）才 1.000 保真，但它在 edit 集上 0.000（因为 edit 集就是「全维学生错」的样本）。

所以「降维运行」有两个不同的问题，答案相反：

| 目标 | 可行域 | 结论 |
|---|---|---|
| 满足线性判据（edit/keep 全对） | k=1 | 可行，但那是换成了教师 |
| 复现全维三值学生的行为 | 无（k<384 都不行） | 不可行 |

## 读数五：判据的非线性边界（`--teacher`）

前四节的判据都是线性的（`sign(readout·(query·x))`）。这一节换判据形状，检验「k=1 零违规」
是不是只依赖线性。4096 采样、`--max-k 32`、`--basis supervised`、`--readout-row 0`：

| teacher | 判据 | k=1 trit | k=32 trit | min_k | disagree |
|---|---|---|---|---:|---|
| linear | `sign(r·(q·x))` | 1.000 / 1.000 | 0.625 / 0.664 | 1 | 1425/4096 |
| tanh | `sign(r·tanh(q·x))` | 1.000 / 1.000 | 0.625 / 0.664 | 1 | 1423/4096 |
| two-tap | `sign((r1·v)(r2·v))` | 0.375 / 0.711 | 0.469 / 0.563 | **null** | 2032/4096 |

**tanh 不是非线性检验。** 它与 linear 逐格相同，连 disagreement 都只差 2 个样本：`query·x` 的
幅度很小，`tanh(v) ≈ v`，符号结构不变。教训是：判据的非线性程度取决于**数值尺度**，不是函数形式。
要真正测非线性，必须让压缩量级可见（例如 `tanh(αv)` 配大 α），或者直接用二次型。

**two-tap 打破 k=1。** `sign((r1·v)(r2·v))` 是二次型，`w_eff` 不存在。此时：

- k=1 只有 0.375 / 0.711，`min_k = null`（没有任何 k 零违规）；
- k=32 也只有 0.469 / 0.563（f32 路径 0.781 / 0.633）；
- `agree_full` 在所有 k 上与 linear 相同——因为全维学生没变，变的是判据。

所以边界可以写死：**「k=1 零违规」依赖「判据能写成单个线性方向」。** 一旦判据是二次型，
32 维都不够。这不是样本量或量化问题，是判据的代数形状决定的。

## 读数六：判据对准谁（`--criterion`）

前面所有读数都用「学生 vs f32 教师」划分 edit/keep，而 k=1 的降维学生恰好退化成教师——
判据在结构上偏袒教师。`--criterion full` 把「过判据」换成「与**全维学生**完全一致」：

| criterion | 判据含义 | min_k | trits | 占全维 |
|---|---|---:|---:|---:|
| teacher | 满足 f32 教师 | **1** | 1,153 | 0.78% |
| full | 复现全维学生 | **384** | 148,225 | 100% |

两种判据下 `width` 的每一格都相同（同一张表），分岔只在 `min_k` 的定义——
「过」的两种意思。

**这是整条线的收口：**

- 判据对准教师：k=1 就够，0.78% 参数，零违规。
- 判据对准学生：只有 k=384，100% 参数，才 1.000。
- 中间 k（1–32）的 `agree_full` 在 0.564–0.652 之间，**比两端都低**，即降维既不像教师也不像原学生。

所以「有些思考没必要」这句话要带限定词：在**满足某个线性判据**的意义下，128 个方向里 127 个
不必要；在**复现原模型行为**的意义下，一个都不能省。两个答案都是真的，差别只在判据对准谁。

## 读数七：保真阈值曲线（`tau_curve`）

把「过判据」从「完全一致」放宽成「`agree_full ≥ τ`」，一次扫 8 个 τ：

| τ | min_k | 占全维 |
|---|---:|---:|
| 0.99 | 384 | 100% |
| 0.95 | 384 | 100% |
| 0.90 | 384 | 100% |
| 0.80 | 384 | 100% |
| 0.75 | 384 | 100% |
| 0.70 | 384 | 100% |
| 0.65 | 1 | 0.78% |
| 0.60 | 1 | 0.78% |

**这是一条阶跃曲线，不是渐变。** 原因在表里：k=1..32 的 `agree_full` 全部挤在 0.564–0.652
（0.652 / 0.614 / 0.570 / 0.564 / 0.586 / 0.576），既上不去也下不来。所以：

- τ 只要高于 0.652，唯一的选择就是 k=384（100% 参数）；
- τ 低于 0.652，k=1（0.78% 参数）就够——但那是「像教师」，不是「像自己」。

**降维运行的完整负结果**：保真可行域是**二值的**。要么用 0.78% 参数换来「像教师」，要么用
100% 参数换来「像自己」，中间没有折中档。这不是搜索没找到，而是 `agree_full` 在 k=1..32 上
本来就没有可用的中间值。

## 读数八：稀疏化对照（`prune_curve`）

前七节都在测「投影」——所有维度都参与，只是被压扁。但「有些思考没必要」更自然的读法是「删掉」，
即只让少数列参与。两者在三值网络里代价不同：投影会搅混坐标，置零不会。

按 `|w_eff|` 降序保留 top-m 列、其余置零，同一份 4096 采样：

| m（保留列） | 非零 trit | agree_full | edit/keep |
|---:|---:|---|---|
| 16 | 4,531 | 0.552 | 0.594 / 0.570 |
| 32 | 8,723 | 0.568 | 0.563 / 0.633 |
| 64 | 17,144 | 0.618 | 0.688 / 0.742 |
| 96 | 25,640 | 0.649 | 0.500 / 0.746 |
| 128 | 34,101 | 0.656 | 0.344 / 0.754 |
| 192 | 51,108 | 0.690 | 0.406 / 0.801 |
| 256 | 68,047 | 0.713 | 0.313 / 0.805 |

对照：投影 k=1 用 **1,153** 个 trit（0.78%）拿到 **0.652**；k=32 用 13,057 个只有 0.576。

**三条读出来的事实：**

1. 稀疏化**单调**（0.552 → 0.713），比投影的抖动更干净——置零没有「加维反而更差」的问题。
2. 但到 m=256（46% 非零 trit，约 21% 的结构）才 0.713，仍远低于 1.0；而投影 k=1 用 0.78%
   就拿到 0.652。**同等保真下，投影的参数效率高一个量级。**
3. 原因在方向：判据 `readout·(query·x) = w_eff·x` 的 `w_eff` 是**稠密**的，每一列都有贡献，
   删列就是删信息；把 384 列压成一个方向，保留的正是那一个和。

所以「有些思考没必要」不能按坐标轴理解。**在坐标轴上删，是删信息；在方向上压，才是压缩。**
这也解释了为什么 k=1 的投影能零违规：它不是「省掉了 383 个思考」，而是「把 384 个思考换成了
它们的一个加权和」。

## 读数九：换排序（`PruneOrder`）

读数八只用 `|w_eff|` 排序，没验证它是否最优。这一节加三种对照：

- `weff`：判据方向 `|w_eff|`，线性可加假设下的精确贡献；
- `variance`：输入列的方差，与标签无关；
- `fisher`：`|μ₊−μ₋| / σ`，列与标签的相关性（互信息的线性代理）；
- `random`：固定种子随机排列，下界基线。

| m | weff | fisher | variance | random |
|---:|---:|---:|---:|---:|
| 16 | 0.552 | **0.562** | 0.526 | 0.493 |
| 32 | 0.568 | 0.569 | 0.536 | 0.524 |
| 64 | 0.618 | 0.598 | 0.573 | 0.557 |
| 96 | 0.649 | 0.615 | 0.594 | 0.564 |
| 128 | 0.656 | 0.636 | 0.610 | 0.593 |
| 192 | 0.690 | 0.671 | 0.637 | 0.627 |
| 256 | 0.713 | 0.689 | 0.687 | 0.685 |

**两件事：**

1. **m=16 时 `fisher` 反超 `weff`**（0.562 vs 0.552）。小规模稀疏化时，「列与标签的相关性」
   比「线性加权和」更能挑出关键列——因为 `w_eff` 假设各列贡献可加，而 Fisher 直接看类间可分性。
   m≥32 后 `weff` 反超并保持领先，说明列一多，加权和的信息优势才显现。
2. **排序不是瓶颈**。四种排序最大差距只有 6 个点（m=64：0.618 vs 0.557），且 m=256 时全部
   收敛到 0.685–0.713。而投影 k=1 只用 1,153 个 trit 就有 0.652。

所以稀疏化的问题不在「留哪些列」，而在「列本身不够」：判据 `w_eff·x` 的稠密性由数据决定，
任何排序都无法把它变成稀疏可分的。**换排序救不了一个稠密的方向。**

## 读数十：换判据框架——非线性教师（`deep-sign`）

前面九节的判据都是**线性教师**（`sign(readout·(query·x))`）或人造二次型。要测「真正的非线性」，
最自然的是让判据本身带上中间 `sign`：

```text
deep-sign:  teacher = sign(readout · sign(query · x))
            student = sign(readout_trit · sign(query_trit · x_trit))
```

这正是「三值学生的 f32 版」——判据不再能写成单个线性方向，`w_eff` 失效。

8192 采样、`--basis supervised`、`--max-k 32`：

| k | edit | keep | f32 edit/keep | agree_full |
|---:|---|---|---|---|
| 1 | 0.656 | 0.852 | 0.656 / 0.852 | 0.637 |
| 2 | 0.656 | 0.750 | 0.656 / 0.848 | 0.601 |
| 4 | 0.563 | 0.656 | 0.750 / 0.832 | 0.560 |
| 8 | 0.531 | 0.680 | 0.625 / 0.844 | 0.564 |
| 16 | 0.469 | 0.668 | 0.625 / 0.820 | 0.581 |
| 32 | 0.625 | 0.656 | 0.563 / 0.816 | 0.577 |
| 384 | 0.000 | 1.000 | 1.000 / 1.000 | 1.000 |

`min_k = null`：**k<384 没有任何一档能零违规。**

disagreement = 3060/8192（37.4%）——三值学生与 f32 非线性教师的差距足够大，edit 集非空（32 条），
所以这个框架是**可用的**（不像「学生≈教师」那种退化情形）。

### 四种教师的完整对照

| teacher | 判据 | w_eff 存在 | k=1 | min_k |
|---|---|---|---|---:|
| linear | `sign(r·(q·x))` | 是，且精确 | 1.000 / 1.000 | 1 |
| tanh | `sign(r·tanh(q·x))` | 名义上有，实际≈精确 | 1.000 / 1.000 | 1 |
| two-tap | `sign((r1·v)(r2·v))` | 不存在（二次型） | 0.375 / 0.711 | null |
| deep-sign | `sign(r·sign(q·x))` | 不存在（带中间 sign） | 0.656 / 0.852 | null |

**边界三方确认**：只有 `linear` 与「无效的 tanh」能让 k=1 零违规；真正的非线性（two-tap、
deep-sign）都是 `min_k = null`。所以「k=1 零违规」是**线性判据的产物**，不是「思考可以压成一维」
的普遍性质。

## 读十一：换任务判据（`stssweep`）

前十节问的都是「压到多低还像原来的学生」。这一节换问题：**压到多低还能把任务做对**。
任务沿用 `editset_sts` 的判定式（句向量余弦），数据用 MiniLM 词向量随机配对（仓库无真实
`sts-pairs.json`）。

### 三次方法修正（实测暴露的）

| # | 初始做法 | 症状 | 修正 |
|---|---|---|---|
| 1 | `cos >= 0.5` 切正负 | `positive_rate = 0.005`，accuracy 0.999 是「全判负」假高分 | 按余弦分位数取 top/bottom quarter |
| 2 | `cos_trit >= 0.5` 判定 | 全维 `pos_recall = 0.013`（三值 cos 分布与 f32 不同） | 改成比较**排序**：top-quarter 重叠率 |
| 3 | 重叠率 | k=1 得 1.000（`pairs` 正例在前 + 稳定排序 + 取值高度并列） | 打乱 pairs；k=1 仍 1.0 ⇒ 并列是主因，该 k 不可用 |

|---:|---:|---:|
| 1 | 1.0000（并列伪影） | 768 |
| 2 | 0.6055 | 1,152 |
| 4 | 0.4902 | 1,920 |
| 8 | 0.4941 | 3,456 |
| 16 | 0.4473 | 6,528 |
| 32 | 0.4805 | 12,672 |
| 64 | 0.4844 | 24,960 |
| 128 | 0.4922 | 49,536 |
| 384 | 0.4766 | 147,840 |

### 换指标：Spearman（overlap 有并列伪影）

上一小节的 `top-quarter overlap` 在 k=1 给出 1.0，是并列造成的假象（k=1 只有 3 种模式、cos 只有
6 个取值，并列太多）。换成 **Spearman 秩相关**（并列取平均秩）后：

| k | spearman | trits | 相对全维 |
|---:|---:|---:|---:|
| 1 | 0.3661 | 768 | 58.0% |
| 2 | 0.4938 | 1,152 | 78.2% |
| 8 | 0.5351 | 3,456 | 84.8% |
| 16 | 0.5285 | 6,528 | 83.8% |
| 32 | 0.5528 | 12,672 | 87.6% |
| 64 | 0.5595 | 24,960 | **88.7%** |
| 128 | 0.5438 | 49,536 | 86.2% |
| 384 | 0.6311 | 147,840 | 100% |

**这修正了上一小节的结论**：overlap 说的「全维也只有 0.48」是指标失真。真实情况是：

- 全维（k=384）Spearman = 0.6311；
- **k=64（1/6 参数）保住 88.7%，k=32 保住 87.6%**；
- 降维的边际成本在 k≥32 之后很小（0.553 → 0.560 → 0.631，翻 10 倍参数只涨 14%）。

所以「三值化本身不行」要改成「三值化有损失但可量化，且降维到 32–64 维的代价可接受」。
**这是整条线唯一一个正面的可行域结论**：不是「能不能降维」，而是「降到 1/6 时能保住近九成」。

## 读十三：真实输入上的 f32 对照（`agree_real`）

`examples/agree_real/` 把同一套监督基放到**真实词向量行**上跑（1000 行，不是随机三值），
并给两条降维路径加了共同的 f32 基准：未压缩的 `sign(readout · (query·x))`。

| k | 三值投影 vs 三值学生 | f32 投影 vs f32 基准 | 三值投影 vs f32 基准 |
|---:|---:|---:|---:|
| 1 | **0.603** | 1.000 | **0.740** |
| 8 | 0.603 | 1.000 | 0.740 |
| 32 | 0.589 | 1.000 | 0.727 |
| 64 | 0.568 | 1.000 | 0.692 |
| 128 | 0.558 | 1.000 | 0.647 |
| 384 | 0.598 | 1.000 | 0.582 |

- f32 列恒为 1.000 是恒等：`score = w_eff·x` 且 `w_eff = queryᵀreadout`，基第 0 维就是
  `w_eff`，投影到它再做 f32 点积不丢信息——**压到一维本身零损失**。
- 因此 0.603 与 1.000 之间的差就是「三值化权重 + 三值化输入」的全部代价，与维度无关。
- `trit_vs_f32` 随 k 单调下降：维度越多，被 absmean 量化的方向越多，扰动越大；这也解释了
  为什么 `rate`（对三值学生）在 k=1 最高。

### 四象限：损失来自哪一半

同口径下逐个打开 absmean 三值化；最后一列把「保留 scale」与「丢弃 scale」（与 `Layer` 一致）分开：

| k | f32/f32 | 权重三值 | 输入三值 | 两半都三值 | 两半保留 scale | readout 三值 | k维输入+sign | 真实网络 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 1.000 | 1.000 | 0.740 | 0.740 | 0.740 | 0.740 | 0.740 | 0.740 |
| 8 | 1.000 | 0.752 | 0.740 | 0.731 | 0.764 | 0.635 | 0.740 | 0.740 |
| 32 | 1.000 | 0.679 | 0.740 | 0.686 | 0.707 | 0.594 | 0.727 | 0.727 |
| 64 | 1.000 | 0.685 | 0.740 | 0.674 | 0.695 | 0.596 | 0.692 | 0.692 |
| 128 | 1.000 | 0.776 | 0.740 | 0.708 | 0.716 | 0.607 | 0.647 | 0.647 |
| 384 | 1.000 | 0.750 | 0.740 | 0.678 | 0.584 | 0.673 | 0.582 | 0.582 |

- **输入量化是固定底噪**：同一批 384 维三值输入，投影到任何 k 都丢 26 点（0.740），与维度无关。
- **权重量化随维度变差**：k=1 的 1.000 是恒等（单元素 absmean 只剩符号，别读成「无损」）；
  k≥8 丢 22–32 点。
- 两半叠加已接近真实网络的低 k 读数。
- **丢 scale 不是高 k 差距的主因**：保留 scale 在 k=8..128 只回补 1–3 点。
- **完整前向列与真实网络逐位相等**：`k维输入+sign` = 0.740 / 0.740 / 0.727 / 0.692 / 0.647 / 0.582，
  与真实网络完全相同（bias 恒零、scale 不影响符号判决），实现自检通过。
- **k=384 的差距（0.673 → 0.582）来自第一层逐行 sign**，不是 bias，也不是 scale；
  `readout 三值` 列把第一层当线性层，因此高估了 readout 量化的代价。
- 修正上一轮：`readout 三值` 在中等 k 掉的 9–10 点里混入了中间 sign 的代价；
  只有 `k维输入+sign` 是真实网络口径。

### 体积：压缩到底省多少

同一套降维网络的 WSP 编码体积（原网络 = 148225 trits / 38630 B 的 WSP2）：

| k | trits | WSP1 (B) | WSP2 (B) | WSP2 压缩比 | trit_vs_f32 |
|---:|---:|---:|---:|---:|---:|
| 1 | 1153 | 4702 | 1862 | **20.7×** | 0.740 |
| 8 | 3841 | 10078 | 2534 | 15.2× | 0.740 |
| 32 | 13057 | 28511 | 4838 | 8.0× | 0.727 |
| 64 | 25345 | 53087 | 7910 | 4.9× | 0.692 |
| 128 | 49921 | 102240 | 14054 | 2.7× | 0.647 |
| 384 | 148225 | 298848 | 38630 | **1.0×** | 0.582 |

- **满秩不省体积**：k=384 的 trits 与 WSP2 字节和原网络完全相同；「满秩投影」只是换行为，
  不换体积。
- **k≤8 是甜点**：k=1 20.7×、k=8 15.2×，保真都停在 0.740；k≥32 体积收益递减且保真下降。
- WSP1 是文本格式（每 trit 一字符），只作 diff/审阅参考；WSP2（2-bit 定长）才是体积口径。

### 多判据行（`readout_row` 0..3）

把 `readout_row` 参数化后重跑（每行一个 f32 读出向量，其余口径不变）：

| readout_row | f32（所有 k） | k=1 | k=8 | k=32 | k=64 | k=128 | k=384 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 | 1.000 | 0.740 | 0.740 | 0.727 | 0.692 | 0.647 | 0.582 |
| 1 | 1.000 | 0.707 | 0.707 | 0.686 | 0.653 | 0.609 | 0.566 |
| 2 | 1.000 | 0.466 | 0.466 | 0.462 | 0.474 | 0.500 | 0.412 |
| 3 | 1.000 | 0.960 | 0.960 | 0.949 | 0.891 | 0.804 | 0.737 |

- **f32 列 4/4 行恒为 1.000**：投影到 `w_eff` 是精确重写，与读出行无关。
- **三值损失幅度随 row 剧烈变化**：row 3 只丢 4 点（0.960），row 2 丢 53 点（0.466）。
  「约四成损失」只是 row 0/1 附近的特例，不是常数；损失由读出向量结构决定。
- 但 **「k 增大不改善」跨 4 行成立**：每行都是 k=1/8 最高、k=384 最低（或接近最低），
  「维度不是瓶颈」的结论稳健。
- 体积与 row 无关（同一网络结构）：k=1 20.7×、k=8 15.2×、k=384 1.0×；
  k≤8 对每一行都是甜点。

### 一读诊断：`diagnose`

```text
trit-wspace diagnose <artifact|-> --oracle <json|-> [--budget N] [--top K]
                      [--max-edits N] [--beam-width N]
```

把四件事聚合成一个结论：

| 结论 | 判定 | 输出里的关键字段 |
|---|---|---|
| `ok` | `loss == 0` | `rows`：清零/取反后漂移最大的行（一碰就坏） |
| `repairable` | `loss > 0` 且预算内找到补丁 | `repair.patch_len`、`edits[0]`（单步最优收益） |
| `not-repairable` | `loss > 0` 且预算内无解 | `edits[0].gain`（最高收益也救不回来） |

全部字段都是实测：`loss` 来自穷举判据，`rows` 来自行级消融，`edits` 来自单点编辑前后重算，
`repair` 来自带 `keep` 约束的最小补丁搜索。**边界**：`repairable` 只保证「预算内找到解」，
不是形式化可修性；`ok` 下的脆弱行也不等于任务保证。

`tests/diagnose.rs` 四条测试钉住三态与 CLI 端到端（完整 XOR → `ok`、打坏一格 →
`repairable`、`max_edits=0` → `not-repairable`、命令输出 `verdict=ok`）。

### 组件清单与能力归属

`inventory <artifact|->` 静态数结构：每层 `rows/cols/trits`、非零偏置、死行（全零权重），
以及神经元 / trit / bias 总数。

`attribute <artifact|-> --oracle <json|-> [--mode flip|zero] [--layer N] [--row N]
[--max-params N] [--top K]` 逐参数算「改它失去什么」：

| 字段 | 含义 |
|---|---|
| `lost` | 改前对、改后错的样本（失去的能力） |
| `gained` | 改前错、改后对 |
| `changed` | 输出变化的样本（含错→错） |
| `specificity` | `lost / changed`；`1.0` 表示只影响它该影响的样本 |
| `sole` | 该参数是某能力的唯一支撑 |
| `specialists` | `specificity = 1.0` 且 `lost ≤ 4` 的参数（专才） |

「能力」由相同的 `lost` 样本集合定义，不需要语义标签；`capabilities` 列出每种能力及其
支撑参数。成本是 `参数数 × 样本数` 次前向，用 `--max-params` / `--layer` / `--row` 限流。
`tests/inventory.rs` 钉住 XOR 上的计数与单参数归属（col0 lost=6、col1 lost=4、3 个能力、
col1 被标为专才、col0 是其能力的唯一支撑）。

### 多参数改动与形式化不可修性

`impact <artifact|-> --oracle <json|-> (--edits <json|-> | --group row|layer --layer N
[--row N] [--mode flip|zero])` 算一组编辑的**联合**收益：

| 字段 | 含义 |
|---|---|
| `gain` | 联合编辑的失配减少 |
| `lost/gained/changed` | 联合编辑后的样本集 |
| `individual[].gain` | 每条编辑单独施加的增益 |
| `synergy` | 联合 `gain - Σ 单点 gain`（正 = 协同，负 = 抵消） |

`--group row|layer` 自动生成整行/整层的翻转或置零编辑，不局限于单一 trit。

`repair-exhaustive <artifact|-> --oracle <json|-> [--max-edits 1|2] [--max-pairs N]`
用全枚举替代束搜索：`analyze` 枚举全部单点、`analyze_pairs` 枚举全部点对，
给出「存在/不存在 ≤N 步解」的确定性结论。**边界**：只对给定验证集成立，不是全部输入的证明；
`--max-pairs` 超出时直接报错，不做静默截断。

### 能力命名

`capability <artifact|-> --oracle <json|-> [--labels <json|->] [--max-params N] [--top K]
[--mode flip|zero] [--layer N] [--row N]` 把 `attribute` 的每种能力命名：

- 有 `--labels`（每样本一个字符串）时取 `lost` 集合的**众数标签**，名字形如 `label:pos`；
- 否则找 `lost` 样本在输入上的**共同坐标值**，形如 `pattern:x0=+1,x1=-1`；
- 都没有时退化为 `samples:N`。

这样「这个参数改掉会失去什么」从样本索引变成了人能读的能力名。

### 两阶段扫描（`scan`）

`scan <artifact|-> --oracle <json|-> [--labels <json|->] [--max-params N]
[--sample-budget N] [--refine K] [--top K] [--mode flip|zero] [--layer N] [--row N]`

`attribute` 的成本是「参数数 × 样本数」；`scan` 先用 `--sample-budget` 个样本粗筛，
只对「在子集上有影响」的参数做全量复核：

| 字段 | 含义 |
|---|---|
| `stats.total_params` | 作用域内参数总数 |
| `stats.screened` | 粗筛后保留数 |
| `stats.refined` | 实际全量复核数 |
| `stats.sampled` | 是否用了两阶段 |

`--refine K` 进一步限制复核数；`sample_budget = 0` 退化为全量，结果与 `attribute` 等价
（`tests/scan.rs` 钉住）。输出同时带 `capability` 的命名能力。

### 时序、分布与输入敏感度

- `trace <artifact|-> --oracle <json|-> --sample N`：逐层逐行给出 `acc`
  （整数 pre-activation）与输出 trit。`acc` 接近 0 的行裕量最小，是「信号在哪衰减」的直接读数。
- `distribution --oracle <json|->`：训练数据分布——每个输入坐标的 `neg/zero/pos` 次数、
  输出类别分布、唯一输入/输出模式数。
- `perturb <artifact|-> --oracle <json|-> [--mode flip|zero]`：样本突变——逐样本逐输入位
  翻转或置零，输出 `flipped/lost/gained` 与逐位、逐样本敏感度。三值网络不可微，
  这里用**逐位翻转的有限差分**替代梯度：`per_position` 是输入侧「梯度」，`per_sample` 是
  样本脆弱度。

### 延迟雷与改良历史

- `cost <artifact|-> --oracle <json|-> [--top K]`：逐样本统计乘法次数
  （非零输出行 × `cols`），给出总量/均值/最大/最小、逐层热点与最贵的样本——
  乘法最多的样本就是「延迟雷」。
- `history --log <jsonl>`：从审计日志汇总改良历史——应用/回滚/跳过/编辑数、
  按记录名分组、按 `seq` 排列的事件；日志写入 `ts`（Unix 毫秒，不参与哈希链），
  `first_ts`/`last_ts` 给出绝对时间范围，旧日志无 `ts` 时为 null。

**边界**：`Net` 不含 attention/残差（M 边界），「注意力被吸走」只能用 `perturb` 的
`per_position`（输入主导位）近似，不是真正的 attention 权重。

### 真实模型案例（`real_analysis`）

MiniLM 的 query 层 + readout，32 个真实词向量行，教师 = f32 `sign(readout · (query·x))`：

| 指标 | 读数 |
|---|---|
| 样本 | 32 |
| cost 总乘法 | 4,590,336（均值 143,448，最大 145,152，最小 141,312） |
| 逐层乘法 | L0 4,578,048 / L1 12,288 |
| 最贵样本 | 2、18（145,152） |
| perturb | 12,288 次突变，2,208 次翻转，lost 1,072，gained 912 |
| 最敏感输入位 | 0（8 次）、4（7 次）、1/2（6 次） |
| trace（样本 0） | L0 非零 372 行 / L1 非零 1 行，输出 -1 |
| scan（readout 层） | 385 参数，粗筛 64，复核 64，7 种能力，0 个专才 |

- 32 个样本的 cost 几乎恒定（141k–145k）：这批词向量的 L0 非零行都接近满激活（372/384），
  延迟主要由网络结构决定，不是样本。
- perturb 的翻转集中在输入位 0/4/1/2——输入侧「注意力」落点；lost > gained，扰动整体破坏大于修复。
- scan 在 readout 层找到 7 种能力、0 个专才：readout 参数的影响集合都较大，没有只影响 ≤4 样本的参数。
- **边界**：32 样本的展示性读数，不是统计结论；MiniLM 原始网络不是三值，这里是 query 层三值化代理。

### 三值注意力（`AttentionHead`）

`AttentionHead` 是 `Net` 之外的新运行时：Q/K/V 权重三值，分数整数点积，softmax 用 f32。
真实 MiniLM 的 Q/K/V 层三值化，4 个 query × 32 个词表 key：

| query | dominant key | 最大权重 | score 范围 |
|---|---|---|---|
| 0 | 1 | 0.999624 | -2..48 |
| 1 | 30 | 0.999997 | -54..2 |
| 2 | 0 | 1.000000 | -43..17 |
| 3 | 0 | 0.999063 | -52..9 |

- 三值整数分数幅度很大（−54..48），softmax 几乎 one-hot——**注意力被单个 key 吸走**，
  不是逐渐分散；这是「注意力为什么被吸走」的直接读数。
- 边界：单头、无位置编码、无多头拼接；Q/K/V 来自 MiniLM 的 query/key/value 层三值化，
  不是原始 f32 attention。

2048 个真实词向量行，1000 次 bootstrap（有放回重采样，LCG，无外部依赖）：

| 指标 | 均值 | 95% CI |
|---|---|---|
| accuracy | 0.597 | [0.575, 0.619] |
| cost（乘法/样本） | 143,406 | [143,348, 143,458] |
| flip_rate（逐位扰动翻转比例） | 0.161 | [0.151, 0.171] |

- accuracy 从 512 样本的 0.613 回到 0.597：512 样本的展示性读数仍有约 1.6 点偏差。
- cost 的 CI 仍极窄（±55）：样本间计算量几乎恒定，延迟由结构决定。

| query | 无位置偏置 dominant（12 头） | 有位置偏置 dominant |
|---|---|---|
| 0 | 30,125,27,29,53,61,5,103,103,125,102,92 | 30,12,27,29,14,13,5,14,5,4,102,92 |

- 多头 dominant 高度分散：12 个头指向 7–10 个不同 key，不是全部吸到同一个位置——
  「注意力被吸走」在多头下是**多个落点**。
- 位置偏置 `-(index)/4` 显著改变 dominant：query 2/3 出现多个头指向 key 0，
  说明位置衰减把近端 key 拉高。
- 边界：位置偏置是整数分数上的线性项，不是可学习的位置编码；Q/K/V 仍来自 MiniLM 的三值化切分。

| 0 | 30,125,27,29,53,61,5,103,103,125,102,92 | 30,12,27,29,14,13,5,14,5,4,102,92 | 74,40,120,76,64,119,114,29,93,110,102,122 |
| 1 | 103,7,102,81,102,63,27,81,101,102,81,103 | 3,7,15,5,7,63,27,81,101,13,12,41 | 103,43,127,36,102,83,5,81,18,46,81,107 |
| 2 | 100,81,103,102,103,64,27,103,81,102,100,0 | 0,16,9,8,0,6,27,103,81,0,0,0 | 15,102,98,67,102,57,101,103,18,50,88,109 |
| 3 | 81,81,81,81,48,126,49,81,101,98,100,101 | 0,81,81,46,0,6,49,81,101,0,40,101 | 76,100,98,103,126,9,88,81,18,68,35,79 |

- 三值位置编码几乎让每个头落到不同 key（12 头 12 个落点），比线性偏置更彻底：
  「训练好的位置嵌入」携带的信息远超 `-(i)` 线性项。
- 边界：编码来自 MiniLM 的 `position_embeddings` 三值化，不是从头学习；位置数 512，
  这里只用前 128。

### 从头学习位置编码（负结果）

`attention_learn.rs` 的 `learn_positions`：每头独立位置表、初始全零，贪心翻转单 trit
让 dominant 匹配目标。真实 MiniLM 12 头、32 key、目标 [0..11]：

| query | 匹配 | 轮数 | 收敛 |
|---|---|---|---|
| 0 | 0/12 | 0 | 否 |
| 1 | 0/12 | 0 | 否 |
| 2 | 2/12 | 1 | 否 |
| 3 | 3/12 | 2 | 否 |

- **负结果**：单 trit 对 32 维 key 的分数影响 ≤1，而三值 Q/K 的分数幅度可达几十；
  1–2 个 trit 的位置编码不足以任意改写 dominant。
- 小网络（2 头、2 key）上算法可收敛，说明搜索本身有效，瓶颈是**三值位置编码的表达力**。
- 要更强表达力，需要更大的位置/维度预算，或回到 f32 位置编码。

### f32 注意力对照（`F32Attention`）

同 12 头 × 32 维、128 key，Q/K/V 全 f32、softmax f32：

| query | dominant（12 头） | top 权重 |
|---|---|---|
| 0 | 12,102,102,22,100,102,100,101,101,102,101,101 | ≈0.0079 |
| 1 | 100,101,103,100,81,100,64,102,101,100,101,101 | ≈0.0079 |
| 2 | 100,103,28,100,100,100,64,100,101,100,101,99 | ≈0.0079 |
| 3 | 100,102,103,100,100,73,64,100,101,100,101,101 | ≈0.0079 |

- f32 下 top 权重 ≈ 0.0079（1/128 ≈ 0.0078），**几乎均匀**；dominant 只是 0.0079 的微小领先。
- 三值版的权重 >0.999（one-hot）——**one-hot 是量化造成的**：整数分数幅度几十，softmax 饱和。
- 结论：三值 attention 的「注意力被吸走」不是网络本身的行为，而是三值整数分数的量化效应。

- 边界：这是有限差分敏感度，不是反向传播梯度；子网络是 MiniLM query 的 4×4 子矩阵，
  不是完整注意力。

### f32 位置编码的反向传播训练（`attention_f32_train`）

Q/K/V 固定，只对位置偏置做解析梯度（交叉熵）。MiniLM 12 头、32 key、20 轮、lr=0.5：

| 指标 | 读数 |
|---|---|
| loss_before | ≈3.464–3.468 |
| loss_after | ≈0.175 |
| grad_norm_first | ≈0.984 |
| positions | [-0.162, +5.007] |

- 每头都把交叉熵从 3.46 降到 0.175（目标权重从 ~0.03 提到 ~0.84），解析梯度有效。
- 与三值贪心学习（0–3/12 匹配）对比：**f32 位置编码 + 真实梯度**才学得动；
  三值位置编码的表达力不足是量化限制，不是搜索问题。
- 边界：只训练位置偏置，Q/K/V 固定；不是完整注意力端到端训练。

### 多头联合训练（Q/K + 共享位置）

MiniLM 12 头、32 key、目标 [0..11]：

| 预算 | 总 loss | 匹配 | positions |
|---|---|---|---|
| 20 轮 / lr=0.1 | 41.59 → 40.46 | 0/12 | [-0.061, +0.101] |
| 100 轮 / lr=0.5 | 41.59 → **31.81** | **11/12** | [-0.807, +1.345] |

- 小预算下共享位置被 12 个不同目标平均掉（`dpos` 除以 12），几乎学不动。
- 100 轮 / lr=0.5 后 11/12 匹配，唯一未匹配是头 2（目标 2、实际 12）——共享位置
  在多头目标冲突下的残余误差。
- 结论：**Q/K 参与 + 共享位置**的联合训练可行，但共享位置与每头不同目标存在冲突；
  要 12/12 需要每头独立位置（退化为每头单训）或更大预算。

### 每头独立位置（12/12）

MiniLM 12 头、32 key、目标 [0..11]，100 轮 / lr=0.5：

| 指标 | 读数 |
|---|---|
| matched | **12/12** |
| loss_before | ≈3.464–3.466 |
| loss_after | ≈0.022 |

- 每头独立位置表消除了共享位置的冲突：12/12 全部匹配（共享位置版本最多 11/12）。
- 代价是位置表从 1 份变成 12 份（32 × 12 = 384 个 f32 参数）。
- 结论：**多头目标冲突是共享位置的上限，不是梯度方法的问题**；独立位置 + 解析梯度可完全拟合。

### 完整 f32 transformer 层（LayerNorm/残差/FFN）

真实 MiniLM 一层的权重（Q/K/V、两个 LayerNorm、intermediate/output dense），4 个词向量 token：

| 指标 | 读数 |
|---|---|
| 输入范数 | 0.767 / 0.433 / 0.460 / 0.472 |
| 输出范数 | 11.48 / 11.04 / 11.12 / 11.22 |
| 输出形状 | 4 × 384 |
| 有限值 | true |

- `x = LN(x + attn(x))`、`x = LN(x + FFN(x))` 在真实权重上可运行；输出范数被 LayerNorm 拉到 ~11。
- 结构完整（attention + 残差 + LN + FFN）；**反向传播未接**（forward-only）。
- attention 是单头（384×384），FFN 隐藏层 1536 维，与 MiniLM 一层一致。

### transformer 层的反向传播训练（只训练 FFN 第二层）

真实 MiniLM 一层、4 个 token 自编码，50 轮 / lr=0.01：

| 指标 | 读数 |
|---|---|
| loss_before | 0.3107 |
| loss_after | 0.2998 |
| 输出范数 | 11.44 / 10.78 / 10.88 / 10.99 |
| 有限值 | true |

- 损失经 `LN2 → 残差 → FFN2` 反向传播，FFN2 权重/bias 被更新；loss 下降约 3.5%。
- 实现：LayerNorm 的解析梯度 + Dense 反向。
- **2 维 LayerNorm 的 Jacobian 退化**（输入梯度恒 0）；测试用 3 维，真实 384 维无此问题。
- 边界：只训练 FFN 第二层，注意力/LN/FFN1 固定；不是全参数端到端。

### 全参数端到端训练（attention Q/K/V + LN + FFN）

真实 MiniLM 一层、4 个 token 自编码、50 轮 / lr=1e-3：

| 指标 | 读数 |
|---|---|
| loss_before | 0.3107 |
| loss_after | 0.3050（约 -1.8%） |
| 输出范数 | 11.42 / 10.92 / 11.01 / 11.11 |
| 有限值 | true |

- 所有参数（注意力 Q/K/V、LN1/LN2、FFN1/FFN2）都参与反向传播；loss 下降 1.8%。
- 对比只训练 FFN2（-3.5%）：全参数在小学习率/50 轮下反而更慢——参数多、目标（自编码）
  与随机初始化不匹配；要更明显的收敛需要更大预算或真实任务。
- 边界：仍是自编码目标，不是下游任务；单层、4 token。

### 库化：`agree`

上面十三节的诊断已提升为库模块 `src/agree.rs`：`Diagnosis` 固定 query/readout/基，

`Projected` / `reference` / `trit_weights` / `absmean_row` 可单独使用。
`examples/agree_real` 现在只负责取模型与组织输出，读数与库化前逐位相同；
`tests/agree.rs` 钉住四条性质（单位基投影 == 基准、完整前向 == `Net::forward`、
absmean 边界、体积计数与编码大小关系）。

### 舍入边界（自检）

`examples/agree_real_selftest`（2123 例，不依赖模型）：库的 f32 absmean 与诊断的 f64 口径
2122 例逐位一致。唯一分歧是 `[0.1, 0.2, 0.3]`——f32 下 `0.1/scale` 恰落 `0.5`
（round 远离零 → 1），f64 下略低于 `0.5`（→ 0）。真实权重上未触发这个边界，
`k维输入+sign` 与真实网络仍逐位相等；自检默认只报告，`--strict` 才失败。
- **k=384 反常**：保留 scale 反而更差（0.584 vs 0.678）——满秩时行级 scale 把行间幅度差带回来，
  与 f32 readout 叠加后偏离基准；丢 scale 相当于按行归一化，反而更稳。

### 预测任务为何不算收敛验证（`transformer_f32_task_real`，负结果）

把自编码换成预测：4 个 token 都预测 token 0 的向量。真实 MiniLM 一层、全参数反向。

| rounds / lr | loss | 余弦（4 token） | 符号准确率 | 输出范数 |
|---|---|---|---|---|
| 50 / 1e-3 | 0.3204 → 0.3147（-1.8%） | 0.740 / -0.027 / 0.003 / 0.048 | 0.646 / 0.495 / 0.518 / 0.513 | 11.42 / 10.92 / 11.01 / 11.11 |
| 200 / 1e-2 | 0.3204 → **0.0769**（-76%） | 0.773 / 0.074 / 0.110 / 0.178 | 0.698 / 0.497 / 0.510 / 0.503 | 8.23 / 4.29 / 4.43 / 4.62 |

- loss 是**逐维 MSE**；目标范数只有 **0.767**，而输出范数 11.4 → 单是尺度差就贡献
  (11.3)²/384 ≈ 0.33，正好是 loss_before 的量级。
- 所以 -76% 的下降主要是把输出**压小对齐目标模长**，不是学到方向：余弦（token 1–3 仅
  0.07–0.18）和符号准确率（≈0.5）都停在随机水平。token 0 的 0.74/0.65 来自残差直通。
- 结论：**MSE 下降不能当作收敛证据**。要真正验证下游收敛，需要交叉熵 + 分类头 + 准确率，
  并且需要真实标注数据；之前 STS 真实数据也没跑成（见上一节），当前没有可用标注语料。
- 边界：单层、4 token、自指目标、无真实标签。

### 分类头 + 交叉熵：准确率能到 1.0，但对照说明是头在学（`classifier_real`）

线性头 + softmax 交叉熵，接在 `transformer_f32_full` 的全参数反向上（两者共用一套反向）。
真实 MiniLM 词向量 32 个样本、4 类，标签由固定随机投影教师在输入词向量上取 argmax。

| 配置 | 准确率 | 交叉熵 | block 改动量（query / ff2） | 头改动量 |
|---|---|---|---|---|
| 200 轮，lr_block=1e-4，lr_head=1e-1 | 0.250 → **1.000** | 1.3682 → 0.1077 | 3e-08 / 5.99e-06 | 0.0875 |
| 200 轮，**lr_block=0**（只训头） | 0.250 → **1.000** | 1.3682 → 0.1165 | 0 / 0 | 0.0889 |

- 机会线 0.25、多数类 0.50；标签分布 [7,16,1,8]；准确率轨迹 0.250/0.250/0.344/1.000/1.000
  （轮 1/41/81/121/161）——约第 81–121 轮之间跃升。
- **关键对照**：把 block 学习率置 0，读数与训练 block 完全一致；训练时 block 参数也只动了
  1e-6 量级。教师是输入的**线性**函数，块输出已可线性解码，所以收敛来自**分类头**。
- 结论：交叉熵 + 准确率管线本身成立（`tests/transformer_f32_cls.rs` 也证梯度回到了 block 参数），
  但**这个任务不构成 transformer 块学到的证据**。要让 block 非学不可，教师必须非线性
  （XOR/二次型），届时 `lr_block=0` 应当卡在机会线——这是下一步的判据。
- 边界：单层、32 token、合成标签，非真实标注语料。

### 分类读数是记忆不是泛化（`quad` 教师 + lr_block 扫描，负结果）

为逼 block 参与，换成非线性且类别均衡的教师：二次型 `s = Σ (a_d·x̂_d)²` 按分位切 4 档
（输入先单位化），得到 `hist [8,8,8,8]`、机会 0.25、初始准确率 0.219。

600 轮、lr_head=0.1：

| lr_block | 准确率 | loss | query 改动 | ff2 改动 | head 改动 |
|---|---|---|---|---|---|
| **0（只训头）** | 0.219 → **1.000** | 1.3991 → 0.0559 | 0 | 0 | 0.1338 |
| 1e-2 | 0.219 → 1.000 | 1.3991 → 0.0009 | 2.32e-06 | 2.48e-04 | 0.0607 |
| 1e-1 | 0.219 → 1.000 | 1.3991 → 0.0007 | 5.95e-04 | 1.16e-03 | 0.0442 |

- **只训头的对照同样是 1.000**，三条轨迹都在第 121 轮前到 1.0。
- 原因不在教师，在规模：**32 个样本、384 维特征、头 1536 个参数** ⇒ 线性头能打散任意
  32 点标注（d ≫ N）。所以 1.000 是**记忆**，不是"学会了二次型"。线性教师那边的 1.000
  是同一个原因，此前"头就能解码"的解释只是巧合说得通。
- 方法修正（两次失败，留档）：
  1. tanh 单隐层教师、输入未归一化且权重除 `sqrt(dim)` ⇒ tanh 退化线性，标签 `[0,32,0,0]`；
  2. 改用单位输入 + O(1) 权重 + 小偏置 ⇒ 仍 `[0,30,0,2]`，跨样本 logit 差异不足。
  最后用分位切档的二次型教师才得到均衡标签——但如上，均衡并不解决记忆问题。
- 要真正回答"block 是否学到东西"，必须同时满足：训练/留出分离（报告 test 准确率）+
  样本数 ≫ 特征维 + attention 上下文与样本集解耦（`train_classify` 现在把 `tokens`
  同时当样本与上下文）。
- 边界：单层、32 样本、合成标签、无留出。

### 冻结 block 的留出集上限（`classifier_probe`，闭式岭回归）

回答"block 不动、只训头能不能做这个任务"。样本 1024（768 训练 / 256 留出，d=384），
闭式解 `(XᵗX + λI)W = XᵗY`，λ=1e-2，教师 quad、标签均衡 `[256,256,256,256]`、机会 0.25。

| 探针 | 训练集准确率 | 留出集准确率 |
|---|---|---|
| `raw_embedding`（原始词向量） | 0.9023 | **0.3945** |
| `frozen_block`（冻结块输出） | 0.8906 | **0.3672** |

- **记忆陷阱有了数字**：训练 0.90 / 留出 0.37–0.40，差 ≈0.5。之前"1.000"就是这一段，
  样本数远小于参数时线性头必然过拟合。
- **block 目前没有增益**：冻结块留出 0.367 < 原始词向量 0.395。换句话说，这层对当前
  任务的线性读出是负贡献（attention 混合 + 两层 LN 让信息更"平"）。
- 判据确定：要声称"block 学到了东西"，留出集准确率必须显著超过 **0.40**
  （任务本身的可解码下限），而不是超过 0.25。
- 边界：单层、1024 样本、合成教师、单次切分、未做 k 折；λ 未扫。

### 训练 block 能不能超过冻结基线？（`classifier_holdout`，未证）

把样本与 attention 上下文解耦后（`train_classify_with`），同一套 768 训练 / 256 留出切分上
做两件事：块不动 + 闭式岭回归只拟合头（基线），以及交叉熵同时训练块与头。

| 配置 | loss | 训练集 | 留出集 | ff2 / query 改动 |
|---|---|---|---|---|
| 冻结基线（闭式） | — | 0.8893 | **0.3438** | 0 / 0 |
| 60 步，0.1 / 0.5 | 1.3863 → **21.59** | 0.2474 | 0.2578 | 199.9 / 48.1 |
| 60 步，0 / 0.5（只训头） | 1.3863 → **18.17** | 0.2500 | 0.2539 | 0 / 0 |
| 30 步，0.01 / 0.02 | 1.3863 → 1.3832 | 0.2800 | 0.2190 | 1e-6 / 0 |
| 100 步，0.005 / 0.05 | 1.3863 → 1.3469 | 0.2940 | 0.2700 | 1e-5 / 1e-6 |

- **没有任何一档超过冻结基线的 0.3438**；能说清的只有失败机制。
- 发散不是 block 的错：**只训头（lr_block=0）同样发散**（loss → 18.17），所以是
  `lr_head=0.5` 在 384 维 LN 特征上把 logit 推到几百、softmax 饱和。反向通路本身没问题——

- 所以答案是**未证**，且附一个可复现的失败边界：这条真实尺度下，需要学习率网格 +
  更多步数（每步 128 样本约 4.5 秒，100 步 ≈ 8 分钟），否则读数只会落在"发散"或"不动"两端。
- 边界：单层、单次切分、λ 未扫、上下文 64 为人为选择、合成标签。

|---|---|---|---|---|---|
| 0.03 | 1.3863 → 1.3160 | 0.406 | 0.4049 | 0.2539 | 2.2e-05 |
| 0.05 | 1.3863 → 1.3010 | 0.375 | 0.3281 | 0.2539 | 3.4e-05 |
| 0.08 | 1.3863 → 1.3223 | 0.391 | 0.3112 | 0.2461 | 5.7e-05 |
| 0.12 | 1.3863 → 1.3202 | 0.414 | 0.3021 | **0.2266** | 8.7e-05 |
| 0（只训头） | 1.3863 → 1.3282 | 0.359 | 0.3164 | 0.2500 | 0 |

- 与 lr_head=0.5 不同，这一区间不发散；但**留出集全部停在机会线附近**，没有一档接近
  冻结基线的 0.3438。
- 判定关键：**训练集最高 0.4049 vs 闭式解 0.8893**。SGD 连训练集都没拟合上，说明预算远未
  收敛——因此"没超过基线"不能归因于 block 的表达力，只能归因于优化预算。
- 另一条独立观察：训练 block 后留出集反而降到 0.2266–0.2539（**低于**冻结的 0.3438），
  即当前预算下更新 block 是在破坏可线性解码性；lr_head 越大破坏越明显（0.12 → 0.2266），
  而训练集越高 ⇒ 拟合噪声。
- 若继续：把步数提到 2000 量级（每步约 4.5 秒 ⇒ 约 2.5 小时），或换 Adam / 特征标准化，
  这些都不在本轮范围内。
- 边界：单次切分、λ 未扫、上下文 64 为人为选择、合成标签。

### 换优化器：Adam（`classifier_train`）

诊断：plain SGD 同一预算下训练集只到 0.40，而同特征闭式解 0.89 ⇒ 不是表达力问题，
是 384 维 LayerNorm 输出的条件数。Adam 用二阶矩逐参数缩放，对尺度不敏感。

实现要点与两个坑：

- `Grads` 搬到独立模块 `grads`，新增 `TensorAdam`（m/v + 偏置校正）与 `BlockAdam`
  （块内 11 个张量各一份状态）。
- **坑 1**：`Grads::add` 一度写成 `&mut self.query.clone()`，累加写进临时副本 ⇒ 梯度全丢。
- **坑 2**：Adam 状态曾在每次训练调用内新建，小批量循环下动量每步归零，退化成近似
  sign-SGD，loss 反升（1.3863 → 1.45~1.89）。改显式 `AdamState` 跨步复用后才正常。
- 顺带消掉每步 11 个张量的临时分配（`ff1/ff2` 权重各 59 万个 f32），否则一次
  200 步 × 四路并行要跑近 40 分钟。

30 步小规模读数（冻结基线留出 0.3438、机会 0.25）：

| lr_block | lr_head | loss | 训练集 | 留出集 | ff2 改动 |
|---|---|---|---|---|---|
| 1e-3 | 1e-2 | 1.3863 → 1.4159 | 0.2747 | 0.2695 | 3.7e-3 |
| 1e-2 | 1e-2 | 1.3863 → 1.3865 | 0.2617 | 0.2227 | 3.2e-2 |

块确实开始被训练了（改动量 1e-5 → 1e-2 量级），但 30 步太少，loss 仍在上坡。
`tests/classifier_adam.rs` 在玩具尺度上证明 Adam 80 步能从零学到了 ≥0.75，
所以通路没问题，卡的是真实尺度的预算。

### 块被大幅改动却学不到：排除优化器与预算（Adam，负结果）

`AdamState` 修好后重跑。冻结基线留出 0.3438、机会 0.25。

| 配置 | loss | 训练集 | 留出集 | ff2 / query 改动 |
|---|---|---|---|---|
| 冻结基线（闭式） | — | 0.8893 | **0.3438** | 0 / 0 |
| Adam 30 步，1e-3 / 1e-2 | 1.3863 → 1.4159 | 0.2747 | 0.2695 | 3.7e-3 / — |
| Adam 30 步，1e-2 / 1e-2 | 1.3863 → 1.3865 | 0.2617 | 0.2227 | 3.2e-2 / — |
| Adam 60 步，1e-2 / 1e-2 | 1.3863 → 1.3786 | 0.2734 | 0.2188 | 3.5e-2 / 5.3e-2 |

- 块改动量 5e-2 量级（SGD 只有 1e-5），loss 只降 0.6%，留出集跌到机会线以下。
- **排除"优化器不行"**：Adam 确实把块推动了 3~4 个数量级。
- **排除"仅仅预算不足"**：改动这么大还没学到，说明方向本身没用。
- 剩下的解释：**任务与该层表示不匹配**。二次型分位标签不能由这一层的线性读出泛化；
  训练会破坏原有的可解码性（0.3438 → 0.219），也就是"越训越差"。
- 实测算力约束：真实尺度每步约 20 秒（128 样本），200 步单路约 1 小时；两路 200 步跑到
  39 分钟仍未收尾被中止，所以本轮只到 60 步。
- 要真正验证表征学习，得改读出或任务：①残差拼接读出 `[x2, embed]`（原始词向量单独就有
  0.3945，拼上后基线会立刻抬高）；②非线性头；③真实下游数据。合成二次型 + 单层 + 线性读出
  这条路已被本轮读数否掉。

### 块没有增量信息——但任务设计本身对块不公平

三路闭式读出，同一套切分（1024 样本 / 64 上下文 / 768 训练 + 256 留出、λ=1e-2）：

| 读出 | 维度 | 训练集 | 留出集 |
|---|---|---|---|
| `raw`（原始词向量） | 384 | 0.9023 | **0.3945** |
| `block`（冻结块输出） | 384 | 0.8893 | 0.3438 |
| `concat`（拼接） | 768 | **0.9701** | 0.3672 |

- 拼接后训练集 0.9701（拟合更强）但留出集 0.3672 < `raw` ⇒ **块没有增量信息**，
  拼上只是稀释原始信号 + 扩大过拟合空间。
- **关键反思：任务设计对块不公平。** quad 标签只依赖 token 自身，而块相对原始向量的
  唯一新增能力是"attention 混合上下文 + FFN"。标签与上下文无关时，绕过块直接用原始向量
  就是最优解，块只会扰动信号。于是 0.3438 < 0.3945 是**结构必然**，Adam 训练把留出拍到
  0.219 也同源：在一个与任务无关的算子上乱动。
- 之前几轮（SGD 网格、Adam、冻结探针）的负结果都应在这个前提下重读：它们证明的是
  "这一层对**忽略上下文的任务**没有增益"，而不是"这一层没有表征能力"。
- 下一步：设计**必须读上下文**的标签（由 context 聚合决定），才是对块公平的判据。

### 换成必须读上下文的任务，块仍无增益（`classifier_context`）

标签改为 `h = Σ softmax(cos/T)·ctx`（T=0.1）的固定投影按分位切 4 档，**必须读上下文**
才能算出来。同一套切分、λ=1e-2、机会 0.25：

| 任务 | 读出 | 训练集 | 留出集 |
|---|---|---|---|
| quad（只看自身） | `raw` | 0.9023 | **0.3945** |
| quad | `block` | 0.8893 | 0.3438 |
| quad | `concat` | 0.9701 | 0.3672 |
| **context（必须读上下文）** | `raw` | 0.8867 | **0.3906** |
| context | `block` | 0.9102 | **0.2969** |
| context | `concat` | 0.9792 | 0.3516 |

- 换到公平任务后结论不变：块 0.2969 < raw 0.3906，拼接 0.3516 也低于 raw。
- 方法修正：初版用硬 argmax 取最近邻 context 的类别，标签塌成常数
  `[11,995,7,11]`，三路都靠猜多数类到 0.99+（平凡解）；改软加权池化 + 分位后才均衡。
- 本轮累计排除：优化器、预算、读出层（拼接无增益）、任务是否读上下文。
- 剩下未被排除的：合成任务（线性投影 + 分位）与本层预训练表示的匹配度低，真实下游验证
  需要标注语料（本仓没有）。因此该问题在当前条件下**不可判**，不是已证否。

### 逐层线性探针：深度不带来可解码性（`classifier_layers`）

MiniLM-L6 六层真实权重依次堆叠，每层输出做闭式岭回归（768/256、λ=1e-2、机会 0.25）：

| 读出 | quad 训练/留出 | context 训练/留出 |
|---|---|---|
| `raw` | 0.9010 / **0.3906** | 0.8841 / **0.4023** |
| layer 0 | 0.8906 / 0.3750 | 0.8932 / 0.3789 |
| layer 1 | 0.8750 / 0.3555 | 0.8828 / 0.3672 |
| layer 2 | 0.8607 / 0.3047 | 0.8659 / 0.3359 |
| layer 3 | 0.8529 / 0.3281 | 0.8333 / 0.3477 |
| layer 4 | 0.7891 / 0.3359 | 0.8073 / 0.3398 |
| layer 5 | 0.7721 / 0.3203 | 0.7617 / 0.3516 |

- 两个任务下都**随深度下降**；训练集也从 0.90 掉到 0.77（深层更难拟合这批标签）。
- 结论：**"层数不足"被排除**。之前单层的负结果不能靠堆层补救。
- 边界：样本只对固定 64 个 context token 做注意力（不是全序列 self-attention）；
  `F32Attention` 忽略 attention bias；无 position embedding；任务是合成"线性投影 + 分位"。
  这些简化都会削弱深层相对浅层的优势，所以"深层更差"不能直接推广到真实 BERT 推理。

### 真实 STS 语料：深层终于有增益（`classifier_sts`）

**语料获取**（此前"读十二"失败的真因）：本地 `datasets--mteb--stsbenchmark-sts` 的 blob
是 **0 字节空占位**；HF 直连 **429 限速**（要 token）；爱丁堡官方源 DNS 不通；
`hf-mirror.com` 镜像可用 → 拿到 train 5749 / dev 1500 / test 1379 对真实 STS 数据。

**方法**：basic tokenizer + 标准 WordPiece（vocab 30522、unk_rate 0.0002、平均 10.62 token），
句向量 = token 平均；指标 = Spearman(cosine, 人类 0–5 分)。

test 全量 1379 对：

| 读出 | Spearman |
|---|---|
| `raw`（词向量平均） | 0.5621 |
| `layer 0` | 0.5509 |
| **`layer 5`** | **0.6157** |

- **深层比 raw 高 5.4 个点**，与合成任务上"随深度下降"完全相反。
- 于是前面七轮负结果的解读要修正：问题在**合成任务与预训练表示不匹配**，
  不在这一层有没有表征能力。
- 边界：无 [CLS]/[SEP]、无 position embedding、单层、token 平均、未微调 ⇒ 绝对值 0.62
  远低于官方 MiniLM（约 0.82）；但同一流水线内三方对比有效。
- 数据不入库：示例要 <model.safetensors> <vocab.txt> <test.tsv> 三个外部输入。

## 结论

- k≥4 全部落在 **0.45–0.49**，不随 k 单调改善；**全维（k=384）也只有 0.4766**。
- 也就是说：三值学生在 STS 类排序任务上**本来就不行**，这不是降维的锅，是**三值化本身**的损失。
- 与前面九节互补：那边全维能 1.000 复现自己（行为克隆），这边全维只有 0.48（任务）。
  **换判据后，主要矛盾从「能不能降维」变成「三值化能不能保住任务」。**

## 结论

1. **PCA 基下不支持降维运行；判据基下 k=1 就够**——差别不在维度，在方向。
2. **量化代价不是常数**：PCA 基下同 k 的三值与 f32 差 14 点，但方向选对时 k=1 的三值路径
   也能 1.000。三值化本身不贵，贵的是「把判据混进一堆无用方向里再取符号」。
3. **方差排序 ≠ 思考必要性**：`cos = 0.0086` 给了定量证据；只有监督基的排序才有意义。
4. **非单调是真实的**，监督基把它推到极端：k=1 最好，k=2 立刻变差。
5. **「有些思考没必要」的可计算形式**：在固定判据下，128 个方向里 127 个不必要；剩下那 1 个
   不能靠无监督方差找到。

## 库化：`Layer::project`

上面十节的结论已经落成库能力：`crates/trit-wspace/src/project.rs` 的 `Layer::project(&basis)`。

```rust
// 用三值基把一层从 cols 维压到 k 维
let compressed = layer.project(&basis)?;   // rows × k
```

语义与 `dimsweep` 里的降维学生一致：`out[r][i] = sign(Σ_j basis[i][j] · self[r][j])`。
不同之处是**基不再是实验内部的 `Vec<f64>`，而是一层三值权重**——所以它能被 `patch` 编辑、
被 `repair` 修补、被 `certify` 验证，也就能存成工件、跨模型复用。

`tests/project.rs` 钉了四条不变量：恒等基不动、维度按 k 缩减、列数不匹配报错、bias 保留。

CLI 已接：`project <artifact|-> --basis <artifact> --out <path> [--layer N]`。
基不需要新格式——它本身就是一层三值权重，按普通 WSP 存即可。

导出基：`dimsweep --out-basis basis.wsp`——当前基（`pca` 或 `supervised`）逐行三值化后写成
一层 WSP，实测 `arch [384, 32]`、`trits 12320`。于是整条链路闭环：

```text
dimsweep --basis supervised --max-k 32 --out-basis basis.wsp
trit-wspace project net.wsp --basis basis.wsp --out small.wsp
trit-wspace certify small.wsp --keep ...
```

注意：导出维度由 `--max-k` 决定，没有单独的「导出多少个基向量」参数。

### `project` 的默认健康检查

`project` 写完工件后会顺手报一个 `agree`：在 64 个随机三值输入上，把原输入按基投影到 k 维，
再比较**原网络**与**投影网络**的输出一致率。

```json
"agree": { "samples": 64, "same": 41, "rate": 0.640625 }
```

这是「压完值不值」的第一道读数：rate 太低就该换更大的 k 或换基，不必再手动串 probe / certify。
注意随机输入不含真实分布信息，真实数据上的 agree 可能更高。

**三条已补齐**：

- `--samples N`：采样数可调（默认 64）。
- `--agree-from <oracle.json>`：用 oracle 工件里的真实输入采样，`source` 会标 `oracle`；
  这是把 `rate` 从「随机粗筛」变成「真实分布保真度」的开关。
- `mismatches`：前 3 个不一致样本（输入 + 两侧输出）。

为腾出模块台账空间，顺带把 `cmd_read` / `cmd_diff` 拆成了独立文件（`cli.rs` 653 → 627）。
