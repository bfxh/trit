# TTX：三进制资产容器格式——竞争力定位与规范

> 自有格式，先回答「它相对业界格式有多强、弱在哪、凭什么存在」，再给字节级规范。
> 数字全部可复算：纹理侧 `cargo run -p trit-texture` / `cargo bench -p trit-texture`，
> 模型侧 `cargo test -p trit-texture ttx2`。结论分四类记账（A 红利 / B 税 /
> C 生态 / D 无关），见 [TERNARY-BOUNDARIES.md](TERNARY-BOUNDARIES.md)。

## 0. 一句话

TTX 是**按内容的基数（3）设计**的资产容器：纹理索引、模型权重、偏置、校验和
全部走同一套 5 trit/字节基 3 打包（1.6 bit/trit），容器校验用 GF(3) CRC-16
（本原多项式）。它**不追求**打败 BC7/ASTC 的画质或 PNG 的通用性——它占的位置
是「三进制资产的原生交换格式」。

## 1. 纹理侧：TT3/TTX 对比业界格式

| 格式 | 码率 (bpp) | 画质机制 | GPU 采样 | 检错 | 定码率 |
|---|---|---|---|---|---|
| 原始 RGBA8 | 32 | 无损 | 直接 | — | 是 |
| PNG | ~8–25（可变） | 无损（zlib） | 否（CPU 解码） | 每块 CRC-32 | 否 |
| QOI | ~6–20（可变） | 无损（预测码） | 否 | 无 | 否 |
| BC1/DXT1 | 4.0 | 4×4 块，4 色调色板 | **硬件采样** | 无 | 是 |
| BC7 | 8.0 | 高质量多模式 | **硬件采样** | 无 | 是 |
| ETC2 (RGB) | 4.0 | 块+翻转模式 | **硬件采样** | 无 | 是 |
| ASTC | 0.89–8 可配 | 多 footprint | **硬件采样** | 无 | 是 |
| BasisU/KTX2 | ~1–2（转码后） | RDO+转码 | 转码后硬件采样 | 无 | 否 |
| **TT3/TTX (TEX)** | **2.125** | 8×8 块，**3 色**调色板 | 计算解码（本仓 WGSL 内核） | **GF(3) CRC-16**（v2）/CRC-3（v1） | 是 |

**强在哪（有数字支撑）：**

- **码率**：2.125 bpp < BC1/ETC2 的 4.0（-47%），且这个数字在**真实 mip 链**里站得住：
  8×8 是 2 的幂，每级减半都不需要补边；旧的 4×10 名义 2.40、补边后实际 3.00。
- **载荷**：64 trit 占 65 槽（13 字节），打包税 1.6%——**不是零浪费**，
  换来的是 mip 全程对齐；同 3 色下 trit 索引 13 字节 < 2-bit 16 字节（省 18.75%）。
- **定码率 + O(1) 寻址**：每块恒 17 字节，任何纹素的偏移可算，适合 GPU 直载。
- **检错**（v2 容器）：载荷 trit 按 GF(3) CRC-16（**x¹⁶+x⁷+2**，本原）校验，
  **≤16 连续 trit 的突发错全检**，随机错图样漏检概率 ≈ 3⁻¹⁶ ≈ 4.6×10⁻⁸；
  BC/ASTC 等块压缩格式没有容器级检错，PNG 有 CRC-32 但不定码率。二进制格式
  的校验用比特 CRC，TTX 按内容自己的基数算——**A 类设计选择**。
- **解码路径齐全**：CPU（`decode_rgba`）+ GPU 计算解码（`trit-gpu` 的 WGSL 内核，
  真机对拍逐字节一致）；编码实测 1025 MB/s（criterion，PR #119）。
- **容器开销**：TTX1 = 17 字节定头尾；TTX2 = 16 字节定头 + 4 字节校验尾；
  128×70 纹理约 +0.7%，4K 纹理 < 0.05%。

**弱在哪（如实）：**

- **3 色调色板画质天花板**：BC1 是 4 色（含两个插值色），ASTC 更高；TT3 每块
  只有 {e0, mid, e1}。平滑/量化风内容合适，照片细节不指望打过 BC7。
- **无硬件采样器支持**（C 类）：采样要走 compute 解码或 CPU 解码；BC*/ETC*/ASTC
  有固定功能单元。这是「自有格式」的宿命，不装作优势。
- **8×8 的代价**：块内索引载荷 13 字节里有 1 个闲置 trit 槽（打包税 1.6%）。
  这是为了 mip 对齐付的税，比 4×10 的 25% 补边便宜得多（旧布局的教训见 §「v1 的教训」）。
- **无 alpha 通道**（解码恒 255）、无 sRGB、无 HDR。实验格式，无生态工具链。

## 2. 模型侧：TTX (MOD) 对比业界权重格式

| 格式 | 每权重比特 | 权重集 | GPU 载入 | 检错 |
|---|---|---|---|---|
| safetensors (f16) | 16 | 任意浮点 | 直载（原始张量） | 无 |
| GGUF Q2_K | ≈2.56 | 量化桶 + 超块 scale | 需反量化内核 | 无（hash 可选） |
| BitNet b1.58（理论） | log₂3 ≈ 1.585 | {-1,0,+1} | 定制内核 | — |
| **TTX (MOD)** | **1.6（基 3 打包）** | {-1,0,+1} | `to_dual_rail()` 一次转换后直载 | **GF(3) CRC-16** |

**强在哪：**

- **1.6 bit/权重**：比 Q2_K ≈2.56 省 37.5%，比理论下限 1.585 只多 0.9%——
  权重与偏置、纹理索引、校验流**全套同一套基 3 打包**，格式里没有第二进制制
  （**A 类**：按内容自己的基数装内容）。
- **兼容三优先级**（本轮重构的主轴）：
  - *trit-net 语义兼容*：`rows()` 无损取回 `Vec<Vec<i8>>`；**层间维度衔接
    （上层输出 = 下层输入）在容器层强制**，与 trit-net `Model::validate` 同语义。
  - *GPU 兼容*：`TritModelLayer::to_dual_rail()` 显式转成 trit-gpu matmul 内核
    的 storage buffer 布局（行整字、bit = 1<<(i%32)），位布局有手算常量钉死。
  - *版本兼容*：TTX1 冻结不动；v2 内演进靠 kind/flags 显式拒绝，不静默猜。
- **校验强度**：权重 + 偏置 trit 流过 GF(3) CRC-16，≤16 连续 trit 突发错全检
  （有穷举测试：40 权重里每个 16-trit 窗口翻转都被抓）；safetensors/GGUF 无
  容器级校验。

**弱在哪（如实）：**

- **GPU 上传多一步转换**：存储用基 3（省 20% 体积），popcount 内核要双轨——
  加载后 `to_dual_rail()` 一次 O(n) 转换（D 类成本，与进制取舍无关）。
  v2 首版曾直接存双轨（零重排但 2 bit/权重 +26%），按「兼容、强度、三进制
  原生」三优先级重构为基 3 存储。
- **只有线性层链**：没有卷积/注意力/名字表/张量命名——是三值 MLP 的交换格式，
  不是通用模型格式。对标的是「BitNet 风格权重的最小可校验容器」。

## 3. 特点清单（两种载荷共有）

1. **小端、定头、逐段校验**：魔数/版本/kind/flags/段长/内容校验和，任何不一致
   都是结构化错误（错误枚举带实际值），绝不猜；解析器全程 checked 算术，
   32 位目标上恶意声明不能回绕骗过长度对账。
2. **校验按内容基数**：GF(3) CRC-16，生成多项式 **x¹⁶+x⁷+2** 本原（x 模 g 的
   阶 = 3¹⁶−1 = 43046720，素因子 {2,5,17,41,193} 逐一排除，独立 Python 验算），
   16 余数 trit 打包 4 字节小端。TTX1 的 CRC-3（x³+2x+1 的互反 x³+2x²+1，
   单 trit 错全检）随 v1 冻结。
3. **零依赖解析**：解析器只做算术与比较，无 serde/alloc 大头（读入时按段切片）。
4. **版本策略**：TTX1（PR #125，纯纹理）保持可读；TTX2 容器 kind 分流，
   未知 kind/非零 flags 显式拒绝（前向兼容留给未来版本号，不留静默猜测）。

## 4. 文件扩展名规范（严格）

**唯一注册扩展名：`.ttx`（小写）。** 规则：

1. **魔数是唯一事实源**：`.ttx` 文件可能是 TTX1（纹理）或 TTX2（kind=TEX/MOD），
   判定只看文件头魔数（`TTX1`/`TTX2`）与 kind 字节，**绝不看后缀**。后缀是给人
   和工具链的提示，不是格式判定依据。
2. **禁止变体后缀**：`.ttx1`、`.ttx2`、`.ttm`、`.ttxm` 等一律不注册不使用——
   后缀分裂会在文件系统、MIME、工具链三个层面制造「同格式多名字」的兼容债。
3. **大小写**：规范小写 `.ttx`。在不区分大小写的文件系统（Windows/默认 macOS）
   上读到 `.TTX` 也按魔数处理，但工具写文件时一律输出小写。
4. **MIME 建议**：`application/x-ttx`（未注册 IANA 类型；格式标准化前不申请，
   避免占坑后改语义）。
5. **新扩展名准入政策**：本仓**不为每个新格式发明新后缀**。只有当格式本身有
   **三进制原生红利（A 类）**——即 radix-3 打包或 GF(3) 校验在该格式的
   主体数据上带来可复算的体积/强度收益——才考虑注册新的独立后缀；纯容器套壳、
   与现有格式逐字节等价、或收益只在二进制层面的一律**复用现有后缀/容器**
   （如 `.bin`、`.json`），不做「后缀通胀」。
6. **工具行为**：本仓工具读写 TTX 时对后缀不敏感（读任何路径、按魔数分派）；
   写默认 `.ttx`，用户显式指定其他后缀时照写不拒（后缀不是合同）。

## 5. TTX1 布局（纹理，v1，冻结）

```text
0     4    magic "TTX1"
4     4    width  u32 LE（4 的倍数）
8     4    height u32 LE（10 的倍数）
12    4    blocks u32 LE（= (width/4)·(height/10)）
16    12N  块载荷（4 字节 RGB565 端点对 + 8 字节基 3 索引）
16+12N 1   GF(3) CRC-3（对全部块的 40·N 个索引 trit；除数为 x³+2x+1 的
            互反多项式 x³+2x²+1，行为随 v1 冻结）
```

## 6. TTX2 布局（容器，v2）

```text
0     4    magic "TTX2"
4     1    kind：0 = TEX（纹理+mip 链），1 = MOD（三值模型）
5     1    flags（bit0 = 8×8 布局；0 = 旧 4×10 → 结构化拒绝；未知位拒绝）
6     2    reserved（必须 0）
8     4    section_len u32 LE（kind 段字节数，不含头尾）
12    S    kind 段（见下）
12+S  4    GF(3) CRC-16（g = x¹⁶+x⁷+2 本原；16 余数 trit 低次在前
            Σ r_i·3^i 打成 u32 小端；对 kind 段的规范 trit 流计算）
```

### 6.1 kind = TEX（GPU 纹理 + mip 链）

```text
0     4    level_count u32 LE（≥1）
每级：
+0    4    width  u32 LE（4 的倍数，≥4）
+4    4    height u32 LE（10 的倍数，≥10）
+8    12B  块载荷（B = (width/4)·(height/10) 块，行主序）
```

约束：每级宽高不增且至少一维严格递减（末级之后不得再有同级）； mip 语义
（半分辨率）由写者负责，容器只钉形状合法与字节对账。**规范 trit 流** =
各级全部索引 trit 依序拼接（与 TTX1 同一抽取：每块后 8 字节按 5 trit/字节
解出 40 个 trit）。

### 6.2 kind = MOD（三值模型，基 3 打包）

```text
0     4    layer_count u32 LE（≥1）
每层：
+0    4    inputs  u32 LE（≥1）
+4    4    outputs u32 LE（≥1）
+8    W    权重：outputs·inputs 个 trit 基 3 打包（5/字节，行主序），
            W = ceil(outputs·inputs / 5) 字节
+8+W  B    偏置：outputs 个 trit 基 3 打包，B = ceil(outputs / 5) 字节
```

digit 映射（权重与偏置同）：`-1→0，0→1，+1→2`（value+1）；低次 trit 在低位
（`Σ digit_i · 3^i`）。**规范 trit 流** = 每层全部权重 trit（行主序，自然个数
无填充）依序 + 该层偏置 trit。约束：**层间衔接（第 i 层 inputs = 第 i-1 层
outputs）由容器强制**（读写同一校验）；层内取值域由 digit 天然限定。

## 7. 转换（已落地）

分层（按本仓发布图门的规矩：**实验层之间禁止常规路径依赖**——独立转换 crate
依赖 trit-texture 会被 `publish_graph` 门拦下，自测钉死；所以文件 I/O 以
**可选 feature** 收进格式 crate，默认构建依旧零图像解码依赖）：

1. **纯转换**（默认构建就有）：`trit_texture::convert`——RGBA ↔ TTX1/TTX2、
   TTX1 ↔ TTX2 升降级（降级仅单级 TEX，mip 链显式拒绝）、盒式 mip 链构造。
2. **PNG 文件 I/O**（`png` feature，默认关）：`trit_texture::pngio`——
   RGBA8/RGB8 读入、RGBA8 写出。
3. **CLI**：`cargo run -p trit-texture --features png --bin ttx-convert -- …`
   ——`png-to-ttx`（`--v1`/`--mip`）、`ttx-to-png`、`ttx-upgrade`、`ttx-downgrade`。
4. **GPU 端到端**（trit-gpu `forward`）：MOD 权重 `to_dual_rail()` 后直接上传
   naive matmul 内核——真机测试逐元素对拍（含 inputs=33 跨行边界；
   该测试曾抓到行起点不在字边界的真 bug，已修并钉死）。
5. **trit-net 兼容**：`Model`/`Layer` ↔ `TritModelLayer` 经 `rows()` 无损往返，
   断链两边同语义拒绝（trit-net 集成测试钉住）。

### GGUF → MOD 入向导入（`trit-texture::gguf`）

- 支持 **GGUF v2/v3**、未量化张量 `F32`/`F16`/`BF16`；`*.weight`（2D）+ 同名 `*.bias`
  （可选，缺省补 0）按名字排序成层，层间衔接由 `TritModel::new` 强制。
- 三值化：`v > ε → +1`、`v < -ε → -1`、其余 `0`（默认 ε=0 即纯符号，`--threshold` 可加稀疏）。
- CLI：`cargo run -p trit-texture --bin gguf-to-mod -- in.gguf out.ttx [--threshold F] [--tensor NAME ...]`。
- **不支持** `TQ1_0`/`TQ2_0`/`Q*_K` 等量化类型（位布局未在本仓验证，显式拒绝而不是猜）；
  只产出线性层链，不处理卷积/注意力/名字表。预算：文件 256 MiB、权重 5000 万个。
