# TTX：三进制资产容器格式——竞争力定位与规范

> 自有格式，先回答「它相对业界格式有多强、弱在哪、凭什么存在」，再给字节级规范。
> 数字全部可复算：纹理侧 `cargo run -p trit-texture` / `cargo bench -p trit-texture`，
> 模型侧 `cargo test -p trit-texture ttx2`。结论分四类记账（A 红利 / B 税 /
> C 生态 / D 无关），见 [TERNARY-BOUNDARIES.md](TERNARY-BOUNDARIES.md)。

## 0. 一句话

TTX 是**按内容的基数（3）设计**的资产容器：纹理侧把 3 级调色板索引用
log₂3≈1.585 bit 的 trit 打包（8×8 块下索引载荷 13 vs 16 字节，省 18.75%；但
64 trit 仍占 65 槽，打包税 1.6%——**不是零浪费**），模型侧把 {-1,0,+1} 权重存成
GPU 内核直接消费的双轨位布局，两侧共用 GF(3) CRC-3 校验。它**不追求**打败
BC7/ASTC 的画质或 PNG 的通用性——它占的位置是「三进制资产的原生交换格式」。

## 1. 纹理侧：TT3/TTX 对比业界格式

| 格式 | 码率 (bpp) | 画质机制 | GPU 采样 | 检错 | 定码率 |
|---|---|---|---|---|---|
| 原始 RGBA8 | 32 | 无损 | 直接 | — | 是 |
| PNG | ~8–25（可变） | 无损（zlib） | 否（CPU 解码） | 每块 CRC-32 | 否 |
| QOI | ~6–20（可变） | 无损（预测码） | 否 | 无 | 否 |
| BC1/DXT1 | 4.0 | 4×4 块，4 色调色板 | **硬件采样** | 无 | 是 |
| BC7 | 8.0 | 高质量多模式 | **硬件采样** | 无 | 是 |
| ETC2 (RGB) | 4.0 | 块+翻转模式 | **硬件采样** | 无 | 是 |
| ASTC | 0.89–8 可配 | 多 footprint | **硬件采样** | 无 | 是 |
| BasisU/KTX2 | ~1–2（转码后） | RDO+转码 | 转码后硬件采样 | 无 | 否 |
| **TT3/TTX (TEX) v2** | **2.125** | 8×8 块，**3 色**调色板 | 计算解码（本仓 WGSL 内核） | **GF(3) CRC-3** | 是 |
| TT3 v1（已废弃的 4×10） | 2.40 名义 / 3.00 实际 | 4×10 块，3 色调色板 | 同 v2 | 同 v2 | 是 |

**强在哪（有数字支撑）：**

- **码率**：v2 **2.125 bpp < BC1/ETC2 的 4.0（-47%）**，且**这个数字在真实 mip 管线里站得住**
  （v1 名义 2.40、补边后实际 3.00，见下面「v1 的教训」）。
  同块结构同 3 级调色板下，trit 索引载荷 13 字节 < 2-bit 方案 16 字节（省 18.75% 载荷），
  PSNR 差 0.000 dB——**A 类红利**。
- **定码率 + O(1) 寻址**：每块恒 17 字节，适合 GPU 直载。
- **检错**：载荷 trit 按 GF(3) CRC-3（x³+2x+1 本原）校验，**单 trit 错全检**。
- **解码路径齐全**：CPU（`decode_rgba`）+ GPU 计算解码（`trit-gpu` 的 WGSL 内核）。

**弱在哪（如实）：**

- **画质天花板，且主因不是调色板而是块尺寸**。480×480 真实照片裁片实测，两组端点
  用同等强度的坐标搜索优化，变量受控：

  | 配置 | bpp | PSNR |
  |---|---|---|
  | TT3 3 色 8×8 | 2.125 | 32.93 |
  | 4 色 8×8（2 bit） | 2.500 | 35.10 |
  | 4 色 4×4（BC1 形状，2 bit） | 4.000 | **39.18** |

  拆开两个变量：**调色板 3→4 色 +2.17 dB**，**块 8×8→4×4 +4.08 dB**。块形状的
  影响更大，而它**与进制完全无关**——二进制格式同样可以选块尺寸。对 BC1 的总差距
  约 **6.3 dB**，代价换来的是 -47% 字节。这是真实取舍，不是靠端点优化能消掉的。
  > 早期本文写过「只差 0.6~1.9 dB」，那是拿**共享 TT3 块结构**的模拟 4 色模式对比，
  > 混淆了调色板与块尺寸两个变量，**结论已撤回**。
- **结构性张力** [D 类]：三进制的 A 类红利（打包省字节）**只有在大块下才体现**
  ——8×8 才有 13 vs 16 字节的载荷差；而大块正是画质损失的主因。缩到 4×4 追画质时，
  3 色 trit 是 4 字节端点 + ceil(16/5)=4 字节 = 8 字节 = **4.0 bpp，与 BC1 同码率**，
  字节优势清零。**省字节与画质在这个设计空间里是对立的。**

  块越大，三进制越划算（打包税越小），但画质越差：

  | 块形状 | 3 色 trit | 4 色 2 bit | trit 省多少 | 打包税 |
  |---|---|---|---|---|
  | 4×4 | 8 B = 4.000 bpp | 8 B = 4.000 bpp | **0%** | 20.0%（16 trit 占 20 槽） |
  | 8×8 | 17 B = 2.125 bpp | 20 B = 2.500 bpp | **15%** | 1.6% |
  | 16×16 | 56 B = 1.750 bpp | 68 B = 2.125 bpp | 17.6% | 0.4% |

  这正是 v1 选 4×10 的动机（40 恰被 5 整除，打包税 0%），也是它药效最差的原因。
  **红利最大的地方，恰是画质最贵的地方。**

- **「4 色调色板」是死路（已验证，不再重提）**。扩到 4 色需要 64 × 2 bit = 128 bit =
  **16 字节整**，而 `4^64 == 2^128` **精确相等**——4 色索引的信息量恰好是整数个字节，
  二进制打包已达信息论最优，**任何进制都赢不了它**；三进制绕道更差
  （ceil(128 / log₂3) = 81 trit = 17 字节）。所以「4 色三进制」是自相矛盾的词组：
  - 8×8 用 2 bit：20 字节 = 2.5 bpp（纯二进制，三进制红利归零）
  - 8×8 用 2 trit：26 字节 = 3.75 bpp，比最优多扔 62.5% 字节换 **0 dB**
  - 8×8 用基 3 打包 81 trit：21 字节 = 2.625 bpp，仍是 0 dB

  三个打包方案 PSNR **完全相同**（画质只由调色板决定，打包只改字节数）。要画质
  就该正视：那是 **D 类**换格式（实质上变成 BC1 的近亲），不是 TT3 的升级。
- **无硬件采样器支持**（C 类）：采样要走 compute 解码或 CPU 解码；BC*/ETC*/ASTC
  有固定功能单元。这是「自有格式」的宿命，不装作优势。
- **无 alpha 通道**（解码恒 255）、无 sRGB、无 HDR。实验格式，无生态工具链。

### v1 的教训：4×10 的「零槽位浪费」是局部最优，全局是亏的

> 本节是**历史记录**：4×10 是 v1 的块形状，已在 v2 改成 8×8，本 crate 不再支持它。

v1 用 4×10 = 40 纹素，理由是 40 恰被 5 整除 ⇒ 载荷 8 字节，**零槽位浪费**；每块 12 字节 = 2.40 bpp。
看着比 v2 的 2.125 更好？**恰恰相反**：

- 10 不是 2 的幂，而 mip 每级高度减半后仍须 %10。正常 2 的幂纹理
  （256/512/1024/2048）**没有一个**是 10 的倍数，必须补到 `10·2^(n-1)` 的倍数——
  **恒定 25% 高度填充**，名义 2.40 实际 **3.00 bpp**（相对 BC1 只省 25%，不是 40%）。
  高 64 的纹理甚至只能拿到 1 级 mip。
- v2 的 8×8 付 **1.6%** 打包税（ceil(64/5) = 13 字节，65 槽用 64），换来全程合法的
  mip 链与 2.125 bpp。**2^n 永远不被 5 整除，「零槽位浪费」与「mip 友好」不可兼得**，
  选后者。

### 端点选择：一个不花字节的画质增益

min/max 端点只在端点色恰好落在块极值角上时才最优；真实纹理的色簇多沿斜线分布。
`endpoints.rs` 的精修分两层：

1. **保留最优**：每轮用**精确块内误差**打分，只采纳严格变好的结果。
   > 为什么必须这样：Lloyd 迭代 + RGB565 再量化**不是单调的**，直接采纳最后一轮
   > 会让误差在平坦块上反升（实测 −0.8 dB）。这是实现缺陷，不是格式限制。
2. **565 格点爬山**：最后在 RGB565 格点上做 ±1 级贪心爬山，擦掉 Lloyd 整数除法
   带来的亚格点偏差（截断方向恒定偏暗）。

本仓实测（480×480 真实裁片，真实 Rust 二进制，**字节数零变化**）：

| 图片 | min/max | 旧 Lloyd | **保留最优 + 爬山** | 相对旧版 |
|---|---|---|---|---|
| 壁纸 480×480 | 32.471 | 32.471 | **33.297** | **+0.83 dB** |
| 照片 480×480 | 38.577 | 38.577 | **43.442** | **+4.87 dB** |
| 本仓合成纹理 128×64 | 20.00 | 23.29 | **24.31** | **+1.02 dB** |

这是 **D 类**（跟基数无关的编码质量），不是三进制红利——二进制基线也能用，只是
本仓把它放在 TT3 侧。代价是编码慢 6~7×（离线步骤，不进采样热路径）。

**三色的天花板在哪（实测）**：`mid` 被格式钉死在端点连线上（解码器只能从 17 字节
重算），这条约束值 **+1.2 ~ +8.3 dB**——但那是 **oracle 自由 3-means**，不可解码。
每块自由 `t` 值需额外 ~3 bit，且最优 `t` 的分布是**双峰**（壁纸 28% 在 t=0.50、
21% 在 t=0.20），**任何全局常数 `t` 都无法覆盖**：实测全扫 0.35~0.65 无增益，
线性光中点、RMS 中点也无增益。所以「非线性中点」这条路已验证走不通。

## 2. 模型侧：TTX (MOD) 对比业界权重格式

| 格式 | 每权重比特 | 权重集 | GPU 直载 | 检错 |
|---|---|---|---|---|
| safetensors (f16) | 16 | 任意浮点 | 是（原始张量） | 无 |
| GGUF Q2_K | ≈2.56 | 量化桶 + 超块 scale | 需反量化内核 | 无 |
| BitNet b1.58（理论） | log₂3 ≈ 1.585 | {-1,0,+1} | 定制内核 | — |
| **TTX (MOD)** | **2（双轨）+ 偏置 log₂3** | {-1,0,+1} | **是（双轨字即内核布局）** | **GF(3) CRC-3** |

**强在哪：**

- **2 bit/权重 < Q2_K ≈2.56**，且**布局即消费格式**：文件里的 pos/neg u32 字
  就是 `trit-gpu` matmul 内核绑定的 storage buffer 布局（行整字、bit = 1<<(i%32)），
  上传零重排——这是「GPU-ready」的实义，不是口号。
- **与纹理侧同一种校验哲学**：权重/偏置 trit 流过 GF(3) CRC-3，单 trit 错全检；
  safetensors/GGUF 无容器级校验（GGUF 有 hash 字段但是可选摘要）。
- **偏置走基 3 打包**（5 trit/字节），与纹理索引同一套打包——格式内部自洽。

**弱在哪（如实）：**

- 双轨 2 bit > 理论下限 1.585 bit（+26%）——**B 类税**：为 popcount 位并行付出的
  代价，与本仓 GPU 内核的取舍一致；要省这 26% 得改打包就得重排，见边界文档。
- **只有线性层链**：没有卷积/注意力/名字表/张量命名——是三值 MLP 的交换格式，
  不是通用模型格式。对标的是「BitNet 风格权重的最小可校验容器」。
- 层间衔接（上层输出 = 下层输入）由写者保证，容器只校验层内形状与字数一致。

## 3. 特点清单（两种载荷共有）

1. **小端、定头、逐段校验**：魔数/版本/kind/flags/段长/内容校验和，任何不一致
   都是结构化错误（错误枚举带实际值），绝不猜。
2. **校验按内容基数**：GF(3) CRC-3，生成多项式 x³+2x+1 本原（x 模 g 阶 = 26），
   3 trit 打包成 1 校验字节。
3. **零依赖解析**：解析器只做算术与比较，无 serde/alloc 大头（读入时按段切片）。
4. **版本策略**：TTX1（PR #125，纯纹理）的**字节规范与读器常量**保持存档；但块形状
   从 4×10 改成 8×8 后它已无法表示当前 crate 的 `TritTexture`，读写入口恒返回
   `TtxV1LayoutMismatch`（§4）。TTX2 容器 kind 分流，
   未知 kind/非零 flags 显式拒绝（前向兼容留给未来版本号，不留静默猜测）。

## 4. TTX1 布局（纹理，v1，保留）

> ⚠ **TTX1 与 v2 的 TT3 块布局已经不兼容**：TTX1 按 4×10 / 12 字节块编码，
> v2 按 8×8 / 17 字节块编码。TTX1 读器只认旧块，v2 的纹理请走 TTX2（kind=TEX）。
> 保留 TTX1 读器的意义是「旧文件还能读」，不是「新旧可互换」——实际上由于块形状
> 已变，`to_ttx` / `from_ttx` 在当前布局下**恒返回 `TtxV1LayoutMismatch`**，v1 格式
> 目前只有常量和读器骨架被冻结保存。
>
> 下表里的「4 的倍数 / 10 的倍数」是 **v1 的冻结约束**，**不是**当前 crate 的约束
> （当前是宽高皆为 **8 的倍数**，见 §5.1）。

```text
0     4    magic "TTX1"
4     4    width  u32 LE（4 的倍数，v1 冻结）
8     4    height u32 LE（10 的倍数，v1 冻结）
12    4    blocks u32 LE（= (width/4)·(height/10)）
16    12N  块载荷（4 字节 RGB565 端点对 + 8 字节基 3 索引）
16+12N 1   GF(3) CRC-3（对全部块的 40·N 个索引 trit）
```

TTX1 的形状常量（4×10、12 字节块、40 trit/块）**冻结在 `ttx.rs` 里**，不跟随
crate 的 `BLOCK_*` 常量走——否则改块形状会静默改变已发布格式的含义。

## 5. TTX2 布局（容器，v2）

```text
0     4    magic "TTX2"
4     1    kind：0 = TEX（纹理+mip 链），1 = MOD（三值模型）
5     1    flags（必须 0，非零拒绝）
6     2    reserved（必须 0）
8     4    section_len u32 LE（kind 段字节数，不含头尾）
12    S    kind 段（见下）
12+S  1    GF(3) CRC-3（对 kind 段的规范 trit 流，定义见各 kind）
```

### 5.1 kind = TEX（GPU 纹理 + mip 链）

```text
0     4    level_count u32 LE（≥1）
每级：
+0    4    width  u32 LE（8 的倍数，≥8）
+4    4    height u32 LE（8 的倍数，≥8）
+8    17B  块载荷（B = (width/8)·(height/8) 块，行主序）
```

**每块 17 字节**：字节 0–1 = e0（RGB565 大端）、2–3 = e1、4–16 = 64 个索引 trit
（基 3 打包，5 trit/字节，低位在前）。

约束：每级宽高不增且至少一维严格递减（末级之后不得再有同级）；mip 语义
（半分辨率）由写者负责，容器只钉形状合法与字节对账。**8×8 方块让 2 的幂尺寸
一路减半到 1×1 全程合法**——这是 v2 换块形状的全部理由。**规范 trit 流** =
各级全部索引 trit 依序拼接（每块后 13 字节按 5 trit/字节解出 64 个 trit）。

**GPU 上传注意**：17 字节不是 4 的倍数，块起点**不再 u32 对齐**。旧内核按
`block_id * 3u` 取字（依赖 12 字节的整除关系）会全图错位；v2 内核按**全局字节
偏移**取字节（`byte_at()`），宿主把字节流尾部补齐到 4 字节倍数即可，不改任何块偏移。

### 5.2 kind = MOD（三值模型，GPU-ready 双轨）

```text
0     4    layer_count u32 LE（≥1）
每层：
+0    4    inputs  u32 LE（≥1）
+4    4    outputs u32 LE（≥1）
+8    4    words_per_row u32 LE（= ceil(inputs/32)）
+12   4W   pos 字：outputs·W 个 u32 LE（行主序，行内 bit = 1 << (i%32) 表 +1）
+12+4W 4W  neg 字（同布局，bit 表 -1）
+…    B    bias：outputs 个 trit 基 3 打包（5/字节），digit = value+1 ∈ {0,1,2}
```

约束：pos 与 neg 同一字同一 bit **不得同时置位**（双轨不变式，违反 = 结构化
错误——这是 PR #116 设计否决的教训：非法轨组合必须显式拒绝，不许 panic、
不许静默当 0）。**规范 trit 流** = 每层每行的 W·32 个权重 trit（含零填充尾，
digit = value+1）依序，随后该层偏置 trit。

## 6. 转换路线（下一步）

容器定位是**交换**：入向（PNG/RGBA → TTX1/TTX2-TEX；三值矩阵/GGUF 风格权重 →
MOD）与出向（TTX → RGBA/PNG 预览）按「先有格式、后有转换」的顺序做；转换器
落在独立模块，不把 PNG 解码依赖塞进本 crate（实验层互不依赖的既有规矩）。
