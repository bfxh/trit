# 经验与负结果

> 这份文档记两件事：三进制的**代价**，和我们试过并已证伪/已修掉的路。
> 每条都尽量给可复算入口；不能在仓库内复现的会标"未复现"，不当结论用。

## 1. 三进制不是免费的（代价清单）

| 代价 | 数字 | 复算入口 |
|---|---|---|
| **浮点精度** | 同比特存储下，三值浮点相对误差上界是二进制的 **3 倍**（`3^{1-p}` vs `2^{-B}`，白丢约 1.58 bit） | `crates/trit-float`（`trit-float stats`） |
| **浮点范围** | 动态范围要拿精度换：32 位匹配指数位时 log10 范围 353 vs IEEE 83，但有效位 6.92 → 5.73（≈15× 误差）；不是白拿 | `trit-float range` |
| **对称舍入** | "奇数基 + 对称舍入 ⇒ 期望误差为零"**未复现**：half-even 只是把平局偏差翻符号（p=4：+0.60% → −0.52%），精度上来后两者都趋 0 | `trit-float rounding` |
| **算术** | 打包三进制的加法/乘法要逐 lane 进位，远慢于 i64；本仓因此**只做逻辑 + 位并行点积**，不做打包算术 | `crates/trit-dot`、[CHANGELOG](../../CHANGELOG.md) |
| **CPU 三值内核带宽** | 掩码 21.5、tryte 24.9 GB/s vs 本机 33 GB/s 访存墙（65–75%） | `crates/trit-ops/README.md` 实测一 |
| **tryte 的适用范围** | 49152 行时仍比掩码慢 5.5%；反超点已抬到 65536 行 | `bench --pair 掩码 tryte` |
| **GPU subgroup** | 1.341 ps/MAC vs SIMT 0.298（**4.5× 慢**） | `crates/trit-gpu/README.md` |
| **GPU 2-popcount** | 比 3-popcount 慢 1.9%（少一次 popcount 抵不过额外移位） | `crates/trit-gpu/README.md` |
| **训练（STE）** | 三个变体在 2×3 无噪任务上同分（都在第 99 步达标），选型需要更大/带噪任务 | `crates/trit-train` |
| **生态** | 没有原生三值硬件；权重必须靠 QAT 才能保住质量（推理端省字节，训练端付代价） | [docs/positioning/DESIGN.md](../positioning/DESIGN.md) |

## 2. 已证负结果（别重复试）

- **打包三进制算术**：取反 1.48×、加法 133×、乘法 3348× 慢于 i64（**未复现**：来自仓库外的
  打包算术原型，未随本仓发布；本仓不依赖这条结论做设计）。
- **GPU 2-popcount**：−1.9%（2026-10-25，说明该内核不是 popcount-bound）。
- **GPU subgroup（SPIR-V 路径）**：16×32/warp，1.341 ps/MAC，4.5× 慢于 SIMT。
- **split-K 单独使用**：0.120–0.122 ps/MAC，输给 3-popc 的 0.101–0.103。
- **K 段 16**：预评估要多 128 次 `workgroupBarrier`/CTA，没做。
- **tryte 小行数整表**：0.40×（已修：拆表 2+3，现 1.07×）。
- **fp16 存储变体**：只有 −16%，是带宽账的一部分，不是免费午餐。
- **位平面算术加法**：进位链串行，不做；位平面只做逻辑与强加法。

## 3. 测量经验（比结论更值钱）

1. **只信相邻配对**。同一段代码换个位置，读数能差 25–40%；`bench --pair` / 交替轮次才有判决力。
2. **小规模会把结论测反**。位平面 ALU 在 1 M trit 时，8 线程（5.4 Gop/s）比单线程（14.9 Gop/s）
   还慢——线程创建开销压过计算；16 M trit 才看到真实扩展性。
3. **计时建表必须用差分法**。直接给建表循环计时会被死存储消除优化掉，测出来不到真实值的一半。
4. **表内横向排名不可当精确排名**。分形状表是顺序测量，只能看量级。
5. **负结果要连同判据一起记**。"慢了多少、靠什么判慢、什么条件下"三者缺一，结论就不能复用。
6. **软件预取对顺序访问没有收益**（±5% 噪声内）——硬件预取器已经覆盖；别拿它当性能优化交差。
7. **换更强的基线，倍数会掉一个量级**。公开系统综述（Nature Machine Intelligence 2024，
   DOI `10.1038/s42256-024-00897-5`）里 79% 的 PDE+ML 论文对着弱基线报加速；Kochkov 2021 的
   40–80×，在伪谱基线上被基线自己快 80× 以上抹平。报倍数前先问「这个基线是不是该问题最强实现」，
   口径见 [DOCUMENTATION.md](../specs/DOCUMENTATION.md) §5。
8. **更低的权重 `rel_l2` 不等于更高的 STS**。GPTQ 残差侧车在 1379 对上：rank 32/64 的
   `rel_l2` 从 rank 16 的 0.874 降到 0.832/0.791，Pearson 反而从 0.7769 降到
   0.7752/0.7677（0.2/0.9 SE，噪声内）；只有 rank 128 升到 0.7995。中间档字节翻倍不涨点。
   低比特补丁必须同时报「权重误差」与「任务指标」，拿前者代理后者会把噪声读成收益，
   见 [WSP-BERT6-RESULTS.md](../research/WSP-BERT6-RESULTS.md) §3.15。
9. **位宽和 group 也不是单调的**。128 对上均匀 int5 g32 的 Pearson 0.9254 高于 f32
   0.9235，int6/int8 反而 0.9232/0.9233；int5 GPTQ 把 `rel_l2` 压到 0.073，Pearson
   却只有 0.9223。4-bit GPTQ 全量把 `rel_l2` 从 0.2750 压到 0.2271，Pearson 只从
   0.826061 涨到 0.826129，仍低 f32 0.00128。全量 5-bit g128 字面越过 f32（0.829203 vs
   0.827406，+0.00180），g64 也越过但更弱，g32 反而低 0.00055；int4 g32（0.826061）只低
   0.00135，同字节 rank16 只有 0.776944。**越过只有 0.16 SE；1251 对留出集 Δ 仍
   +0.001785，方向没有消失，但 10k 配对 bootstrap 95% CI 含 0、单侧 p=0.075，
   幅度不显著**。结论是「方向稳定、幅度不显著」，不是稳定超过 f32。选档泄漏可以
   通过留出集排除，但「小幅度 + 小样本」本身仍不足以支撑更强结论。见 §3.16。
   真正稳定的越过来自**容量**：12 层 L12 int4 g32 全量 0.837505 / 0.832047，对 6 层
   f32 是 +0.010099 / +0.011723，95% CI (+0.003183, +0.017247)，p=0.0026，留出集
   p=0.0029；它只用 6 层 f32 的 25.0% 线性字节，且和 L12 自己的 f32 统计平手
   （−0.000089 Pearson）。先导复用 L6 embedding 会污染结论：两模型 `word_embeddings`
   的 `rel_l2` 是 0.376，L12 必须用自己的第 0 层输入。见 §3.16.3。
10. **全量评测先砍诊断，再按句并行**。原 `bert6` 每趟跑 4 次全量前向（f32 real、
   f32 random、量化 real、量化 random），后两次只服务 `random_vs_f32`；L12 1379 对
   要 99 分钟。`TRIT_SKIP_DIAG=1` 砍掉两次 random，`TRIT_THREADS=24` 按句并行，
   同一趟降到 171.7 s（34.7×），f32/int5 的 Pearson、Spearman 与 1379 个 preds
   逐位不变（maxdiff 0）。并行只切 batch，不动句内层序与归约顺序；`capture=true`
   的逐层快照仍走串行。见 §3.16.6。
11. **同一模型/数据的 f32 基线可以跨趟缓存**。同一 `model + data_dir + layers`
   下 f32 `f32_sts` 不随量化位宽变；缓存命中后只跑量化前向，1379 对从 173.1 s
   降到 88.6 s（1.95×），128 对从 16.3 s 到 8.0 s，f32/int4/int5 的 preds 逐位
   不变。代价是 `f32_vs_reference` / `real_vs_f32` / `random_vs_f32` 变 null；
   `activation=all` 或带 sidecar 时必须禁用缓存。JSON 缓存必须开
   `serde_json` 的 `float_roundtrip`，否则重解析 preds 会差 1 ULP。见 §3.16.7。
12. **校准必须先跳 padding，再谈层内重建**。旧 `quant_compare_exact.py` 每 172 行抽
   token、不读 mask；176,512 行里只有 39,031 个有效 token，padding 行带共同偏移，
   全行均值 RMS 0.396，mask-aware 只有 0.103。用前者算 bias 修正，层输出误差假降
   37–40%；用后者只有 0.4–0.8%。接到 `bert6` 全模型后，1379 对 STS 只动
   +0.000041（int3）/ +0.000070（int4）Pearson，与 0.4–0.8% 一致。更关键的是
   L12 int4 全量 `0.837505` 已经和 f32 `0.837595` 统计平手，4-bit 没有可买的
   Pearson。复算：`TRIT_CALIB_BIAS=1 TRIT_CALIB_SCALE=1 TRIT_WEIGHT_BITS=4`
   跑 `miniLM-l12-sts-full`；结果在 `WSP-ALT.md` §3.5。
13. **同字节预算先问块的位置，再问权重误差**。L12 上把层 11 的
   `attention.output.dense` 的 int2 降级换成层 9 的同类矩阵，形状、字节、
   `proxy_err_ratio`（0.91552）都不变，全量 Spearman 却从 `0.816255` 到
   `0.818137`（+0.001882）；纯 int3 是 `0.813362`。权重 MSE 代理看不见块在残差流
   里的位置，也看不见它离最终句向量多远。另一个反例：规划器 v1 在 128 对低于
   int3（0.885716 vs 0.897582），全量却高于 int3（0.819473 vs 0.818440）；
   **128 子集能测反，预算变体至少跑全量**。严格同字节结果见
   `WSP-BUDGET-RESULTS.md`。
14. **同字节块交换也不要信 128 的单块排名**。把 v6e 的层 11 `intermediate.dense`
   的 int2 平移到层 10（I10），128 对只涨 `+0.001766 / +0.004692`，全量是
   `+0.000934 / +0.000761`；把层 11 `output.dense` 的 int2 平移到层 3（F3），
   128 对双指标为正，全量 Spearman 反而 `−0.000471`。128 只能筛候选，不能定胜负。
   I10 对纯 int3 的 10k bootstrap CI 两个指标都过 0，但对 v6e 的两个 CI 都跨 0；
   所以 I10 只能算中间基线；K10K11 在其上再改两个升级位置。复算：
   `python scripts/wsp_budget_swap.py --base budget-l12-int3-v6e.json --move 11:i>10:i`
   生成同字节预算，再按 `WSP-BUDGET-RESULTS.md` §7 跑全量。
15. **升级块也有位置，但 128 的增益不能相加**。K10K11 把 I10 的 Q3、K4 两个 int4
   升级移到 K10、K11：128 对只涨 `+0.001138 / +0.001495`（相对 I10），全量是
   `+0.001858 / +0.001651`；这次 128 低估。对纯 int3 全量 `+0.005039 / +0.007187`，
   10k CI 双指标过 0；但对 I10 的 50k Spearman 下界只有 `+0.000048`，对 v6e 的
   Spearman CI 还跨 0。结论只能写到“K10K11 是当前严格同字节优先点，late key
   位置略好”，不能写“全面优于 v6e/追平 int4”。K9 再补一个 late key 在 128 上只有
   `+0.0002–0.0003`，没有全量追。复算：
   `python scripts/wsp_budget_swap.py --base swap-11ito10i.json --move 3:q>10:k --move 4:k>11:k`
   再按 `WSP-BUDGET-RESULTS.md` §7 跑全量。
16. **逐块全量双向表能把“位置”从代理猜变成可测，但单块 Δ 不能相加，
   而且 in-sample 表不等于留出验证**。
   M1.3 对纯 int3 的 72 个线性矩阵逐个做 `3→2`，各跑 1,379 对：29 块双升、
   38 块双降、5 块混合。最耐降级是层 5–9 的 f/v/i/o（`7f +0.005461`、
   `7v +0.004741`、`8v +0.004321`、`5f +0.004127` ΔSpearman），最不能碰是
   late key（`11k −0.009777`、`11v −0.008801`、`10k −0.004831`）。
   按表把供体换成 F5/F7/V7 得到 `F5F7V7`：全量 `0.830384 / 0.828678`，
   相对 K10K11 `+0.006905 / +0.008129`；但 128 上反而低
   `−0.006245 / −0.008888`，**128 与全量符号相反**；两者
   `proxy_err_ratio` 仍同为 `0.91552`，代理仍看不见位置。`F5F7V7` 距 int4
   仍差 `−0.007121 / −0.003369`，50k CI 跨 0，不能写“追平 int4”。
   M1.4 再做 72 块 `3→4`（45 双升 / 17 双降 / 10 混合），得到 `R12`
   （6 int2 / 54 int3 / 12 int4，仍 `10,782,720 B`）：全量
   `0.833671 / 0.835411`，相对 F5F7V7 `+0.003287 / +0.006733`（Spearman
   50k CI 过 0，Pearson 跨 0）；相对纯 int4 Pearson `−0.003834`、
   Spearman `+0.003364`，两个 50k CI 都跨 0。**升级收益和降级伤害不是同一张
   曲线**：`11k` 升 int4 只有 `+0.000207`，`8v`/`3v` 反而双降；`R15`（15 int4）
   两个指标都低于 `R12`（12 int4），说明 int4 数量不保证更好。按 6 个来源拆开，
   `R12` 对 F5F7V7 是 4 胜 1 平 1 负，但对纯 int4 是 0/6 胜（MSRvid/headlines
   各低 `−0.017`）；总体 Spearman 反超更像跨来源排序/校准效应。`R12` 仍是同一批
   1,379 对上的 in-sample 搜索，没有 held-out；数据里 2,758 个句子 ID 全部唯一，
   按 pair 切分天然 sentence-disjoint，但本轮还没做切分复验。下一步必须补
   leave-one-source-out / train-test 切分或第二模型，不能直接写“3-bit 超过 4-bit”。
   复算：`python scripts/wsp_budget_perturb.py --base budget-l12-pure-int3.json
   --bits 2 --run ...` 和 `--bits 4 --run ...`；表见
   `WSP-BUDGET-RESULTS.md` §8/§9。
17. **in-sample 块表在外部数据上会负迁移；“总体点估计最好”不等于“默认候选”**。
   STS benchmark 上 `R12` 是 1,379 对的点估计最优（`0.833671 / 0.835411`），
   对 F5F7V7 也双正；但三套外部数据（SICK-R/STS12/STS13，各前 1,000 对）
   给出不同方向：`R12`/`R10`/`F5F7V7` 在 SICK-R 负、STS12/13 正；
   `K10K11` 在 SICK-R/STS12 正、STS13 轻微负（`−0.000308 / −0.000291`）；
   已测 6 个同字节配置里只有 `v6e`/`I10` 三套外部点估计全正，且 `I10` 只有
   SICK-R 双 10k CI 过 0。`I10` 对 K10K11 在 SICK-R 略低、STS12 略高
   （CI 都跨 0），STS13 显著更高（`+0.002435 / +0.002197`，CI 过 0）；
   代价是 STS 全量 K10K11 对 I10 `+0.001858 / +0.001651`（50k CI 下界过 0）。
   回头看，6 来源上 `R12` 对 int4 是 0/6 胜、留一来源时符号会翻转，已经提示
   “总体反超依赖来源构成”；三套外部只是把它坐实。**结论：选默认不能只看
   in-domain 点估计，要看外部最差方向；in-domain 赢家和外部稳健赢家可以是
   两个不同配置。** 三套都有句子跨 pair 复用（SICK-R 1,088、STS12 1,891、
   STS13 1,898 唯一句 / 各 1,000 对），下一步要第二模型/任务头。

18. **第二模型会推翻“块表可迁移”的假设；重扫不等于有通用规则**。把 L12 的
   `I10`/`K10K11`/`R12` 位宽布局按绝对层号投影到 `all-MiniLM-L6-v2`（6 层/
   384 hidden，全量 1,379 对），三个都低于 L6 纯 int3：I10 投影
   `−0.004152 / −0.001109`、K10K11 投影 `−0.004421 / −0.001300`、R12 投影
   `−0.006938 / −0.003261`；按输出端对齐缩放的 R12 尾段是
   `−0.000100 / −0.000702`，10k CI 都跨 0，只是统计中性。L6 自己重扫 36 块
   后能选到同字节 `5 int2/26 int3/5 int4` 的 `0.828687 / 0.821084`，相对纯
   int3 `+0.014093 / +0.010660`（双 CI 过 0），点估计高于 int4
   `+0.002626 / +0.001731`，但对 int4 的两个 CI 都跨 0；它仍是同一批 pairs
   上的 in-sample 选块。两折 held-out 的 ΔS 是 `+0.009694 / +0.000707`，
   CI 都跨 0（690 对测试折不够）。**结论：块级敏感度有模型内信号，但没有
   一个 L12 布局能在 L6 上保住增益；`I10` 只能写成 L12 外部保守默认，不能
   当跨模型默认。下一步要的是与模型无关的选择规则，或每个模型重跑块表。**
   表见 `WSP-BUDGET-RESULTS.md` §11 与 `data/wsp-budget-l6-*.tsv`。

19. **减少手工块数不等于消除选择方差**。新增 `scripts/wsp_budget_rescan.py`
   后，按“每形状组 2 降 2 升”在 L6 上选出 `6/24/6`，全量
   `0.831304 / 0.824457`，比纯 int3 高 `+0.016710 / +0.014032`，点估计也
   高于纯 int4 `+0.005244 / +0.005103`。但同一结构在两折训练折上选块后，
   测试折对 int3 的 ΔP/ΔS 是 `+0.007193 / +0.002260`（A→B）和
   `+0.007985 / +0.006351`（B→A），CI 全跨 0；对 int4 的点估计两折都转负。
   **固定结构只减少自由度，不消除“从 36 块里挑块”的搜索方差；全量点估计
   仍是 in-sample，选择本身必须交叉拟合留出，不能当默认规则。** 表见
   `WSP-BUDGET-RESULTS.md` §11.6 与 `data/wsp-budget-l6-bootstrap.tsv`。

20. **两折不够，5 折交叉拟合才看到 procedure 的均值**。把选择器放进 5 折 ×
   2 种子：每折只用其余 4 折的块 Δ 选 `per_shape=2`，候选只在测试折计分，
   5 个测试折拼成 OOF。两个种子 OOF 是 `0.827074 / 0.821085` 和
   `0.824388 / 0.817272`，均值 `0.825731 / 0.819179`；相对纯 int3 均值
   `+0.011137 / +0.008754`（10 折中 P 9/10、S 8/10 正），相对纯 int4 均值
   `−0.000330 / −0.000175`（10 折中只有 5/10 正）。折级均值与 OOF 差小于
   `0.0005`。**两折的 50% 训练让选择方差压过均值；80% 训练后 procedure 稳定
   优于 int3，但仍只打平 int4。** 结论：评估“选择过程”要用交叉拟合，不能
   拿一次 50/50 切分下结论；也不能把全量 in-sample `0.831304` 当泛化读数。
   表见 `WSP-BUDGET-RESULTS.md` §11.7 与 `data/wsp-budget-l6-cv.tsv`。

21. **“相对深度 + 块类型”的规则不是对称的跨模型规则**。`wsp_budget_rule.py`
   只读源表、不看目标块表：L12→L6 选出 `6/24/6`，`0.828707 / 0.824484`，
   对纯 int3 `+0.014113 / +0.014060`（双 10k CI 过 0），对纯 int4
   `+0.002646 / +0.005131`（CI 跨 0）；反过来 L6→L12 选出 `6/60/6`，
   `0.827813 / 0.823365`，对 int3 `+0.009373 / +0.010004`（CI 过 0），
   对 int4 `−0.009692 / −0.008682`，Pearson CI 整段为负。**单看一个方向会
   误以为规则能跨模型；两个方向都做后才知道它只稳定优于 int3，从没统计上
   超过 int4。** 这类规则只能当候选生成器，不能替代每模型重扫。表见
   `data/wsp-budget-rule-candidates.tsv` 与
   `data/wsp-budget-rule-bootstrap.tsv`，正文见 `WSP-BUDGET-RESULTS.md`
   §11.9。

22. **一对模型的正向不等于跨模型规则**。M1.9 的相对深度规则在 L12→L6 上
   `+0.014113 / +0.014060`（对 int3，双 CI 过 0），看起来可用；M1.10 换到
   3 层 L3 后，两条规则候选对纯 int3 是 `−0.012450 / −0.010778` 和
   `−0.010801 / −0.013168`，CI 都整段为负；换到同深度不同训练目标的
   par-L6 后是 `−0.016161 / −0.007308` 和 `−0.011203 / −0.008646`。
   更关键的是**同一套 L12 布局**在 all-MiniLM-L6 上是 `+0.014113 / +0.014060`，
   在 par-L6 上是 `−0.016161 / −0.007308`；**L6 自己的最优 `6/24/6` 布局**
   也从 `+0.016710 / +0.014032` 翻成 `−0.011203 / −0.008646`。同为 6 层、
   同为 384 hidden、同字节账，只换训练目标就双指标符号翻转。L3 的原生重扫
   k1 `3/12/3` 只打平 int3（`+0.000045 / +0.002787`，CI 跨 0），k2 `4/10/4`
   Pearson 转负（`−0.004695`），说明 3 层没有同字节 headroom；但原生 k2 仍
   比规则候选高 0.006–0.008（P）/0.011–0.014（S），所以不能拿“L3 太浅”
   替规则选错块开脱。**跨模型迁移必须至少换一个同深度、不同训练目标的模型；
   只做一对模型的双向检验，仍可能把“模型对特定”误写成“规则可用”。**
   表见 `data/wsp-budget-l3-candidates.tsv`、`data/wsp-budget-parl6-candidates.tsv`，
   正文见 `WSP-BUDGET-RESULTS.md` §11.10。

23. **STS 相关性增益不等于检索增益**。M1.11 把 STS 最优布局
   `R12`（L12，6/54/12）和 L6 `rescan-k2`（6/24/6）送 SciFact 检索：
   `R12` 的 STS 对 int3 是 `+0.015231 / +0.022050`，但检索 MRR `0.482`
   低于 int3 `0.497`/int4 `0.529`，nDCG@10 `0.526` 低于 `0.532`/`0.568`；
   对 int3 的 MRR/nDCG CI 都跨 0，对 int4/f32 基本整段为负。L6 `rescan-k2`
   的 STS 对 int3 是 `+0.016710 / +0.014032`，检索 MRR `0.474` 却显著低于
   int3 `0.510`（CI `[−0.065,−0.008]`），nDCG@10 `0.515` 显著低于 `0.541`。
   **块级重排能改善同一对句子的相对分数，不等于改善 corpus 全体的近邻几何；
   STS 候选进任务头前必须单独过检索/分类门。** 这轮只做 SciFact 检索、300 个
   qrels query、seq 64；分类头见第 24 条。表见
   `data/wsp-retrieval-scifact-*.tsv`，正文见 `WSP-BUDGET-RESULTS.md` §11.11。

24. **STS 增益也不转分类；量化对线性 probe 的正向要单独归因**。M1.12 在
   SST-2（6,920/1,821）上冻结编码器、只训 logistic 线性 probe，`C` 由 train
   内 5 折选出：L12 `R12` accuracy `0.814937` 低于 int3 `0.823723`/int4
   `0.840198`，`R12−int3` CI 跨 0、`R12−int4` CI 整段为负；L6 `rescan-k2`
   `0.802306` 对 int3/int4 的 CI 都跨 0。**检索和分类两个任务头都没有接住
   STS 的块级增益。** 另有一条独立观察：L12 均匀 int4 比 f32 高
   `+0.040088`（CI 整段为正），但 f32 probe 直接投到量化档会掉 `−0.029` 到
   `−0.062`；这是表示/正则化变化，不是 `R12` 的块级重排，不能混写成
   “BUDGET 布局提升分类”。表见 `data/wsp-classify-sst2-*.tsv`，正文见
   `WSP-BUDGET-RESULTS.md` §11.12。

25. **换一种线性头能复现排序，但仍不等于跨任务头通用**。M1.13 只把
   logistic 换成平方 hinge `LinearSVC`，同一批 SST-2 embedding/split：
   L12 `int4−f32` 从 `+0.040088` 扩到 `+0.043932`（CI 全正），
   `int3−f32` `+0.020769`（CI 全正），`R12−int3` `−0.004502`（CI 跨 0），
   `R12−int4` `−0.027516`（CI 整段为负）；L6 各档仍全跨 0。
   **L12 均匀 int4 的正向不是 logistic 损失特有，但 `R12` 仍不是块级增益；
   L6 仍没有量化优势。** f32 共享 SVM probe 投到 L6 量化档只剩
   `0.650–0.690`（自评 `0.802306`），说明线性边界方向也变了；没有几何诊断，
   不能写成量化普遍提升分类。表见 `data/wsp-classify-sst2-svc*.tsv`，正文见
   `WSP-BUDGET-RESULTS.md` §11.13。

26. **换分类集前先查标签分布；accuracy 口径会在不平衡集上塌到多数类**。
   M1.14 用 GLUE CoLA（8,551/1,043，dev 作 test）复验 int4 的正向。
   CoLA dev 是 69/31；按 SST-2 的“无类别权重 + accuracy 选 C”口径，
   四档全部塌到多数类：R12 正好是 `0.691275 / 0.408730`（全判 acceptable），
   看起来“所有量化档一样”其实是没有学到少数类。改成
   `class_weight="balanced"` + train 内 macro-F1 选 C 后，才有可比的读数。
   **不平衡二分类必须先固定类别权重和选 C 的指标，再比较表示。**
   在这个口径下，SST-2 的 int4 正向没有复现：L12 logreg `int4−f32 =
   +0.013341`（CI `[−0.006711,+0.033557]`），SVC `+0.008467`（CI
   `[−0.011505,+0.028763]`），L6 打平或略低；SST-2 的 +0.040/+0.044
   同量级效应已落在 CoLA 的 95% CI 之外。**单数据集的正向不能直接写成
   跨数据集结论；弱 probe 只能排除同量级效应，不能证明“完全不存在”。**
   表见 `data/wsp-classify-cola-*.tsv`，正文见 `WSP-BUDGET-RESULTS.md` §11.14。

27. **同一批线性头换第三个任务族才够判“泛化”；单数据集的正向要当成局部观察**。
   M1.15 用 TweetEval/hate（清洗后 8,985/2,734，`non-hate`/`hate`）做第三个
   单句二分类集。无权重口径沿用 SST-2：L12 logreg `int4−f32 = −0.003679`
   （CI `[−0.012802,+0.005486]`），SVC `−0.004826`（CI
   `[−0.015362,+0.005852]`）；balanced 口径反转为 logreg `−0.012694`
   （CI `[−0.022677,−0.002917]`）、SVC `−0.013028`（CI
   `[−0.022312,−0.003292]`），fixed C=1 仍为 `−0.009860`；L6 两 probe
   方向不一致。**SST-2 的 +0.040/+0.044 没有跨任务/跨数据集复现；hate 的
   2,734 条 test 把同量级效应更严格地排除。** 但 hate 的线性 probe raw
   accuracy 只有 `0.51–0.58`（低于多数类 `0.592173`）、AUC `0.67–0.71`，
   弱 probe 只能排除 +4pp 量级，不能证明更小效应不存在。表见
   `data/wsp-classify-hate-*.tsv`，正文见 `WSP-BUDGET-RESULTS.md` §11.15。

28. **数据集内稳定和跨数据集泛化要分开写**。M1.16 固定 SST-2 官方 test，
   只在 train 上做分层 5 折 × 5 种子（25 次重训），每次 80% train、C 固定，
   检验 probe 训练样本变化对 `int4−f32` 的影响。L12 logreg 均值
   `+0.042987`（min `+0.028556`，25/25 正），SVC `+0.044437`（min
   `+0.034596`，25/25 正），与全量 test 的 `+0.040/+0.044` 一致；L6 int4
   只有 `+0.0063/+0.0036` 且 22/25、19/25 为正，`rescan-k2` 接近 0。
   **SST-2 的 L12 int4 正向不是单次划分偶然，但不能据此说它跨数据集成立：
   CoLA/hate 仍不复现，L6 也不稳定。** 先问“同一数据集内是否稳定”，再问
   “跨任务/数据集是否泛化”，两个结论不能互相替代。表见
   `data/wsp-classify-sst2-subsample*.tsv`，正文见
   `WSP-BUDGET-RESULTS.md` §11.16。

29. **“稳定”之后先问“为什么只有这个数据集”，几何干预比再堆一个数据集更省**。
   M1.17 对同一批 SST-2/CoLA/hate embedding 做几何诊断和 PCA 干预：所有
   `WSPEMB1` 行都是单位范数，样本范数先排除；SST-2 L12 的 f32 有效秩只有
   `77.6`、两类质心余弦 `0.994`，int4 把有效秩提到 `200.1`、质心余弦压到
   `0.943`，类均值差方向落在前 4 个主成分的比例从 `0.405` 提到 `0.855`
   （test `0.422→0.821`）；CoLA/hate 的 `signal_top4` 基本不动，有效秩还略降。
   PCA 只保留 4 维时 SST-2 L12 `int4−f32 = +0.166392`（CI
   `[+0.138935,+0.194399]`），白化后仍 `+0.049423`（CI 全正）；CoLA balanced
   的所有 mode CI 都跨 0，hate 除 L6 raw（`−0.014631`、CI 全负）外也都跨 0。
   **SST-2 的正向是数据集特异的类别方向低秩
   集中，不是样本范数，也不只是协方差谱；但 PCA 是线性干预，不是量化过程的
   因果证明。** 这条比“再换第四数据集”更能解释“为什么只有 SST-2”，也避免
   把数据集内稳定误写成普遍提升。表见 `data/wsp-classify-geometry.tsv` /
   `data/wsp-classify-pca.tsv`，正文见 `WSP-BUDGET-RESULTS.md` §11.17。

30. **“相关结构”要再做一次可搬运性检验，才配叫机制**。M1.18 把 int4 的
   PCA 基搬到 f32（`--pca-fit`）：f32 的 `keep4` 从 `0.603` 回到 `0.694`、
   `keep16` 从 `0.680` 到 `0.722`，说明 int4 的基里确实有类别方向；但同
   维数下 int4 仍有 `0.769 / 0.806`，`int4−f32` 从 raw `+0.040088` 扩到
   `+0.075233 / +0.083470`。反方向把 int4 投到 f32 基，`keep4 +0.033498`、
   `keep64 +0.047776`，优势也没消失。**低秩集中只是伴随读数，不是充分
   机制；优势跟着 int4 自己的坐标/尺度走，搬基搬不过去。** 做机制解释时，
   先问“这个结构能不能被搬到另一档复现”，比再加一个数据集更快证伪。
   表见 `data/wsp-classify-pca-transfer.tsv`，正文见
   `WSP-BUDGET-RESULTS.md` §11.18。

31. **“基对齐”不等于“方向对齐”：先量跨档类方向，再谈低秩**。M1.19 直接
   比较 f32/int4 的类均值差方向，SST-2 L12 的 cos 只有 `0.5715`（test
   `0.5891`），夹角 `55.1°`，int4 方向长度是 f32 的 `1.94×`；f32 的方向
   只有 `27.8%` 落在 int4 前 4 个主成分里，int4 的方向只有 `7.2%` 落在
   f32 前 4 个主成分里。CoLA/hate 则几乎同向（cos `0.970–0.976`，夹角
   `12.6–14.1°`，范数比 `0.91–0.98`），跨基 top4 与自基 top4 接近。
   **M1.18 的负迁移不能只归因于“基不够好”：基对齐了，方向没对齐；
   M1.17 的 `signal_top4 0.855` 是 int4 自己旋转后方向的集中度，不是两档
   共享的低秩结构。** 做子空间/低秩类解释时，先算跨档方向余弦和跨基
   捕获率，再决定这个“低秩”是不是公共结构。表见
   `data/wsp-classify-direction.tsv`，正文见 `WSP-BUDGET-RESULTS.md`
   §11.19。

32. **方向角是症状，不是机制；先量类可分性，再用旋转对照一票否决**。
   M1.20 把 f32 的类方向转到 int4 方向（train 估计 Householder 反射，
   test 只做同一变换），再重训线性 probe：SST-2 L12 的 f32 仍是
   `0.800110`、`int4−f32` 仍是 `+0.040088`，L6 也逐位不变；反向把 int4
   转到 f32 方向同样不变。原因是正交旋转可逆，线性 probe 能把边界原样
   转回去。真正随 int4 变化的是 `sep = sqrt(between/within)`（Fisher 比值
   的平方根，旋转下不变）：SST-2 L12 train `1.288×`、test `1.236×`，
   Fisher `1.659× / 1.529×`；L6 `1.126× / 1.073×`；CoLA/hate 都在 1
   附近。**SST-2 的正向对应类可分性上升，不是方向旋转；低秩集中、基
   迁移失败、方向夹角都是伴随读数。** 旋转只改方向、保持范数，`sep` 还
   包含方向长度和类内散度，所以旋转对照只排除“方向角”，不排除“长度/
   类内结构”。以后遇到“方向/角度变了”的几何解释，先做一个可逆线性变换
   对照；如果精度不变，就别把它写成机制。表见
   `data/wsp-classify-rotation.tsv`，正文见 `WSP-BUDGET-RESULTS.md`
   §11.20。

33. **几何量同向不等于中介量：两端同向必须再过剂量-反应（M1.21）**。
    M1.20 看到 SST-2 L12 的 `sep` 和 int4 正向同向，很容易写成“类可分性
    是机制”；M1.21 沿 f32→int4 插值后发现：SST-2 L12 的 `int4−f32` 在
    1/16 剂量就是 `+0.0104`、1/8 `+0.0253`（约最终 `+0.0401` 的 63%）、
    1/4 `+0.0390`（约 97%）、1/2 `+0.0417`，而 `sep` 到 1/8 只有
    `1.068×`、到 1 才 `1.288×`；SST-2 L6 的精度峰值在 1/8（`+0.0198`），
    全剂量回落到 `+0.0066`，`sep` 到 1/2 才见顶；CoLA L12 的 `sep` 降到
    `0.936×`，accuracy 反升 `+0.0115`（CI 跨 0）。所以 `sep` 只是 SST-2
    L12 的伴随读数，M1.20 的解释要降级。教训：**两个端点同向只是相关性；
    要做剂量-反应，看谁先饱和、是否反向、是否只在某一数据集成立。**
    另外，线性 probe 对可逆线性变换不变，只有非可逆路径（量化、截维、
    加噪）才可能改精度；但即使路径非可逆，`sep` 也未必是中介量。表见
    `data/wsp-classify-interpolate.tsv` / `wsp-classify-interpolate-svc.tsv`，
    正文见 `WSP-BUDGET-RESULTS.md` §11.21。

34. **对角差值不是机制：train×test 交叉矩阵才能拆开“表示”和“正则化”**。
    M1.21 看到 SST-2 L12 低剂量早饱和，最容易写成“int4 像噪声一样正则化
    probe”。M1.22 固定每个 train λ 的 probe、评全部 test λ：SST-2 L12 的
    `(0,1) f32→int4` 是 `−2.86pp`、`(1,0) int4→f32` 是 `−23.23pp`，
    只有 `(1,1)` 是 `+4.00pp`；`(1/8,0)` 只有 `−0.50pp`、CI 跨 0。
    **单边量化都掉点，训练侧低剂量也不正则化；SST-2 的正向只在 train/test
    同时处于 int4 几何时成立，是匹配表示效应。** 同一矩阵里 CoLA L12
    的 `(1,0)` 是 `+2.88pp`（CI 全正）、`(0,1)` 是 `−5.27pp`、对角只剩
    `+1.15pp`（CI 跨 0）——CoLA 的小正向才是 train-only 正则化；hate L12
    只有 `(0,1)` 的 `+1.87pp`、train 侧为负、对角仍负。同样一个
    `int4−f32` 对角数字，在三个数据集上由三种不同的单边效应组成。
    教训：**任何一个“A 比 B 好”的端点差值，先做 train×test 或
    treatment×evaluation 的交叉表；如果两个单边各自为负、只有对角为正，
    那是交互/匹配效应，不是任一单边的普遍属性。** 表见
    `data/wsp-classify-cross.tsv` / `wsp-classify-cross-svc.tsv`，正文见
    `WSP-BUDGET-RESULTS.md` §11.22。

35. **量化残差不是“噪声”：先在 probe 方向上看它的类别条件投影**。
    M1.22 把 SST-2 L12 定位成 train/test 匹配表示后，最容易把 int4 的
    增益写成“量化噪声正则化”。M1.23 直接看 `r=int4−f32`：SST-2 L12 上
    只用 `r` 训练同一个线性 probe 就有 `0.832510`，比 f32 高 `+3.23pp`；
    逐行归一化 `0.833608` 不降，逐行范数只有 `0.550247`。PCA 子空间里
    `f32 + int4 rest(k=16)` 是 `0.839649`，与 int4 `0.840198` 打平，
    而 `int4 top16 + f32 rest` 退回 `0.800110`。几何上，SST-2 L12 的
    残差类均值是 f32 的 `1.59×`，与 f32 类均值近正交（cos `0.068`），
    但在 f32 probe 上的投影 `+2.665`，是 f32 margin `+2.206` 的
    `1.21×`；CoLA/hate 的残差类均值只有 `0.22–0.25×` 且投影为负，
    SST-2 L6 同向但只有 `0.33×`。高斯噪声掉 `−14.17pp`、整体行置换掉
    `−12.08pp`，残差缩放基本不掉。教训：**“残差/噪声”先别当正则化；
    先算它的类别条件均值、它在原 probe 权重上的投影、以及它在低方差
    子空间里的分量。残差方向可以带类别信息，幅度往往不是关键；投影
    为正且足够大时才可能变成端点增益。** 类别内置换/去类均值使用 test
    标签，是 oracle 诊断，不能写成可部署方法。表见
    `data/wsp-classify-residual.tsv` / `wsp-classify-residual-geometry.tsv`，
    正文见 `WSP-BUDGET-RESULTS.md` §11.23。

## 4. 工程经验

- **`enable f16;` 是模块级开关**：放进共享着色器，会让不支持 `SHADER_F16` 的 adapter
  连 f32 基线都建不出来（真实事故，已拆成独立 `matmul_f16.wgsl`）。
- **跨架构必须验编译**：x86_64 内建函数需要标量回退，否则 arm64 上直接编译失败。
- **文件行数不等于结构**：一个 786 行的文件里可以有 655 行的单函数；拆模块时要按职责看，
  而不是只看行数。
- **文档用仓库相对路径**：不写本机绝对路径，别人拿到仓库就能点开。
- **wgpu 30 复用 staging buffer 必须显式 `Buffer::unmap()`**：`BufferView` 的 `Drop`
  只清 host 侧映射记录，显存侧仍算 mapped；下一次 `submit` 直接判
  `Buffer ... is still mapped`。一次性 buffer 的写法（每次新建）掩盖了这条，
  改成持久 buffer 才暴露（WF32 `Wf32Plan`，PR #255）。
- **拿备份文件回滚源码后要 `touch` 它**：`mv x.bak x` 恢复的 mtime 可能比构建产物还旧，
  cargo 判定「没变更」继续链那份被变异过的 rlib —— 于是测试红的是刚刚已经被撤销的变异，
  而源码看起来是对的。做「删一行看测试会不会挂」这类验证时必踩（WF32 链式内核实测）。
- **本地门线要用 CI 的逐字命令，不要自创弱口径**：`cargo clippy -p <crate> --tests` 少了 examples/benches、
  也漏掉没点名的包；CI 是 `cargo clippy --workspace --all-targets --locked -- -D warnings`。
  2026-11-06 就是靠这条差别让三平台的 Clippy 步骤一起红（rust 1.99 新 lint `manual_contains`）。
- **两张门的口径不能互相顶牛**：`doc_pointers.py` 要求"同名文件必须写带目录的全路径"，而 `model_status.py`
  第一版只认 `src/` 相对 —— 表一改成全路径它就自己报红。改完它两种都认，并补一条变异钉住（`scripts/mutants/scripts__model_status.py.json`）。
- **一片做完再推**：同一分支连续 push 会把在跑的 run 顶掉（实测连续 4 次推 ⇒ 前一趟 CI 被 cancelled），
  白等一轮 8–10 分钟。收尾的门线全绿之后再推一次，比边写边推省时间。
- **CLI 的解析本身就吃栈**：clap 派生在 debug 下会把 20+ 个分支的临时量摊进同一个栈帧。
  只把**分发**搬到工作线程没用——`Cli::parse()` 还在主线程上；要连解析一起搬。
  本地尺子：`RUSTFLAGS="-C link-arg=-Wl,--stack,524288" cargo test -p trit-cli --test capacity_exec`
  （压小主线程栈就能稳定复现，不必等 CI 抽奖）。见 `crates/trit-cli/src/bigtask.rs`。
