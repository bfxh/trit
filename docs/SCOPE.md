# 仓库边界：主库存什么、不存什么

> 这份是**判据**，不是愿望清单。每条后面标它靠什么落地：
> `门` = CI 里能判红的脚本；`表` = `scripts/layers.json` 等登记表；`人` = 只能靠评审（这类要尽量少，
> 且必须写下"为什么门判不了"）。
> 分层与归位见 [LAYERS.md](LAYERS.md)，往里搬什么的排期见 [ROADMAP.md](ROADMAP.md)。

## 0. 一句话

**主库 `bfxh/trit` 是三值/多值计算的底座**：语义、算子、算法、学习机制在这里实现**一次**；
把底座接到某个产品、数据、平台上的那层代码（生产链）在各自的仓。
判据不是"这段代码重不重要"，而是"**换掉我手上这个项目，它还有没有意义**"——有，才可能进主库。

## 1. 收进来的四条（必须全满足，缺一条就不该进）

| # | 判据 | 反证的样子 | 落地 |
|---|---|---|---|
| R1 | **与具体项目无关**：不依赖某个项目的数据布局、服务、账号、UI | `parts_depth.rs` 里读某个场景目录名 | `人`（评审时看 import 与常量） |
| R2 | **有独立判据**：能对拍（穷举 / 闭式解 / 另一引擎 / 上游参考），不是只跟自己比 | 新算法没有任何 oracle，只有"跑通一次" | `门` `mutation_check`（改一个真值表项必须判红）+ `门` `test_surface`（无断言测试会被警告） |
| R3 | **可归位**：落进 L0–L4 某一层的定义（见 LAYERS §1） | 说不清它是算子还是产品逻辑 | `门` `scripts/layers.py`（不登记就红） |
| R4 | **能长期守**：公开面进 semver，或明确标 `publish = false` 的实验层 | 半截实现、TODO 挂三个月 | `门` `publish_graph` + `表` `layers.json` |

## 2. 不收的六类（逐类给真实例子与去处）

| 类别 | 例子（本机上真实存在的） | 正确去处 |
|---|---|---|
| 生产链 / 接入层 | diffusion 的训练脚本与数据管道、BSHSQ 物理引擎、memtri 的 MCP 外壳、DSH/桌面宠物类工具 | 各自项目仓，按 **git pin + tag** 依赖主库 |
| 治理与 CI 工具 | `repo-tools`（认领门、交接同步、技术标签索引）、`gitflow`、`snapshot`、`pr_hygiene` | `bfxh/repo-tools`；主库只**调用**它，不抄实现 |
| 一次性分析与笔记 | openai/math 的三份分析稿、逆向台账之外的手记、agent-wiki、`_handoff/*` | 本地笔记 / `_handoff`；结论要进主库就写成 `docs/` 的一节，不搬原文 |
| 大数据与不可再生素材 | 1,299 张 256² 纹理语料、场景渲染帧、风格样本视频、GGUF 权重 | 见 §3 的指纹政策，**不进仓** |
| 别的语言生态的成品依赖 | torch / triton / numpy / 外部 C++ 库 | 不进仓；主库只留接口与读数，依赖在各自生产链环境里 |
| 私有环境与凭据 | 本机路径、token、账号、hosts 配置 | `secret scan` 判红；文档里写能力不写机器 |

## 3. 数据与二进制政策（最容易写坏的一条，定死）

一个素材要不要进仓，问三个问题：

1. **它是不是判据的一部分？**（缺了它，某条测试就无法证明任何东西）
2. **能不能再生？**（脚本 + 固定种子能否逐位重新产出）
3. **多大？**（进仓的单文件上限 1 MiB，整个夹具目录上限 8 MiB；超了走指纹路径）

- 三问里 1 是且 2「可再生」⇒ 仓里存**生成脚本 + 种子**，不存产物。
- 1 是且 2 否（真机样本、外部下载）⇒ 存**内容级 SHA-256 清单 + 取数脚本 + 最小可判红切片**；
  全量素材留在本地数据目录，清单里写清指纹与规模。清单格式与指纹算法走
  `docs/DATASETS.md` 与 `trit-learn` 的 `fingerprint` 面（内容级，不只看文件名与大小）。
- 3 超限一律走上一条，不许"先塞进来再说"。
- 权重、缓存、`target/`、虚拟环境、模型 checkpoint ⇒ **永不进仓**（`.gitignore` + 门）。

落地：`门` `hazard_gate`（大文件/二进制面）、`门` `secret scan`、`人` 评审三问的回答有没有写在 PR 里。

## 4. 构建产物与机器状态

仓内文档（`CHANGELOG.md`、`docs/*.md`、crate 的头注释）记的是**读数与口径**，不记机器状态：
不写盘符绝对路径、不写"我机器上还剩多少 G"、不写只有本机才懂的目录。
要指代本机的动作，写成「清掉失效的旧 target 目录」这种与机器无关的描述。
`门` `scripts/docs_hygiene.py`：新增盘符路径判红，存量按目录计数进棘轮基线，只许变少。

## 5. 谁的事在哪个仓（分工）

| 仓 | 负责 | 不负责 |
|---|---|---|
| `bfxh/trit`（本仓） | 语义、算子、算法、学习机制、底座级门（分层/预算/发布图/变异） | 产品接入、数据管道、UI、治理自动化 |
| `bfxh/repo-tools` | 跨仓治理：认领门、交接同步、仓库体检、技术标签索引 | 三值语义本身 |
| 各项目仓（生产链） | 把底座接到该产品：数据、评测协议的产品侧口径、上线与回滚 | 重复实现底座算子/算法 |
| 本地 `_handoff/`、笔记 | 会话之间的状态与排期 | 不作为对外文档，不进任何公开仓 |

## 6. 进门流程（新东西来了走哪几步）

1. 先在 §1 四问 + §2 六类里定性质：**收 / 拒 / 搬（从别处搬进来）/ 拆（搬出去）**。
2. 收或搬 ⇒ 在 `scripts/layers.json` 登记层；有跨层依赖就登记 `allows` 并给原因；
   同能力已有权威实现 ⇒ 登记 `capabilities`，第二份必须带**含数字**的 `measured_gap`。
3. 加 `[[bin]]`/CLI 面 ⇒ 想清楚是不是该进 `trit-cli`（可发布），别让底座 crate 各自长壳。
4. 数据/夹具 ⇒ 按 §3 三问回答，答案写进 PR 描述。
5. 收尾：`fmt` / `clippy --all-targets` / `doc` / 测试 / `mutation_check` / `module_budget` /
   `test_surface` / `publish_graph` / `deps` / `ci_integrity` / `hazard` / `layers` / `docs_hygiene`。

## 7. 规矩 ↔ 门 的对照（哪条机器判、哪条只能人判）

| 规矩 | 靠什么 | 判红条件 |
|---|---|---|
| 依赖方向向下、crate 必须归位 | `门` `scripts/layers.py` | 回边、未登记、失效例外、陈旧登记、未知层名 |
| 同能力第二实现必须带实测差 | `门` `scripts/layers.py`（`capabilities`） | 缺字段、读数无数字、缺理由、同能力两条 |
| 可发布 crate 不依赖未发布 crate | `门` `publish_graph.py` | 方向违例、必填字段缺 |
| 不搞上帝模块 | `门` `module_budget.py` | 单文件 >800 行且未登记债务 |
| 测试要真判东西、不许删 | `门` `test_surface.py` | 无断言测试（警告）、计数跌破台账（红） |
| 关键规则改坏必须被发现 | `门` `mutation_check.py` | 存活变异、锚点找不到、空/等价变异混入 |
| 仓内文档不写本机路径 / CHANGELOG 不被覆盖 | `门` `scripts/docs_hygiene.py` | 新增盘符路径、CHANGELOG 结构与字节数棘轮跌破 |
| 密钥不外泄 | `门` secret scan（CI） | 命中形状 |
| 「换掉这个项目它还有没有意义」（R1） | `人` | 门判不了语义相关性，靠评审；记在这里是为了不假装它是门 |
| 素材三问（§3） | `人` + PR 描述 | 同上 |

## 8. 现状与欠账（不粉饰）

- prod 层 12/35 偏重；`trit-vcs`/`trit-orch`/`trit-procscan`/`trit-redteam`/`trit-unsafe`/`trit-lsp`
  方向是拆 `bfxh/trit-tools`，**必须排在分层门进 CI 之后**（见 ROADMAP §3）。
- 评测协议三件（清单 / 内容指纹 / 独立复核器）还在 `trit-parts` 里，该下沉 `trit-learn`（ROADMAP §1）。
- `docs/` 存量文档里有本机绝对路径（`GENERAL-PLAN.md`、`DATASETS.md`、`VISUAL-PLAN.md` 等），
  `docs_hygiene` 按目录计数进基线，**只许变少**；我没批量改别人的历史记录。
- `scripts/layers.py` 与 `docs_hygiene.py` 还没挂进 CI（`.github` 目录正被别的会话认领），
  现阶段只在本地与变异面生效——这是本文件所有"门"字目前最大的水分，写在这是为了不被当成已完成。
