# trit-gpu

三值矩阵乘的 WGSL 内核与同结构 f32 基线。三值数据用**双导轨**（`pos`/`neg` 两张位平面，2 bit/trit），
点积用四组 `countOneBits`：`Σ popc(aₚ&bₚ) + popc(aₙ&bₙ) − popc(aₚ&bₙ) − popc(aₙ&bₚ)`。

```bash
cargo run -p trit-gpu --features gpu -- bench --trits 1048576
```

没有可用 adapter 时测试自动跳过（`matmul::run` 返回 `None`）。

## 内核与实测（RTX 4060 Ti，512×4096×512，ps/MAC，5 次中位数，多轮复测）

| 内核 | 结构 | 三值 | f32 基线 |
|---|---|---|---|
| `main` | naive，一线程一输出 | 1.37–1.56 | 23.27–23.29 |
| `main_tiled` | 共享内存 16×16 tile | 0.173–0.209 | 2.409–2.424 |
| `main_tiled2` | 8×8 线程 / 每线程 2×2 | **0.125–0.138** | 2.412–2.424 |
| `main_tiled4` | 8×8 线程 / 每线程 4×4（32×32 tile） | 0.131–0.139 | **1.357–1.365** |
| `main_tiled2v` | 2×2 + `vec2<u32>` 打包共享读 | 0.151–0.156 | — |
| `main_splitk` | 2×2 + K 切 4 片 + atomicAdd | 0.123–0.125 | — |

**四个实验的结论（含三个负结果）**

1. **4×4 阻塞：三值无收益（慢 ~8%），f32 快 1.77×**。f32 每元素 32 位，load 是瓶颈，tile 复用直接见效；
   三值每 MAC 已经是 4 次 popc 主导，加深阻塞只加寄存器压力、还砍掉一半 workgroup。
2. **`vec2` 打包共享读：三值慢 ~20%**（0.125 → 0.153）。这条目标架构上向量化共享读没换来指令数下降，
   反而多了打包/取分量的开销。
3. **split-K×4：没有收益**（0.123–0.125，与 2×2 同级）。说明并行度并不是限制——
   2×2 本来就有 1024 个 workgroup / 65k 线程，早把 SM 填满了。
4. **popcount 天花板**：纯 `countOneBits` 微基准 **1.33–1.44e12 popc/s**；矩阵乘达到 **71–75%**。
   微基准本身还有约 1/3 的非 popc 指令，所以真实天花板更高、差距更大；
   但 split-K/vec2/4×4 都试过不赢 ⇒ 剩下的差距在**指令混合**（共享读、索引、屏障），不在并行度或共享内存宽度。

## 局限

- 只测这一张卡与一个规模档（512×4096×512）；没有 subgroup、fp16 基线、没有 K-split 的确定性归约版本。
- 计时是 5 组 ×20 次提交的中位数；GPU clock 与首次 pipeline 编译抖动大（reg2×2 在不同轮次 0.125–0.138）。
- GPU 测试需要 `--features gpu` + 真实 adapter，CI 上没有，因此**变异门不覆盖这些内核**；
  正确性靠 `tests/matmul.rs` 在本机对拍（含 1×1×1 与 33×100×17 非整字/非方阵边界）。
