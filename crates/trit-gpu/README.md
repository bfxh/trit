# trit-gpu

三值矩阵乘的 WGSL 内核与同结构 f32 基线。三值数据用**双导轨**（`pos`/`neg` 两张位平面，2 bit/trit），
点积用四组 `countOneBits`：`Σ popc(aₚ&bₚ) + popc(aₙ&bₙ) − popc(aₚ&bₙ) − popc(aₙ&bₚ)`。

```bash
cargo run -p trit-gpu --features gpu -- bench --trits 1048576
```

没有可用 adapter 时测试自动跳过（`matmul::run` 返回 `None`）。

## 内核与实测（RTX 4060 Ti，512×4096×512，ps/MAC，5 次中位数，多轮复测）

| 内核 | 结构 | 三值 | f32 基线 |
|---|---|---|---|
| `main` | naive，一线程一输出 | 1.37–1.56 | 23.27–23.29 |
| `main_tiled` | 共享内存 16×16 tile | 0.173–0.209 | 1.98–1.99 |
| `main_tiled2` | 8×8 线程 / 每线程 2×2 | **0.125–0.138** | 2.412–2.424 |
| `main_tiled4` | 8×8 线程 / 每线程 4×4（32×32 tile） | 0.131–0.139 | **1.00–1.01** |
| `main_tiled2v` | 2×2 + `vec2<u32>` 打包共享读 | 0.151–0.156 | — |
| `main_splitk` | 2×2 + K 切 4 片 + atomicAdd | **0.120–0.122** | — |
| `main_tiled2o3` | 2×2 + **3-popc**（OR 合并两次 popc） | **0.110–0.114** | — |
| `main2d`（f32） | 2D 16×16 线程块 naive | — | **3.118** |
| `main_tiled2k8`（f32） | 2×2 + K 段 8 | — | **1.155** |
| `main_tiled4k32`（f32） | 4×4 + K 段 32（共享 8 KB） | — | **0.911** |

**f32 侧的关键一步：128 位向量化装载**（全局 `array<vec4<f32>>` 视图 + 共享内存按
`vec4<f32>` 组织，内层一次读喂 4 个乘加）。四个 f32 内核都因此翻倍到两位数百分比：
naive 6.24→3.12、tiled 2.37→1.99、reg2 1.45→1.16、reg4 1.34→1.00。
三值侧试同样的 vec4 共享读是**负收益**（reg2 0.126→0.128、o3 0.110→0.126）——
三值每 MAC 已由 popc 主导，砍共享读没有回报，故只在 f32 侧启用。

**四个实验的结论（含三个负结果）**

1. **4×4 阻塞：三值无收益（慢 ~8%），f32 快 1.77×**。f32 每元素 32 位，load 是瓶颈，tile 复用直接见效；
   三值每 MAC 已经是 4 次 popc 主导，加深阻塞只加寄存器压力、还砍掉一半 workgroup。
2. **`vec2` 打包共享读：三值慢 ~20%**（0.125 → 0.153）。这条目标架构上向量化共享读没换来指令数下降，
   反而多了打包/取分量的开销。
3. **split-K×4：稳定快 3–5%**（0.120–0.122 vs 0.125–0.126，连测 5 轮）。并行度不是唯一原因
   （2×2 已有 1024 workgroup / 65k 线程），但它把每个 workgroup 的 K 循环缩短 4 倍、
   尾段不齐的浪费变小；代价是输出要先清零 + atomicAdd（整数加法可交换，结果仍是确定的）。
4. **K 段 16 word（屏障减半）：慢约 35%**（0.168–0.173）⇒ **屏障不是瓶颈**；
   把共享内存从 2 KB 抬到 4 KB 反而掉占用。
5. **3-popc（把两次 `popc` 用 `OR` 合并）：0.110–0.114，目前最快**（比 reg2×2 快 ~12%）。
   等号靠双导轨不交叠不变量 `aₚ&aₙ = 0`，`(aₚ&bₙ)&(aₙ&bₚ) = 0`，所以两次 popc 可并成一次 OR+popc。
6. **popcount 天花板**：纯 `countOneBits` 微基准 **1.33–1.44e12 popc/s**；按各内核 popc 密度校正后，
   最优内核达到 **79–82%**。
   微基准本身还有约 1/3 的非 popc 指令，所以真实天花板更高；
   barriers / 并行度 / 共享内存宽度都试过不赢 ⇒ 剩余差距在**指令混合**（共享读 + 索引 + 累加）。

## 对 NVIDIA cuda-oxide（Rust → PTX）的同尺对照

同卡（4060 Ti）、同形状（512×4096×512）、同布局（B 转置）、同一计时口径：

| 内核 | cuda-oxide | 本仓 WGSL（最新） | 谁快 |
|---|---|---|---|
| naive（2D 16×16 块） | 6.205 | **3.118** | 本仓 **2.0×** |
| tiled 16×16 | 2.225 | **1.989** | 本仓 **12%** |
| reg2×2 + K 段 8 | 1.348 | **1.155** | 本仓 **17%** |
| reg4×4 + K 段 8 | 1.557 | **1.002** | 本仓 **55%** |
| **最优对最优** | 1.348（reg2） | **0.911**（reg4 + K 段 32） | 本仓 **48%** |

**改进过程（同尺可复算）**：naive 23.4 → 6.24（1D→2D 线程映射）→ **3.12**（128 位装载）；
reg2 2.36 → 1.45（K 段 16→8）→ **1.16**（vec4 共享读）；reg4 1.36 → 1.34 → **1.00**（vec4 共享读），
K 段 16 到 0.953、K 段 32（共享 8 KB，接近上限）到 **0.911**；tiled 2.37 → **1.99**（vec4 装载）。
四对同结构全部领先。

**口径（不回避）**：仍是同算法、同分块结构，但向量化装载是实现级差异——cuda-oxide 的参考内核
没做；若他们同样向量化，差距会缩小（幅度未知）。三值 `main_tiled2o3` 0.110 对 cuda-oxide
最优 f32 0.911 ≈ 8.3×，但属不同表示，不能当同尺结论。
对照工程与安装步骤见 [`benchmarks/cuda-oxide-compare`](../../benchmarks/cuda-oxide-compare/README.md)。

## 局限

- 只测这一张卡与一个规模档（512×4096×512）；没有 subgroup、fp16 基线、没有 K-split 的确定性归约版本。
- 计时是 5 组 ×20 次提交的中位数；GPU clock 与首次 pipeline 编译抖动大（reg2×2 在不同轮次 0.125–0.138）。
- GPU 测试需要 `--features gpu` + 真实 adapter，CI 上没有，因此**变异门不覆盖这些内核**；
  正确性靠 `tests/matmul.rs` 在本机对拍（1×1×1、33×100×17 非整字/非方阵、k=37 标量装载回退；
  三值与 f32 共 11 个内核全部逐元素校验）。
