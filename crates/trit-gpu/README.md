# trit-gpu

三值矩阵乘的 WGSL 内核与同结构 f32 基线。三值数据用**双导轨**（`pos`/`neg` 两张位平面，2 bit/trit），
点积用四组 `countOneBits`：`Σ popc(aₚ&bₚ) + popc(aₙ&bₙ) − popc(aₚ&bₙ) − popc(aₙ&bₚ)`。

```bash
cargo run -p trit-gpu --features gpu -- bench --trits 1048576
```

没有可用 adapter 时测试自动跳过（`matmul::run` 返回 `None`）。

## 内核与实测（RTX 4060 Ti，512×4096×512，ps/MAC，5 次中位数）

| 内核 | 结构 | 三值 | f32 基线 |
|---|---|---|---|
| `main` | naive，一线程一输出 | 1.514–1.563 | 23.27–23.29 |
| `main_tiled` | 共享内存 16×16 tile | 0.173–0.190 | 2.409–2.424 |
| `main_tiled2` | 8×8 线程 / 每线程 2×2（16×16 tile） | **0.119–0.126** | 2.412–2.424 |
| `main_tiled4` | 8×8 线程 / 每线程 4×4（32×32 tile） | 0.131–0.134 | **1.357–1.365** |

**结论（如实）**：

- **三值侧 4×4 没有收益**（比 2×2 慢约 8%，两次复测稳定）。三值每 MAC 的计算已经很小
  （2 bit/trit 打包 + 4 次 popc），瓶颈不在共享内存搬运；再加寄存器阻塞只加了压力。
  所以三值最快仍是 `main_tiled2`。
- **f32 侧 4×4 快 1.77×**（2.41 → 1.36）。f32 每元素 32 位，load 才是瓶颈，32×32 tile 的复用直接见效。
- 最优对最优：三值 `main_tiled2`（0.119–0.126） vs f32 `main_tiled4`（1.36）≈ **10.8×**。

## 局限

- 只测了这一张卡与一个规模档（512×4096×512）；没有 K-split、没有 subgroup、没有 fp16 基线。
- 计时含 5 组 ×20 次提交的中位数，但 GPU 首次 pipeline 编译与 readback 抖动大（见本机 wgpu 笔记）。
- GPU 测试需要 `--features gpu` + 真实 adapter，CI 上没有，因此**变异门不覆盖这些内核**；
  正确性靠 `tests/matmul.rs` 在本机对拍（含 1×1×1 与 33×100×17 非整字/非方阵边界）。
