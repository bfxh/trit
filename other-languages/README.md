# 其他语言参考实现

本目录存放 `trit` 的跨语言**参考实现**，目的是让其他语言的使用者直接读懂三值语义、平衡三进制、5 trits/byte 与准入表，而不是把 Rust 工作区整体移植一遍。

## 硬规则

1. **非默认**：不进入 Cargo 工作区，不被任何 Rust crate 依赖，不参与默认 CI、发布和版本号。
2. **非稳定 API**：没有兼容性承诺，可以随时改写或删除。
3. **只供借鉴**：不承诺与 Rust 实现逐位等价；跨语言交换必须显式定义字节协议，不能把某个语言的内存布局当协议。
4. **零外部依赖**：参考实现只依赖标准库；不引入模型、训练框架或二进制现成件。
5. **结论仍按 A/B/C/D**：性能/精度结论必须带二进制基线，并按 [`docs/TERNARY-BOUNDARIES.md`](../docs/TERNARY-BOUNDARIES.md) 归类。
6. **保持最小**：每个实现只覆盖“能读懂语义”的最小切片；完整能力以 Rust 工作区为准。

## 当前实现

| 语言 | 路径 | 范围 | 运行 |
|---|---|---|---|
| Go | [`go/`](go/) | 平衡三进制整数、K3、5 trits/byte、KGate | `cd go && go test ./...` |

## 语言评估：什么语言值得做三进制

判断标准不是“语言流行度”，而是：

1. 有没有明确的消费方（嵌入式、FFI、Web、形式化验证、教学）？
2. 语言能否把三值语义表达清楚（ADT/枚举、位运算、溢出检查、SIMD）？
3. 维护成本是否低于“让用户直接调 Rust 或 WASM”？

### 优先做

| 语言/目标 | 价值 | 理由 | 建议范围 |
|---|---|---|---|
| **Lean 4** | 高 | K3/Ł3/B3 适合用归纳类型表达；[`openai/math`](https://github.com/openai/math) 的 Lean 语料提供了现成的验证生态；能把“可判红”从测试提升到定理 | 形式化真值表、准入表、5 trits/byte 的编解码不变量；不做运行时 |
| **C (C11)** | 高 | 最小 ABI、嵌入式、WASM，几乎所有语言的 FFI 都能调；header-only 小库复用面最大 | `trit_t`、K3、5 trits/byte、溢出检查；不做 SAT/BDD |
| **Python** | 中高 | 教学、原型、数据分析的入口；NumPy 可演示位并行；纯 Python 不适合性能路径 | 语义参考 + 真值表 + 测试；性能路径指向 Rust/WASM；按本仓 `AGENTS.md` 只作对齐基线，不交付生产实现 |
| **Zig** | 中高 | 现代 C 替代；显式分配器、comptime、C ABI 友好 | 与 C 同范围，强调无隐藏分配与边界检查 |
| **C#** | 中高 | .NET 生态、`Span<T>`/`System.Numerics`/SIMD、企业集成；`readonly struct` 适合表达 trit | 平衡三进制 + K3 + 位并行；不做完整 EDA |
| **TypeScript/JS** | 中 | 浏览器演示和 WASM 胶水；`BigInt` 可用但慢，TypedArray 更适合位平面 | 只做 WASM 绑定/演示，不手写高性能内核 |

### 有明确消费方再做

| 语言 | 价值 | 理由 | 边界 |
|---|---|---|---|
| **C++** | 中 | 游戏引擎、EDA、HFT 有 FFI 需求；维护成本高，和 C 重叠 | 已有 C++ 消费方时做 header-only；否则用 C |
| **Java/Kotlin** | 中低 | JVM 企业生态；Panama/Vector API 可做位并行，值类型仍在演进 | 有 JVM 消费方再做；否则用 WASM/FFI |
| **Swift** | 中低 | Apple 生态、值类型和 SIMD 友好 | 有 iOS/macOS 消费方再做 |
| **Julia** | 中低 | 数值/多重派发适合三值浮点与数组实验 | 只做研究原型，不作为生产内核 |
| **Haskell/OCaml/F#** | 中低 | ADT 表达三值语义自然，适合教学/语义参考 | 只做语义与真值表，不做性能 |
| **Go** | 中 | CLI/服务端易部署；GC 与跨平台 SIMD 支持仍不如 C/Rust 成熟，使其不适合高性能内核 | 已完成最小切片；不扩成完整工具箱 |

### 不建议单独做

- **PHP/Ruby/Perl/Lua**：除非有明确的宿主嵌入需求，否则维护成本大于收益；优先通过 C/WASM 复用。
- **R**：统计场景可能用到三值决策，但生态桥接成本高；先看具体包的需求。
- **纯前端手写 JS 内核**：性能不如 WASM；JS 只做胶水。
- **再来一个 Rust 端口**：Rust 已是主实现，重复没有收益。

### 一句话排序

如果只再加两个：**Lean 4（形式化语义）+ C（最大复用面）**。
如果还要一个教学/对齐入口：**Python**（只作 baseline，不交付生产）。
如果要做 Web 演示：**Rust→WASM** 比手写 TypeScript 内核更划算。

## 新增语言的最低要求

- 一个可读的 `README.md`：范围、非目标、与 Rust 语义的映射、运行方式。
- 一个最小测试集：K3 真值表、平衡三进制往返、5 trits/byte、边界与溢出。
- 不引入外部依赖；不复制 Rust 的内部实现细节。
- 在 [`docs/TERNARY-BOUNDARIES.md`](../docs/TERNARY-BOUNDARIES.md) 的 A/B/C/D 框架下写结论；没有二进制基线不算性能结论。
